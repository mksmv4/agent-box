# agent-box

agent-box запускает Claude Code в Docker-контейнере и ведёт с ним задачи твоего проекта по шагам.

- **Контейнер.** Claude работает в контейнере и видит папку проекта, а не весь компьютер. Файл `.env` ему закрыт. Без присмотра он выходит в интернет только по списку адресов.
- **Задача по шагам.** Задача — файл в проекте со списком шагов. Одна сессия Claude делает один шаг, коммитит и записывает, с чего продолжить. Следующая сессия продолжает с этого места.
- **Без присмотра.** Скрипт `agent-loop.sh` запускает сессии одну за другой, пока задача не готова. Нужно твоё решение — скрипт останавливается и присылает вопрос в терминал и в Telegram.
- **Оркестратор.** Скрипт может вести сессия Claude на твоём компьютере — оркестратор. На вопросы, которые решает проверка или поиск, он отвечает сам. Остальные задаёт тебе — в сессии и пушем на телефон. Ход задачи видно на странице claude.ai.
- **Документация.** Первая задача после подключения проекта — собрать его документацию из кода и старых документов.

## Быстрый старт

Нужны Docker с Compose, `git`, `jq` и подписка Claude. Оркестратору нужны ещё [Claude Code на компьютере](https://code.claude.com/docs/en/quickstart) и `python3`. Проверено только на Linux.

### 1. Поставь agent-box

Один раз на компьютер. В терминале, в папке, где будет лежать agent-box:

```bash
git clone https://github.com/mksmv4/agent-box.git
cd agent-box
docker compose build claude
./agent-loop.sh
```

Последняя команда делает `agent-loop.sh` и `box-connect` командами для любой папки. Пишет, что папки `~/.local/bin` нет в PATH, — добавь её в PATH и запусти команду снова.

### 2. Подключи проект

В проекте всё должно быть закоммичено. Пустую папку Claude сам сделает git-репозиторием. Папку с файлами без git сделай репозиторием сам: что попадёт в git, решаешь ты.

В терминале, в папке проекта, запусти Claude в контейнере:

```bash
box-connect
```

Первый запуск на компьютере ставит Claude Code и просит войти: открой ссылку в браузере и вставь код в терминал.

В сессии Claude в контейнере:

```
/box-init
```

Claude покажет адреса интернета, нужные проекту, — ответь «ок» или поправь список. Потом спросит, где хранить старые документы проекта: в git или только на диске. В конце он кладёт в проект документы и команды agent-box и делает коммит.

Дальше Claude в этом проекте запускается короче:

```bash
docker compose -f claude-box.yml run --rm claude
```

### 3. Веди задачу

Новая задача — в сессии Claude в контейнере:

```
/box-task <что нужно сделать>
```

Claude расспросит о цели и шагах и запишет задачу в файл `docs/tasks/<задача>.md`. `<задача>` — имя этого файла без `.md`, например `docs-2026-10-15`.

Один шаг — в сессии Claude в контейнере:

```
/box-next <задача>
```

Следующий шаг — в новой сессии.

Все шаги без присмотра — в терминале, в папке проекта:

```bash
agent-loop.sh <задача>
```

Скрипт останавливается, когда задача готова или Claude нужен твой ответ. Вопрос записан в конце файла задачи, в разделе «Блокер». Допиши в конец файла строку `ответ: <твой ответ>` и запусти скрипт снова.

Все шаги, и отвечать только на важные вопросы, — оркестратор. В Claude на компьютере, запущенном в папке проекта:

```
/box-orchestrate <задача>
```

Оркестратор запускает скрипт и сам отвечает на вопросы, которые решает проверка или поиск. Остальные задаёт тебе окном вопроса. Ссылку на страницу с ходом задачи пишет в чат. Вопросы на телефоне — раздел [Вести задачу оркестратором](#вести-задачу-оркестратором).

## Важные настройки

### Уведомления в Telegram

Вопросы Claude и остановки скрипта приходят в Telegram. Без настройки скрипт пишет только в терминал. Нужен `curl`.

1. Создай бота у @BotFather и скопируй его токен целиком, с двоеточием.
2. Впиши в файл `~/.config/agent-loop.env` строку `TELEGRAM_BOT_TOKEN=<токен>`.
3. Напиши боту любое сообщение. В течение суток запусти скрипт с любой задачей: он найдёт твой чат по этому сообщению.

### Адреса интернета проекта

Без присмотра Claude выходит только к сервисам Claude, GitHub, npm, PyPI и к сервисам проекта в Docker. Другие адреса открывает строка в `claude-box.yml` в папке проекта:

```yaml
    environment:
      CLAUDE_BOX_ALLOW: "api.example.com 203.0.113.7"
```

Строку пишет `/box-init` по списку, который ты поправил. Дальше её правишь ты: Claude этот файл менять запрещено. Claude упёрся в закрытый адрес — скрипт остановится с вопросом и готовой строкой.

### Модель Claude

Модель сессий проекта — строка `ANTHROPIC_MODEL` в `claude-box.yml`: `opus`, `sonnet`, `haiku` или `fable`. `/box-init` ставит `opus`.

### Пределы скрипта

Файл `config.yml` в папке agent-box — один на все проекты компьютера. В нём — сколько сессий скрипт запускает за раз, пауза между ними и через сколько минут прислать «сессия идёт долго». Правка действует со следующего запуска.

## Вести задачу оркестратором

Оркестратор — сессия Claude на твоём компьютере, которая ведёт задачу скриптом вместо тебя. Запуск — в быстром старте, шаг «Веди задачу». Здесь — что оркестратор делает сам, вопросы и запуск с телефона, разрешение для Claude.

### Что делает оркестратор

Оркестратор запускает скрипт и запускает его снова после остановок, где твоё решение не нужно. Например, после сбоя сети или предела сессий за запуск.

На вопрос сессии, который решает проверка или поиск, оркестратор отвечает сам. Его помощник читает код, запускает команды и тесты, ищет в интернете. Такой ответ в файле задачи начинается словами «ответ: оркестратор —».

Вопрос с решением оркестратор задаёт тебе окном вопроса и шлёт пуш. Решение — это выбор с разными последствиями, согласие на план или действие руками. Твой ответ он записывает в файл задачи и запускает скрипт снова.

Задача готова — оркестратор спросит, какую задачу брать дальше. К другой задаче он переходит только с твоего согласия.

Ход задачи — на приватной странице claude.ai: шаги, сессии, открытый вопрос. Ссылку оркестратор пишет в чат. Копия страницы — файл `my_local/pages/<задача>.html` в проекте. Оркестратор следующего дня обновляет страницу по прежней ссылке.

Без имени задачи оркестратор предложит задачи из роадмапа проекта. Уведомления скрипта в Telegram под оркестратором выключены. Включает их слово `telegram` после имени задачи:

```
/box-orchestrate <задача> telegram
```

Флаги `--host` и `--no-firewall` после имени задачи оркестратор передаёт скрипту. Что они делают — раздел [Вести задачу скриптом](#вести-задачу-скриптом). Модели помощников оркестратора задаёт `config.yml` в папке agent-box.

Сессия оркестратора идёт часами, и её контекст заполняется. Со 150 тыс. токенов оркестратор новых запусков скрипта не делает и заканчивает итогом. Продолжение — `/box-orchestrate <задача>` в новой сессии: задача пойдёт дальше по её файлу и журналу.

Команду `/box-orchestrate` кладут в проект `/box-init` и `/box-update`. В проекте, подключённом раньше, её может не быть: обнови проект по разделу [Обновить agent-box и проекты](#обновить-agent-box-и-проекты).

### Вопросы на телефон

Вопросы оркестратора приходят на телефон через Remote Control. Сессия на компьютере видна в приложении Claude, ответ из приложения доходит до сессии. Нужен вход Claude Code на компьютере через claude.ai по подписке Pro, Max, Team или Enterprise. С ключом API Remote Control не работает.

Настройка — один раз на компьютер:

1. Поставь приложение Claude на телефон. QR-код страницы загрузки показывает команда в Claude на компьютере:

   ```
   /mobile
   ```

   Войди в приложение тем же аккаунтом, что в Claude на компьютере. Разреши приложению уведомления, когда телефон спросит.

2. Открой настройки в Claude на компьютере:

   ```
   /config
   ```

   Включи оба пуша. «Push when actions required» — пуш на окно вопроса. «Push when Claude decides» — пуши, которые оркестратор шлёт сам: «готово», вопрос, остановка, которую он не снял.

3. Там же включи «Enable Remote Control for all sessions». Теперь каждая сессия Claude на компьютере сразу видна в приложении.

Без третьего пункта Remote Control включается на одну сессию. В терминале, в папке проекта:

```bash
claude --remote-control "<проект>"
```

`<проект>` — название сессии в приложении, по нему различаются проекты. Оркестраторы разных проектов идут одновременно, каждый в своей сессии.

### Запуск с телефона

Оркестратор запускается и с телефона, если на компьютере заранее поднят сервер Remote Control. В терминале, в папке проекта:

```bash
claude remote-control
```

Сервер сразу открывает одну сессию в папке проекта. В приложении она в списке сессий, раздел Code. В этой сессии, в приложении на телефоне:

```
/box-orchestrate <задача>
```

Из приложения на сервере открываются и новые сессии в той же папке, до 32 сразу. Режим разрешений сессий сервера задаёт флаг `--permission-mode <режим>` после `remote-control`. Первый запуск в папке, которой Claude Code ещё не доверяет, спросит в терминале, доверять ли ей.

### Разрешение для Claude на компьютере

Оркестратор запускает Claude в контейнере без вопросов о разрешениях. Claude на компьютере в режиме auto может счесть это опасным запуском агента и отказать. Разрешение — запись в личных настройках Claude Code: она объясняет, что контейнер — песочница. Запись нужна всем, кто ведёт скрипт из Claude на компьютере: оркестратором или просьбой «запусти скрипт».

В терминале, в папке agent-box:

```bash
agent-loop.sh --sandbox-rule
```

Команду запускаешь ты, потому что Claude в режиме auto получает отказ на запись своих разрешений. Команда оставит рядом с настройками их копию с датой. В конце она покажет запись так, как её видит Claude Code, или напишет, что запись не применилась.

Запись — подсказка проверке режима auto: отказы станут редкими, но гарантии нет. Что запись разрешает — [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) § Ступени изоляции. После обновления agent-box команду нужно повторить.

## Вести задачу скриптом

Скрипт `agent-loop.sh` запускает сессии Claude одну за другой, каждая делает один шаг задачи. Запуск — в быстром старте, шаг «Веди задачу». Здесь — как следить за скриптом и что делать, когда он остановился.

Проект почти без документов удобнее вести в Claude командой `/box-next`. Сборка его документации берёт содержимое из твоих ответов, и скрипт останавливался бы на каждом шаге.

Скрипт запускается и не из папки проекта — путём к файлу задачи. В терминале, в любой папке:

```bash
agent-loop.sh ~/<проект>/docs/tasks/<задача>.md
```

`~/<проект>` — путь к папке проекта.

### Пробный запуск

На новой задаче сначала посмотри на одну сессию без присмотра. Запусти скрипт как обычно и дождись конца первой сессии. В паузе между сессиями скрипт пишет «Ctrl+C останавливает цикл чисто» — нажми Ctrl+C. Первая сессия к этому времени закоммичена. Её ход — в журнале скрипта, итог — в коммите и файле задачи.

Скрипт остановился сам до паузы — значит, сессия задала вопрос или задача готова.

### Журнал

Скрипт пишет ход задачи в журнал. Путь журнала — в строке «журнал цикла:» при старте скрипта, обычно `.git/agent-loop.log` проекта. В журнале — начало каждой сессии с шагом и идентификатором сессии. Дальше — что Claude читает, правит и запускает, конец сессии с коммитами, остановки с причиной.

Следить вживую — в терминале, в папке проекта:

```bash
tail -f .git/agent-loop.log
```

Сессию из журнала можно открыть и продолжить. В терминале, в папке проекта:

```bash
docker compose -f claude-box.yml run --rm \
  claude --resume <сессия>
```

`<сессия>` — идентификатор сессии из журнала. В строке остановки скрипт даёт эту команду готовой.

### Остановки

Остановившись, скрипт пишет в терминал причину и строку «дальше:» — что делать. Та же строка — в уведомлении Telegram.

- **Задача готова.** Проверь сделанное по журналу работ `docs/JOURNAL.md` и хвостам раздела «Контекст» в файле задачи. Или поручи проверку Claude — ревью и QA, команды ниже. Принял — поставь `[x]` строке задачи в `docs/ROADMAP.md`.
- **Вопрос сессии.** Вопрос — в конце файла задачи, в разделе «Блокер». Допиши в конец файла строку `ответ: <твой ответ>` и запусти скрипт снова.
- **Предел сессий за запуск.** Запусти скрипт снова, он продолжит с того же места.
- **Сессии без прогресса.** Несколько сессий подряд не продвинули задачу. Посмотри журнал скрипта и раздел «Контекст» в файле задачи, потом запусти скрипт снова.
- **Сессия упала или оставила правки без коммита.** Открой сессию командой из строки остановки и разберись. Правки закоммить или откати, потом запусти скрипт снова.
- **Ctrl+C.** В паузе между сессиями остановка чистая. Во время сессии Ctrl+C обрывает и её — проверь `git status`.
- **Скрипт не запустился.** Строка называет причину, например нет файла задачи или `claude-box.yml`. В этой папке уже идёт другой запуск скрипта — строка назовёт его задачу.

Ревью готовой задачи — в сессии Claude в контейнере:

```
/box-review <задача>
```

Claude допишет в файл задачи шаги ревью. Запусти скрипт снова: ревью пройдёт как обычные шаги. Нашлись ошибки — скрипт остановится с вопросом. В нём список находок и шаги правок. Ответь `ответ: ок` или поправь шаги, и скрипт сделает правки.

QA готовой задачи — проверка глазами пользователя, в браузере. Её делают после ревью. В сессии Claude в контейнере:

```
/box-qa <задача>
```

Claude составит сценарии: что пройти в приложении и что должно получиться. Он назовёт файл со сценариями — прочитай и поправь. После твоего согласия Claude допишет в файл задачи шаги прогона.

Браузер есть только у Claude на компьютере, поэтому запусти скрипт с флагом `--host`. В терминале, в папке проекта:

```bash
agent-loop.sh --host <задача>
```

Сценарий не прошёл — скрипт остановится с вопросом. В нём провалы, шаги правок и вопрос, чинить ли то, чего задача не обещала. Ответь `ответ: ок` или поправь шаги.

После каждого действия сессия снимает экран. Снимки лежат в папке `my_local/qa/<задача>/` проекта, вне git. Оркестратор показывает их на странице задачи у каждого сценария: нажми на снимок и листай кадры.

Сессия идёт долго — скрипт пришлёт уведомление с её идентификатором. Сессия при этом продолжается. Сколько сессий за запуск, сколько сессий без прогресса и сколько минут до уведомления — задаёт `config.yml` в папке agent-box.

### Где идут сессии

Сессии скрипта идут в контейнере проекта. Сеть контейнера открыта только по списку адресов, Claude работает без вопросов о разрешениях. Флаг перед именем задачи меняет это на один запуск:

- сеть контейнера открыта, разрешения оценивает классификатор режима auto — `--no-firewall`;
- сессии идут в Claude на компьютере в режиме auto — `--host`; нужен Claude Code с входом на компьютере;
- уведомления только в терминал, без Telegram, — `--quiet`.

Например, в терминале, в папке проекта:

```bash
agent-loop.sh --host <задача>
```

Устройство режимов — [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) § Ступени изоляции.

### Проверить уведомления Telegram

Проверка — запуск скрипта на временном проекте с готовой задачей. В терминале, в любой папке:

```bash
d=$(mktemp -d) && git -C "$d" init -q
mkdir -p "$d/docs/tasks" && touch "$d/claude-box.yml"
echo 'статус: готово' >"$d/docs/tasks/t.md"
agent-loop.sh "$d/docs/tasks/t.md"
```

В Telegram придёт «tmp.…: задача t — готово» и строка «дальше:». Потом убери временную папку:

```bash
rm -rf "$d"
```

## Обновить agent-box и проекты

Обновление идёт в два этапа. Сначала обновляется agent-box на компьютере, потом каждый подключённый проект. Проекты можно обновлять по одному, когда до них дойдут руки.

### agent-box на компьютере

1. В терминале, в папке agent-box, забери свежую версию и пересобери образ:

   ```bash
   git pull
   docker compose build claude
   ./agent-loop.sh
   ```

   Скрипт и `box-connect` обновились уже после `git pull`: команды ведут на файлы этой папки. Последняя строка поставит команды, которых ещё нет, например `box-connect`. Свежие команды agent-box для проектов лежат в новом образе.

2. Ставил разрешение для Claude на компьютере (раздел [Вести задачу оркестратором](#вести-задачу-оркестратором))? Повтори команду в терминале, в папке agent-box:

   ```bash
   agent-loop.sh --sandbox-rule
   ```

   Команда заменит прежнюю запись свежим текстом и покажет, как её видит Claude Code.

3. Закрой сессии Claude, открытые в контейнерах проектов. Контейнер берёт команды agent-box из образа только при старте. В старом контейнере `/box-update` возьмёт старые команды или скажет, что обновлять нечего.

### Каждый проект

Обновляй каждую копию проекта отдельно. У клона на другом компьютере и у рабочей копии git — свой файл `claude-box.yml` с сервисом Claude. Незакоммиченные правки закоммить заранее. С ними `/box-update` и `/box-init` перечислят правки и закончат без изменений. Ответы в файлах задач можно оставить: команды не возьмут их в свой коммит. Исключение — ответ в незаконченной задаче сборки документации: перед `/box-init` его нужно закоммитить.

- **В папке копии есть `claude-box.yml`** — копия подключена по нынешней схеме. В терминале, в папке копии, запусти Claude:

  ```bash
  docker compose -f claude-box.yml run --rm claude
  ```

  В сессии Claude в контейнере:

  ```
  /box-update
  ```

  Он положит свежий протокол — правила работы сессий — и команды agent-box и сделает коммит. Документы и задачи проекта останутся как есть. Следующий шаг задачи веди уже в новой сессии: эта работает по старому протоколу.

- **`claude-box.yml` нет** — копия подключена по старой схеме, или это новая копия: клон или рабочая копия git. В терминале, в папке копии, запусти Claude:

  ```bash
  box-connect
  ```

  В сессии Claude в контейнере:

  ```
  /box-init
  ```

  Он положит сервис Claude в `claude-box.yml`. Сервис `claude` в основном compose-файле проекта он оставит и назовёт его строки в итоге. Убери эти строки руками. Дальше Claude запускается командой из первого пункта.

Если сборка документации в проекте уже закончена, `/box-init` заведёт новую — задачу `docs-<дата>` с вехой в роадмапе. Вести её или нет — решаешь ты.

`/box-init` вместо `/box-update` годится и для копии с `claude-box.yml`. Он ещё обновит правила проекта и сверит сборку документации. Строки для `claude-box.yml` он выдаст в итоге — допиши их руками. Подробно — [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) § Скиллы контейнера.

## Подключить проект в рабочей копии git

Рабочая копия git — вторая папка того же репозитория, её делает `git worktree add`. В её папке `.git` — файл, а не папка. Подключается она как обычный проект: `box-connect`, потом `/box-init`. `box-connect` сам подключит в контейнер основной репозиторий.

Чем рабочая копия отличается:

- файл `claude-box.yml` у каждой копии свой и лежит вне git, поэтому `/box-init` нужен в каждой копии;
- журнал скрипта лежит в основном репозитории, а не в `.git/agent-loop.log` рабочей копии; путь — в строке «журнал цикла:» при старте;
- скрипты в двух копиях одного репозитория идут одновременно, по одному на копию;
- `/box-init` в контейнере без основного репозитория остановится и выдаст длинную команду `docker run` — она делает то же, что `box-connect`.

## Пересобрать образ после правки agent-box

Образ собирается из папок `container/`, `template/` и `skills/` agent-box. Правил что-то в них — пересобери образ. В терминале, в папке agent-box:

```bash
docker compose build claude
```

Имя сервиса в команде обязательно: без него Compose ничего не соберёт. Образ собирается под архитектуру этого компьютера.

Новый образ действует в новом контейнере. Сессия Claude, открытая до пересборки, работает со старыми командами agent-box. Закрой её и запусти Claude снова.

Claude в самой папке agent-box запускается сервисом со сборкой образа. В терминале, в папке agent-box:

```bash
docker compose run --rm claude
```

Скрипт по задачам самого agent-box запускай только с `--host`. В терминале, в папке agent-box:

```bash
agent-loop.sh --host <задача>
```

У контейнера agent-box нет защиты настроек и compose-файла. Сессия без вопросов о разрешениях может поменять контейнер следующего запуска.

## Если что-то пошло не так

- **Скрипт остановился.** Что делать, написано в строке «дальше:». Все остановки — раздел [Вести задачу скриптом](#вести-задачу-скриптом).
- **Скрипт остановился с вопросом о закрытом адресе интернета.** В вопросе — готовая строка `CLAUDE_BOX_ALLOW` с новым адресом. Замени ею прежнюю строку в `claude-box.yml` и ответь на вопрос. Подробно — раздел [Адреса интернета проекта](#адреса-интернета-проекта).
- **Сессия скрипта упала с «правила сети не ставятся».** Сервису `claude` в `claude-box.yml` нужна строка `cap_add: [NET_ADMIN, NET_RAW]`. Допиши её руками или запусти `/box-init`: он назовёт недостающие строки в итоге.
- **Сессия скрипта упала с «адрес … не найден».** Домен из строки `CLAUDE_BOX_ALLOW` не нашёлся в DNS. Поправь его или убери из `claude-box.yml`.
- **После пересборки образа в контейнере старые команды agent-box.** Контейнер, открытый до пересборки, работает со старыми. Закрой сессию и запусти Claude снова.
- **`/box-init` или `/box-update` перечислил правки и закончил без изменений.** Закоммить правки или убери их, потом запусти команду снова. Папку с файлами без git сделай репозиторием сам и сделай первый коммит.
- **Нет команды `agent-loop.sh` или `box-connect`.** Запусти `./agent-loop.sh` в папке agent-box. Пишет, что папки `~/.local/bin` нет в PATH, — добавь её и запусти снова. Перенёс папку agent-box — запусти `./agent-loop.sh` на новом месте. Без команды `agent-loop.sh` оркестратор заканчивает сессию.
- **Запуск Claude пишет `Found orphan containers … --remove-orphans`.** Это контейнеры основного compose-файла проекта, с ними всё в порядке. Флаг `--remove-orphans` не ставь: с ним Compose их удалит.
- **Тестам проекта в контейнере нужен `ANTHROPIC_API_KEY`.** Ключи входа Claude Code убраны из окружения контейнера, тесты ключа не получат. Запускай такие тесты вне контейнера.
- **Уведомления Telegram не приходят.** Строка старта скрипта называет причину. Неверный токен — поправь строку `TELEGRAM_BOT_TOKEN` в `~/.config/agent-loop.env`. Чат не найден — напиши боту и в течение суток запусти скрипт снова.
- **`/config` пишет «No mobile registered».** Открой приложение Claude на телефоне: отметка уйдёт при следующем подключении Remote Control.
- **Телефон не видит сессию оркестратора.** Сессия и скрипт работают на компьютере, приложение — только окно в сессию. Компьютер должен быть включён, терминал с `claude` — открыт. Пропала сеть — сессия ждёт и подключится снова сама.
- **Сервер `claude remote-control` завершился.** Без сети сервер ждёт около 10 минут и завершается. Запусти его снова в той же папке: в течение примерно четырёх часов он вернёт прежние сессии.
- **Оркестратор кончился, а задача не готова.** Запусти `/box-orchestrate <задача>` в новой сессии, он поведёт задачу дальше. Скрипт прошлой сессии ещё идёт — оркестратор спросит, что с ним делать.
