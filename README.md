# agent-box

Обвязка проектов под работу с Claude Code: состояние проекта живёт в файлах репозитория, каждая сессия агента делает один шаг задачи и сохраняет итог по общему протоколу. Цели и решения — `docs/DESCRIPTION.md`, устройство — `docs/ARCHITECTURE.md`.

## Quick start

Нужны Docker с плагином Compose и подписка Claude: в контейнере Claude Code входит только по ней. Запуск на macOS и Windows пока не проверялся (`docs/ROADMAP.md`).

1. Образ и команда движка — в корне клона этого репозитория: `docker compose build claude` (§ Деплой), затем `./agent-loop.sh` — движок автоцикла ставит себя командой `agent-loop.sh` (§ Движок автоцикла).
2. Хук context-guard в `~/.claude` хоста — по желанию, § Хук context-guard.
3. Проект — любой: пустой, с кодом, со своей документацией любой раскладки. Папка с файлами, но без git — сначала `git init` и первый коммит руками: что уходит в git, решает человек. Незакоммиченные правки — закоммитить или убрать: `/box-init` работает на чистом рабочем дереве и при правках перечисляет их и заканчивает без изменений.
4. Первый запуск в папке проекта — `docker run` из § Запуск: сервиса `claude` в проекте ещё нет. Первый старт на машине ставит Claude Code — около полуминуты; логин — ссылку открыть в браузере хоста, код вставить в терминал.
5. `/box-init` в сессии: заготовки каркаса в проект — файлы с занятыми именами уходят в `.old`, в `.gitignore`, compose-файл и настройки Claude Code проекта дописывается нужное каркасу; задача `docs-<дата>` на сборку документации из того, что в проекте уже есть; коммит. По ходу он показывает адреса интернета, нужные проекту, с причинами — на правку, и спрашивает, где хранить архив разобранных файлов — в git или на диске вне git.
6. Дальше — `docker compose run --rm claude` и `/box-next docs-<дата>` сессия за сессией или движок автоцикла `agent-loop.sh docs-<дата>` в терминале хоста из папки проекта (§ Движок автоцикла): шаг на документ, чего не вывести из кода и файлов — сессия спрашивает, у движка вопросы шага приходят одной остановкой. Проект почти без документов удобнее вести в Claude: содержимое документов приходит из ответов, и движок останавливается на каждом шаге. Последний шаг переносит разобранные старые файлы в `archive/` с картой исходных путей; как удалить архив — в его `README.md`.
7. Новая задача — `/box-task <описание задачи>`: вопросы о цели, шагах, проверке шага и блокере, затем таск-файл `docs/tasks/<задача>.md` и строка задачи в `docs/ROADMAP.md`. Работа — `/box-next <задача>`, за сессию не больше одного шага; без присмотра задачу ведёт движок автоцикла на хосте — § Движок автоцикла.

## Запуск

В папке проекта: `docker compose run --rm claude`; флаги после имени сервиса уходят в Claude Code (`… claude -p "/box-next <задача>"`). В корне этого репозитория — тот же сервис. Первый старт на машине ставит Claude Code официальным установщиком, дальше старт мгновенный, а Claude Code обновляется сам. Логин — один раз на машину, при первом интерактивном запуске.

Правила проекта от `/box-init` закрывают агенту, на хосте и в контейнере, `.env` и его рабочие варианты — `.env.example` и другие примеры остаются открыты, — а также правку compose-файлов и настроек Claude Code проекта и принудительный push: их делает человек. В контейнере compose-файл проекта и настройки и хуки git подключены только на чтение (`docs/ARCHITECTURE.md` § Ступени изоляции).

Первый запуск в проекте, где сервиса `claude` ещё нет, — до `/box-init`, тем же образом без compose:

```bash
n=$(basename "$PWD" | tr A-Z a-z | tr -cd 'a-z0-9_-' | sed 's/^[-_]*//')
docker run --rm -it -v "$PWD":/workspace/"$n" -w /workspace/"$n" \
  -v "$HOME"/.claude-box:/home/node -v "$HOME":/root/host-home:ro maksim44/claude-box
```

Первая строка приводит имя папки к имени проекта Compose, так что первый запуск попадает под тот же путь в контейнере, что и следующие через compose, и сессии, автопамять и доверие Claude Code у проекта общие. `name:` в compose-файле проекта задаёт имя явно — тогда сессия первого запуска остаётся под путём от имени папки.

Домашняя папка контейнера — `~/.claude-box` на хосте, общая для всех проектов машины: логин, история сессий, сам Claude Code; создаётся при первом запуске. Домашняя папка хоста подключена только на чтение и агенту закрыта: личные настройки — `CLAUDE.md`, хуки, `.gitconfig`, строка состояния, язык и модель — скрипт запуска копирует в контейнер при каждом старте, правка на хосте действует со следующего запуска. Модель сессий проекта держит строка `ANTHROPIC_MODEL` в его compose-файле (её кладёт `/box-init`): она выше скопированной с хоста, так `/model` в другой сессии модель проекта и его автоцикла не меняет. Креды хоста и ключи `~/.ssh` остаются на хосте — push делается с хоста. Полный список переносимого — `docs/ARCHITECTURE.md` § Образ и скрипт запуска.

Переменные `.env` проекта скрипт запуска контейнера передаёт Claude Code — MCP-серверам (`${VAR}` в `.mcp.json`) и командам агента; часть запуска с правами root их не видит, и агент не выполнит через `.env` свою программу с этими правами. `.env` читается по правилам Compose — кавычки, подстановки `${…}`; расхождения — `docs/ARCHITECTURE.md` § Образ и скрипт запуска. Ключи входа Claude Code и переключатели провайдера из них убираются: тесты проекта, которым нужен `ANTHROPIC_API_KEY`, в контейнере его не получат. В проектах, заведённых раньше, у сервиса `claude` в compose-файле осталась строка `env_file` с `.env` — её убирает повторный `/box-init`, а когда запись в compose-файл ему закрыта, называет строки, которые убрать руками.

Проект со своим compose-файлом: `/box-init` вписывает сервис `claude` в его `services:` — Claude в одной сети с сервисами проекта, база доступна по имени сервиса.

### Движок автоцикла

Задача идёт итерациями `/box-next` без ручного запуска каждой сессии — запуск на хосте, из папки проекта по имени задачи или из любой папки путём к таск-файлу:

```bash
agent-loop.sh <задача>
agent-loop.sh ~/<проект>/docs/tasks/<задача>.md
```

Команда `agent-loop.sh` появляется после первого запуска скрипта на машине — `./agent-loop.sh` в папке клона: скрипт кладёт ссылку на себя в `~/.local/bin`. Папки `~/.local/bin` нет в `PATH` — скрипт так и пишет, и запуск остаётся полным адресом. Перенесённый клон — снова `./agent-loop.sh` в его новой папке.

Итерации идут в контейнере проекта — сервисе `claude`, как `docker compose run --rm claude`; флаг `--host` перед именем задачи ведёт их Claude Code хоста. На хосте нужны `git` и `jq`; для контейнера — Docker с Compose, сервис `claude` в проекте (его кладёт `/box-init`) и логин в контейнере — первый интерактивный запуск; для `--host` — Claude Code с логином на хосте.

В контейнере итерации идут без вопросов о разрешениях, а сеть контейнера ограничена: открыты сервисы Claude, GitHub, npm, PyPI, сервисы проекта в его сети Docker и сам компьютер по адресу этой сети; закрыты прочие сайты — поиск работает, страницы по ссылкам агент не открывает, — подключения аккаунта claude.ai, SSH, телеметрия и домашняя сеть. Свои адреса проекта — строка в `environment:` сервиса `claude` compose-файла, домены и адреса через пробел: `CLAUDE_BOX_ALLOW: "api.example.com 203.0.113.7"`. Её пишет `/box-init` по списку, который пользователь правит: откуда качаются зависимости, внешние сервисы, MCP-серверы и сайты документации проекта. Сессия, упёршаяся в закрытый адрес, останавливается блокером с этой строкой, дополненной новым адресом, — её вставляет человек. Ограничению нужны права сервиса `cap_add: [NET_ADMIN, NET_RAW]` — их кладёт `/box-init`; в проекте, заведённом раньше, их дописывает повторный `/box-init` в новом контейнере, без них итерация останавливается с сообщением, какую строку добавить. Образ, собранный раньше, — пересборка (§ Деплой). Флаг `--no-firewall` перед именем задачи оставляет сеть контейнера открытой, а итерации — в режиме auto, как с `--host`: правки внутри папки проекта проходят сами, остальное оценивает классификатор (`docs/ARCHITECTURE.md` § Ступени изоляции). Ручной запуск `docker compose run --rm claude` идёт с открытой сетью.

Перед первым запуском на задаче — одна-две итерации руками строкой итерации из `docs/ARCHITECTURE.md` § Движок автоцикла: видно, как сессия без присмотра пишет блокер, получает отказы в разрешениях и коммитит.

Движок проводит до 10 итераций за запуск с паузой 10 секунд и останавливается с сообщением в терминале: «готово»; блокер — с текстом секции «Блокер»; провал итерации или правки без коммита — с командой, открывающей сессию итерации для доследования; три итерации подряд без прогресса. Ответ на блокер — строка «ответ:» в секции «Блокер» таск-файла (`docs/PROTOCOL.md` § Таск-файлы), затем запуск снова: статус «в работе» движок ставит сам. Ctrl+C в паузе останавливает цикл чисто — прошлая итерация закоммичена; Ctrl+C во время итерации обрывает и её, в дереве могут остаться правки — `git status`. В репозитории идёт один цикл: второй запуск сразу завершается с именем задачи идущего. Коды выхода и правила остановки — `docs/ARCHITECTURE.md` § Движок автоцикла.

Остановки и долгие итерации движок шлёт в Telegram-бота. Настройка — один раз на машину: бот создаётся у @BotFather, его токен целиком, вместе с двоеточием, ложится в `~/.config/agent-loop.env` строкой `TELEGRAM_BOT_TOKEN=<токен>`; затем — любое сообщение боту и запуск движка: chat_id движок берёт из этого сообщения и дописывает в файл. Сообщение старше суток не годится — Telegram хранит входящие бота 24 часа. Каждое уведомление кончается строкой «дальше:» — что делать пользователю, уведомление о блокере — строкой «Как ответить:»; длинное приходит файлом `.md`, начало текста и эта строка — в подписи. Проверка — запуск движка на хосте из папки клона agent-box на пустом репозитории с задачей в статусе «готово», в Telegram приходит «tmp.…: задача t — готово» и строка «дальше:»:

```bash
s=$PWD/agent-loop.sh; d=$(mktemp -d) && git -C "$d" init -q && mkdir -p "$d/docs/tasks" && echo 'статус: готово' >"$d/docs/tasks/t.md" && cd "$d" && "$s" --host t
```

Без файла движок пишет только в терминал; флаг `--quiet` перед именем задачи делает так же на один запуск при настроенном боте. Неверный токен движок замечает при старте: строка «уведомления выключены: неверный токен» с подсказкой, где его поправить. Итерация дольше часа даёт алерт с `session_id` — итерация при этом идёт дальше.

### Хук context-guard

При заполнении контекста до порога сессия получает сигнал и завершается по протоколу проекта; без хука длинная сессия доходит до встроенного автосжатия, которое сжимает историю с потерями. Скрипта хука в репозитории пока нет — он живёт в личной `~/.claude` хоста; перенос в образ — задача релиза (`docs/ROADMAP.md`).

Что должно лежать в `~/.claude` хоста:

- скрипт `hooks/context-guard.sh` с порогами в `hooks/context-guard.conf`;
- снимок занятости контекста в конце скрипта строки состояния; скрипт прописан в `statusLine` хостового `settings.json` и лежит внутри `~/.claude` — в контейнер копируются только файлы оттуда;
- раздел «Контекстное окно» в `CLAUDE.md`: текст сигнала выполнять как инструкцию;
- для сессий на хосте — регистрация скрипта в `settings.json` на событиях `UserPromptSubmit` и `PostToolUse`; в контейнере регистрация берётся из образа и включается, когда скрипт на месте.

Устройство, режимы сигнала и поведение без строки состояния — `docs/ARCHITECTURE.md` § Хук context-guard.

## Деплой

Образ пересобирается после правки `container/`, `template/` или `skills/`, из корня репозитория:

```bash
docker compose build claude
```

Имя сервиса в команде обязательно: сервис под профилем `claude`, и `docker compose build` без имени ничего не собирает. Образ собирается под архитектуру машины сборки. Публикация — `docker push maksim44/claude-box`, на других машинах — `docker compose pull claude`. На Docker Hub образ пока не опубликован — это задача релиза (`docs/ROADMAP.md`); до неё образ собирается на каждой машине из клона.

Новый образ действует в новом контейнере: открытый до пересборки работает со старыми скиллами (`AGENTS.md` § Грабли). Протокол и `/box-next` в проекте обновляет `/box-update` в новом контейнере: свежие копии, коммит, остальные документы и задачи проекта остаются как есть (`docs/ARCHITECTURE.md` § Правила зависимостей). Повторный `/box-init` обновляет их же, но вдобавок сверяет сборку документации с шаблоном, а после законченной сборки заводит новую.
