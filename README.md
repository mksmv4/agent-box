# agent-box

Обвязка проектов под работу с Claude Code: состояние проекта живёт в файлах репозитория, каждая сессия агента делает один шаг задачи и сохраняет итог по общему протоколу. Цели и решения — `docs/DESCRIPTION.md`, устройство — `docs/ARCHITECTURE.md`.

## Quick start

Нужны Docker с плагином Compose и подписка Claude: в контейнере Claude Code входит только по ней. Запуск на macOS и Windows пока не проверялся (`docs/ROADMAP.md`).

1. Образ — в корне клона этого репозитория: `docker build -t maksim44/claude-box -f container/Dockerfile .` (§ Деплой).
2. Хук context-guard в `~/.claude` хоста — по желанию, § Хук context-guard.
3. Проект — любой: пустой, с кодом, со своей документацией любой раскладки. Папка с файлами, но без git — сначала `git init` и первый коммит руками: что уходит в git, решает человек. Незакоммиченные правки — закоммитить или убрать: `/box-init` работает на чистом рабочем дереве и при правках перечисляет их и заканчивает без изменений.
4. Первый запуск в папке проекта — `docker run` из § Запуск: сервиса `claude` в проекте ещё нет. Первый старт на машине ставит Claude Code — около полуминуты; логин — ссылку открыть в браузере хоста, код вставить в терминал.
5. `/box-init` в сессии: заготовки каркаса в проект — файлы с занятыми именами уходят в `.old`, в `.gitignore` и compose-файл проекта дописывается нужное каркасу; задача `docs-<дата>` на сборку документации из того, что в проекте уже есть; коммит. До записи задачи он спрашивает, где хранить архив разобранных файлов — в git или на диске вне git.
6. Дальше — `docker compose run --rm claude` и `/box-next docs-<дата>` сессия за сессией: шаг на документ, чего не вывести из кода и файлов — сессия спрашивает. Последний шаг переносит разобранные старые файлы в `archive/` с картой исходных путей; как удалить архив — в его `README.md`.
7. Новая задача — `/box-task <описание задачи>`: вопросы о цели, шагах, проверке шага и блокере, затем таск-файл `docs/tasks/<задача>.md` и строка задачи в `docs/ROADMAP.md`. Работа — `/box-next <задача>`, за сессию не больше одного шага; без присмотра задачу ведёт движок автоцикла на хосте — § Движок автоцикла.

## Запуск

В папке проекта: `docker compose run --rm claude`; флаги после имени сервиса уходят в Claude Code (`… claude -p "/box-next <задача>"`). В корне этого репозитория — тот же сервис. Первый старт на машине ставит Claude Code официальным установщиком, дальше старт мгновенный, а Claude Code обновляется сам. Логин — один раз на машину, при первом интерактивном запуске.

Первый запуск в проекте, где сервиса `claude` ещё нет, — до `/box-init`, тем же образом без compose:

```bash
n=$(basename "$PWD" | tr A-Z a-z | tr -cd 'a-z0-9_-' | sed 's/^[-_]*//')
docker run --rm -it -v "$PWD":/workspace/"$n" -w /workspace/"$n" \
  -v "$HOME"/.claude-box:/home/node -v "$HOME":/root/host-home:ro maksim44/claude-box
```

Первая строка приводит имя папки к имени проекта Compose, так что первый запуск попадает под тот же путь в контейнере, что и следующие через compose, и сессии, автопамять и доверие Claude Code у проекта общие. `name:` в compose-файле проекта задаёт имя явно — тогда сессия первого запуска остаётся под путём от имени папки.

Домашняя папка контейнера — `~/.claude-box` на хосте, общая для всех проектов машины: логин, история сессий, сам Claude Code; создаётся при первом запуске. Домашняя папка хоста подключена только на чтение и агенту закрыта: личные настройки — `CLAUDE.md`, хуки, `.gitconfig`, строка состояния, язык и модель — скрипт запуска копирует в контейнер при каждом старте, правка на хосте действует со следующего запуска. Креды хоста и ключи `~/.ssh` остаются на хосте — push делается с хоста. Полный список переносимого — `docs/ARCHITECTURE.md` § Образ и скрипт запуска.

Переменные `.env` проекта сервис `claude` передаёт в окружение контейнера — MCP-серверам (`${VAR}` в `.mcp.json`) и командам агента. Ключи входа Claude Code и переключатели провайдера из них убираются: тесты проекта, которым нужен `ANTHROPIC_API_KEY`, в контейнере его не получат.

Проект со своим compose-файлом: `/box-init` вписывает сервис `claude` в его `services:` — Claude в одной сети с сервисами проекта, база доступна по имени сервиса.

### Движок автоцикла

Задача идёт итерациями `/box-next` без ручного запуска каждой сессии — на хосте, из папки проекта:

```bash
~/<клон agent-box>/agent-loop.sh <задача>
```

На хосте нужны Claude Code с логином, `git` и `jq`. Итерации идут в режиме auto: правки внутри папки проекта проходят сами, остальное оценивает классификатор (`docs/ARCHITECTURE.md` § Ступени изоляции). Перед первым запуском на задаче — одна-две итерации руками строкой итерации из `docs/ARCHITECTURE.md` § Движок автоцикла: видно, как сессия без присмотра пишет блокер, получает отказы в разрешениях и коммитит.

Движок проводит до 10 итераций за запуск с паузой 10 секунд и останавливается с сообщением в терминале: «готово»; блокер — с текстом секции «Блокер»; провал итерации или правки без коммита — с `session_id` для `claude --resume`; три итерации подряд без прогресса. Ответ на блокер — правка таск-файла по `docs/PROTOCOL.md` § Таск-файлы, затем запуск снова. Ctrl+C в паузе останавливает цикл чисто — прошлая итерация закоммичена; Ctrl+C во время итерации обрывает и её, в дереве могут остаться правки — `git status`. В репозитории идёт один цикл: второй запуск сразу завершается с именем задачи идущего. Коды выхода и правила остановки — `docs/ARCHITECTURE.md` § Движок автоцикла.

Пока работает хостовая ступень без уведомлений в Telegram и таймера итерации — `docs/ROADMAP.md`.

### Хук context-guard

При заполнении контекста до порога сессия получает сигнал и завершается по протоколу проекта; без хука длинная сессия доходит до встроенного автосжатия, которое сжимает историю с потерями. Скрипта хука в репозитории пока нет — он живёт в личной `~/.claude` хоста; перенос в образ — задача релиза (`docs/ROADMAP.md`).

Что должно лежать в `~/.claude` хоста:

- скрипт `hooks/context-guard.sh` с порогами в `hooks/context-guard.conf`;
- снимок занятости контекста в конце скрипта строки состояния; скрипт прописан в `statusLine` хостового `settings.json` и лежит внутри `~/.claude` — в контейнер копируются только файлы оттуда;
- раздел «Контекстное окно» в `CLAUDE.md`: текст сигнала выполнять как инструкцию;
- для сессий на хосте — регистрация скрипта в `settings.json` на событиях `UserPromptSubmit` и `PostToolUse`; в контейнере регистрация берётся из образа и включается, когда скрипт на месте.

Устройство, режимы сигнала и поведение без строки состояния — `docs/ARCHITECTURE.md` § Хук context-guard.

## Деплой

Образ пересобирается после правки `container/`, `template/` или `skills/`, из корня репозитория:

```bash
docker build -t maksim44/claude-box -f container/Dockerfile .
```

Образ собирается под архитектуру машины сборки. Публикация — `docker push maksim44/claude-box`, на других машинах — `docker compose pull claude`. На Docker Hub образ пока не опубликован — это задача релиза (`docs/ROADMAP.md`); до неё образ собирается на каждой машине из клона.

Новый образ действует в новом контейнере: открытый до пересборки работает со старыми скиллами (`AGENTS.md` § Грабли). Протокол и `/box-next` в проекте обновляет повторный `/box-init` в новом контейнере; остальные документы проекта он оставляет как есть (`docs/ARCHITECTURE.md` § Правила зависимостей).
