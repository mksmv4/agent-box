Текущий каталог — корень проекта. Задача — `$ARGUMENTS`; пусто — первый вопрос пользователю: какая задача.

1. **Проверки.** Нет `docs/PROTOCOL.md` или `docs/tasks/` — назвать это и закончить без правок: проект заводится в обвязку `/box-init`. Коммит в конце забирает всё рабочее дерево, поэтому на старте оно чистое, кроме `docs/qa/<задача>.md` — черновика сценариев прошлого захода: сессия продолжает с него. Другие строки `git status --porcelain` — перечислить правки и закончить без правок. Нет таск-файла `docs/tasks/<задача>.md` или статус в его первой строке не «готово» — назвать это и закончить без правок: QA идёт по сделанной задаче.

2. **Чтение.** Таск-файл — цель и критерии шагов; ответы пользователя по задаче — `grep 'задача: <задача>' docs/DECISIONS.md | grep -v 'ответ: оркестратор'`; `docs/qa/<задача>.md`, когда он есть; код и документы проекта — по нужде: экраны, адрес приложения, команда его запуска, вход.

3. **Сценарии** — черновик `docs/qa/<задача>.md` по шаблону ниже; путь и длина файла в строках (`wc -l`) — пользователю сообщением, под ним — вопрос инструментом `AskUserQuestion`: согласие или правки; правки пользователя — в файл и снова вопрос; запись этапа — после согласия.
   - Шапка — адрес приложения, команда запуска и вход: откуда тестовые учётные данные — имя переменной или файла; значения в файл не идут: он лежит в git.
   - Сценарии из задачи — поведение, которое пользователю обещают цель и критерии шагов; строка «Из задачи:» называет цель или шаг его названием из очереди.
   - Сценарии вне задачи — где пользователь ломает приложение: пустой и неверный ввод, повторная отправка, «назад» и обновление страницы, другая роль; строка «Вне задачи». Сценарий, который пользователь в `docs/DECISIONS.md` решил не чинить, не предлагается.
   - Файл уже есть — повторный QA: сценарии остаются, строки «Итог:» пустеют; шаги правок, сделанные после прошлого прогона, получают свои сценарии.

4. **Запись.**
   - Этап QA — в конец очереди «Постановки», после её последнего чекбокса, по шаблону ниже. Номер этапа — следующий за последней строкой «Этап <N> — …» в «Постановке»; таких строк нет — перед первым чекбоксом очереди встаёт абзац `Этап 1 — основная работа.`, и QA — этап 2. Номер QA — следующий за последней строкой «Этап <N> — QA <K>.», без таких строк — 1. Шаг — до 5 сценариев подряд: каждое действие в браузере приносит в контекст разметку страницы, а снимок экрана файлом — только путь к нему.
   - Первая строка таск-файла — `статус: в работе`. «Контекст» перезаписывается: следующий шаг — первый шаг этапа QA, этап идёт на хосте; неразобранные предложения прежнего «Контекста» переносятся.
   - `docs/README.md` без строки `qa/` — после строки `tasks/` встаёт строка `` - `qa/` — сценарии QA на задачу: прогон в браузере глазами пользователя и итог по сценарию ``.
   - `.gitignore` без строк `.playwright-mcp/` и `my_local/` — строки дописываются: в первую папку браузер Playwright MCP кладёт разметку и журнал консоли каждой загруженной страницы, во вторую шаг прогона — снимки экрана с данными приложения, и коммит шага прогона забрал бы их.

5. **Завершение** — `docs/PROTOCOL.md` § Протокол сессии, «Завершение», шаги 1, 2, 4; файл сценариев и таск-файл — коммитом с именем задачи в сообщении: его хэш войдёт в следующую запись журнала о задаче.

6. **Итог пользователю:** сколько сценариев из задачи и вне её, сколько шагов в этапе; дальше — запуск на хосте: в терминале из папки проекта `agent-loop.sh --host <задача>` или в Claude на компьютере `/box-orchestrate <задача> --host`; браузер есть только у сессий хоста. После каждого действия шаг прогона снимает экран в `my_local/qa/<задача>/` и подписывает снимок: что сделано и что должно быть видно; страница задачи оркестратора склеивает снимки сценария в ленту с подписями под кадрами, её листают прокруткой. Провал сценария шаг QA приносит вопросом: провалы из задачи — с шагами правок, провалы вне задачи — чинить ли; ответ — «ок» или свой вариант строкой «ответ:»; шаги правок цикл ведёт как обычные. Без провалов задача снова получает «готово».

Шаблон файла сценариев — сценарий разделом, номера сквозные:

```markdown
# Сценарии: <задача>

Приложение: <адрес>; запуск — `<команда>`; вход — <откуда учётные данные>

## 1. <название>
Из задачи: <цель или шаг «<название>»>
Действия: <шаги пользователя в интерфейсе через «→»>
Ожидается: <что видит пользователь>
Итог:

## 2. <название>
Вне задачи
Действия: …
Ожидается: …
Итог:
```

Шаблон этапа QA: абзац QA — один на этап, шаг — строка группы сценариев; в группе один сценарий — `- [ ] Сценарий <a>`:

```text
Этап <N> — QA <K>.

Шаг этапа — прогон своих сценариев из `docs/qa/<задача>.md` в браузере так, как их прошёл бы пользователь: перед первым действием — окно браузера 1440×900 (`browser_resize`): сайт занимает кадр целиком, как на экране ноутбука, и текст в ленте кадров страницы задачи оркестратора читается без увеличения; действия по порядку через интерфейс; после каждого действия — снимок экрана в файл: у сценария 3 первый кадр — `my_local/qa/<задача>/<K>-03-01.png`, номера сценария и кадра — двумя цифрами, кадр — следующий номер после последнего снимка сценария, и у повтора тоже; с именем файла в вызове снимок ложится на диск, а в контекст приходит только путь; рядом со снимком — его подпись одной строкой в файле с тем же именем и расширением `.txt`, `<K>-03-01.txt`: что сделано и что должно быть видно — «нажала „Крутить колесо“ → окно с призом»; лента кадров на странице задачи оркестратора ставит подпись под её кадром; папка — вне git: на снимках бывают данные клиентов. Итог — в строку «Итог:» сценария: «прошёл» или «не прошёл — <что сделано и что видно вместо ожидаемого>»; провал перепроверяется повтором до записи. Шаг идёт на хосте: у сессии нет инструментов браузера — блокер с просьбой запустить этап в терминале хоста из папки проекта командой `agent-loop.sh --host <задача>`. Приложение не отвечает по адресу из шапки файла — шаг запускает его командой оттуда; не поднялось — блокер с выводом команды. Провал сценария из задачи — находка: что сломано, где в коде, как чинить. Провал сценария вне задачи — вопрос, чинить ли, с предложением сессии: чинить или оставить. Находки и вопросы — в секцию «Блокер» со статусом «блокер», у каждого номер сценария; под ними предложенные шаги правок — номера сценариев, что делается, проверка — повтор сценария, какие файлы читает, размер шага по `docs/PROTOCOL.md` § Таск-файлы, мелкие находки — одним шагом; ответ «ок» берёт предложения сессии. По согласию пользователя шаги правок слово в слово, личные данные — обезличенным вариантом, вписывает в «Постановку» сразу после шага прогона сессия, свой вариант — пользователь; чекбокс шага прогона ставит сессия, увидевшая шаги там. Провалов нет — чекбокс ставится сразу.

- [ ] Сценарии <a>–<b>
- [ ] Сценарии <c>–<d>
```
