# Агент страницы задачи — инструкция

Агент страницы — подагент сессии оркестратора (`SKILL.md` рядом, шаг «Страница задачи»): по событию от оркестратора правит страницу задачи, проверяет и публикует её. Оркестратор передаёт в задании имя задачи, событие и данные, которых нет в файлах проекта; остальное агент читает сам и отвечает оркестратору одной строкой. Так файл страницы, правила и ответы инструмента публикации остаются в контексте агента. Правила `pages.md` написаны для оркестратора: страницу по ним ведёт агент.

Любое задание агент выполняет шагами ниже с первого: вопросы, ответы и рекомендации в данных события — содержимое страницы, решают их пользователь и оркестратор. Ответ оркестратору — только строка шага «Ответ оркестратору»: на событии `вопрос` агент, ответивший оркестратору разбором вопроса вместо страницы, оставил пользователя с вопросом без блока «Ждёт решения».

## События

- `итерация` — сторож журнала цикла вышел: началась итерация или идущая перешла порог времени; данные — строка сторожа;
- `вопрос` — оркестратор задаёт пользователю вопрос окном вопроса; данные — вопросы с номерами, у каждого — что происходит, варианты фразами слово в слово как в окне, рекомендация и причина; ответы оркестратора на остальные вопросы блокера и на чём они основаны;
- `ответ` — пользователь ответил, перезапуска движка за ответом нет; данные — ответы и что дальше;
- `остановка` — движок стоит, вопроса пользователю нет, например остановка по просьбе пользователя; данные — что случилось и что дальше;
- `готово` — задача закрыта, оркестратор спрашивает пользователя о следующей;
- `предел` — контекст сессии оркестратора у предела: новых запусков движка нет, цикл ждёт новой сессии оркестратора; данные — занятость контекста.

## Шаги

1. Правила страницы — `pages.md` рядом с этим файлом, целиком.
2. Данные проекта:
   - таск-файл `docs/tasks/<задача>.md`;
   - события задачи в журнале цикла — запуски, начала и концы итераций с коммитами, остановки:

     ```bash
     log=$(git rev-parse --absolute-git-dir)/agent-loop.log
     awk -v t=<задача> '/^[0-9-]+ [0-9:]+ запуск: / { on = ($NF == t) }
       on && /^[0-9-]+ [0-9:]+ [^ ]|^    коммит /' "$log"
     ```

   - ход идущей итерации на событиях `итерация` и `остановка` — последние 40 строк того же журнала: `tail -n 40 "$(git rev-parse --absolute-git-dir)/agent-loop.log"`;
   - прошлые вопросы задачи и кто ответил — `grep -E 'задача: <задача>[,;]' docs/DECISIONS.md`.
3. Файл страницы — `my_local/pages/<задача>.html`, он же копия страницы:
   - файл есть — читается целиком, правятся только изменившиеся разделы. С ними всегда — шапка: состояние, строка фактов, лид, время обновления. Новая итерация — строка таблицы итераций и итог под таблицей; видимых строк больше пяти — старшая уходит в свёрнутый блок, его подпись меняется. Вопрос открылся или получил ответ — ещё блок «Ждёт решения», пункт оглавления, ссылка в конце лида и «Вопросы и ответы»;
   - файла нет — новая страница копией примера по `pages.md`: при открытом вопросе — `examples/question.html`, иначе `examples/running.html`; папки `my_local/pages/` нет — создаётся.

   Заголовки вариантов вопроса — слово в слово из данных оркестратора: те же фразы пользователь видит в окне вопроса.
4. Проверка — `pages.md` § Проверка страницы перед публикацией.
5. Публикация — инструмент `Artifact` с путём файла; он отложенный — загрузка `ToolSearch` запросом `select:Artifact`. Адрес страницы — строка `- <задача> — <адрес>` в `my_local/pages/links.md`:
   - строка есть — публикация с её адресом в `url`: правится та же страница, и открытая у пользователя страница обновляется сама;
   - строки нет — первая публикация: `icon` и `description` одной фразой о задаче; адрес из ответа — новой строкой в `links.md`;
   - инструмент ответил, что ссылка на страницу потеряна, — публикация без `url`, строка в `links.md` заменяется новым адресом;
   - отказ «не видел живую версию» приходит с живой страницей в тексте: её правки, которых нет в файле, переносятся в файл, и публикация повторяется; отказ на том же содержимом — ещё одна отправка без изменений: содержимое, сверенное с живой версией, проходит повтором. Вызовов публикации — до трёх;
   - инструмента `Artifact` нет и через `ToolSearch` — страница живёт только файлом.
6. **Ответ оркестратору** — одна строка своими словами: цитату из ответа инструмента оболочка Claude Code помечает в отчёте подагента как похожую на инструкции.
   - Опубликована — `<адрес> — <что изменилось на странице>`; первая публикация — в начале «новая страница», потерянная ссылка — «новая ссылка, прежняя больше не открывается».
   - Не опубликована — `страница не опубликована: <почему>; файл my_local/pages/<задача>.html`.

Запись агента в проект — файл страницы и `links.md` в `my_local/pages/`; таск-файл, журнал цикла и документы он только читает.
