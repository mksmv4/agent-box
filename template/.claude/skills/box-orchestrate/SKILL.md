name: box-orchestrate
description: Оркестратор задачи проекта — интерактивная сессия на хосте ведёт задачу движком автоцикла agent-loop.sh до «готово». Шаги идут без остановок; блокер, снимаемый проверкой или сведениями вне сети контейнера, оркестратор снимает своим ответом; вопрос с решением — пользователю окном вопроса и пушем. Вызов /box-orchestrate <задача> [telegram] [--host | --no-firewall]; без задачи — выбор задачи первой незакрытой вехи роадмапа.
argument-hint: "[задача] [telegram] [--host | --no-firewall]"
disable-model-invocation: true
---

1. Задача и флаги движка — из `$ARGUMENTS`: имя задачи; слово `telegram` — уведомления движка в Telegram, без него движок идёт с `--quiet`; `--host` или `--no-firewall` — флаг движку как есть. Имени задачи нет — вопрос пользователю инструментом `AskUserQuestion`: варианты — до трёх первых строк задач без чекбокса под первой вехой без чекбокса в `docs/ROADMAP.md` § Вехи, в описании варианта — статус из первой строки таск-файла; последний вариант — конец сессии без запуска. Таких строк нет — назвать веху и закончить сессию. Старт — после выбора.
2. **Запуск движка** — фоновой командой Bash (`run_in_background`) из корня проекта; завершение команды будит сессию. `setsid -w` даёт движку свою группу процессов, `env --default-signal=INT` снимает унаследованный игнор Ctrl+C — так остановка в шаге 7 доходит до движка и его итерации:

   ```bash
   env --default-signal=INT setsid -w agent-loop.sh [--quiet] [--host | --no-firewall] <задача>
   ```

   Команды `agent-loop.sh` нет — сказать пользователю, что движок ставится запуском `./agent-loop.sh` в папке клона agent-box, и закончить сессию. Второй фоновой командой — сторож алерта таймера: выходит на первой строке алерта, появившейся в журнале цикла после запуска. На остановке движка сторож снимается (`TaskStop`), на каждом запуске ставится заново.

   ```bash
   log=$(git rev-parse --absolute-git-dir)/agent-loop.log
   n=$(cat "$log" 2>/dev/null | wc -l)
   until tail -n +$((n + 1)) "$log" 2>/dev/null | grep -m1 'идёт дольше'; do sleep 30; done
   ```

3. **Разбор остановки и алерта** — по хвосту вывода движка (файл вывода фоновой команды), журналу цикла и таск-файлу; исход — код выхода и строка остановки:
   - 0, «готово» — шаг 6;
   - 0, лимит итераций за запуск — перезапуск, шаг 2, без вопроса;
   - 1, блокер — шаг 4;
   - 1, падение итерации, правки без коммита, итерации без прогресса, статус вне протокола — шаг 5;
   - вывод без строки остановки — движок оборван снаружи, шаг 5;
   - вышел сторож алерта, движок идёт — шаг 5;
   - 2 — движок не запустился: причина из вывода — вопросом пользователю по шагу 4, например итерации на хосте флагом `--host` в проекте без сервиса `claude`;
   - 130 — остановка по просьбе пользователя (шаг 7): итог пользователю, правки без коммита — по шагу 5, перезапуск — по его слову.
4. **Блокер.** Каждый вопрос секции «Блокер» — в одну из двух групп:
   - снимается без решения пользователя: проверка с однозначным итогом — команда, тест, чтение кода, документов или истории git; сведения, закрытые сети контейнера, — поиск в интернете и документации. Ответ оркестратора — что проверено или найдено и источник;
   - требует решения пользователя: выбор между вариантами с разными последствиями, согласие на очередь шагов, цель и способ проверки задачи, просьба сделать руками — правка compose-файла или настроек Claude Code, пересборка, вход в сервис. Граница неясна — тоже сюда.

   Вопросы с решением — одним вызовом `AskUserQuestion`: до четырёх вопросов, у вопроса — от двух до четырёх вариантов, свой ответ окно добавляет само; больше четырёх вопросов — вызовами подряд. Перед вызовом — пуш `PushNotification` одной строкой, что ждёт решения, и сообщение в чат: ответы оркестратора на остальные вопросы — пользователь может их поправить — и просьба сделать руками с готовыми командами: из окна вопроса текст не копируется. Вопрос — одной фразой по `docs/PROTOCOL.md` § Сообщения пользователю; варианты — полными фразами: предложение сессии и другие живые варианты.

   Ответы ложатся в конец секции «Блокер», когда ответ есть на каждый вопрос: свой — строкой `ответ: оркестратор — <текст>`, пользователя — строкой `ответ: <его слова>`: выбранный вариант — его текстом, свой ответ в окне или в чате — дословно. Вопросов несколько — строка на вопрос, номер вопроса в начале текста. Затем перезапуск — шаг 2.
5. **Падение, правки без коммита, без прогресса, оборванный движок, алерт** — разбор по журналу цикла (ход последней итерации, строка её конца), `git status` и «Контексту» таск-файла. Причина снимается без решения — перезапуск, шаг 2: сбой сети или API; лимит подписки — после его сброса, время — в тексте ошибки, ожидание — фоновой командой `sleep`; шаг длиной в несколько сессий — в журнале живой ход, в «Контексте» точка продолжения. Алерт при живом ходе итерации — новый сторож и ожидание. Иначе — вопрос пользователю по шагу 4: что видно в журнале и что предлагает оркестратор. Правки без коммита в рабочем дереве — всегда вопрос: принять их коммитом или откатить, решает пользователь, делает по его ответу оркестратор.
6. **«Готово»** — пуш `PushNotification` и вопрос о следующей задаче по правилам шага 1; выбрана задача — шаг 2 с ней, конец — шаг 8.
7. **Границы — на всю сессию:**
   - запись оркестратора в проект — строки «ответ:» в секции «Блокер» и коммит по ответу пользователя из шага 5; строки «ответ:» забирает коммит следующей итерации. Цель и способ проверки задачи меняет пользователь, очередь шагов — он сам или сессия по его согласию (`docs/PROTOCOL.md` § Таск-файлы);
   - идущий движок останавливается только прямой просьбой пользователя «останови»; «не запускай» — про следующий запуск. Остановка — сигнал Ctrl+C группе движка: `kill -INT -- -<PID>`, PID — второе слово файла `$(git rev-parse --absolute-git-dir)/agent-loop.lock`; движок доводит остановку сам и выходит с кодом 130;
   - к другой задаче — только по согласию пользователя: вопрос шага 6 или его просьба;
   - пуш — на «готово», вопрос пользователю и остановку, которую оркестратор не снял сам; перезапуск без вопроса идёт без пуша;
   - всё, что оркестратор пишет пользователю, — по `docs/PROTOCOL.md` § Сообщения пользователю; вопрос о ходе цикла — ответ по журналу цикла.
8. **Итог пользователю** — последним сообщением сессии: итерации и шаги, пройденные за сессию; блокеры — кто ответил: оркестратор или пользователь; статус задачи и действие пользователя по исходу — «готово»: проверка сделанного по записям `docs/JOURNAL.md` и хвостам «Контекста», затем чекбокс строке задачи в `docs/ROADMAP.md`; «в работе» или «блокер» — снова `/box-orchestrate <задача>`.
