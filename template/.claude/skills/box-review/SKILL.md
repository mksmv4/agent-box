Текущий каталог — корень проекта. Задача — `$ARGUMENTS`; пусто — первый вопрос пользователю: какая задача.

1. **Проверки.** Нет `docs/PROTOCOL.md` или `docs/tasks/` — назвать это и закончить без правок: проект заводится в обвязку `/box-init`. Коммит в конце забирает всё рабочее дерево, поэтому на старте оно чистое: `git status --porcelain` непуст — перечислить правки и закончить без правок. Нет таск-файла `docs/tasks/<задача>.md` или статус в его первой строке не «готово» — назвать это и закончить без правок: ревью идёт по сделанной задаче.

2. **Коммиты задачи** — все, от первого: `git log --reverse --format='%h %s' --grep '<задача>'`; коммит, где имя задачи — часть имени другой задачи или слово в другом смысле, — не её.

3. **Деление.** Объём шага ревью — изменения его коммитов, таск-файл и `ARCHITECTURE.md` вместе; таск-файл, журнал и реестр шаг читает в нынешнем виде, поэтому их изменения в счёт не идут: `{ git show --format= <хэши> -- . ':!docs/tasks/<задача>.md' ':!docs/JOURNAL.md' ':!docs/DECISIONS.md'; cat docs/tasks/<задача>.md docs/ARCHITECTURE.md; } | LC_ALL=C.UTF-8 wc -m`; норма — размер шага из `docs/PROTOCOL.md` § Таск-файлы без 3 тыс. знаков: столько займёт в таск-файле этап ревью. Все коммиты в норме — один шаг. Больше — коммиты делятся на группы подряд, каждая в норме; коммит больше нормы — шаг сам по себе.

4. **Запись.** Этап ревью — в конец очереди «Постановки», после её последнего чекбокса, по шаблону ниже. Номер этапа — следующий за последней строкой «Этап <N> — …» в «Постановке»; таких строк нет — перед первым чекбоксом очереди встаёт абзац `Этап 1 — основная работа.`, и ревью — этап 2. Номер ревью — следующий за последней строкой «Этап <N> — ревью <K>.», без таких строк — 1. Первая строка таск-файла — `статус: в работе`. «Контекст» перезаписывается: следующий шаг — первый шаг этапа ревью; неразобранные предложения прежнего «Контекста» переносятся.

5. **Завершение** — `docs/PROTOCOL.md` § Протокол сессии, «Завершение», шаги 1, 2, 4, 5; таск-файл — коммитом с именем задачи в сообщении: его хэш войдёт в следующую запись журнала о задаче.

6. **Итог пользователю:** этап ревью — сколько в нём частей и по скольким коммитам; дальше — запуск в Claude `/box-next <задача>` или в терминале хоста из папки проекта `agent-loop.sh <задача>`. Шаг ревью с находками кончается вопросом: находки и предложенные шаги правок, ответ — «ок» или свой вариант строкой «ответ:»; шаги правок цикл ведёт как обычные. Без находок задача снова получает «готово».

Шаблон этапа ревью: абзац ревью — один на этап, шаг — строка части; частей одна — строка шага `- [ ] Ревью: коммиты <хэши>`; `<хэши>` — коммиты части через запятую:

```text
Этап <N> — ревью <K>.

Шаг этапа — часть ревью задачи по своим коммитам: изменения — `git show <хэши шага> -- . ':!docs/tasks/<задача>.md' ':!docs/JOURNAL.md' ':!docs/DECISIONS.md'`, таск-файл, журнал и реестр — в нынешнем виде — сверяются с целью задачи, критериями её шагов, ответами пользователя по задаче (`grep 'задача: <задача>' docs/DECISIONS.md`), `RULES.md` и `ARCHITECTURE.md` и проверяются на ошибки — логика, краевые случаи, безопасность; другие коммиты и файлы проекта читаются по нужде; сомнительная находка перепроверяется чтением кода или запуском до записи; находка, отклонённая пользователем в `docs/DECISIONS.md`, повторно не предлагается. Простота — по результату: после правки код не сложнее, чем нужно задаче, — без обходов, лишних слоёв, опций на вырост и обработки случаев, которых в задаче нет. Случай из задачи, который код не обрабатывает, — находка. Сложность решения задачи, которую можно убрать, — тоже находка. Когда простой результат требует переделки базового кода — ошибки устройства с самого начала, — вариантов два: переделка — её объём в шагах и что станет проще; запасная правка на месте — что она оставляет сложным. Рекомендация — один из двух. Находки — в секцию «Блокер» со статусом «блокер»: у каждой номер, что сломается, где, как чинить; под ними предложенные шаги правок — номера находок, что делается, чем проверяется, какие файлы читает, размер шага по `docs/PROTOCOL.md` § Таск-файлы, мелкие находки — одним шагом; у находки с двумя вариантами — шаги каждого, ответ «ок» берёт рекомендованный. По согласию пользователя шаги правок слово в слово, личные данные — обезличенным вариантом, вписывает в «Постановку» сразу после шага ревью сессия, свой вариант — пользователь; чекбокс шага ревью ставит сессия, увидевшая шаги там. Находок нет — чекбокс ставится сразу.

- [ ] Часть 1 из <M>: коммиты <хэши>
- [ ] Часть 2 из <M>: коммиты <хэши>
```
