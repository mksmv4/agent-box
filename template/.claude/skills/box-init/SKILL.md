Карточки документов — `.claude/skills/box-init/documents.md`, рядом с этим файлом. Текущий каталог — корень проекта.

1. **Проверки.** Нет манифеста `.claude/agent-box.sha256` — проект не подключён к agent-box: назвать это и закончить без правок, в итог — в терминале компьютера в папке проекта `box-connect`, затем `box-claude` и в нём снова `/box-init`; файлы agent-box, заготовки документов и `claude-box.yml` кладёт `box-connect`. Коммит в конце забирает всё рабочее дерево, кроме правок пользователя в таск-файлах, поэтому на старте остальное дерево чистое: `git status --porcelain` непуст — перечислить правки и закончить без правок. Строки таск-файлов `docs/tasks/*.md` — ответ на блокер, правка «Постановки» — в счёт не идут, кроме таск-файла `docs-*` со статусом не «готово»: его дорабатывает шаг 4. Такие таск-файлы остаются в рабочем дереве как есть, их забирает коммит сессии задачи.

2. **Адреса проекта** — при любом заходе. Итерации движка в контейнере выходят в интернет только на открытые адреса — сервисы Claude, GitHub, npm, PyPI, сервисы проекта в его сети Docker — и на свои адреса проекта из строки `CLAUDE_BOX_ALLOW` в `environment:` сервиса `claude` в `claude-box.yml`. Адреса, нужные проекту, собираются по коду и файлам:
   - откуда качаются зависимости: манифесты и lock-файлы, настройки менеджеров пакетов (`.npmrc`, `pip.conf`, источники пакетов в `pyproject.toml`), зависимости по ссылке на git;
   - внешние сервисы из кода и примеров `.env` (`.env.example` и подобные): API, базы, хранилища;
   - MCP-серверы проекта из `.mcp.json`: адреса серверов и сервисов, к которым они ходят;
   - сайты документации фреймворков и библиотек проекта.

   Открытые адреса и сервисы compose-файла проекта в список не входят. Список — пользователю на правку, обычным текстом сообщения: строка на адрес с причиной; адреса нынешней строки `CLAUDE_BOX_ALLOW` — с пометкой «уже открыт»; домен без адреса IPv4 (`getent ahostsv4` пуст) — с пометкой «не найден», в строку он не идёт: на нём ограничение сети останавливает старт итерации. Ответ пользователя — текстом: «ок» или правки списка; окно вопроса (`AskUserQuestion`) список не показывает и правок не принимает. По ответу — строка `CLAUDE_BOX_ALLOW: "<адреса через пробел>"` в итог: её ставит пользователь в `environment:` сервиса `claude` в `claude-box.yml` на место нынешней, дальше `box-update` переносит её сам. Значение — буквально: подстановку `${…}` Compose берёт из `.env`, а его агент переписывает скриптом. Список совпал с нынешней строкой — правка не нужна; пустой список — строки нет, нынешнюю итог просит убрать.

3. **Опись источников** — документы и заметки проекта вне каркаса, по путям и заголовкам: `*.md`, `*.txt`, содержимое `docs/`, раскладки других агентских инструментов, переименованное `box-connect` при подключении — с исходным именем (`README.md.old` ← `README.md`). Файлы под `.gitignore` — тоже, с пометкой «под gitignore»: копии в git у них нет; зависимости и артефакты сборки (`node_modules`, `.venv` и подобное) в опись не входят. Каркас — заготовки, файлы agent-box из манифеста, `docs/tasks/`, `docs/researches/`, `docs/architecture/`, `docs/rules/` и архив прошлых сборок — в опись не входит. Строка на источник: путь → для каких документов. Код и манифесты сборки шаги сборки читают напрямую. Пустой проект — опись пустая, содержимое документов придёт из вопросов пользователю.

   Раздел по областям (`documents.md` § Раздел по областям) — архитектура и правила, каждый документ по своему условию: он уже разделён — папка `docs/architecture/` или `docs/rules/` прошлой сборки, в источниках — отдельные файлы на части проекта со своими папками; или его текст больше порога. Текст документа — его файл в `docs/` и источники описи, отданные ему, счёт — `LC_ALL=C.UTF-8 wc -m`; порог — ключ `split_chars` конфига agent-box по `docs/PROTOCOL.md` § Порядок на месте. Области — из § Области прошлой сборки, разделённых источников или папок кода верхнего уровня: имя латиницей — оно же имя файлов области — и папки. Областей меньше двух — документ остаётся одним файлом. Строка описи на документ: `раздел: <документ> — <причина: разделён или знаков больше порога>; области: <имя> — <папки>, …`, у документа выше порога без областей — с пометкой «без раздела: областей меньше двух».

4. **Задача сборки.**
   - Доработка — есть таск-файл `docs-*` со статусом не «готово»: новая задача не заводится, «Постановка» этой задачи сверяется с шаблоном ниже. Шаг очереди узнаётся по началу строки — документу или слову до двоеточия. Незакрытый шаг «архив» сверяется с вариантом хранения, чей текст в нём стоит; ни одного варианта в нём нет — в списке правок вопрос о хранении, как у новой задачи. Шаги шаблона, которых в очереди нет, встают на своё место по шаблону незакрытыми; шаги раздела по областям — шаги своего документа: незакрытый шаг документа одним файлом они заменяют, за закрытым встают незакрытыми; незакрытые шаги и остальной текст «Постановки», расходящиеся с шаблоном, получают текст шаблона; шаги, которых в шаблоне нет, остаются на местах. Все правки — одним списком пользователю до записи, закрытые шаги с изменённым текстом — с вопросом, открыть ли их заново; запись — после ответа: «Постановку» меняет только пользователь. Открыть — чекбокс снят, текст шаблона; оставить — строка как есть. Опись в «Контексте»: у строк источников дописываются адресаты новых шагов, источники, которых там нет, — строками по шагу 3, строки раздела по областям — заново по шагу 3. Предложения в хвостах «Контекста», закрытые доработкой, убираются; «Следующий шаг» — первый незакрытый шаг очереди. Веха в `docs/ROADMAP.md` остаётся прежней.
   - Новая задача — таск-файла `docs-*` нет или все со статусом «готово»: `docs-<ISO-дата>` (имя занято — `docs-<ISO-дата>-2`), таск-файл `docs/tasks/<задача>.md` по шаблону ниже, с шагами раздела по областям по описи. До записи таск-файла — вопрос пользователю, где хранить архив разобранных файлов: «в git» — архив в репозитории и в каждом клоне; «на диске» — архив вне git, только на этой машине; в шаг «архив» ложится выбранный вариант хранения. В `docs/ROADMAP.md` § Вехи (раздела нет — дописать в конец) — строка задачи с чекбоксом и ссылкой на таск-файл: под первой незакрытой вехой, имя которой начинается с «Сборка документации» — прежняя с датой тоже, — после строк её задач; незакрытой нет — новая веха `Сборка документации` с чекбоксом, строка задачи под ней.

5. **Завершение** — как у работы вне задачи: `docs/PROTOCOL.md` § Протокол сессии, «Завершение», шаги 1, 2, 4, 5. Таск-файлы с правками пользователя из шага 1 в коммиты скилла не идут: `git add -A -- . ':!<путь таск-файла>'` на каждый.

6. **Итог пользователю:** строка адресов `CLAUDE_BOX_ALLOW` для `claude-box.yml` — готовой строкой, с местом и сроком: поставить до запуска движка, адреса итерация берёт при старте контейнера; или что правка не нужна; имя задачи, при доработке — что изменилось в её очереди; раздел по областям — какие документы делятся, почему и на какие области с папками: области правит пользователь в «Постановке» до их шагов; документ выше порога, оставшийся одним файлом, — назвать; дальше — запуск в Claude `/box-next <задача>`, шаг за сессию, или в терминале хоста из папки проекта `agent-loop.sh <задача>` — движок автоцикла ведёт шаги сам, вопросы шага приходят одной остановкой, или `/box-orchestrate <задача>` в сессии Claude Code на хосте — движок под присмотром оркестратора, вопросы с решением приходят на телефон; опись пуста или почти пуста — совет вести сборку в Claude: содержимое документов приходит из ответов пользователя, и движок останавливается на каждом шаге.

```markdown

Очередь — шаг на документ:

- [ ] `docs/DESCRIPTION.md` — цели, стек, ключевые решения
- [ ] `docs/ARCHITECTURE.md` — устройство системы, правила зависимостей, анти-паттерны

Источники, что остаются на месте, отмечены в «Контексте» с причиной.

Проверка шага: документ соответствует своей карточке — обязательные разделы и границы, прежняя история от шага «история» — в своём формате; факты из кода и источников, относящиеся к документу, лежат в нём или в своём доме по карточкам; личные данные в документе обезличены, их исходные значения — в `my_local/personal.md` (`docs/PROTOCOL.md` § Личные данные и скрытые настройки); источники, взятые в работу, отмечены в «Контексте».
```

Раздел архитектуры:

```text
- [ ] `docs/architecture/ARCHITECTURE.md` — общая часть раздела по областям: сервисы, связи между областями, деплой, правила зависимостей между областями, § Области; прежний `docs/ARCHITECTURE.md`, когда он есть, переезжает сюда `git mv`

```

Раздел правил:

```text
- [ ] `docs/rules/RULES.md` — конвенции работы и общие конвенции кода; прежний `docs/RULES.md`, когда он есть, переезжает сюда `git mv`, строка хаба `@docs/RULES.md` становится `@docs/rules/RULES.md`
- [ ] `docs/rules/<область>.md` — конвенции кода области `<область>`; указатель — строка `@`-импорта этого файла в `CLAUDE.md` каждой папки области (<папки>), путь от папки указателя; свой `CLAUDE.md` папки остаётся на месте с отметкой в «Контексте», строка дописывается в него
```

Раздел одних правил — строка `docs/ARCHITECTURE.md` в очереди кончается так: `— устройство системы, правила зависимостей, анти-паттерны; § Области`.

Варианты хранения — текст на место `<хранение архива>`, дословно.

В git:

```text
Архив в git: файл в git — `git mv`; файл под gitignore — `mv` и строка на его путь в архиве в корневом `.gitignore` под комментарием `# сборка документации: бывшее под gitignore` (комментария нет — дописывается), прежняя строка сборки на него убирается; так он остаётся вне git и после удаления архива из git. `README.md` архива: первая строка `# Архив сборки документации`, под ней — «Артефакт сборки документации: что где лежало до неё. Папка в git; удаление — `git rm -r` папки: файлы, бывшие под gitignore, остаются в ней вне git — копии в истории у них нет.»
```

На диске:

```text
Архив на диске вне git: строка `/<папка архива>/` в корневом `.gitignore` под комментарием `# архив сборки документации`; файл в git — `git rm --cached` и `mv`, его прежняя версия остаётся в истории git под прежним путём; файл под gitignore — `mv`, его строка под комментарием сборки в корневом `.gitignore` убирается, опустевший комментарий — тоже. `README.md` архива: первая строка `# Архив сборки документации`, под ней — «Артефакт сборки документации: что где лежало до неё. Папка вне git, только на этой машине; удаление — кроме файлов с пометкой «под gitignore» в карте: копии в истории у них нет.»
```
