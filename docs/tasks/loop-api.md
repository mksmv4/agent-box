# loop-api

## Постановка
Просьба пользователя, 2026-11-21: «можем сделать флаг для неинтерактивных сессий под апи?»; «мне нужно чтобы скилы тоже умели запускать циклы по апи»; «несколько флагов же можно ставить?»

Решения по теме: кредиты кончились посреди задачи — оркестратор сам продолжает на подписке и сообщает об этом: «2» (2026-11-21); этапы ресерча и проверки постановки — оба: «1» (2026-11-21).

Дописала сессия:
- повод — ежемесячные API-кредиты плана Max (100 $): по документации Anthropic их тратит `claude -p` с ключом организации Console, привязанной к подписке, а интерактивный Claude Code они не покрывают — https://platform.claude.com/docs/en/about-claude/api-credits-for-subscribers, https://support.claude.com/en/articles/15036540-use-the-claude-agent-sdk-with-your-claude-plan; итерация движка — как раз `claude -p`;
- ключ из Console — строка `ANTHROPIC_API_KEY` в `~/.config/agent-loop.env`; `agent-loop.sh --api` отдаёт его только итерациям движка, в контейнере и с `--host`; без флага и в интерактивных сессиях — `box-connect`, ручной запуск контейнера — ключа нет, всё по подписке;
- запуск с `--api` без строки ключа в файле — остановка движка с ошибкой: без ключа итерация молча пошла бы по подписке;
- флаг ставится вместе с прочими и в любом порядке: `--host` или `--no-firewall`, `--quiet`, `--resume`, у оркестратора — слово `telegram`;
- цикл из скиллов запускает сам только `/box-orchestrate`: `/box-orchestrate <задача> --api` передаёт флаг движку на каждом запуске за беседу, как `--host`; `/box-review` и `/box-qa` только называют команду запуска;
- ключ в окружении Claude видят команды агента, `printenv` его покажет; README советует под флаг отдельный workspace Console с лимитом трат и отдельный ключ;
- ресерч ищет точный текст ошибки исчерпанных кредитов — по нему оркестратор узнаёт, что пора на подписку, — и способ спрятать ключ от команд агента;
- последний шаг — живой прогон пользователя после пересборки образа (`docs/RULES.md` § Конвенции работы): расход пробного запуска на странице Cost в Console;
- имя задачи и веха «Сессия хоста над движком».

Цель: `agent-loop.sh --api <задача>` ведёт итерации движка — в контейнере и с `--host` — на API-ключе из `~/.config/agent-loop.env`, и расход идёт с API-кредитов организации Console; без флага, а в интерактивных сессиях всегда, Claude Code работает по подписке и ключа в окружении нет; `/box-orchestrate <задача> --api` передаёт флаг движку на каждом запуске, а на ошибке исчерпанных кредитов перезапускает движок без `--api` и сообщает об этом пользователю; `--api` ставится вместе с прочими флагами движка и оркестратора.

Блокер: правки задачи по ресерчу и проверке постановки; итог живого прогона, видный только глазами, — расход на странице Cost в Console.

Этап 1 — ресерч.

Шаг этапа называет одной фразой, что за дело делает задача, — например, «выгрузка таблицы в CSV», — и ищет, как такое дело обычно делают и где оно ломается: готовые решения и библиотеки, типовые ошибки, советы документации — поиск в интернете, документация инструментов проекта, прошлые ресерчи `docs/researches/` и решения пользователя в `docs/DECISIONS.md` grep-ом по словам темы — и по каждой находке решает, к месту ли она в этой задаче, по `docs/PROTOCOL.md` § Ресерч и проверка постановки. У каждого утверждения — источник: адрес страницы или файл; вывод по выдаче поиска без чтения страницы так и помечен; закрытая ограничением сети контейнера страница, от которой зависит вывод, — блокер по `docs/PROTOCOL.md` § Таск-файлы. Итог — `docs/researches/<дата>-<задача>.md`: практики и решение по каждой, в конце — правки задачи, у каждой «сейчас → после» и зачем, или вывод «по ресерчу нынешний план оптимален» с причиной. Дальше в очереди проверка постановки — чекбокс, правки возьмёт она; иначе правки — блокером по тому же разделу, без правок — чекбокс.

Этап 2 — проверка постановки.

Шаг этапа сверяет задачу до начала работы: цель и шаги — со словами пользователя в «Постановке» и его решениями по теме в `docs/DECISIONS.md`; решение ведёт к цели; шаги вместе закрывают цель, каждый ей нужен, порядок выполним; проверка шага даёт однозначный итог; задуманное не спорит с `RULES.md`, `ARCHITECTURE.md` и файлами областей, чей код задача меняет, — `docs/architecture/<область>.md` и `docs/rules/<область>.md`; был ресерч — каждая его правка по тем же пунктам. Находка — по `docs/PROTOCOL.md` § Ресерч и проверка постановки. Находки и прошедшие правки ресерча — правками задачи блокером по тому же разделу; правок нет — чекбокс.

Этап 3 — основная работа.

- [ ] Движок и контейнер: флаг `--api` у `agent-loop.sh` — ключ из строки `ANTHROPIC_API_KEY` в `~/.config/agent-loop.env`, без строки — остановка с кодом 2 и строкой причины; итерация с `--host` получает ключ в своём окружении, итерация в контейнере — через скрипт запуска, а `container/env-run.py` пропускает ключ к Claude только у итерации движка с флагом, интерактивный запуск контейнера ключа не получает; справка флага — в шапке скрипта и строке запуска; документы движка и контейнера в `docs/architecture/` — в лад. Читает `agent-loop.sh`, `container/env-run.py`, `container/entrypoint.sh`, `docs/architecture/engine.md`, `docs/architecture/container.md`. Проверка: `bash -n agent-loop.sh` без ошибок; `agent-loop.sh --api <задача>` при файле без строки ключа — код 2 и строка причины; `container/env-run.py` на хосте с пустым `.env` и командой `printenv ANTHROPIC_API_KEY` печатает пробный ключ при окружении итерации движка с флагом и пустую строку без него.
- [ ] Оркестратор и README: `/box-orchestrate` принимает `--api` в аргументах вместе с `telegram` и `--host` или `--no-firewall` и передаёт его движку на каждом запуске за беседу; на ошибке исчерпанных кредитов в выводе движка — текст по ресерчу — перезапускает движок без `--api` и одной строкой сообщает пользователю, что цикл перешёл на подписку; README — строка о флаге: куда положить ключ, что расход идёт с API-кредитов, отдельный workspace с лимитом трат. Читает `template/.claude/skills/box-orchestrate/SKILL.md`, `README.md` и `docs/architecture/orchestrator.md`. Проверка: дифф скилла и README совпадает с этим шагом; README — по `docs/RULES.md` § README.
- [ ] Живой прогон — ведёт пользователь: сессия пишет блокер с шагами руками по `docs/PROTOCOL.md` § Таск-файлы, «Просьба сделать руками, итог которой виден в файлах»: пересборка образа (`README.md` § Пересобрать образ после правки agent-box), ключ в `~/.config/agent-loop.env`, пробная задача в тестовой папке движком с `--api` в контейнере, `printenv ANTHROPIC_API_KEY` в интерактивной сессии того же контейнера, оркестратор с `--api` на пробной задаче, уборка с переносом историй бесед в `my_local/loop-api/`; отдельным вопросом блокера — расход на странице Cost в Console. Прошёл, когда по копии прогона итерации движка и оркестратора шли с `--api`, интерактивная сессия ключа не видела, а пользователь видит расход в Console.

Выяснено при заведении задачи, 2026-11-21:
- при нескольких способах входа Claude Code берёт `ANTHROPIC_API_KEY` раньше входа по подписке, а в режиме `-p` ключ из окружения используется всегда — https://code.claude.com/docs/en/authentication § Authentication precedence;
- скрипт запуска контейнера вычищает ключи входа и переключатели провайдера из окружения Claude на каждом старте — список `LOGIN` в `container/env-run.py`, основание — `docs/architecture/container.md`;
- итерация в контейнере идёт строкой `docker compose … run … -e CONTEXT_GUARD_MODE=protocol -e CLAUDE_CODE_PROMPT_CACHE_TTL=5m claude …` в `agent-loop.sh`; правило песочницы claude-box для классификатора режима auto пропускает `-e` только с этими двумя переменными — текст правила там же, решение — `docs/DECISIONS.md` grep-ом по «-e/--env»;
- `~/.config/agent-loop.env` движок читает построчно и берёт из него только `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`.
