# agent-loop

## Постановка

Цель: пользователь запускает на хосте одну команду с именем задачи — и задача проекта идёт итерациями `/box-next` без ручного запуска каждой сессии, на хосте и в контейнере; остановки, таймер и уведомления в Telegram — по `ARCHITECTURE.md` § Движок автоцикла. Контейнерная ступень защищена: deny-правила образца закрывают неприкасаемое, egress-firewall пропускает только разрешённые адреса, правка агентом `compose.yml` своего проекта закрыта. Итог `/box-task` называет команду запуска движка. Потолок ходов, порог «без прогресса» и порог таймера выбраны пользователем по обкатке. Открытые вопросы `ROADMAP.md` § Движок автоцикла закрыты.

Проверка — пользователь: пересборка, новый контейнер — запрос к разрешённому адресу проходит, к прочим — отказ, `claude -p` работает. Список адресов — блокер.

Проверка шага: правка скрипта движка — проба в тестовом git-репозитории в контейнере с заглушкой вместо `claude`, изображающей исход итерации (коммит с закрытым чекбоксом, блокер, «готово», падение, правки без коммита): движок останавливается или продолжает по разбору итога из `ARCHITECTURE.md` § Движок автоцикла с ожидаемым сообщением и кодом выхода. Проба проверяет сам скрипт при разработке, в продукт она не входит. Запуск через `docker compose`, правки образа и скиллов — живая проверка пользователем по `RULES.md` § Конвенции работы; такой шаг кончается блокером с командой и ожидаемым итогом.

Блокер: числа — потолок ходов, лимит итераций, пауза, порог «без прогресса», порог таймера; строка итерации контейнерной ступени и переход на bypass; состав неприкасаемого для deny-правил и список адресов firewall; поведение CLI, разошедшееся с `ARCHITECTURE.md` § Движок автоцикла, — например, `/box-next` не раскрылся в `-p`.

## Контекст

Шаг «скрипт запуска вне досягаемости `.env`»: код и пробы сделаны, ждёт живой проверки пользователем — секция «Блокер». Сделано: строки `env_file` нет в сервисе `claude` в `template/compose.yml` и `compose.yml`; `.env` читает новая программа `container/env-run.py` (в образе — `/usr/local/bin/claude-box-env`) уже от `node` и запускает `claude` с его переменными, ключи входа убирает она — `unset` из `container/entrypoint.sh` ушёл; `/box-init` убирает строку `env_file` с `.env` у сервиса `claude`, при отказе записи называет её в итоге; описание и расхождения разбора с Compose — `ARCHITECTURE.md` § Образ и скрипт запуска, README § Запуск.

Пробы сессии — в папке сессии вне репозитория, сети Compose сняты:

- сверка разбора с Compose 5.6.0: 41 запись, строка из одного имени и шесть ошибочных записей совпали; `PATH` из `.env` Compose ставит, программа — нет, по правилу «окружение контейнера главнее»;
- ловушка: `.env` со строками `PATH` и `LD_PRELOAD` на программу и библиотеку из папки проекта; прежний способ (`--env-file` образа до правки) — десятки выполнений от root, новый скрипт запуска на том же образе — ни одного, библиотека сработала только в процессе `claude` от `node`; переменная из `.env` дошла, `ANTHROPIC_API_KEY` убран.

Следующая сессия: ответ «прогон прошёл» — чекбокс шага, перенос блокера в `DECISIONS.md`, запись журнала; расхождение — разбор и блокер с тем, что разошлось. Затем шаг egress-firewall.

Заметки к шагу egress-firewall — по ресерчу `researches/2026-10-04-firewall.md` и ответу пользователя 2026-10-04 (`DECISIONS.md`):

- ограничение сети — только в итерациях движка в контейнере; флаг движка, например `--no-firewall`, его снимает: с флагом итерации идут как сейчас — auto с классификатором, без флага — за ограничением и в bypass, после живой проверки; ручной `docker compose run --rm claude` — интернет открыт. Включение — переменная окружения от движка через `-e`, скрипт запуска читает её от root до перехода к `node`: `.env` до этой части больше не доходит;
- открыто: `api.anthropic.com`, `claude.ai`, `platform.claude.com`, `downloads.claude.ai`, `code.claude.com`; диапазоны GitHub из `api.github.com/meta`, `registry.npmjs.org`, `pypi.org`, `files.pythonhosted.org`; DNS; подсеть сети Compose — сервисы проекта и сам компьютер по адресу шлюза этой сети. Закрыто остальное: другие сайты (WebSearch работает, WebFetch — нет), `mcp-proxy.anthropic.com` — подключения аккаунта claude.ai, SSH, телеметрия Datadog, домашняя сеть;
- скрипт firewall в образе, вызов из скрипта запуска от root до установки Claude Code; права `cap_add: [NET_ADMIN, NET_RAW]` сервису `claude` в `template/compose.yml` и `compose.yml`, `/box-init` дописывает их в проект; пакеты `iptables`, `ipset` в Dockerfile; адреса доменов — `getent ahostsv4` (в образе не проверено), подсеть сети Compose — `/proc/net/route`: `ip` и `dig` в образе нет;
- переход к `node` — `setpriv … --bounding-set -all --no-new-privs`;
- итерация с ограничением без права `NET_ADMIN` не стартует, сообщение называет строку `cap_add` для compose-файла;
- свои адреса проекта — переменная в `environment:` сервиса `claude` со значением в compose-файле; объявлять её пустой больше не нужно — `.env` до части от root не доходит;
- IPv6 — политика DROP в `ip6tables`.

Хвосты:

- Наблюдения живой проверки правил запрета: отказ по `.env` агент дал сначала сам — по глобальному правилу о секретах из `~/.claude/CLAUDE.md` хоста, который едет в контейнер; правило запрета отклонило его следующую команду — вывод имён переменных, и агент назвал это отказом пользователя. Правило `Edit` на compose-файл в проверке не сработало ни разу: агент увидел подключение только на чтение и инструментом правки не пробовал. На машине без глобального правила барьер по `.env` — только правило запрета.
- Пути, которых защита не закрывает: `.git/commondir` переадресует настройки git — ручной `git status` пользователя на хосте выполнит подложенную команду; флаги движка проверены только на fsmonitor и хуках, другие команды из переадресованных настроек git не проверялись. `.claude/settings.local.json` с хуками, записанный скриптом агента, сработает в сессии Claude Code на хосте. Скрипт агента обходит правила запрета. Варианты `.env` вне списка имён (`.env.backup` и подобные) открыты.
- Пилотный проект получит правила, подключения только на чтение и снятие `env_file` повторным `/box-init` в новом контейнере — решает пользователь.
- `--max-turns 200` и порог таймера «до замера — час» (`alert=3600` в скрипте) выбраны агентом без согласия пользователя — `DECISIONS.md` 2026-09-30 «правка реестра по сверке с переписками»; числа решает пользователь.
- Ctrl+C во время итерации по настоящей сессии не проверялся ни на хосте, ни в контейнере; в контейнере Compose отдаёт SIGINT сессии и сразу выходит с 130 (проба на `sh`).
- Предложение нового шага: проверка токена при старте движка (метод `getMe`) — неверный токен виден сразу при запуске, пока пользователь у терминала, а не на первой остановке; ответ Telegram «Not Found» переводится в «неверный токен».

Среда на 2026-10-04: хост — `docker` с Compose 5.6.0, `git`, `jq`, `python3`; образ `maksim44/claude-box` собран до правок этого шага — живая проверка начинается с пересборки; тестового проекта `~/box-test` нет.

## Блокер

Переменные из файла секретов проекта (.env) теперь получает только Claude в контейнере: часть запуска с правами администратора их не видит, и агент через этот файл свою программу с такими правами не запустит. Пробы это подтвердили; нужна проверка на пересобранном образе — заодно видно, что повторная настройка проекта (`/box-init`) в проекте, заведённом раньше, просит убрать из compose-файла старую строку подключения `.env`.

Сделать руками:

1. В папке клона agent-box — пересборка образа и тестовый проект со старым compose-файлом:
   `docker compose build claude && mkdir ~/box-test && git show 5d8a440:template/compose.yml > ~/box-test/compose.yml`
2. `cd ~/box-test && git init -q && printf 'PROBE_VAR="значение с пробелом"\nANTHROPIC_API_KEY=sk-test\n' > .env && printf '.env\n' > .gitignore && git add -A && git commit -qm init`
3. `docker compose run --rm claude`, в сессии — `/box-init`, на вопрос об архиве — любой вариант. Ожидание: в итоге — строка `env_file` в `compose.yml`, которую нужно убрать руками. Выйти из сессии.
4. Убрать её — по итогу `/box-init` или командой: `sed -i '/# переменные .env проекта/d; /env_file:/,/required: false/d' compose.yml`
5. Снова `docker compose run --rm claude`, в сессии набрать `! printenv PROBE_VAR ANTHROPIC_API_KEY`.

Ожидание в п. 5: одна строка «значение с пробелом» — ключа `ANTHROPIC_API_KEY` в контейнере нет, второй строки не будет. Пошло иначе — напиши, на каком пункте и что видно.

Уборка после проверки: `docker network rm box-test_default; rm -rf ~/box-test ~/.claude-box/.claude/projects/-workspace-box-test`

Как ответить: допиши в конец файла docs/tasks/agent-loop.md строку, которая начинается с «ответ:», и после двоеточия — сам ответ. Потом запусти в Claude /box-next agent-loop или в терминале agent-loop.sh agent-loop.
