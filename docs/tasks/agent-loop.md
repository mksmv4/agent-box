# agent-loop

## Постановка

Цель: пользователь запускает на хосте одну команду с именем задачи — и задача проекта идёт итерациями `/box-next` без ручного запуска каждой сессии, на хосте и в контейнере; остановки, таймер и уведомления в Telegram — по `ARCHITECTURE.md` § Движок автоцикла. Контейнерная ступень защищена: deny-правила образца закрывают неприкасаемое, egress-firewall пропускает только разрешённые адреса, правка агентом `compose.yml` своего проекта закрыта. Итог `/box-task` называет команду запуска движка. Потолок ходов, порог «без прогресса» и порог таймера выбраны пользователем по обкатке. Открытые вопросы `ROADMAP.md` § Движок автоцикла закрыты.

## Контекст

Шаг «deny-правила образца и защита `compose.yml`» сделан по ответу на блокер 2026-10-04 (`DECISIONS.md`), ждёт живой проверки пользователем — секция «Блокер». Сделано: правила запрета в `template/.claude/settings.json` — `.env` и рабочие варианты списком имён, примеры вроде `.env.example` открыты; compose-файлы с дополнениями; `.claude/settings.json` и `.claude/settings.local.json`; `git push --force`/`-f`. В `template/compose.yml` — подключения только на чтение: compose-файл, `.git/config`, `.git/hooks`. `/box-init` дописывает недостающие правила в чужой `.claude/settings.json` через `jq` и недостающие подключения в сервис `claude` проекта; отказ записи — строки в итог. Движок: git хоста через обёртку с `-c core.fsmonitor=false -c core.hooksPath=/dev/null`, Compose — с явным `-f <compose-файл>`, без compose-файла — код 2. Документы: `ARCHITECTURE.md` § Движок автоцикла, § Ступени изоляции, § Образец проекта, § Образ и скрипт запуска; `README.md`.

Пробы 2026-10-04 в песочнице сессии: заглушка `docker` — `-f compose.yml` в `config --services` и в строке итерации, без compose-файла — код 2; слияние `jq` — недостающие правила дописаны без дублей, прочие ключи целы, файл без `permissions` получает весь список; образцовый `compose.yml` в настоящем контейнере — запись в compose-файл, `.git/config`, `.git/hooks` и `mv` compose-файла отклонены, остальная папка проекта пишется.

Следующее: ответ «прошло» — чекбокс шага, запись журнала; расхождение — разбор по ответу. Затем шаг «egress-firewall».

Хвосты:
- Пути, которых защита не закрывает: `.git/commondir` переадресует настройки git — ручной `git status` пользователя на хосте выполнит подложенную команду; флаги движка проверены только на fsmonitor и хуках, другие команды из переадресованных настроек git не проверялись. `.claude/settings.local.json` с хуками, записанный скриптом агента, сработает в сессии Claude Code на хосте. Скрипт агента обходит правила запрета. Варианты `.env` вне списка имён (`.env.backup` и подобные) открыты.
- Пилотный проект получит правила и подключения только на чтение повторным `/box-init` в новом контейнере после пересборки образа — решает пользователь.
- `--max-turns 200` и порог таймера «до замера — час» (`alert=3600` в скрипте) выбраны агентом без согласия пользователя — `DECISIONS.md` 2026-09-30 «правка реестра по сверке с переписками»; числа решает пользователь.
- Ctrl+C во время итерации по настоящей сессии не проверялся ни на хосте, ни в контейнере; в контейнере Compose отдаёт SIGINT сессии и сразу выходит с 130 (проба на `sh`).
- Предложение нового шага: проверка токена при старте движка (метод `getMe`) — неверный токен виден сразу при запуске, пока пользователь у терминала, а не на первой остановке; ответ Telegram «Not Found» переводится в «неверный токен».

Среда на 2026-10-04: сессия шла на хосте — `docker` с Compose 5.6.0, `git`, `jq`; образ `maksim44/claude-box` собран 2026-10-03, без правок этого шага. Пробы шага — в песочнице сессии, в репозитории следов нет.

## Блокер

Защита готова, нужна живая проверка в новом контейнере: агент с полной свободой действий не читает `.env` и не меняет compose-файл проекта, а `.env.example` менять может.

Сделать руками:

1. Пересобрать образ — в папке клона agent-box: `docker compose build claude`
2. Создать тестовый проект:
   `mkdir ~/box-test && cd ~/box-test && git init -q && printf 'TEST_SECRET=123\n' >.env && printf 'TEST_SECRET=\n' >.env.example && printf '.env\n' >.gitignore && git add -A && git commit -qm init`
3. Первый запуск там — команда `docker run` из README agent-box, раздел «Запуск»; в сессии — `/box-init`, на вопрос об архиве — любой вариант; затем выйти.
4. Там же: `docker compose run --rm claude --dangerously-skip-permissions` — и попросить агента по очереди: «покажи содержимое .env», «допиши комментарий в конец compose.yml», «допиши строку # test в конец .env.example».

Ожидание: на первые две просьбы — отказ (если агент попробует дописать compose.yml через терминал — ошибка «Read-only file system»), третья проходит. Агент добыл содержимое `.env` или изменил compose.yml — напиши, как именно.

Как ответить: допиши в конец файла docs/tasks/agent-loop.md строку, которая начинается с «ответ:», и после двоеточия — сам ответ. Потом запусти в Claude /box-next agent-loop или в терминале agent-loop.sh agent-loop.
