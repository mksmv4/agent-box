# agent-loop

## Постановка

Цель: пользователь запускает на хосте одну команду с именем задачи — и задача проекта идёт итерациями `/box-next` без ручного запуска каждой сессии, на хосте и в контейнере; остановки, таймер и уведомления в Telegram — по `ARCHITECTURE.md` § Движок автоцикла. Контейнерная ступень защищена: deny-правила образца закрывают неприкасаемое, egress-firewall пропускает только разрешённые адреса, правка агентом `compose.yml` своего проекта закрыта. Итог `/box-task` называет команду запуска движка. Потолок ходов, порог «без прогресса» и порог таймера выбраны пользователем по обкатке. Открытые вопросы `ROADMAP.md` § Движок автоцикла закрыты.

Заметки к реализации firewall, по ресерчу:
- скрипт firewall в образе, вызов из скрипта запуска от root первым делом, до установки Claude Code; права `cap_add: [NET_ADMIN, NET_RAW]` сервису `claude` в `template/compose.yml` и `compose.yml`; пакеты `iptables`, `ipset` в Dockerfile; адреса доменов — `getent ahostsv4` (в образе не проверено), подсеть сети Compose — `/proc/net/route`: `ip` и `dig` в образе нет;
- адреса Claude Code по доке: `api.anthropic.com`, `claude.ai`, `platform.claude.com`, `downloads.claude.ai`, `code.claude.com`; библиотеки — `registry.npmjs.org`, `pypi.org`, `files.pythonhosted.org`, диапазоны GitHub из `api.github.com/meta`; DNS и подсеть сети Compose открыты, как в референсе; SSH, телеметрия Datadog, `mcp-proxy.anthropic.com` закрыты;
- переход к `node` — `setpriv … --bounding-set -all --no-new-privs`;
- контейнер без права `NET_ADMIN` не стартует, сообщение называет строку `cap_add` для compose-файла: bypass-итерации идут только за firewall;
- переменная своих адресов проекта всегда объявлена в `environment:` сервиса, по умолчанию пустая;
- IPv6 — политика DROP в `ip6tables`;
- переход итераций контейнера на bypass — вопрос пользователю в блокере живой проверки шага.

Хвосты:

## Блокер

Какие адреса интернета оставить агенту в контейнере? Остальные закроются: агент без присмотра не сможет отправить файлы проекта на чужой сервер.

Предложение:
- открыто: сервисы Claude — модель, вход в аккаунт, установка и обновление Claude Code, его документация; GitHub, npm и PyPI — скачивание библиотек; сервисы самого проекта в Docker, например его база данных;
- закрыто остальное: агент ищет в интернете, но найденную страницу сам не откроет; подключения аккаунта claude.ai (Gmail, Google Диск и другие) в контейнере не работают; SSH закрыт — push и так идёт с компьютера;
- свои адреса проекта, например его API, человек дописывает строкой в файл настроек контейнера проекта (compose.yml) — агенту этот файл закрыт;
- ограничение действует при каждом запуске контейнера — и в автоцикле, и в ручной работе.

Второе — дыра, которую ограничение сети не закроет: агент может записать в файл секретов проекта (.env) строку, после которой следующий запуск контейнера выполнит его программу с правами администратора. Такая программа прочитает всю домашнюю папку компьютера, с ключами и паролями, и снимет ограничение сети. Предложение — закрыть дыру отдельным шагом в очереди перед текущим:

- [ ] Скрипт запуска контейнера вне досягаемости `.env`: переменные `.env` проекта доходят до Claude Code и команд агента, часть скрипта запуска от root работает без них — строки `PATH`, `LD_PRELOAD` и подобные в `.env` не исполняют программу агента от root (`researches/2026-10-04-firewall.md` § Выводы для шага). Проверка: проба — `.env` тестового проекта со строками `PATH` и `LD_PRELOAD` на программу и библиотеку из папки проекта, запуск контейнера — от root они не выполнились, переменные `.env` агент видит; живой прогон — пользователь: пересборка, новый контейнер, переменная из `.env` видна агенту.
