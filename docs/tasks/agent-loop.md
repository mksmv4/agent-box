# agent-loop

## Постановка

Цель: пользователь запускает на хосте одну команду с именем задачи — и задача проекта идёт итерациями `/box-next` без ручного запуска каждой сессии, на хосте и в контейнере; остановки, таймер и уведомления в Telegram — по `ARCHITECTURE.md` § Движок автоцикла. Контейнерная ступень защищена: deny-правила образца закрывают неприкасаемое, egress-firewall пропускает только разрешённые адреса, правка агентом `compose.yml` своего проекта закрыта. Итог `/box-task` называет команду запуска движка. Потолок ходов, порог «без прогресса» и порог таймера выбраны пользователем по обкатке. Открытые вопросы `ROADMAP.md` § Движок автоцикла закрыты.

## Контекст

Шаг «контейнерная ступень движка» сделан, кроме живого прогона — он в секции «Блокер». Ответ «прогон прошёл» — чекбокс шага и следующий шаг: deny-правила образца и защита `compose.yml`; начать с `ARCHITECTURE.md` § Ступени изоляции — режимы разрешений и `researches/2026-09-24-container.md`, состав неприкасаемого — блокер. Ответ с поломкой — доследование: команду, открывающую сессию итерации, движок печатает в выводе.

Сделано: итерации по умолчанию идут через сервис `claude` проекта, `--host` — на хосте; режим в контейнере — auto (`DECISIONS.md` 2026-10-03 «ступень и режим итераций движка в контейнере»). Строка итерации и поведение Compose по пробам — `ARCHITECTURE.md` § Движок автоцикла. Наличие сервиса движок проверяет перед первой итерацией: проверка Telegram из `README.md` идёт на пустом репозитории без compose-файла.

Проба шага шла заглушками `docker` и `claude` в scratchpad сессии, не сохранена: строка контейнера сверена слово в слово, `CONTEXT_GUARD_MODE=protocol` уходит через `-e`, ввод сессии пуст; исходы — коммит и «готово» (код 0), упор в ходы и падение без JSON (код 1, доследование через `docker compose run --rm claude --resume`), нет сервиса (код 2), `--host` с подсказками `agent-loop.sh --host`. Поведение самого Compose — пробы на образе с `sh` вместо точки входа.

Хвосты:
- `--max-turns 200` и порог таймера «до замера — час» (`alert=3600` в скрипте) выбраны агентом без согласия пользователя — `DECISIONS.md` 2026-09-30 «правка реестра по сверке с переписками»; числа решает пользователь.
- Ctrl+C во время итерации по настоящей сессии не проверялся ни на хосте, ни в контейнере; в контейнере Compose отдаёт SIGINT сессии и сразу выходит с 130 (проба на `sh`).
- Предложение нового шага: проверка токена при старте движка (метод `getMe`) — неверный токен виден сразу при запуске, пока пользователь у терминала, а не на первой остановке; ответ Telegram «Not Found» переводится в «неверный токен». В живой проверке разрезанный по двоеточию токен проявился только строкой «уведомление не ушло: Not Found».

Среда на 2026-10-03: сессия шла на хосте — `docker` с Compose 5.6.0, `claude` 2.1.288, `git`, `jq`; образ `maksim44/claude-box` собран 2026-10-03.

## Блокер

Работает ли автоцикл в контейнере на настоящей сессии? На подставных проверках всё сходится, живой прогон — за тобой.

Сделать руками: в терминале хоста, из папки клона agent-box, одной командой — она собирает тестовый проект с задачей из двух простых шагов и запускает автоцикл:

```bash
s=$PWD/agent-loop.sh; d=$(mktemp -d)/loop-test && cp -r template "$d" && cd "$d" && git init -q && printf 'статус: в работе\n\n# t\n\n## Постановка\n\nЦель: проба автоцикла в контейнере.\n\n- [ ] Файл hello.txt со строкой «привет». Проверка: файл есть.\n- [ ] Файл bye.txt со строкой «пока». Проверка: файл есть.\n\nБлокер: нет.\n\n## Контекст\n\nНачать с первого шага.\n' >docs/tasks/t.md && git add -A && git commit -qm init && "$s" t
```

Ожидается: две итерации, в истории тестового проекта (`git log --oneline`) — коммиты с обоими файлами, движок заканчивает строкой «задача t — готово», в Telegram приходит «loop-test: задача t — готово». По желанию — Ctrl+C во время итерации: движок пишет «остановлен Ctrl+C во время итерации».

В ответ — «прогон прошёл» или что пошло не так.
