# agent-loop

## Постановка

Цель: пользователь запускает на хосте одну команду с именем задачи — и задача проекта идёт итерациями `/box-next` без ручного запуска каждой сессии, на хосте и в контейнере; остановки, таймер и уведомления в Telegram — по `ARCHITECTURE.md` § Движок автоцикла. Контейнерная ступень защищена: deny-правила образца закрывают неприкасаемое, egress-firewall пропускает только разрешённые адреса, правка агентом `compose.yml` своего проекта закрыта. Итог `/box-task` называет команду запуска движка. Потолок ходов, порог «без прогресса» и порог таймера выбраны пользователем по обкатке. Открытые вопросы `ROADMAP.md` § Движок автоцикла закрыты.

## Блокер

Вопрос: как движку распознавать провал итерации? Пробы показали, что ненулевого кода выхода для этого мало.

Что выяснено (CLI 2.1.287, `ARCHITECTURE.md` § Движок автоцикла, исходы под `--output-format json`):
- остановка итерации через SIGINT — тот самый способ вмешательства по алерту таймера — даёт код 0, хотя итог помечен ошибкой (`is_error: true`); по нынешнему разбору движок при чистом дереве сочтёт итерацию «без прогресса» и запустит следующую;
- SIGTERM (код 143) и ошибка в строке запуска (код 1) не печатают JSON — `session_id` для уведомления взять неоткуда;
- упор в `--max-turns` и ошибка API (нет логина) дают код 1, как записано; ошибка API при этом приходит с `subtype: success` — отличать исходы надо по `is_error` и `terminal_reason`, не по `subtype`;
- остальное сошлось: `/box-next` раскрывается в `-p` при `disable-model-invocation: true`, флаги строки на месте.

Предложение: провал итерации — ненулевой код, или `is_error: true`, или stdout без JSON. На провале движок останавливается; уведомление несёт `session_id`, `terminal_reason` и текст ошибки из `result` или `errors`, а когда JSON нет — хвост stderr и код выхода. Так SIGINT, посланный итерации, останавливает и движок: вмешательство пользователя не превращается в следующую итерацию. Правка — в разборе итога § Движок автоцикла, реализация — в ядре движка следующим шагом.
