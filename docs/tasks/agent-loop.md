# agent-loop

## Постановка

Цель: пользователь запускает на хосте одну команду с именем задачи — и задача проекта идёт итерациями `/box-next` без ручного запуска каждой сессии, на хосте и в контейнере; остановки, таймер и уведомления в Telegram — по `ARCHITECTURE.md` § Движок автоцикла. Контейнерная ступень защищена: deny-правила образца закрывают неприкасаемое, egress-firewall пропускает только разрешённые адреса, правка агентом `compose.yml` своего проекта закрыта. Итог `/box-task` называет команду запуска движка. Потолок ходов, порог «без прогресса» и порог таймера выбраны пользователем по обкатке. Открытые вопросы `ROADMAP.md` § Движок автоцикла закрыты.

Проверка — пользователь: пересборка, новый контейнер — запрос к разрешённому адресу проходит, к прочим — отказ, `claude -p` работает. Список адресов — блокер.

Сессия, упёршаяся в закрытый адрес, ставит блокер с адресом и строкой для compose-файла. Проверка — пользователь: пересборка, новый контейнер, `/box-init` в тестовой папке с зависимостями — список с причинами, строка в compose-файле.

Проверка шага: правка скрипта движка — проба в тестовом git-репозитории в контейнере с заглушкой вместо `claude`, изображающей исход итерации (коммит с закрытым чекбоксом, блокер, «готово», падение, правки без коммита): движок останавливается или продолжает по разбору итога из `ARCHITECTURE.md` § Движок автоцикла с ожидаемым сообщением и кодом выхода. Проба проверяет сам скрипт при разработке, в продукт она не входит. Запуск через `docker compose`, правки образа и скиллов — живая проверка пользователем по `RULES.md` § Конвенции работы; такой шаг кончается блокером с командой и ожидаемым итогом.

Блокер: числа — потолок ходов, лимит итераций, пауза, порог «без прогресса», порог таймера; строка итерации контейнерной ступени и переход на bypass; состав неприкасаемого для deny-правил и список адресов firewall; поведение CLI, разошедшееся с `ARCHITECTURE.md` § Движок автоцикла, — например, `/box-next` не раскрылся в `-p`.

## Контекст

Шаг «Список адресов проекта в `/box-init`» — вторая живая проверка после правки по первой. Первая (2026-10-04, п. 4 прогнал агент по просьбе пользователя): ограничение сети строку приняло — 8 доменов, 18 адресов, Claude Code стартовал; сбор адресов верный — сервер пакетов PyTorch, Stripe, Sentry, документация Django, Express, PyTorch, Stripe, PostgreSQL, `legacy.box-test.invalid` исключён как ненайденный, база `db`, npm и PyPI вне списка. Две ошибки исправлены в `skills/box-init/SKILL.md`: правила запрета теперь отдельный шаг 4 после записи в compose-файл — раньше копия настроек образца в шаге 2 закрыла сессии `compose.yaml`, и сервис `claude` ушёл в итог на ручную вставку; список адресов — обычным текстом, ответ — текстом: раньше агент спросил окном вопроса с двумя вариантами, сам список остался в его рассуждениях. Решения — `DECISIONS.md` 2026-10-04.

Ответ «ок» на блокер — чекбокс шага, перенос блокера в `DECISIONS.md`, журнал; дальше — шаг «Итог `/box-task`…», начать с `skills/box-task/SKILL.md`. Другой ответ — правка `skills/box-init/SKILL.md` шаги 3–4 и снова проверка.

Хвосты:

- `.claude/settings.local.json`, который Claude Code создаёт после ответа о MCP-сервере проекта, на хосте висит незакоммиченным и останавливает автоцикл «правками без коммита» — по решению пользователя так и надо: решение о файле за ним.
- Правило блокера на закрытом адресе вживую не проверено: сессия за ограничением сети, упёршаяся в адрес, — при обкатке. До проектов оно доезжает через `/box-update` или повторный `/box-init`.
- Доступность чужих сайтов Cloudflare и Fastly через адреса npm и PyPI не проверена: пробу отклонил классификатор режима auto прошлой сессии.
- Наблюдения живой проверки правил запрета: отказ по `.env` агент дал сначала сам — по глобальному правилу о секретах из `~/.claude/CLAUDE.md` хоста, который едет в контейнер; правило запрета отклонило его следующую команду — вывод имён переменных, и агент назвал это отказом пользователя. Правило `Edit` на compose-файл в проверке не сработало ни разу: агент увидел подключение только на чтение и инструментом правки не пробовал. На машине без глобального правила барьер по `.env` — только правило запрета.
- Пути, которых защита не закрывает: `.git/commondir` переадресует настройки git — ручной `git status` пользователя на хосте выполнит подложенную команду; флаги движка проверены только на fsmonitor и хуках, другие команды из переадресованных настроек git не проверялись. `.claude/settings.local.json` с хуками, записанный скриптом агента, сработает в сессии Claude Code на хосте. Скрипт агента обходит правила запрета. Варианты `.env` вне списка имён (`.env.backup` и подобные) открыты.
- Пилотный проект получит правила, подключения только на чтение, права ограничения сети, снятие `env_file` и список адресов повторным `/box-init` в новом контейнере — решает пользователь.
- `--max-turns 200` и порог таймера «до замера — час» (`alert=3600` в скрипте) выбраны агентом без согласия пользователя — `DECISIONS.md` 2026-09-30 «правка реестра по сверке с переписками»; числа решает пользователь.
- Ctrl+C во время итерации по настоящей сессии не проверялся ни на хосте, ни в контейнере; в контейнере Compose отдаёт SIGINT сессии и сразу выходит с 130 (проба на `sh`).
- Предложение нового шага: проверка токена при старте движка (метод `getMe`) — неверный токен виден сразу при запуске, пока пользователь у терминала, а не на первой остановке; ответ Telegram «Not Found» переводится в «неверный токен».

Среда на 2026-10-04: хост — `docker` с Compose 5.6.0, `git`, `jq`, `python3`; образ `maksim44/claude-box` собран до правки шагов 3–4 `/box-init` — проверка начинается с пересборки; тестовый проект `~/box-test` первой проверки на месте — с блоком сервиса `claude`, вставленным агентом, и сетью `box-test_default`, его убирает п. 2 блокера; сеть `agent-box_default` — сервиса этого репозитория.

## Блокер

`/box-init` починен по первой проверке. Теперь он сам вписывает сервис `claude` со строкой адресов в compose-файл проекта — раньше собственные запреты закрывали ему этот файл посреди сессии. Список адресов с причинами он показывает обычным текстом и ждёт ответа текстом — раньше вместо списка был вопрос с двумя вариантами. Нужна повторная проверка на пересобранном образе в свежей тестовой папке.

Сделать руками:

1. В папке клона agent-box — пересборка образа:
   `docker compose build claude`
2. Уборка тестовой папки первой проверки и новая — с зависимостями с отдельного сервера пакетов, внешним сервисом и несуществующим адресом в примере `.env`, MCP-сервером, базой в compose-файле:
   `cd ~ && docker network rm box-test_default; rm -rf ~/box-test ~/.claude-box/.claude/projects/-workspace-box-test; mkdir ~/box-test && cd ~/box-test && git init -q && printf '{"name":"box-test","dependencies":{"express":"^4.19.0"}}\n' >package.json && printf -- '--extra-index-url https://download.pytorch.org/whl/cpu\ndjango==5.1\ntorch\n' >requirements.txt && printf 'DATABASE_URL=postgres://app:app@db:5432/app\nSTRIPE_API_BASE=https://api.stripe.com\nLEGACY_API=https://legacy.box-test.invalid\n' >.env.example && printf '{"mcpServers":{"sentry":{"type":"http","url":"https://mcp.sentry.dev/mcp"}}}\n' >.mcp.json && printf 'services:\n  db:\n    image: postgres:16\n' >compose.yaml && git add -A && git commit -qm init`
3. Claude в контейнере тестового проекта — именно этой командой `docker run`: сервиса `claude` в `compose.yaml` ещё нет, его вписывает `/box-init`, и `docker compose run --rm claude` до него отвечает «no such service: claude». Команда работает из любой папки:
   `docker run --rm -it -v "$HOME"/box-test:/workspace/box-test -w /workspace/box-test -v "$HOME"/.claude-box:/home/node -v "$HOME":/root/host-home:ro maksim44/claude-box`
   В сессии — `/box-init`. Вопрос о MCP-сервере из `.mcp.json` при старте — любой ответ. На список адресов ответь текстом: убери один адрес на свой выбор. Вопрос об архиве — любой ответ. После итога — выход из сессии.
4. Запуск контейнера так, как его запускает автоцикл, — с ограничением сети и адресами проекта из `compose.yaml`; вместо задачи Claude Code получает `--version`, печатает версию и выходит, испорченная строка адресов остановила бы старт:
   `cd ~/box-test && docker compose run --rm -T --entrypoint claude-box-firewall claude --version </dev/null`

Ожидание в п. 3: до вопросов — сообщение со списком адресов, у каждого причина: сервер пакетов PyTorch из `requirements.txt`, Stripe из `.env.example`, Sentry из `.mcp.json`, сайты документации; `legacy.box-test.invalid` — с пометкой «не найден»; базы `db`, npm и PyPI в списке нет. После ответа `/box-init` сам вписывает сервис `claude` в `compose.yaml`, ручной вставки в итоге нет; строка `CLAUDE_BOX_ALLOW` — без убранного адреса и без `legacy.box-test.invalid`. Проверка строки: `grep -n CLAUDE_BOX_ALLOW ~/box-test/compose.yaml`. Ожидание в п. 4: строка «claude-box-firewall: сеть ограничена: …, своих адресов проекта N …» с N больше нуля, затем версия Claude Code. Пошло иначе — напиши, на каком пункте и что видно.

Уборка после проверки: `cd ~ && docker network rm box-test_default; rm -rf ~/box-test ~/.claude-box/.claude/projects/-workspace-box-test`

«Ок» — список пришёл текстом с причинами, сервис со строкой адресов `/box-init` вписал сам, ограничение сети строку приняло.
