# agent-loop

## Постановка

Цель: пользователь запускает на хосте одну команду с именем задачи — и задача проекта идёт итерациями `/box-next` без ручного запуска каждой сессии, на хосте и в контейнере; остановки, таймер и уведомления в Telegram — по `ARCHITECTURE.md` § Движок автоцикла. Контейнерная ступень защищена: deny-правила образца закрывают неприкасаемое, egress-firewall пропускает только разрешённые адреса, правка агентом `compose.yml` своего проекта закрыта. Итог `/box-task` называет команду запуска движка. Потолок ходов, порог «без прогресса» и порог таймера выбраны пользователем по обкатке. Открытые вопросы `ROADMAP.md` § Движок автоцикла закрыты.

Хвосты:
- Пути, которых предложение не закрывает: `.git/commondir` переадресует настройки git — ручной `git status` пользователя на хосте выполнит подложенную команду, движок защищён флагами `-c`; `.claude/settings.local.json` с хуками сработает в сессии Claude Code на хосте в этом проекте; скрипт агента обходит deny-правила. `Read(.env.*)` закрывает и `.env.example`.
- `--max-turns 200` и порог таймера «до замера — час» (`alert=3600` в скрипте) выбраны агентом без согласия пользователя — `DECISIONS.md` 2026-09-30 «правка реестра по сверке с переписками»; числа решает пользователь.
- Ctrl+C во время итерации по настоящей сессии не проверялся ни на хосте, ни в контейнере — в живом прогоне 2026-10-03 тоже; в контейнере Compose отдаёт SIGINT сессии и сразу выходит с 130 (проба на `sh`).

В живой проверке разрезанный по двоеточию токен проявился только строкой «уведомление не ушло: Not Found».

Среда на 2026-10-03: сессия шла на хосте — `docker` с Compose 5.6.0, `claude` 2.1.288, `git`, `jq`; образ `maksim44/claude-box` собран 2026-10-03. Пробы шага — в песочнице сессии, в репозитории следов нет.

## Блокер

Что закрыть от агента в контейнере? Пробы нашли больше дыр, чем ожидалось: агент может подложить команду в служебные настройки git проекта, и её выполнит ваш компьютер — движок после каждой итерации запускает git на хосте. А контейнер следующей итерации агент может перенастроить и без правки compose-файла — файлом-дополнением рядом с ним или строкой в `.env`.

Предложение:
- Правила Claude Code в образце, для хоста и контейнера: агент не читает и не меняет `.env` и его варианты (`.env.local`, `.env.production`…), не меняет compose-файлы и настройки Claude Code проекта, не делает принудительный push. Это защита от обычных действий агента — написанный им скрипт её обходит.
- В контейнере только для чтения: compose-файл проекта, настройки и хуки git. Изнутри их не изменить ничем.
- Движок запускает git с выключенными хуками и подложенными командами, а контейнер собирает только по основному compose-файлу — дополнения рядом и подмена файла через `.env` не сработают.

Значения из `.env` агент в контейнере видит и так — в переменных окружения, это нужно MCP-серверам; правило закрывает только сам файл.

Как ответить: допиши в конец файла docs/tasks/agent-loop.md строку, которая начинается с «ответ:», — «ответ: ок» или «ответ:» и свой вариант. Потом запусти в Claude /box-next agent-loop или в терминале agent-loop.sh agent-loop.
