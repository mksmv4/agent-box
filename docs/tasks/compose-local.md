# compose-local

## Постановка

Цель: сервис Claude в проекте живёт в отдельном файле `claude-box.yml` в корне проекта под `.gitignore`: основной compose-файл проекта, его git и деплой сервиса Claude не несут. Claude из этого файла — в одной сети с сервисами проекта, база доступна по имени сервиса, в том числе когда основной compose-файл задаёт имя проекта строкой `name:`. Ручной запуск — `docker compose -f claude-box.yml run --rm claude`, движок ведёт итерации из того же файла. Уже заведённый проект переходит на отдельный файл повторным `/box-init`.

Вторая часть цели — проект в дополнительной рабочей копии git (worktree): в контейнере работают git и коммит, а настройки, хуки и список исключений git основного репозитория изнутри контейнера закрыты на запись, как в основной копии.

- [ ] Отдельный файл: образец `template/compose.yml` → `template/claude-box.yml`, первая строка — назначение и команда запуска; `/box-init` (`skills/box-init/SKILL.md`, шаги 2–4 и 8) кладёт `claude-box.yml` в любой проект — со своим compose-файлом и без, — дописывает его в `.gitignore`, переносит строку `name:` основного compose-файла; в уже заведённом проекте сервис `claude` основного compose-файла переезжает в `claude-box.yml` — запись в основной файл в контейнере закрыта, строки к удалению оттуда — в итог пользователю; движок `agent-loop.sh` берёт `claude-box.yml` вместо поиска compose-файла по именам Compose и передаёт Compose `COMPOSE_IGNORE_ORPHANS=true`; правило запрета `template/.claude/settings.json` и подключение только на чтение — на `claude-box.yml`; тексты `container/firewall.sh`, `README.md`, `docs/ARCHITECTURE.md`, `docs/DESCRIPTION.md` — под новую схему, в `README.md` — предупреждение: флаг `--remove-orphans`, который советует строка Compose о чужих контейнерах, в команде запуска Claude не ставится. Проверка: в тестовой папке во временной папке — git-репозиторий, основной compose-файл с сервисом базы и строкой `name:`, `claude-box.yml` из образца с той же строкой и под `.gitignore`: `docker compose -f claude-box.yml --profile claude config --services` печатает `claude`, `git status --porcelain` пуст, `docker compose -f claude-box.yml run --rm --entrypoint getent claude hosts db` печатает адрес базы; `agent-loop.sh` на задаче из одного шага в этой папке проходит итерацию из `claude-box.yml` без строки о чужих контейнерах. Файлы шага — около 126 тыс. символов.

Файлы шага — ресерч, `skills/box-init/SKILL.md`, `template/claude-box.yml`, `docs/ARCHITECTURE.md`, `README.md`.

Ожидание: `claude-box.yml` под `.gitignore` с той же строкой `name:`, основной compose-файл без сервиса `claude` — у проекта по старой схеме итог `/box-init` называет строки к удалению; Claude получает адрес базы; итерация движка закрывает задачу коммитом; в worktree `/box-init` проходит проверки git и делает коммит, запись в `.git/config` основного репозитория из контейнера отклоняется.

Проверка шага: правка образца и движка — проба во временной папке, ожидание записано в шаге; правка скилла и образа — живая проверка пользователем (`RULES.md` § Конвенции работы), последний шаг очереди.

Блокер: защита основного compose-файла проекта — правило запрета и подключение только на чтение: снимать ли её, когда контейнер агента задаёт `claude-box.yml`; перенос сервиса из основного compose-файла в заведённых проектах, когда путь шага не сработал; подключение основного репозитория worktree, не прошедшее пробу; первый запуск контейнера в worktree до `/box-init`, когда у него больше одного пути.

Следующий шаг — «Отдельный файл», остаток: правка образца настроек пользователем по блокеру. Сделано и проверено пробой (`researches/2026-10-14-compose-local.md` § Проба образца и движка): образец `template/claude-box.yml` с подключением только на чтение самого себя, `/claude-box.yml` в `template/.gitignore`, правило `Edit(/claude-box.yml)` в `template/.claude/settings.json`; `/box-init` шаги 2–4 и 8 — сервис в `claude-box.yml` в любом проекте, переезд сервиса из основного compose-файла, перенос `name:`, строки на удаление из основного файла — в итог; движок берёт `claude-box.yml` и передаёт Compose `COMPOSE_IGNORE_ORPHANS=true`; тексты `container/firewall.sh`, `README.md`, `docs/ARCHITECTURE.md`, `docs/DESCRIPTION.md`, `docs/GLOSSARY.md`, строка о закрытом адресе в `template/docs/PROTOCOL.md` § Таск-файлы.

По ответам блокера 2026-10-14 (`DECISIONS.md`): основной compose-файл агент правит — `/box-init` шаг 4 убирает 8 правил `Edit` compose-файлов из настроек проекта, шаг 2 — без правил запрета, шаг 8 называет убранное; тексты — `README.md` § Запуск, `docs/ARCHITECTURE.md` § Ступени изоляции и § Скиллы контейнера; строка дерева `skills/box-init/documents.md` — `claude-box.yml`. Из `template/.claude/settings.json` те же 8 правил не убраны: запись скриптом классификатор режима auto отклонил (`[Self-Modification]`, `AGENTS.md` § Грабли) — правка пользователем, команда в блокере проверена выводом на экран.

Хвосты:

- `compose.yml` этого репозитория остаётся: в нём сборка образа (`docker compose build claude`), движок по задачам agent-box — с `--host` (`AGENTS.md` § Грабли); `README.md` § Запуск называет его.
- Правило песочницы для сессии хоста переустанавливать не нужно: его текст — «compose-файл в корне проекта», `claude-box.yml` под него подходит; текст в `agent-loop.sh` не менялся.
- Предложение: сервисы проекта только в своих сетях (`networks:` без сети по умолчанию) Claude из `claude-box.yml` по имени не увидит — не проверено; кандидат в живую проверку или отдельный шаг.
- Пилотный проект ждёт этой задачи: повторный `/box-init` в нём после пересборки образа перенесёт сервис в `claude-box.yml` и снимет запрет на правку основного compose-файла.

Среда: временная папка пробы `/tmp/compose-local-*` — копия образца с задачей `t` в статусе «готово»; контейнеры и сеть пробы убраны; история сессии итерации пробы — в домашней папке контейнера под путём `/workspace/shopprobe`.

## Блокер

Ответы учтены: агент правит основной compose-файл проекта, как остальной код, — заведение проекта убирает старый запрет из настроек проекта; строка в описании файлов проекта поправлена. Осталась одна правка, которую сессия сделать не может: убрать тот же запрет из образца настроек, который получает каждый новый проект. Запись в него проверка безопасности режима auto отклонила как ослабление разрешений агента — такую правку делает человек.

Сделай руками — в терминале, в корне клона agent-box:

```
jq '.permissions.deny -= ["Edit(/compose.yaml)","Edit(/compose.yml)","Edit(/docker-compose.yaml)","Edit(/docker-compose.yml)","Edit(/compose.override.yaml)","Edit(/compose.override.yml)","Edit(/docker-compose.override.yaml)","Edit(/docker-compose.override.yml)"]' template/.claude/settings.json > /tmp/box-settings.json && cp /tmp/box-settings.json template/.claude/settings.json && rm /tmp/box-settings.json && git diff template/.claude/settings.json
```

Ожидание: `git diff` показывает 8 убранных строк с `compose` в имени, остальные правила на месте. Коммит не нужен — правку заберёт следующая сессия.

Как ответить: допиши в конец файла docs/tasks/compose-local.md строку, которая начинается с «ответ:», и после двоеточия — сам ответ, например «ответ: сделано». Потом запусти в Claude /box-next compose-local или в терминале agent-loop.sh --host compose-local.
