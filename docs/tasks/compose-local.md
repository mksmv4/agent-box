# compose-local

## Постановка

Цель: сервис Claude в проекте живёт в отдельном файле `claude-box.yml` в корне проекта под `.gitignore`: основной compose-файл проекта, его git и деплой сервиса Claude не несут. Claude из этого файла — в одной сети с сервисами проекта, база доступна по имени сервиса, в том числе когда основной compose-файл задаёт имя проекта строкой `name:`. Ручной запуск — `docker compose -f claude-box.yml run --rm claude`, движок ведёт итерации из того же файла. Уже заведённый проект переходит на отдельный файл повторным `/box-init`.

Вторая часть цели — проект в дополнительной рабочей копии git (worktree): в контейнере работают git и коммит, а настройки, хуки и список исключений git основного репозитория изнутри контейнера закрыты на запись, как в основной копии.

Проверка шага: правка образца и движка — проба во временной папке, ожидание записано в шаге; правка скилла и образа — живая проверка пользователем (`RULES.md` § Конвенции работы), последний шаг очереди.

## Блокер

Шаг сделан и проверен во временной папке: сервис Claude теперь живёт в отдельном файле `claude-box.yml` вне git проекта, движок и заведение проекта работают с ним, Claude видит базу проекта по имени. Нужны два решения.

1. Снять ли запрет на правку основного compose-файла проекта — того, что уходит в git и деплой? Запрет остался с тех пор, когда этот файл задавал контейнер Claude; теперь контейнер задаёт только `claude-box.yml`, и закрыт от агента он. Сейчас агент основной compose-файл и его дополнения не правит — по задаче, где нужен новый сервис проекта, правку делает человек.
   Предложение: снять. Агент правит основной compose-файл, как остальной код проекта; правка видна в коммите и сработает на следующем `docker compose up` проекта на компьютере — как любой код проекта, который человек запускает. Запрет уходит из образца, у проектов, заведённых раньше, его убирает повторный `/box-init`. Вторая защита — файл только на чтение в контейнере — в новой схеме уже снята: образец не знает имени основного файла, а проект без него получил бы на его месте пустую папку от root. Другой вариант — оставить запрет, и тогда `/box-init` закрывает файл в контейнере по его имени.

2. Можно ли поправить одну строку в описании файлов проекта, по которому собирается документация (эти описания правятся только с твоего разрешения)? Сейчас там старое имя файла сервиса Claude.
   Было: `├── compose.yml          # сервис claude: Claude Code в контейнере, docker compose run --rm claude`
   Станет: `├── claude-box.yml       # сервис claude вне git проекта: Claude Code в контейнере, docker compose -f claude-box.yml run --rm claude`
   Предложение: поправить.

Как ответить: допиши в конец файла docs/tasks/compose-local.md строку, которая начинается с «ответ:», — «ответ: ок» (согласие с обоими предложениями) или «ответ:» и свой вариант по каждому вопросу. Потом запусти в Claude /box-next compose-local или в терминале agent-loop.sh --host compose-local.
