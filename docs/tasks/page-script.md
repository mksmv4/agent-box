# page-script

## Постановка

Цель: страницу задачи оркестратор ведёт без агента страницы — создание страницы, галочку шага, строку новой итерации, состояние в шапке, блок вопроса и «готово» он делает командой скрипта по файлу страницы и одним вызовом публикации; заголовок, лид и цель новой страницы обычными словами — несколько фраз, которые оркестратор передаёт скрипту, схем на странице нет; вопросы пользователю идут словами протокола — шаг, задача, веха, итерация, — без придуманных замен. Повод — беседа оркестратора пилотного проекта `9cfcdaef-ae66-48dd-902c-fe94c9b2c26c` 2026-10-19: агент страницы запускался 10 раз — 6 на начала итераций, 4 на один вопрос (первый показ и три повтора после переспросов пользователя), каждый стартовал с 56 тыс. токенов контекста и кончал на 90–113 тыс., а сама правка у него — одна команда скрипта по файлу и один вызов публикации; вопрос шёл словами «заход» и «часть работы», потому что скилл запрещает в вопросе «закрыть шаг» и названия шагов, а образец «понятно» в `questions.md` сам пишет «ещё заход». Решение пользователя об агенте на отметки — `DECISIONS.md` 2026-10-18 («чтобы на [чёртовы] галочки не вызывался .. агент»).

## Контекст

Шаги «Скрипт страницы» и «Вопросы словами протокола» закрыты 2026-10-20. Страницу ведёт скрипт `template/.claude/skills/box-orchestrate/page.py`, публикует оркестратор; вопросы пользователю идут словами протокола.

Шаг «Живой прогон» 2026-10-20: блокер с просьбой о прогоне на тестовом проекте скрипта `my_local/orchestrator-check-probe.sh` — задача report в `/tmp/orch-check`: страницы у неё нет, первый блокер снимает оркестратор агентом проверок, второй — выбор подписи — идёт пользователю, итераций от трёх. Скрипт сверен с образцом: `template/docs/tasks/` и `template/claude-box.yml` на месте. Образ не пересобирается: задача правила скилл оркестратора, `agent-loop.sh` и `config.yml` хоста, тестовый проект берёт копию `template/` целиком.

Следующее — по ответу: история беседы `~/.claude/projects/-tmp-orch-check/<id>.jsonl` (прогон на другом проекте — его папка в `~/.claude/projects/`), выборка командой из «Проверки шага». Проверка по описанию шага: вызовы `Agent` — только агенты проверок; `Artifact` на создании страницы, каждом начале итерации, вопросе и его повторах, «готово»; галочки шагов и строки итераций на опубликованной странице — по журналу цикла; вопрос и варианты — по сверке шага «Вопросы словами протокола» ниже; числа — новым разделом в `docs/researches/2026-10-15-page-agent.md`, рост контекста на каждом событии против критерия 2 тыс. токенов. Сессия разбора — на хосте: итерация в контейнере историю беседы хоста не видит.

Сверка для прогона — событие шага «Страница задачи» `SKILL.md` оркестратора → команда скрипта:
- выход сторожа — начало итерации или алерт — `iteration` с фразой об итерациях, публикация, та же фраза в чат;
- вопрос пользователю о блокере или остановке (шаги 3–5) и повтор с новыми фразами — `question` с JSON вопросов, публикация, затем фоновая `sleep 5`, сообщение текстом, которым кончается ход, пуш на уведомление `sleep`, окно; повтор с теми же фразами — без команды и публикации;
- ответы, записанные в «Блокер», пользователя и оркестратора — `answer`; публикация — когда перезапуска нет;
- остановка без вопроса и предел контекста (шаг 2) — `stop` с фразой, публикация;
- «готово» (шаг 6) — `done` с фразой, публикация, затем тот же порядок с `sleep 5`, пуш, окно о следующей задаче;
- страницы или меток нет, код 3 — `new` с заголовком, лидом и частями цели, затем команда события снова;
- первая публикация и потерянная ссылка — адрес из ответа `Artifact` командой `link`.

Сверка шага «Вопросы словами протокола» 2026-10-20 — место прежнего запрета → новое правило:
- шаг 4 `SKILL.md` оркестратора, абзац «Вопрос пользователю — выбор между тем…», и вступление `questions.md`: запрет на «закрыть шаг», очередь, номера и имена шагов → слова протокола — шаг, задача, веха, итерация, блокер — как есть, в смысле `docs/PROTOCOL.md`; шаг — названием из очереди в кавычках, новый шаг — тем, что он сделает; номера шагов и итераций и «n из m» в вопрос не идут; условия проверки шага — тем, что будет дальше для пользователя;
- образец «Условие проверки с числом» — «ещё заход» → «новым шагом этой же задачи»;
- образец «Ход задачи» — «плохо» прежнее, с причиной: шаг без своего названия, варианты о порядке работы; «понятно» — «Чинить — новым шагом этой же задачи: …»;
- образец «Номера шагов» — «понятно»: шаг названием из очереди, новый шаг — тем, что он сделает;
- новый образец «Слово вместо шага» по вопросу беседы `9cfcdaef`; название шага пилотного проекта в «понятно» — обобщённое «Прогон раз в час и по кнопке», личных данных в образце нет;
- шаг 7 `SKILL.md`, фразы `iteration`, — «шаги названиями из очереди в кавычках, без номеров итераций» — сходится с новым правилом;
- `grep -rn -E 'заход|часть работы'` по папке скилла пуст; шапка скилла не менялась, конвенции `RULES.md` § Конвенции кода держатся.

Состояние среды 2026-10-20: папки `/tmp/orch-check` нет, скрипт тестового проекта запустится; от прошлых прогонов остались сеть Docker `orch-check_default` и истории `~/.claude/projects/-tmp-orch-check/` и `~/.claude-box/.claude/projects/-workspace-orch-check/` — новая беседа ищется по id из ответа. Команды уборки — в блокере, после разбора.

Хвосты:
- предложение: `template/docs/PROTOCOL.md` § Сообщения пользователю — «имена файлов, функций и шагов остаются в коде и «Контексте»» расходится с новым правилом вопроса, где шаг очереди идёт своим названием в кавычках; уточнить, что шаг очереди в сообщении пользователю называется своим названием, а «имена шагов» — шаги скиллов и кода;
- шапка страницы от `page.py` пишет «шаг n из m» рядом с названием шага в лиде; новое правило убирает номера только из вопроса — живой прогон покажет, путает ли это пользователя, как в образце «Номера шагов»;
- отказ публикации «не видел живую версию» приходит с живой страницей в тексте — до задачи orchestrator-context это 22 тыс. токенов в контексте оркестратора; в новой беседе такой отказ ждёт первую публикацию по прежнему адресу — живой прогон покажет, сколько он стоит;
- `page-agent.md` с маркером под удаление удаляет пользователь; `/box-update` разнесёт маркер в проекты, пока файл в образце.

## Блокер

Шаг «Живой прогон» проводишь ты: оркестратор теперь сам ведёт страницу задачи, без помощника, и проверить это можно только в настоящей беседе Claude.

Вопрос: прошёл ли прогон оркестратора на тестовом проекте и какой id у его беседы? В ответ — id и что заметил на странице и в вопросах.

Предложение: тестовый проект с задачей report. Страницы у задачи ещё нет. Первый вопрос задачи оркестратор снимает сам, второй — выбор подписи отчёта — задаёт тебе. По id следующая сессия разберёт историю беседы: звал ли оркестратор помощника ради страницы, обновлялась ли страница на каждом событии, понятен ли вопрос, сколько памяти беседы уходит на каждое обновление.

Сделай руками:

1. В терминале на компьютере — тестовый проект:

   ```
   bash ~/tools/agent-box/my_local/orchestrator-check-probe.sh
   ```

   Увидишь строку «тестовый проект готов: /tmp/orch-check».

2. Там же — Claude в папке проекта:

   ```
   cd /tmp/orch-check
   claude
   ```

3. В Claude:

   ```
   /box-orchestrate report
   ```

   Веди задачу до конца. Подпись отчёта выбери любую, на вопрос о следующей задаче ответь концом работы. Ссылку на страницу задачи оркестратор пишет в чат — загляни, отмечен ли на ней каждый шаг и каждый запуск.

4. Id беседы — имя самого свежего файла истории:

   ```
   ls -t ~/.claude/projects/-tmp-orch-check | head -1
   ```

Уборка — после разбора прогона: следующей сессии нужна история беседы.

```
docker network rm orch-check_default
rm -rf /tmp/orch-check
rm -rf ~/.claude/projects/-tmp-orch-check
rm -rf ~/.claude-box/.claude/projects/-workspace-orch-check
```

Как ответить: допиши в конец файла docs/tasks/page-script.md строку, которая начинается с «ответ:», и после двоеточия — сам ответ. Потом запусти в Claude /box-next page-script или в терминале agent-loop.sh --host page-script.
