# qa-frames

## Постановка

Цель: страница задачи оркестратора публикуется при любом числе кадров QA. Кадры сценария склеены в вертикальную ленту: нажатие на обложку открывает ленту, её листают прокруткой, кнопки «+» и «−» увеличивают только ленту, и её можно двигать вбок. Файлы, которых на странице больше нет, публикация убирает. Сессия QA снимает в окне браузера 1440×900.

Повод — пилотный проект 2026-11-06: 797 кадров при пределе 511 файлов на версию страницы, публикации страницы падали с вечера 2026-11-05 ошибкой `manifest exceeds 512 entries`. Кадры там 3440×1301 — окно браузера во весь широкий монитор, сайт занимает треть ширины. Замер на 30 кадрах: PNG — 229 КБ, WebP с качеством 80 — 68 КБ, текст не отличить, JPEG с качеством 85 — 218 КБ. Решения — `docs/DECISIONS.md`, 2026-11-06; лента прокруткой заменяет листание кадров по одному из решения 2026-10-30.

## Контекст

Следующий шаг — окно браузера в QA: шаг прогона в `template/.claude/skills/box-qa/SKILL.md`, строка 1440×900 перед первым действием.

Окно просмотра ленты сделано и проверено в Chromium через Playwright на тестовой странице 2026-11-06, окно 1440×900 и 400×800, сервер на 127.0.0.1: куски вплотную на ширину окна, прокрутка колесом и Page Down, «+» и «−» — ширина в 1,5 раза за нажатие от 0,3 до 7,6 ширины окна с гаснущими кнопками на краях, середина окна остаётся на месте кадра, перетаскивание мышью двигает ленту вбок и вниз, Esc и крестик закрывают, повторное открытие — с начала ленты и в исходном размере, место на странице после закрытия прежнее, одиночная картинка встаёт целиком в экран и закрывается нажатием. Загрузок вне локального сервера нет.

Состояние среды: тестовая папка `/tmp/qa-frames-test` — git-репозиторий с копией задачи QA пилотного проекта под именем `pilot-qa`: таск-файл, сценарии, 804 снимка, страница `my_local/pages/pilot-qa.html`, пересозданная командой `new` с новым каркасом, 53 обложки, 144 файла WebP рядом и отметки `sent.txt`. Команды скрипта — из этой папки: `python3 ~/tools/agent-box/template/.claude/skills/box-orchestrate/page.py pilot-qa <команда>`. `/tmp/qa-frames-view` — обёртка публикации `index.html` и ссылка на папку кадров, сервер — `python3 -m http.server 8765 --bind 127.0.0.1` из неё. `/tmp/qa-frames-probe` — скрипт сборки тестовой папки `setup.sh`, скрипт `rebuild.sh`: пример с вопросом из каркаса, страница `new`, обёртка; в `playwright/` — снимки экрана и журналы проверки. На снимках — данные клиентов пилотного проекта: все три папки убираются после задачи.

Хвосты:
- Окно просмотра лежит в каркасе вне меток, а каркас скрипт берёт из примера только командой `new`: страница пилотного проекта получит новое окно только пересозданием; до него прежнее окно листает куски ленты как кадры по одному.
- Палец на телефоне — прокрутка ленты, сдвиг вбок, щипок — в безголовом браузере не проверялся: его проверяет живая проверка.
- Все кадры тестовой копии — 3440 в ширину: лента из кадров 1440×900 в браузере не открывалась. На ширине 400 пикселей кадр 3440 встаёт в 385 пикселей; при какой ширине ленты текст читается — не проверено.
- Уборка на пилотном проекте по пробе в тестовой папке 2026-11-06 идёт тремя публикациями: 255 убранных, затем 246 убранных и 9 новых, затем 133 новых; до третьей у части обложек файлов на странице нет. Считается ли `null` в предел 255 записей и принимает ли публикация `null` на файл, которого на странице нет, — не проверено: второе бывает после потерянной ссылки, публикация без адреса несёт убранные файлы прежней страницы.
- Первая команда на 804 кадрах склеивает 142 файла за 3 минуты, `SKILL.md` оркестратора велит вызывать скрипт с `timeout` 600000 — на живом прогоне не проверено.
- Прежние куски лент и обложки после новых кадров остаются файлами в `my_local/pages/<задача>/` проекта: уборка убирает их со страницы, с диска — нет.
- Пределы показа большой картинки на телефоне не проверены: кусок из 12 кадров 3440×1301 — около 54 мегапикселей, из 17 кадров 1440×900 — около 22.
