# qa-frames

## Постановка

Цель: страница задачи оркестратора публикуется при любом числе кадров QA. Кадры сценария склеены в вертикальную ленту: нажатие на обложку открывает ленту, её листают прокруткой, кнопки «+» и «−» увеличивают только ленту, и её можно двигать вбок. Файлы, которых на странице больше нет, публикация убирает. Сессия QA снимает в окне браузера 1440×900.

Повод — пилотный проект 2026-11-06: 797 кадров при пределе 511 файлов на версию страницы, публикации страницы падали с вечера 2026-11-05 ошибкой `manifest exceeds 512 entries`. Кадры там 3440×1301 — окно браузера во весь широкий монитор, сайт занимает треть ширины. Замер на 30 кадрах: PNG — 229 КБ, WebP с качеством 80 — 68 КБ, текст не отличить, JPEG с качеством 85 — 218 КБ. Решения — `docs/DECISIONS.md`, 2026-11-06; лента прокруткой заменяет листание кадров по одному из решения 2026-10-30.

Очередь:

- [x] Склейка и уборка в скрипте страницы. Кадры сценария — вертикальная лента из кусков WebP: кадры друг под другом, кусок — до 16 000 пикселей в высоту (предел WebP — 16 383), качество 80; обложка сценария — последний кадр отдельным файлом WebP. Снимки в `my_local/qa/<задача>/` остаются PNG, лента собирается из них одним сжатием. Склейка — библиотекой Pillow; Pillow нет — код 2 и строка с командой установки. Уборка: файлы, отмеченные отправленными и больше не показанные страницей, уходят в JSON `files` ответа скрипта со значением `null`, команда `sent` после удачной публикации снимает их с отметок; в одном ответе — не больше 255 записей, остаток — со следующим событием. Правится `page.py`, `pages.md`, шаг публикации в `SKILL.md` оркестратора, `docs/architecture/orchestrator.md` (скрипт больше не только на стандартной библиотеке), требования в `README.md` — Pillow для оркестратора. Читает: `template/.claude/skills/box-orchestrate/page.py`, `pages.md`, `SKILL.md`, `docs/architecture/orchestrator.md`, `README.md` — 109 тыс. знаков. Проверка: на копии снимков пилотного проекта в тестовой папке скрипт кладёт рядом со страницей ленты и обложки, файлов не больше 150 на 797 кадров; ответ скрипта на странице с отправленными одиночными кадрами несёт их со значением `null`.
- [x] Окно просмотра ленты. Нажатие на обложку открывает ленту сценария поверх страницы: куски вплотную друг под другом на ширину окна, листание прокруткой, кнопки «+» и «−» меняют ширину ленты, при увеличении лента двигается вбок; закрытие — крестиком и Esc. Листание по одному кадру и счётчик «кадр N из M» уходят. Правится каркас `examples/running.html`, пример `examples/question.html` собирается заново, описание просмотра — в `pages.md`, разметка обложки — в `page.py`. Читает: `examples/running.html`, `examples/question.html`, `pages.md`, `page.py` — 88 тыс. знаков. Проверка: тестовая страница из первого шага открывается в браузере без сети, лента прокручивается, кнопки меняют размер, Esc закрывает.
- [x] Окно браузера в QA: шаг прогона в `template/.claude/skills/box-qa/SKILL.md` перед первым действием ставит окно браузера 1440×900. Читает: этот файл — 7 тыс. знаков. Проверка: строка в шаге прогона стоит до первого действия.
- [ ] Живая проверка — ведёт пользователь: свежие скиллы в пилотном проекте, страница задачи QA пилотного проекта пересоздаётся по прежнему адресу и публикуется. С компьютера и телефона: ленты открываются, прокручиваются, кнопки «+» и «−» увеличивают ленту, текст читается при увеличении; одиночных кадров на странице нет. Блокер: живая проверка; расхождение этой постановки с документами или возможностями инструмента.

## Контекст

Шаг живой проверки ждёт ответа пользователя — секция «Блокер»: пересборка образа, свежие скиллы в пилотном проекте командой `/box-update`, пересоздание страницы задачи QA пилотного проекта оркестратором и осмотр лент с компьютера и телефона. Следующая сессия переносит блокер с ответом в `DECISIONS.md`; всё работает — чекбокс шага, статус «готово», запись журнала по задаче; кусок ленты не открылся на телефоне — шаг резки кусков по площади картинки встаёт в очередь по согласию пользователя (`docs/PROTOCOL.md` § Таск-файлы).

Состояние пилотного проекта на 2026-11-06: образ `claude-box` собран 2026-11-05, раньше правок задачи, — скиллы пилотного проекта старые, копия скрипта страницы от 2026-11-05; рабочее дерево чистое; задача QA — «готово», на её странице 501 файл отмечен отправленным, снимков прогона 804. Pillow на компьютере стоит — 10.2.0. Пересоздание страницы командой `new` оркестратор сам зовёт только на коде 3 — страницы нет, меток нет или нет этапа, — поэтому блокер даёт пользователю фразу для оркестратора: `new`, затем `done` с публикацией, пока скрипт называет остаток кадров. Имена папки и задачи QA пилотного проекта — `my_local/personal.md`.

Окно браузера в QA сделано 2026-11-06: шаг прогона в шаблоне этапа QA `/box-qa` перед первым действием ставит окно 1440×900 инструментом `browser_resize`. Окно просмотра ленты проверено в Chromium через Playwright на тестовой странице 2026-11-06, окно 1440×900 и 400×800: куски вплотную на ширину окна, прокрутка, «+» и «−» — ширина в 1,5 раза за нажатие от 0,3 до 7,6 ширины окна, перетаскивание мышью, Esc и крестик закрывают, загрузок вне локального сервера нет.

Состояние среды: тестовые папки `/tmp/qa-frames-test` (копия задачи QA пилотного проекта под именем `pilot-qa`, 804 снимка, страница и 144 файла WebP), `/tmp/qa-frames-view` (обёртка публикации) и `/tmp/qa-frames-probe` (скрипты `setup.sh`, `rebuild.sh`, снимки и журналы Playwright) лежат до уборки пользователем — команда в секции «Блокер»; на снимках — данные клиентов пилотного проекта. Сервер `http.server` на 127.0.0.1:8765 не запущен.

Хвосты:
- Этап QA, уже записанный в таск-файл проекта, несёт абзац шага прогона без размера окна: окно 1440×900 ставят этапы, которые `/box-qa` запишет после обновления скиллов.
- Окно просмотра лежит в каркасе вне меток, а каркас скрипт берёт из примера только командой `new`: страница проекта получит новое окно только пересозданием; до него прежнее окно листает куски ленты как кадры по одному.
- Остаток файлов кадров сверх 255 записей несёт следующее событие, а у задачи со статусом «готово» событий после `done` нет: остаток дойдёт до страницы только повтором `done` с публикацией — на пилотном проекте нужны три публикации (255 убранных, затем 246 убранных и 9 новых, затем 133 новых, проба в тестовой папке 2026-11-06). Предложение: оркестратор после `done` повторяет `done` с публикацией, пока скрипт называет остаток, — новым шагом по согласию пользователя.
- Палец на телефоне — прокрутка ленты, сдвиг вбок, щипок — в безголовом браузере не проверялся: его проверяет живая проверка.
- Все кадры тестовой копии — 3440 в ширину: лента из кадров 1440×900 в браузере не открывалась. На ширине 400 пикселей кадр 3440 встаёт в 385 пикселей; при какой ширине ленты текст читается — не проверено.
- Считается ли `null` в предел 255 записей и принимает ли публикация `null` на файл, которого на странице нет, — не проверено: второе бывает после потерянной ссылки, публикация без адреса несёт убранные файлы прежней страницы.
- Первая команда на 804 кадрах склеивает 142 файла за 3 минуты, `SKILL.md` оркестратора велит вызывать скрипт с `timeout` 600000 — проверит живая проверка: первую склейку делает оркестратор.
- Прежние куски лент и обложки после новых кадров остаются файлами в `my_local/pages/<задача>/` проекта: уборка убирает их со страницы, с диска — нет.
- Пределы показа большой картинки на телефоне не проверены: кусок из 12 кадров 3440×1301 — около 54 мегапикселей, из 17 кадров 1440×900 — около 22.

## Блокер

Ленты кадров на странице задачи сделаны и проверены в браузере на компьютере без сети. Как они ведут себя на живой странице claude.ai с компьютера и телефона, видит только человек.

Вопрос: ленты кадров на живой странице задачи QA пилотного проекта открываются, листаются и увеличиваются — с компьютера и с телефона?

Предложение сессии: всё работает — шаг закрыт, задача готова. Кусок ленты не открылся на телефоне — новый шаг: резать ленту на куски по числу пикселей картинки, а не только по высоте.

Просьба сделать руками:

1. Пересобери образ: в нём ещё скиллы до этой задачи. Терминал в папке agent-box:

   ```bash
   docker compose build claude
   ```

2. Обнови скиллы пилотного проекта. Терминал в папке пилотного проекта — путь в `my_local/personal.md`, строка «папка пилотного проекта»:

   ```bash
   docker compose -f claude-box.yml run --rm claude
   ```

   В сессии Claude в контейнере:

   ```
   /box-update
   ```

   Увидишь коммит со свежими командами agent-box. Закрой эту сессию.

3. Пересоздай страницу. Claude на компьютере, запущенный в папке пилотного проекта:

   ```
   /box-orchestrate <задача QA>
   ```

   `<задача QA>` — имя задачи QA пилотного проекта, та же строка `my_local/personal.md`. Задача уже готова, поэтому скрипт сразу остановится. Оркестратор склеит кадры — до 3 минут — и опубликует страницу по прежнему адресу. На вопрос о следующей задаче выбери конец и напиши в чат:

   ```
   Пересоздай страницу задачи командой new по цели
   таск-файла. Потом команда done и публикация —
   повторяй их, пока скрипт называет остаток кадров.
   ```

   Увидишь ещё две-три публикации и ссылку на страницу в чате.

4. Открой страницу с компьютера, потом с телефона. Проверь:
   - у каждого сценария — одна обложка, одиночных кадров нет;
   - нажатие на обложку открывает ленту, она листается прокруткой, на телефоне — пальцем;
   - «+» и «−» меняют размер ленты, увеличенную ленту можно двигать вбок;
   - текст на кадрах читается при увеличении;
   - крестик закрывает ленту, на компьютере — и Esc.

   Кадры этого прогона сняты в окне шириной 3440 точек, поэтому без увеличения текст мелкий. Следующий прогон QA снимет окно 1440×900.

5. Убери тестовые папки этой задачи — в них снимки с данными клиентов пилотного проекта. Терминал в любой папке:

   ```bash
   rm -rf /tmp/qa-frames-test \
     /tmp/qa-frames-view /tmp/qa-frames-probe
   ```

Как ответить: допиши в конец файла docs/tasks/qa-frames.md строку, которая начинается с «ответ:», и после двоеточия — сам ответ: что работает, что нет, и на каком устройстве. Потом запусти в Claude /box-next qa-frames или в терминале agent-loop.sh --host qa-frames.
