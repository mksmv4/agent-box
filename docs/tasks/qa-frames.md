# qa-frames

## Постановка

Цель: страница задачи оркестратора публикуется при любом числе кадров QA. Кадры сценария склеены в вертикальную ленту: нажатие на обложку открывает ленту, её листают прокруткой, кнопки «+» и «−» увеличивают только ленту, и её можно двигать вбок. Файлы, которых на странице больше нет, публикация убирает. Сессия QA снимает в окне браузера 1440×900.

Повод — пилотный проект 2026-11-06: 797 кадров при пределе 511 файлов на версию страницы, публикации страницы падали с вечера 2026-11-05 ошибкой `manifest exceeds 512 entries`. Кадры там 3440×1301 — окно браузера во весь широкий монитор, сайт занимает треть ширины. Замер на 30 кадрах: PNG — 229 КБ, WebP с качеством 80 — 68 КБ, текст не отличить, JPEG с качеством 85 — 218 КБ. Решения — `docs/DECISIONS.md`, 2026-11-06; лента прокруткой заменяет листание кадров по одному из решения 2026-10-30.

Очередь:

- [x] Склейка и уборка в скрипте страницы. Кадры сценария — вертикальная лента из кусков WebP: кадры друг под другом, кусок — до 16 000 пикселей в высоту (предел WebP — 16 383), качество 80; обложка сценария — последний кадр отдельным файлом WebP. Снимки в `my_local/qa/<задача>/` остаются PNG, лента собирается из них одним сжатием. Склейка — библиотекой Pillow; Pillow нет — код 2 и строка с командой установки. Уборка: файлы, отмеченные отправленными и больше не показанные страницей, уходят в JSON `files` ответа скрипта со значением `null`, команда `sent` после удачной публикации снимает их с отметок; в одном ответе — не больше 255 записей, остаток — со следующим событием. Правится `page.py`, `pages.md`, шаг публикации в `SKILL.md` оркестратора, `docs/architecture/orchestrator.md` (скрипт больше не только на стандартной библиотеке), требования в `README.md` — Pillow для оркестратора. Читает: `template/.claude/skills/box-orchestrate/page.py`, `pages.md`, `SKILL.md`, `docs/architecture/orchestrator.md`, `README.md` — 109 тыс. знаков. Проверка: на копии снимков пилотного проекта в тестовой папке скрипт кладёт рядом со страницей ленты и обложки, файлов не больше 150 на 797 кадров; ответ скрипта на странице с отправленными одиночными кадрами несёт их со значением `null`.
- [x] Окно просмотра ленты. Нажатие на обложку открывает ленту сценария поверх страницы: куски вплотную друг под другом на ширину окна, листание прокруткой, кнопки «+» и «−» меняют ширину ленты, при увеличении лента двигается вбок; закрытие — крестиком и Esc. Листание по одному кадру и счётчик «кадр N из M» уходят. Правится каркас `examples/running.html`, пример `examples/question.html` собирается заново, описание просмотра — в `pages.md`, разметка обложки — в `page.py`. Читает: `examples/running.html`, `examples/question.html`, `pages.md`, `page.py` — 88 тыс. знаков. Проверка: тестовая страница из первого шага открывается в браузере без сети, лента прокручивается, кнопки меняют размер, Esc закрывает.
- [x] Окно браузера в QA: шаг прогона в `template/.claude/skills/box-qa/SKILL.md` перед первым действием ставит окно браузера 1440×900. Читает: этот файл — 7 тыс. знаков. Проверка: строка в шаге прогона стоит до первого действия.
- [x] Живая проверка — ведёт пользователь: свежие скиллы в пилотном проекте, страница задачи QA пилотного проекта пересоздаётся по прежнему адресу и публикуется. С компьютера и телефона: ленты открываются, прокручиваются, кнопки «+» и «−» увеличивают ленту, текст читается при увеличении; одиночных кадров на странице нет. Кусок ленты из старых кадров 3440×1301 на телефоне не открывается — предложение резать куски по площади.
- [x] Досылка остатка после «готово». После `done` и публикации оркестратор сам повторяет `done` с публикацией, пока ответ скрипта страницы называет остаток кадров сверх 255 записей; просить его об этом пользователю больше не нужно. Правится шаг «Готово» и публикация в `SKILL.md` оркестратора, при нужде — ответ скрипта в `page.py` и его описание в `pages.md`. Читает: `template/.claude/skills/box-orchestrate/SKILL.md`, `page.py`, `pages.md` — 72 тыс. знаков. Проверка: на копии снимков пилотного проекта в тестовой папке цепочка `done` → `sent` доходит до ответа скрипта без остатка — по пробе 2026-11-06 за три публикации; текст `SKILL.md` велит повторять до такого ответа.
- [x] Подписи под кадрами. Сессия QA при каждом снимке пишет подпись одной строкой: что сделала и что должно быть видно — «нажала „Крутить колесо“ → окно с призом»; подпись лежит рядом со снимком в `my_local/qa/<задача>/`. Лента сценария на странице показывает подпись под её кадром: подпись видна при прокрутке и читается при увеличении ленты; кадр без подписи идёт в ленту без неё. Правится шаг прогона в `template/.claude/skills/box-qa/SKILL.md`, склейка в `page.py`, описание в `pages.md`, при нужде — окно просмотра в каркасе `examples/running.html`. Читает: `box-qa/SKILL.md`, `page.py`, `pages.md`, `examples/running.html` — 77 тыс. знаков. Проверка: тестовая страница из копии снимков пилотного проекта с подписями у части кадров открывается в браузере без сети — под каждым подписанным кадром ленты его подпись, у остальных подписи нет; шаг прогона в `box-qa` велит писать подпись при каждом снимке.

Проверка шага: записана у каждого шага.

Блокер: живая проверка; расхождение этой постановки с документами или возможностями инструмента.

## Контекст

Все шаги сделаны, задача готова.

Подписи под кадрами: сессия QA кладёт рядом со снимком файл подписи с тем же именем и расширением `.txt`; скрипт страницы рисует подпись в ленте тёмной полосой с белым текстом под её кадром, кегль — 1/50 ширины кадра, шрифт DejaVu Sans; нет шрифта при подписанных кадрах — код 2 со строкой установки `fonts-dejavu-core`. Обложка — без подписи. У кадров без подписей ключ в имени файла прежний: ленты прежних прогонов не собираются заново — проба на копии задачи QA пилотного проекта: событие без подписей — 0,1 с, ни одного нового файла. Проба 2026-11-06 там же: подписи у 5 кадров сценария 2 и длинная у одного кадра сценария 4 — пересобрались только эти две ленты, за 3 с; страница с локального сервера в браузере без внешних запросов — под подписанными кадрами подпись, между неподписанными полосы нет, на 1440 пикселях подпись читается сразу, на ширине телефона — после двух «+». Синтетический кадр 1440×30 000 с подписью на 40 слов ужат под кусок — 15 852 пикселя.

Состояние среды: тестовая папка `/tmp/qa-frames-remainder` — копия задачи QA пилотного проекта, на снимках данные клиентов: в папке снимков теперь 6 файлов подписей `1-02-*.txt` и `1-04-03.txt`, рядом со страницей — 2 новые ленты сценариев 2 и 4. Папка `/tmp/qa-frames-captions-check` — вырезки полос подписей со снимков браузера, прежние светлые ленты и синтетический кадр. Обе папки — до уборки пользователем.

Хвосты:
- Подписи вживую ещё не писались: их даст следующий прогон QA с обновлёнными скиллами; страница при этом пересоздаётся не обязательно — подписи лежат в самих картинках ленты.
- Этап QA, уже записанный в таск-файл проекта, несёт абзац шага прогона без размера окна и без подписей: их ставят этапы, которые `/box-qa` запишет после обновления скиллов.
- Окно просмотра лежит в каркасе вне меток, а каркас скрипт берёт из примера только командой `new`: страница другого проекта получит новое окно только пересозданием; до него прежнее окно листает куски ленты как кадры по одному.
- Принимает ли публикация `null` на файл, которого на странице нет, — не проверено: так бывает после потерянной ссылки, публикация без адреса несёт убранные файлы прежней страницы.
- Прежние куски лент и обложки после новых кадров остаются файлами в `my_local/pages/<задача>/` проекта: уборка убирает их со страницы, с диска — нет.
- Лента из кадров 1440×900 вживую ещё не открывалась: её даст следующий прогон QA с обновлёнными скиллами.
- Живой прогон оркестратора с повторами `done` до ответа без остатка не проводился.
