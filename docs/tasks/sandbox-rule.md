# sandbox-rule

## Постановка

Цель: пользователь, который ведёт движок из интерактивной сессии Claude Code на хосте, ставит в исключения классификатора режима auto своих личных настроек правило песочницы claude-box — сознательно, короткой командой или одним действием, без копирования длинного текста из консоли. Повторная установка заменяет правило по метке в его начале. После установки сессия хоста запускает сессии Claude в контейнере проекта через точку входа сетевого фильтра без отказа классификатора при любом имени compose-файла. Форма — инструкция в `README.md`, установка вместе с движком при первом запуске на машине или обе — выбор пользователя по предложению первого шага. Разбор и черновик правила — `researches/2026-10-10-auto-mode-host.md`.

Вторая часть цели — личные данные в git проектов. `/box-init` и сессии проекта кладут в git личную информацию — названия личных проектов, пути и директории машины, названия компаний, адреса, имена, коды и подобное — только по отдельному согласию пользователя; без согласия в git попадает обезличенный вариант, а исходные данные остаются вне git.

Третья часть цели — скрытые настройки. Настройки, которых пользователь не видит в обычной работе, — `.git/info/exclude`, конфиг и хуки в `.git/`, личные настройки git и Claude Code в домашней папке и подобное — сессии Claude под обвязкой правят только с разрешения пользователя на эту правку: что меняется, где и зачем. Тихая правка скрытой настройки — антипаттерн: система ведёт себя иначе, чем видно по файлам проекта, и пользователь не находит причину.

## Блокер

Вопрос: добавить ли в разрешение для Claude на компьютере ещё одно исключение — запуск контейнера со своими переменными окружения?

Почему: проверка показала, что переменная, добавленная в команду запуска контейнера, перекрывает его настройку из compose-файла. Одна такая переменная — `CLAUDE_BOX_ALLOW=0.0.0.0/0` — снимает ограничение сети, и контейнер перестаёт быть песочницей; нынешний текст разрешения такую команду не исключает. Сам движок передаёт контейнеру две свои безопасные переменные — они остаются разрешены.

Предложение: дописать в список «не разрешено» команды с переменными окружения, кроме двух переменных движка. Последняя фраза разрешения станет такой: «Правило не покрывает запуск без точки входа claude-box-firewall и команды с -v/--volume, --user, --privileged, --cap-add, --env-from-file, -e/--env с переменными, кроме CONTEXT_GUARD_MODE и CLAUDE_CODE_PROMPT_CACHE_TTL, или compose-файлом вне корня проекта.» Остальной текст — как решено раньше.

Как ответить: допиши в конец файла docs/tasks/sandbox-rule.md строку, которая начинается с «ответ:», — «ответ: ок» или «ответ:» и свой вариант. Потом запусти в Claude /box-next sandbox-rule или в терминале agent-loop.sh sandbox-rule.
