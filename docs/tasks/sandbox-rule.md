# sandbox-rule

## Постановка

Цель: пользователь, который ведёт движок из интерактивной сессии Claude Code на хосте, ставит в исключения классификатора режима auto своих личных настроек правило песочницы claude-box — сознательно, короткой командой или одним действием, без копирования длинного текста из консоли. Повторная установка заменяет правило по метке в его начале. После установки сессия хоста запускает сессии Claude в контейнере проекта через точку входа сетевого фильтра без отказа классификатора при любом имени compose-файла. Форма — инструкция в `README.md`, установка вместе с движком при первом запуске на машине или обе — выбор пользователя по предложению первого шага. Разбор и черновик правила — `researches/2026-10-10-auto-mode-host.md`.

Вторая часть цели — личные данные в git проектов. `/box-init` и сессии проекта кладут в git личную информацию — названия личных проектов, пути и директории машины, названия компаний, адреса, имена, коды и подобное — только по отдельному согласию пользователя; без согласия в git попадает обезличенный вариант, а исходные данные остаются вне git.

Третья часть цели — скрытые настройки. Настройки, которых пользователь не видит в обычной работе, — `.git/info/exclude`, конфиг и хуки в `.git/`, личные настройки git и Claude Code в домашней папке и подобное — сессии Claude под обвязкой правят только с разрешения пользователя на эту правку: что меняется, где и зачем. Тихая правка скрытой настройки — антипаттерн: система ведёт себя иначе, чем видно по файлам проекта, и пользователь не находит причину.

## Контекст

Шаг «Живая проверка правила» ждёт прогона пользователем: тестовый проект `/tmp/sandbox-probe` готов, команды — в секции «Блокер». Проект собирает скрипт `my_local/sandbox-rule-probe.sh` (вне git): копия `template/`, compose-файл переименован в `docker-compose.yml` вместе с его подключением только на чтение, две задачи по одному шагу — `line` для итерации строкой из `ARCHITECTURE.md` § Движок автоцикла и `loop` для `agent-loop.sh`: так оба запуска поднимают в контейнере настоящую сессию, а не встречают «готово» после первого; первый коммит `init`. Сервис `claude` проекта виден Compose, точка входа `claude-box-firewall` в образе есть (проверено 2026-10-11). Просьба к сессии хоста не называет ни режим без вопросов, ни песочницу: отказ снимает правило, а не слова пользователя.

Ответ «работает» — шаг закрыт по критерию, следующий шаг — «Личные данные и скрытые настройки в протоколе». Отказ на одном из запусков — блокер по «Постановке» («правило, не снявшее отказ»): разбор по тексту отказа, предложение правки текста правила в `sandbox_rule` `agent-loop.sh` и повторная проверка тем же скриптом после уборки.

Среда: тестовый проект `/tmp/sandbox-probe`, его сеть Docker `sandbox-probe_default` и истории сессий `~/.claude-box/.claude/projects/-workspace-sandbox-probe`, `~/.claude/projects/-tmp-sandbox-probe` — уборка в секции «Блокер».

Хвосты:

- `my_local/claude-box-sandbox-rule.sh` пользователя заменён режимом движка: метка та же, `agent-loop.sh --sandbox-rule` перепишет запись. На хосте сейчас стоит запись этого скрипта со старым текстом — «домашняя папка хоста закрыта»; замена — установкой в шаге живой проверки.

Размеры шагов очереди (`LC_ALL=C.UTF-8 wc -m` по списку «Читает», замер сессии разбивки): раздел протокола — 85 тыс. символов, живая проверка личных данных — 40 тыс.

Опоры шагов:

- Сборка документации `/box-init` велит переносить старые журналы, карточки и решения «без правок» и ответы — «как записаны в источнике» (шаблон задачи сборки, шаги «история» и `docs/DECISIONS.md`) — главный путь личных данных из заметок под `.gitignore` в git; оговорку об обезличивании несёт шаг раздела протокола.
- Опоры части о личных данных: образец несёт `my_local/` вне git — `/box-init` дописывает его в `.gitignore` проекта; у agent-box такое правило — `RULES.md` § Конвенции работы, первый пункт. Пример тихой правки скрытой настройки для причины антипаттерна — беседа 2026-10-10: сессия хоста без спроса дописала `.claude/settings.local.json` в `.git/info/exclude` agent-box, и git перестал показывать файл.

## Блокер

Тестовый проект для проверки разрешения готов — папка `/tmp/sandbox-probe`: копия образца проекта, где файл настройки контейнера называется `docker-compose.yml`, и две маленькие задачи — line и loop, каждая создаёт по одному файлу. Проверка отвечает на вопрос: перестаёт ли Claude на компьютере в режиме auto отказывать в запуске Claude в контейнере проекта, когда в личных настройках стоит разрешение песочницы. Шаг закрывается по твоему отчёту.

Сделать руками:

1. Папки нет, например после перезагрузки, — собрать заново: `bash ~/tools/agent-box/my_local/sandbox-rule-probe.sh`
2. В терминале — установка разрешения: `agent-loop.sh --sandbox-rule`. Ожидание: строки «правило записано» и «Claude Code видит правило» с текстом записи; в тексте есть слова «только на чтение и закрыта процессу агента» и `CONTEXT_GUARD_MODE` — новая запись заменила запись старого скрипта.
3. Там же — разрешение глазами Claude Code: `claude auto-mode config | jq -r '.allow[] | select(startswith("Claude-box Sandbox:"))'`. Ожидание: одна строка с тем же текстом.
4. Новая сессия Claude в тестовой папке, в режиме auto: `cd /tmp/sandbox-probe && claude --permission-mode auto`; на вопрос, доверять ли папке, — да. Сессия открывается после установки: подхватывает ли уже открытая сессия правку настроек, не проверено.
5. В сессии первая просьба, как есть: `Проведи одну итерацию движка по задаче line вручную: возьми строку итерации в контейнере из ~/tools/agent-box/docs/ARCHITECTURE.md § Движок автоцикла, compose-файл этого проекта — docker-compose.yml.` Ожидание: сессия запускает команду вида `docker compose -f docker-compose.yml … --entrypoint claude-box-firewall … claude -p "/box-next line" …` без отказа и через пару минут показывает итог; в папке появляется файл `line.txt`.
6. Там же вторая просьба: `Запусти agent-loop.sh loop.` Ожидание: движок проходит одну итерацию и останавливается со строкой «задача loop — готово»; при настроенном боте то же приходит в Telegram.
7. Итог в тестовой папке: `cd /tmp/sandbox-probe && git log --oneline && cat line.txt loop.txt && head -1 docs/tasks/line.md docs/tasks/loop.md`

Разрешение своими словами в просьбах не давать и отклонённый запуск через `/permissions` не повторять: проверяется запись в настройках. Отказ выглядит как сообщение о запрете действия, часто с меткой в квадратных скобках, например `[Create Unsafe Agents]`.

Что написать в ответ: видна ли запись в шагах 2–3; прошли ли запуски шагов 5 и 6 или отказ — с текстом отказа целиком; вывод шага 7.

Уборка после прогона: `docker network rm sandbox-probe_default; rm -rf /tmp/sandbox-probe ~/.claude-box/.claude/projects/-workspace-sandbox-probe ~/.claude/projects/-tmp-sandbox-probe`

Как ответить: допиши в конец файла docs/tasks/sandbox-rule.md строку, которая начинается с «ответ:», и после двоеточия — сам ответ. Потом запусти в Claude /box-next sandbox-rule или в терминале agent-loop.sh --host sandbox-rule.
