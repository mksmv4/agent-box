# sandbox-rule

## Постановка

Цель: пользователь, который ведёт движок из интерактивной сессии Claude Code на хосте, ставит в исключения классификатора режима auto своих личных настроек правило песочницы claude-box — сознательно, короткой командой или одним действием, без копирования длинного текста из консоли. Повторная установка заменяет правило по метке в его начале. После установки сессия хоста запускает сессии Claude в контейнере проекта через точку входа сетевого фильтра без отказа классификатора при любом имени compose-файла. Форма — инструкция в `README.md`, установка вместе с движком при первом запуске на машине или обе — выбор пользователя по предложению первого шага. Разбор и черновик правила — `researches/2026-10-10-auto-mode-host.md`.

Очередь:

- [ ] Разбивка на шаги по `researches/2026-10-10-auto-mode-host.md`, `README.md` § Движок автоцикла, установке команды в начале `agent-loop.sh`, `ARCHITECTURE.md` § Ступени изоляции — режимы разрешений: предложение формы доставки правила и очереди — у каждого шага что делается, чем проверяется и какие файлы читает, размер шага по `PROTOCOL.md` § Таск-файлы — в секцию «Блокер» со статусом «блокер»; по согласию пользователя очередь слово в слово вписывает в «Постановку» сессия, свой вариант — пользователь; чекбокс этого шага ставит сессия, увидевшая очередь там.

Проверка шага: правка скрипта записи правила — проба в контейнере на копии настроек во временной папке (`AGENTS.md` § Грабли): первый запуск добавляет правило после `"$defaults"`, повторный заменяет его, запись с меткой одна, прочие ключи файла на месте. Установка на хосте и живая проверка — пользователь по `RULES.md` § Конвенции работы: `claude auto-mode config` показывает правило; сессия хоста в режиме auto запускает сессию в контейнере проекта строкой итерации движка без отказа классификатора. Такой шаг кончается блокером с командой и ожидаемым итогом.

Блокер: форма доставки правила; текст правила — что песочница покрывает и что нет; правило, не снявшее отказ на живой проверке.
