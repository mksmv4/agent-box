# sandbox-rule

## Постановка

Цель: пользователь, который ведёт движок из интерактивной сессии Claude Code на хосте, ставит в исключения классификатора режима auto своих личных настроек правило песочницы claude-box — сознательно, короткой командой или одним действием, без копирования длинного текста из консоли. Повторная установка заменяет правило по метке в его начале. После установки сессия хоста запускает сессии Claude в контейнере проекта через точку входа сетевого фильтра без отказа классификатора при любом имени compose-файла. Форма — инструкция в `README.md`, установка вместе с движком при первом запуске на машине или обе — выбор пользователя по предложению первого шага. Разбор и черновик правила — `researches/2026-10-10-auto-mode-host.md`.

Вторая часть цели — личные данные в git проектов. `/box-init` и сессии проекта кладут в git личную информацию — названия личных проектов, пути и директории машины, названия компаний, адреса, имена, коды и подобное — только по отдельному согласию пользователя; без согласия в git попадает обезличенный вариант, а исходные данные остаются вне git.

Третья часть цели — скрытые настройки. Настройки, которых пользователь не видит в обычной работе, — `.git/info/exclude`, конфиг и хуки в `.git/`, личные настройки git и Claude Code в домашней папке и подобное — сессии Claude под обвязкой правят только с разрешения пользователя на эту правку: что меняется, где и зачем. Тихая правка скрытой настройки — антипаттерн: система ведёт себя иначе, чем видно по файлам проекта, и пользователь не находит причину.

## Контекст

Шаг «Живая проверка личных данных и скрытых настроек» не закрыт и ждёт ответа на блокер — согласия на очередь под ответ прошлого блокера (`DECISIONS.md` записи «уточнение правила о скрытых настройках» и «отмена своих коммитов»). Ответ «ок» — сессия вписывает слово в слово оба шага из секции «Блокер» в «Постановку» под этим шагом и ставит его чекбокс: личные данные прошли, скрытую настройку проверяет новый шаг; затем — первый новый шаг.

Проба сессии 2026-10-11 — скрипт `/tmp/gitinfo-probe-tool/probe.sh`, тестовая папка `/tmp/gitinfo-probe`, Compose 5.6.0, git 2.43.0; подключения как в `template/compose.yml` и вдобавок `./.git/info` только на чтение, пользователь `node`:

- обычный `git init`: запись в `.git/info/exclude` оболочкой и Python, `mv`, `rm -rf .git/info`, `touch .git/info/attributes` изнутри — «Read-only file system»; `git add`, `git commit`, `git status` в контейнере проходят; `git sparse-checkout set` в контейнере — «failed to initialize worktree config»: команда пишет в `.git/config`, а он и раньше только на чтение;
- `git init --template=`: папок `.git/info` и `.git/hooks` нет; `docker compose run` создаёт обе пустыми, `root:root`, 755; `git status` хоста работает, `printf … >> .git/info/exclude` с хоста — «Permission denied», `git sparse-checkout` хоста не создаёт lock-файл. Факт о `.git/hooks` записан в `ARCHITECTURE.md` § Образ и скрипт запуска; о `.git/info` его допишет первый новый шаг вместе с подключением;
- `docker compose -f template/compose.yml --profile claude config --quiet` на текущем образце — без ошибок: проверка первого нового шага рабочая.

Проекты, заведённые до правки образца, строку подключения `.git/info` получат повторным `/box-init`: он дописывает сервису `claude` недостающие подключения только на чтение образца (`skills/box-init/SKILL.md`). Поэтому фраза протокола о контейнере — с условием «где `.git/info` подключена только на чтение».

Тестовый проект `/tmp/personal-probe` оставлен для повторной проверки: ветка на `f63f1da` — конец сборки документации, `scratch.txt` — строкой в `.git/info/exclude`; подключения `.git/info` в его compose-файле нет — его добавит режим `hidden` второго нового шага. Сценарий — три сообщения цикла после строки «скрытая настройка: просьба про scratch.txt» в `my_local/personal-data-probe.sh`; история сессии прошлой просьбы — `~/.claude-box/.claude/projects/-workspace-personal-probe/fec9501a-2827-4eb6-b935-4c2f59d4d592.jsonl`.

Хвосты — предложения шагов:

- карточка `docs/PROTOCOL.md` в `skills/box-init/documents.md` (список «Обязательно») и строка протокола в картах `template/docs/README.md` и `docs/README.md` перечисляют разделы протокола без § Сообщения пользователю и нового § Личные данные и скрытые настройки; предложение — дописать оба раздела; карточки правятся только по прямому разрешению пользователя (`RULES.md` § Конвенции работы);
- первый пункт `RULES.md` § Конвенции работы agent-box («Репозиторий публичный…») частично повторяет новый раздел протокола; предложение — оставить в нём только своё для этого репозитория — репозиторий публичный, проект обкатки — «пилотный проект» — и сослаться на раздел протокола.

Среда: тестовый проект `/tmp/personal-probe`, его сеть Docker `personal-probe_default` и истории сессий `~/.claude-box/.claude/projects/-workspace-personal-probe` — уборка после повторной проверки: `docker network rm personal-probe_default; rm -rf /tmp/personal-probe ~/.claude-box/.claude/projects/-workspace-personal-probe`. Проба этой сессии — уборка руками пользователя по секции «Блокер»: `docker network rm gitinfo-probe_default; rm -rf /tmp/gitinfo-probe /tmp/gitinfo-probe-tool /tmp/box-next-tool`. Проект шага правила песочницы `/tmp/sandbox-probe` с его сетью и историями — уборка руками пользователя, если ещё не сделана: `docker network rm sandbox-probe_default; rm -rf /tmp/sandbox-probe ~/.claude-box/.claude/projects/-workspace-sandbox-probe ~/.claude/projects/-tmp-sandbox-probe`.

Оба непроверенных пункта из ответа:

Так же уже сейчас ведёт себя папка хуков git — это записано в описание устройства.
- Ловит ли правило запрета Claude Code запись в эту папку командой оболочки, не проверялось: правил запрета в выбранном варианте нет.

По второму ответу поправлено ожидание проверки: отменить свою работу новым коммитом Claude теперь может без вопроса, поэтому проверка смотрит не на то, что ветка не сдвинулась, а на то, что прежние коммиты остались в её истории.
