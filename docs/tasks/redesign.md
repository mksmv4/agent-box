# redesign

## Постановка

Просьба пользователя, 2026-11-26: «Сейчас обвязкой довольно неудобно пользоваться. Обновление через скилл, хотя как будто можно делать детерменированно, протокол и другие локальные доки будут стирать локальные правила при обновлении (или не будут?), возможно стоит сделать отдельно локальный протокол, который может дополнять и переопределять глобальный? В целом обвязка выглядит как то тяп ляп. Что с этим можно сделать? Может провести ресерч? Только не как обычно ты делаешь - что то поменять и накинуть правил, а прям полностью переделать если такое требуется сохранив функционал.»

Решения по теме: об условии шага «Проект новой схемы» «правил становится меньше; заплатка поверх старой схемы итогом не считается» — «Условие в 3 может привести к снижению ради снижения, так что где нельзя обойтись снижением - на решение юзера. Про заплатку там согласен.» (2026-11-26); об остальных незакрытых вехах — «Остальное думаю можно заморозить пока.» (2026-11-26); этапы ресерча и проверки постановки — «Оба» (2026-11-26); о правке под одну беседу — «.. ТЫ ОПЯТЬ РЕШАЕШЬ .. ПРОБЛЕМУ ОДНОЙ СЕССИИ ..? ЭТОТ ПРОЕКТ ДЛЯ РЕШЕНИЯ ПРОБЛЕМЫ ОДНОЙ СЕССИИ ..?» (2026-11-13); об отдельной команде обновления вместо повторного `/box-init` — «… надо сделать на будущее! делай и пиши что делать там» (2026-10-02); о сжатии контекста — выбор «на сжатие контекста схема не опирается» к словам «Сжатие я не использую никогда вообще» (2026-11-26).

Дописала сессия:
- шаги «Опись функций», «Проект новой схемы» и «Разбивка переезда» — из предложения сессии в беседе 2026-11-26, принятого с уточнением пользователя об условии схемы;
- опись — двумя шагами по размеру шага `docs/PROTOCOL.md` § Таск-файлы: протокол и скиллы образца — около 142 тыс. знаков, остальное — около 93 тыс. знаков без `README.md`;
- проверка описи — каждый раздел протокола, каждый скилл и каждая точка входа `AGENTS.md` § Точки входа попали в опись хотя бы одной функцией;
- схема — отдельным файлом на проверку по `docs/RULES.md` § Конвенции работы; расхождение с решениями пользователя — пометкой «против решения от <дата>» по `docs/PROTOCOL.md` § Таск-файлы;
- переезд — шагом разбивки, как у `/box-task`: шаги переезда в очередь добавляет пользователь своим согласием; живой прогон после переезда ведёт пользователь — `docs/RULES.md` § Конвенции работы;
- имя задачи и новая веха «Переделка обвязки»; остальные незакрытые вехи заморожены до её итога.

Цель: обвязкой удобно пользоваться. Обновление проекта идёт без пересказа моделью; правила проекта переживают обновление, дополняют и переопределяют общие правила agent-box, и при споре видно, какое правило главнее; устройство переделано целиком там, где это нужно, а каждая функция из описи сохранена.

Проверка шага: у каждого шага — своя, записана в шаге.

Блокер: правки задачи по ресерчу и проверке постановки; схема на проверку; место, где схема без роста правил не выходит; расхождение схемы с решениями пользователя; очередь переезда.

Этап 1 — ресерч.

Шаг этапа называет одной фразой, что за дело делает задача, — например, «выгрузка таблицы в CSV», — и ищет, как такое дело обычно делают и где оно ломается: готовые решения и библиотеки, типовые ошибки, советы документации — поиск в интернете, документация инструментов проекта, прошлые ресерчи `docs/researches/` и решения пользователя в `docs/DECISIONS.md` grep-ом по словам темы — и по каждой находке решает, к месту ли она в этой задаче, по `docs/PROTOCOL.md` § Ресерч и проверка постановки. У каждого утверждения — источник: адрес страницы или файл; вывод по выдаче поиска без чтения страницы так и помечен; закрытая ограничением сети контейнера страница, от которой зависит вывод, — блокер по `docs/PROTOCOL.md` § Таск-файлы. Итог — `docs/researches/<дата>-<задача>.md`: практики и решение по каждой, в конце — правки задачи, у каждой «сейчас → после» и зачем, или вывод «по ресерчу нынешний план оптимален» с причиной. Дальше в очереди проверка постановки — чекбокс, правки возьмёт она; иначе правки — блокером по тому же разделу, без правок — чекбокс.

Как сверять: загрузка скилла видна в истории беседы — вызов инструмента `Skill` и строка `Base directory for this skill:` с путём папки скилла, у скилла проекта — `/workspace/<проект>/.claude/skills/…`; истории — `my_local/redesign/run/sessions/-workspace-<проект>/`, у итераций движка — там же; история git тестовой папки — `git -C my_local/redesign/run/live-test log --stat`; образ без образца и скиллов — `docker run --rm --entrypoint ls maksim44/claude-box /etc/claude-box`, ждём только `settings.json`. Коммит сессии на хосте — обычной командой `git commit`: с `-c core.hooksPath=/dev/null` классификатор режима auto его отклонил («Undermining Oversight», 2026-11-27).

Риски:
- `box-update` пилотного проекта остановился бы на правиле с пропавшим разделом протокола или скиллом `/box-update`: шаг прогона просит переписать строки с `/box-update` заранее, остальное видно в `pilot-update.log`; после остановки `/box-init` без манифеста кончает подсказкой — расхождение пунктов, блокер с правкой правила.

Хвосты:
- предложение новой задачи после переезда: сокращение скилла оркестратора — 57,5 тыс. знаков с `questions.md` и `pages.md`, схема оставляет его как есть.
- правило «за результат отвечает оркестратор, о работе сессий — «я»» в скилле оркестратора живым прогоном не проверено: в шаге «Живой прогон» беседы оркестратора нет. Предложение — проверить его в первой новой беседе оркестратора на любом проекте: в чате о сделанном итерациями — «я», ошибка итерации — своей. Беседа, начатая до коммита правки, работает по прежнему тексту скилла до `/clear` (`AGENTS.md` § Жёсткие ограничения).

Среда: до шага уборки блокера — образ пробы `claude-box:redesign-probe`, папки `/tmp/redesign-precedence/`, `/tmp/redesign-task/` и `/tmp/redesign-net/`; уборка их убирает вместе с папкой прогона `/tmp/box-live/`, сетью Docker тестовой папки и её беседами. ## Блокер

Переделка обвязки сделана и проверена пробами по частям. Остался живой прогон — твой путь целиком на новом образе: подключить новую пустую папку и обновить один пилотный проект, подключённый прежним способом. Шаги пишут всё нужное в файлы, присылать вывод не нужно: пункты в конце сверит следующая сессия по копиям.

**Просьба.** Одиннадцать шагов: компьютер и чат Claude в контейнере.

1. компьютер — пересобрать образ
Вход: терминал в папке agent-box
Закрой сессии Claude в контейнерах проектов: новый образ действует в новом контейнере.
```
docker compose build claude
mkdir -p /tmp/box-live/sessions
touch /tmp/box-live/start
```

2. компьютер — подключить пустую тестовую папку
Скрипт сделает папку git-репозиторием, положит файлы agent-box и закоммитит.
```
mkdir /tmp/box-live/live-test
cd /tmp/box-live/live-test
box-update 2>&1 | tee ../update-1.log
```

3. компьютер — своё правило тестовой папки
Правило меняет сообщение коммита шага; второй `box-update` назовёт его в итоге.
```
cat >> docs/RULES.md <<'EOF'

- вместо `PROTOCOL.md` § Протокол сессии, «Завершение»,
  пункт 4: сообщение коммита шага задачи — ровно
  `live-x7`, без имени задачи и шага. Коммит записи
  журнала — по протоколу.
EOF
git commit -qam 'docs: project rule'
box-update 2>&1 | tee ../update-2.log
```

4. чат Claude — `/box-init` в тестовой папке
Вход: тот же терминал, папка тестового проекта
```
box-connect
```
В чате:
```
/box-init
```
На вопросы — «ок» или как предложит Claude. Дождись коммита.

5. чат Claude — завести задачу просьбой, без команды
Новая беседа и просьба обычными словами: беседа сама возьмёт команду заведения задачи.
```
/clear
```
```
заведи задачу: файл hello.txt со словом «привет»
```
Имя задачи — `hello`, один шаг, ресерч и проверка постановки не нужны, остальное — как предложит Claude. После коммита выйди командой `/exit`.

6. компьютер — одна сессия задачи скриптом
Вход: тот же терминал после `/exit`, папка тестового проекта
Задача в один шаг: скрипт остановится сам на «готово».


7. компьютер — обновить пилотный проект
Вход: `cd <папка пилотного проекта>`

```
  docs/RULES.md docs/rules

```

8. чат Claude — `/box-init` в пилотном проекте
Вход: тот же терминал, папка пилотного проекта

В чате:
```
/box-init
```
На вопросы — «ок» или как предложит Claude. После коммита выйди командой `/exit`.

9. компьютер — одна сессия задачи пилотного проекта
Вход: тот же терминал после `/exit`
`<задача>` — задача проекта в статусе «в работе», например сборка документации, которую завёл `/box-init`. Скрипт остановится сам или напишет «Ctrl+C останавливает цикл чисто» — тогда нажми Ctrl+C. Следом — копии итогов.

Убирает сеть Docker тестовой папки, временные папки прогона и прошлых проб, беседы тестовой папки и образ проб.

```
cd -

rm -rf ~/.claude-box/.claude/projects/-workspace-live-test
```
