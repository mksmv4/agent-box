# readme

## Постановка

Цель: `README.md` agent-box читается человеком. Читатель — автор обвязки или новый пользователь — по оглавлению находит свой сценарий: поставить обвязку на машину, завести проект, работать в нём, вести задачу движком или оркестратором, обновить обвязку и заведённые проекты, пересобрать образ — и доходит до готовых команд, не читая подробностей устройства. Факты README сходятся с кодом. Подробности, ушедшие из README, живут в своих документах по `docs/README.md`, README ссылается на них. Итог анализа — ресерч `researches/2026-10-14-readme.md`: разбор нынешнего README, сверка с кодом, источники о README, предложение структуры и макет.

Повод — беседа 2026-10-14. На вопрос «как обновить обвязку там, где она была» README одного ответа не дал: части лежат в трёх разделах, порядка для проекта по старой схеме и для рабочей копии git нет. Жалоба пользователя: в README слишком много текста — автор проекта сам не может его прочитать.

Границы: README проектов — карточка `skills/box-init/documents.md` § `README.md` — задача не правит: карточки правятся по прямому разрешению пользователя (`RULES.md` § Конвенции работы); предложение по ней — в хвосты «Контекста».

## Контекст

Шаг «Итог и макет» сделан до проверки пользователя: раздел «Итог и макет» в конце ресерча `researches/2026-10-14-readme.md` — выводы, структура нового README таблицей «раздел → сценарий → содержание → объём», что уходит из README и куда, девять правил текста, решения пользователя в новой структуре, макет — оглавление и раздел «Обновить обвязку и проекты» целиком. Чекбокс шага ждёт ответа на блокер.

Следующая сессия начинает с ответа на блокер: переносит его в `DECISIONS.md` — запись на каждый из четырёх ответов, — дописывает в конец раздела «Итог и макет» ресерча строку «Проверка пользователя, <дата>: …», при согласии ставит чекбокс шага и пишет журнал шага. Ответ с правками макета — правка ресерча и новый блокер, шаг остаётся открытым. Дальше — шаг «Переписывание»: README по таблице «Структура нового README», правила текста — в `docs/RULES.md`, факты — по § Сверка с кодом, раздел обновления — из макета.

Прочитано за шаг: таск-файл, ресерч, README, выдержки `DECISIONS.md`, `skills/box-update/SKILL.md`, строки `skills/box-init/SKILL.md` и `template/.claude/skills/box-orchestrate/pages.md` — около 95 тыс. символов. Черновик раздела макета — `/tmp/readme-maket/`, его копия — в ресерче; тексты источников — `/tmp/readme-src/`, скрипты замера — `/tmp/readme-scripts/`; всё до перезагрузки машины.

Хвосты:

- адрес репозитория для клонирования — вопрос 4 блокера; исходное значение — `my_local/personal.md`;
- работают ли на GitHub ссылки оглавления на кириллические заголовки — не проверено; проверка — README на github.com после пуша, его делает пользователь;
- пробный прогон в разделе «Вести задачу движком» — готовая команда для человека; в `docs/ARCHITECTURE.md` § Движок автоцикла только строки итерации с флагами, команду собрать и сверить с `agent-loop.sh` при переписывании;
- для шага «Перенос»: итог `/box-update` называет раздел README «Оркестратор» (`skills/box-update/SKILL.md`, шаг 5) — после переписывания разделы «Вести задачу оркестратором» и «Необязательно: телефон для оркестратора»; правка — в образ, команда пересборки — в итог пользователю;
- предложение новой задачи вне readme: повторный `/box-init` в проекте с законченной сборкой документации заводит новую, даже когда нужен только перенос сервиса или файл сервиса для второй копии (ресерч § Сверка с кодом, «Обновление заведённого проекта», п. 5); вариант с копией `claude-box.yml` из другой копии — не проверен;
- предложение по карточке README проектов (`skills/box-init/documents.md` § `README.md`): те же правила текста; правка карточки — по прямому разрешению пользователя.

Движок по этой задаче — с `--host` (`AGENTS.md` § Грабли).
