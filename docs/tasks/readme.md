# readme

## Постановка

Цель: `README.md` agent-box читается человеком. Читатель — автор обвязки или новый пользователь — по оглавлению находит свой сценарий: поставить обвязку на машину, завести проект, работать в нём, вести задачу движком или оркестратором, обновить обвязку и заведённые проекты, пересобрать образ — и доходит до готовых команд, не читая подробностей устройства. Факты README сходятся с кодом. Подробности, ушедшие из README, живут в своих документах по `docs/README.md`, README ссылается на них. Итог анализа — ресерч `researches/2026-10-14-readme.md`: разбор нынешнего README, сверка с кодом, источники о README, предложение структуры и макет.

Повод — беседа 2026-10-14. На вопрос «как обновить обвязку там, где она была» README одного ответа не дал: части лежат в трёх разделах, порядка для проекта по старой схеме и для рабочей копии git нет. Жалоба пользователя: в README слишком много текста — автор проекта сам не может его прочитать.

Границы: README проектов — карточка `skills/box-init/documents.md` § `README.md` — задача не правит: карточки правятся по прямому разрешению пользователя (`RULES.md` § Конвенции работы); предложение по ней — в хвосты «Контекста».

## Контекст

Шаг «Итог и макет» — второй круг. Первый макет пользователь отклонил: порядок README по его ответу — что делает проект, быстрый старт, важные настройки, остальное. Второй макет — файл `researches/2026-10-15-readme-maket.md`, около 110 строк: начало README целиком и оглавление остального. Новая структура и правки правил текста 1, 2 и 8 — ресерч § Итог и макет, «Второй макет». Ответы первого блокера — в `DECISIONS.md`: правила текста и адрес репозитория в README приняты. Чекбокс шага ждёт ответа на новый блокер.

Следующая сессия начинает с ответа на блокер: переносит его в `DECISIONS.md`, дописывает в конец раздела «Итог и макет» ресерча строку «Проверка пользователя, <дата>: …», при согласии ставит чекбокс шага и пишет журнал шага — коммиты задачи после записи журнала о шаге «Источники о README». Ответ с правками — правка файла макета и новый блокер, шаг остаётся открытым. Дальше — шаг «Переписывание»: README по таблице «Второй макет»; начало — из файла макета; раздел обновления — из первого макета, «Макет» ресерча, со словом agent-box вместо «обвязка»; правила текста — девять из «Правил текста README» с правками 1, 2 и 8 — в `docs/RULES.md`; факты — по § Сверка с кодом.

Прочитано за сессию: таск-файл, README, ресерч § Сверка с кодом, § Источники о README от «Длины разделов» до конца, § Итог и макет, начало `docs/DESCRIPTION.md` и `docs/DECISIONS.md`, `config.yml`, `template/claude-box.yml`, строки `agent-loop.sh` и `skills/box-init/SKILL.md` — около 100 тыс. символов. Скрипт замера — `/tmp/readme-scripts/measure.py`, до перезагрузки машины.

Хвосты:

- работают ли на GitHub ссылки оглавления на кириллические заголовки — не проверено; проверка — README на github.com после пуша, его делает пользователь;
- быстрый старт макета вживую от клонирования до первой задачи не прогонялся; кандидат — шаг «Проверка чтением» или прогон пользователя в новом клоне;
- пробный прогон в разделе «Вести задачу скриптом» — готовая команда для человека; в `docs/ARCHITECTURE.md` § Движок автоцикла только строки итерации с флагами, команду собрать и сверить с `agent-loop.sh` при переписывании;
- для шага «Перенос»: итог `/box-update` называет раздел README «Оркестратор» (`skills/box-update/SKILL.md`, шаг 5) — после переписывания раздел «Вести задачу с телефона»; правка — в образ, команда пересборки — в итог пользователю;
- предложение новой задачи вне readme: повторный `/box-init` в проекте с законченной сборкой документации заводит новую, даже когда нужен только перенос сервиса или файл сервиса для второй копии (ресерч § Сверка с кодом, «Обновление заведённого проекта», п. 5); вариант с копией `claude-box.yml` из другой копии — не проверен;
- предложение по карточке README проектов (`skills/box-init/documents.md` § `README.md`): те же правила текста и порядок README из ответа пользователя; правка карточки — по прямому разрешению пользователя;
- предложение по протоколу образца (`template/docs/PROTOCOL.md` § Сообщения пользователю): текст на проверку в блокере — отдельным файлом с длиной в строках, как правило этого репозитория в `docs/RULES.md` § Конвенции работы; правка протокола меняет все проекты — по согласию пользователя.

Движок по этой задаче — с `--host` (`AGENTS.md` § Грабли).
