# compose-net

## Постановка

Цель: запуск Claude из `claude-box.yml` не трогает ресурсы проекта — контейнеры, сети — при любом имени и настройках сети проекта и любом порядке запуска, а Claude видит сервисы проекта по имени, как сейчас. Сбой среды, не связанный с шагом, сессия не обходит, а выносит блокером с причиной и предложением починки.

Решения и почему — для ревью до первой итерации; разбор случая и пробы — `researches/2026-11-09-compose-net.md`:

- **Своё имя проекта Compose у `claude-box.yml`** — `<проект>-claude`. Сейчас у файла Claude то же имя проекта, что у основного compose-файла, и Compose считает файл Claude описанием всего проекта: контейнеры проекта для него лишние, а сеть проекта со своим именем — чужая сеть по умолчанию. Compose 5.7.0 такую сеть убирает, и запуск Claude при работающей базе падает — случай пилотного проекта 2026-11-09. Со своим именем проекта запуск Claude ресурсы основного проекта со своим файлом не сверяет; строка о лишних контейнерах пропадает сама, переменная движка `COMPOSE_IGNORE_ORPHANS` уходит.
- **Сеть проекта в файле Claude — тем же именем, без пометки «внешняя».** Нет сети — Compose создаёт её сам, есть — входит; проба на Compose 5.7.0 прошла в обоих порядках запуска, повторные запуски сеть не пересоздают. Внешняя сеть (`external: true`) по документации Compose не создаётся: Claude не стартовал бы без поднятого стека проекта.
- **Описание сети — целиком из основного compose-файла,** а не одно имя. Сеть, созданную запуском Claude, проект получает с настройками файла Claude: в пробе проект с подсетью `10.99.77.0/24`, поднятый после Claude, молча встал в `192.168.176.0/20`. Цена: проект, сменивший настройки сети, отстаёт от файла Claude до повторного `/box-init`.
- **Описание сети `/box-init` берёт из текста основного compose-файла:** в образе контейнера нет Docker. Нет у сети своего имени — в файле Claude имя, которое Compose даёт сети проекта сам: `<имя проекта основного файла>_default`.
- **Путь папки проекта в контейнере — явной строкой с нынешним значением.** Сейчас путь — `/workspace/${COMPOSE_PROJECT_NAME}`, со своим именем проекта он сменился бы на `/workspace/<проект>-claude`, а к пути привязаны сессии, автопамять и доверие Claude Code: контейнер принял бы папку за новый проект.
- **Комментарий о предупреждении Compose в файле Claude.** Каждый запуск печатает «сеть создана не этим проектом, поставь `external: true`»: предупреждение безвредно, а его совет ломает старт Claude без поднятого проекта.
- **Правило о сбоях среды — в протоколе образца, рядом с правилом о закрытом адресе.** Итерации 2026-11-06 удалили сеть руками и вырезали предупреждения Compose из вывода, оркестратор 2026-11-09 назвал причину без проверки и рекомендовал запуск на хосте: протокол сбой среды, не связанный с шагом, не разбирает. Протокол читают все сессии проекта, оркестратор тоже — хаб образца грузит его на старте. Отдельных слов про `--host` правило не несёт — решение пользователя: посмотреть, как агенты будут им пользоваться дальше.

Очередь:

Этап 1 — сеть контейнера Claude. Пробы — во временной папке на Compose машины, временные контейнеры и сети с отдельными именами, уборка — в конце пробы.

- [x] Образец `template/claude-box.yml`: строка `name:` — своё имя проекта Claude; сеть по умолчанию — заготовка блока с именем сети проекта и комментарием, откуда его берёт `/box-init`; путь папки проекта в рабочем каталоге и подключениях — явной строкой; комментарии о своём имени проекта и о предупреждении Compose. Проверка — проба: основной compose-файл с сервисом базы и сетью по умолчанию со своим именем и подсетью, файл Claude по образцу; Claude видит базу по имени в обоих порядках запуска; повторные запуски сеть не пересоздают; сеть с подсетью основного файла, кто бы её ни создал; запуск Claude с `--remove-orphans` контейнеры проекта не трогает; основной файл без блока сети — Claude в сети `<проект>_default`, база по имени отвечает. Итог пробы — в `researches/2026-11-09-compose-net.md`. Файлы шага: `template/claude-box.yml`, ресерч, `researches/2026-10-14-compose-local.md`.
- [x] `/box-init` (`skills/box-init/SKILL.md`, шаг 2 и итог): в `claude-box.yml` — своё имя проекта Claude, описание сети по умолчанию из текста основного compose-файла, путь папки проекта явной строкой — тот же, что сейчас; проект без своего compose-файла — без блока сети. Заведённый проект: запись в `claude-box.yml` изнутри контейнера закрыта — строки на замену и дописку идут в итог пользователю. Проверка — сверка текста шага с образцом и пробой прошлого шага; вживую — шаг «Живая проверка». Файлы шага: `skills/box-init/SKILL.md`, `template/claude-box.yml`, `box-connect`, ресерч.
- [x] Движок и документы: из `agent-loop.sh` уходит `COMPOSE_IGNORE_ORPHANS` с его комментарием; `README.md` — пункт о строке `Found orphan containers` заменяет пункт о предупреждении «сеть создана не этим проектом»; устройство — `docs/architecture/container.md`, `engine.md`, `template.md`, `ARCHITECTURE.md`. Проверка: `bash -n agent-loop.sh`; `grep -rn COMPOSE_IGNORE_ORPHANS` по продукту и `docs/architecture/` пуст; итерация движка на задаче из одного шага во временной папке с поднятой базой закрывает задачу коммитом. Файлы шага: перечисленные, ресерч.
- [ ] Живая проверка — ведёт пользователь: сессия пишет блокером команды — пересборка образа (`README.md` § Пересобрать образ после правки agent-box); тестовый проект с сервисом базы и сетью со своим именем и подсетью; второй тестовый проект с `claude-box.yml` по старой схеме — общее имя проекта; в каждом — новый контейнер и `/box-init`, правка `claude-box.yml` по итогу, Claude в контейнере просит адрес базы по имени сервиса, затем `agent-loop.sh` на задаче из одного шага; затем команды уборки. Ожидание: `/box-init` пишет своё имя проекта, сеть и путь, у проекта по старой схеме называет строки в итоге; Claude получает адрес базы; итерация движка закрывает задачу коммитом; `docker network ls` — одна сеть проекта.

Этап 2 — правило о сбоях среды.

- [ ] Правило в `template/docs/PROTOCOL.md` § Таск-файлы, после абзаца о закрытом адресе интернета: сбой среды — Docker, сеть, инструменты, — не связанный с шагом, — тоже блокер; сессия его не обходит — не удаляет ресурсы руками, не вырезает предупреждения из вывода, не меняет способ запуска, — а ищет причину и пишет в секции «Блокер», что сломалось, почему и что предлагает починить. Сверка со скиллом оркестратора, шаг 5 — «вопрос пользователю: что видно в журнале и что предлагает оркестратор»: правило доходит до оркестратора протоколом; правка скилла — только когда без неё правило к его вопросу не применяется. Проверка — сверка текста с решением пользователя в `DECISIONS.md` 2026-11-09 и § Порядок на месте протокола: у факта один дом. Файлы шага: `template/docs/PROTOCOL.md`, `template/.claude/skills/box-orchestrate/SKILL.md`, `template/.claude/skills/box-next/SKILL.md`, ресерч.

Проверка шага: записана в шаге; правка образца и движка — проба во временной папке, правка скилла и образа — живая проверка пользователем (`RULES.md` § Конвенции работы), шаг «Живая проверка».

Блокер: проба, разошедшаяся с ожиданием, — сеть пересоздаётся, проект встаёт в сеть с чужими настройками, Claude не видит базу; сеть проекта, описанная вне основного compose-файла — в дополнении или файле из `COMPOSE_FILE`, — откуда `/box-init` берёт описание; сервисы проекта только в своих сетях, без сети по умолчанию; формулировка правила о сбоях среды, когда шаг упирается в выбор его границ.

## Контекст

Шаг «Живая проверка» ждёт пользователя: секция «Блокер» — пересборка образа, два тестовых проекта, вопрос Claude об адресе базы, итерация движка на задаче `t` из одного шага, проверка сетей и уборка. Проект `/tmp/cnt-a` — основной файл `name: cnt-a`, сеть `cnt-a-net` с подсетью `10.99.81.0/24`, заводится `box-connect` и `/box-init`, запись в `claude-box.yml` открыта. Проект `/tmp/cnt-b` — основной файл без `name:` и без блока сети, сеть `cnt-b_default`; `claude-box.yml` прежней схемы из `c0ccf04` — общее имя проекта и путь `${COMPOSE_PROJECT_NAME}`; `/box-init` из контейнера этого файла, запись в него закрыта — строки идут в итог. После ответа: итог живой проверки — разделом в конец ресерча; всё как ждали — чекбокс шага; разошлось — разбор по словам пользователя, расхождение с решениями задачи — блокер с предложением. Дальше — этап 2, правило о сбоях среды в `template/docs/PROTOCOL.md`.

Хвосты:

- Пилотный проект: `claude-box.yml` поправлен руками 2026-11-09 — сеть по умолчанию с именем сети проекта при общем имени проекта Compose, лишняя сеть убрана; конфиг Compose сходится с сетью проекта, запуск итерации в контейнере после правки не проверялся. Переход на новую схему — повторный `/box-init` после задачи.
- Проект по старой схеме оставляет на машине сеть `<проект>_default`, созданную прежним запуском Claude с меткой проекта основного файла; у проекта со своим именем сети она лишняя. Как Compose 5.7.0 обойдётся с ней на `up` проекта после перехода, не проверено; живая проверка этого случая не касается — у `cnt-b` сеть без своего имени, `cnt-b_default` и есть сеть проекта.
- Предложение пункта `README.md` § Обновить agent-box и проекты, «Каждый проект»: копия с `claude-box.yml` прежней схемы — без строки `name: <проект>-claude` — переходит на новую схему повторным `/box-init`, `/box-update` файл Claude не трогает; сейчас пункт «В папке копии есть `claude-box.yml`» ведёт такую копию на `/box-update`. На усмотрение пользователя.
- `COMPOSE_PROJECT_NAME` из `.env` действует и на запуски движка `docker compose -f claude-box.yml run`: строка, дописанная в `.env` после `/box-init`, возвращает Claude в проект основного файла. `/box-init` такой проект не заводит, движок строку не проверяет — предложение на усмотрение пользователя: проверка в движке или пункт `README.md`.
- Сервисы проекта только в своих сетях, без сети по умолчанию, — отдельная задача с пробой (`DECISIONS.md` 2026-11-09), в эту задачу не входит.
- `box-connect` при строке `name:` основного файла, отличной от имени папки, кладёт сессии первого запуска под путь от папки, запуски из `claude-box.yml` — под путь от `name:`: так было и до задачи (`architecture/container.md`), не правилось.
- Временные папки проб `/tmp/cbn-probe.DHBi`, `/tmp/cbe-probe.SYPO`, `/tmp/cnl-probe.Ww6v`, скрипты `/tmp/cnl-scripts`, `/tmp/cn-edit*.py`, `/tmp/cn-live` и история сессий пробы движка `~/.claude-box/.claude/projects/-workspace-cnl-proj` — уборка командами блокера, пункт 6; контейнеров и сетей проб на машине нет.

## Блокер

Сеть контейнера Claude переделана и проверена пробами во временных папках. Осталась живая проверка в новом контейнере на двух тестовых проектах. Первый подключается с нуля. Второй — с файлом Claude прежнего вида, как у проектов, подключённых до этой задачи. Проверку ведёшь ты, по пунктам ниже.

1. Пересобери образ. В терминале, в папке agent-box:

```
docker compose build claude
```

2. Первый проект: база в сети со своим именем и подсетью. В терминале:

```
mkdir /tmp/cnt-a && cd /tmp/cnt-a
git init -q -b main
cat > compose.yml <<'Y'
name: cnt-a
services:
  db:
    image: alpine
    command: sleep 3600
networks:
  default:
    name: cnt-a-net
    ipam:
      config:
        - subnet: 10.99.81.0/24
Y
git add -A && git commit -qm init
docker compose up -d
box-connect
```

В сессии Claude в контейнере:

```
/box-init
```

На список адресов интернета ответь «ок», на остальные вопросы — как удобно. Ждём в итоге: имя проекта Claude `cnt-a-claude`, сеть взята из основного compose-файла. Закрой сессию командой `/exit` и запусти Claude из его файла:

```
docker compose -f claude-box.yml run --rm claude
```

Перед стартом Compose напишет, что сеть `cnt-a-net` создана не этим проектом, — так и задумано. Спроси Claude: «какой адрес у сервиса db? проверь через getent hosts db». Ждём адрес вида `10.99.81.…`. Закрой сессию.

3. Второй проект: файл Claude прежнего вида, база в сети по умолчанию. В терминале:

```
mkdir /tmp/cnt-b && cd /tmp/cnt-b
git init -q -b main
cat > compose.yml <<'Y'
services:
  db:
    image: alpine
    command: sleep 3600
Y
echo /claude-box.yml > .gitignore
git add -A && git commit -qm init
al=$(readlink -f "$(command -v agent-loop.sh)")
git -C "${al%/*}" show \
  c0ccf04:template/claude-box.yml > claude-box.yml
docker compose up -d
docker compose -f claude-box.yml run --rm claude
```

Строка Compose о лишних контейнерах `Found orphan containers` здесь ожидаема: так работала прежняя схема. В сессии Claude в контейнере:

```
/box-init
```

Ждём в итоге: записать файл Claude сессия не может, поэтому называет строки на правку — имя проекта `cnt-b-claude`, путь `/workspace/cnt-b` вместо `${COMPOSE_PROJECT_NAME}`, блок сети с именем `cnt-b_default`. Закрой сессию и поправь `/tmp/cnt-b/claude-box.yml` по итогу. Запусти Claude той же командой `docker compose -f claude-box.yml run --rm claude` и спроси адрес db, как в пункте 2. Закрой сессию.

4. В каждом проекте — задача из одного шага скриптом. В терминале, сначала в `/tmp/cnt-a`, потом то же в `/tmp/cnt-b`:

```
cat > docs/tasks/t.md <<'T'
статус: в работе

# t

## Постановка

Цель: файл `probe.txt` в корне со строкой `ok`.

- [ ] `probe.txt` со строкой `ok`; проверка — `cat`.

Блокер: нет.

## Контекст

Начало задачи.
T
git add -A && git commit -qm 'task t'
agent-loop.sh t
```

Ждём: скрипт заканчивает задачу статусом «готово», `git log --oneline -3` показывает коммит шага и коммит журнала.

5. Сети и базы. В терминале:

```
docker network ls --filter name=cnt-
docker network inspect cnt-a-net \
  -f '{{range .IPAM.Config}}{{.Subnet}}{{end}}'
docker ps --filter name=cnt-
```

Ждём: сетей две, по одной на проект, — `cnt-a-net` и `cnt-b_default`; подсеть `10.99.81.0/24`; обе базы работают — `cnt-a-db-1` и `cnt-b-db-1`.

6. Уборка. В терминале:

```
cd /tmp/cnt-a && docker compose down
cd /tmp/cnt-b && docker compose down
docker network rm cnt-a-net cnt-b_default 2>/dev/null
cd ~ && rm -rf /tmp/cnt-a /tmp/cnt-b
rm -rf ~/.claude-box/.claude/projects/-workspace-cnt-*
rm -rf /tmp/cb?-probe.* /tmp/cnl-* /tmp/cn-edit*.py
rm -rf /tmp/cn-live
rm -rf ~/.claude-box/.claude/projects/-workspace-cnl-proj
```

Как ответить: допиши в конец файла docs/tasks/compose-net.md строку, которая начинается с «ответ:», и после двоеточия — сам ответ: «всё как ждали» или что разошлось и на каком пункте. Потом запусти в Claude /box-next compose-net или в терминале agent-loop.sh --host compose-net.
