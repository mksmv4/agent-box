# orchestrator

## Постановка

Цель: в проекте под обвязкой пользователь одной командой делает интерактивную сессию Claude Code на хосте оркестратором задачи. Оркестратор ведёт задачу движком: шаги идут без остановок; блокер, который снимается проверкой без решения или сведениями, недоступными контейнеру, снимает сам и помечает ответ как свой; вопрос, требующий решения пользователя, задаёт инструментом вопроса — при Remote Control он приходит пушем в приложение Claude; ответ пользователя записывает для цикла его словами; к другой задаче переходит только с согласия пользователя. Под оркестратором движок по умолчанию не шлёт уведомлений в Telegram. Ход цикла виден: движок пишет журнал в постоянное место на хосте, оркестратор ведёт на claude.ai приватную страницу задачи со схемами по описанным правилам страниц, копия страницы — в `my_local/pages/` проекта. `README.md` описывает подключение Remote Control и запуск оркестратора.

Документ описывает структуру страницы задачи — разделы и их порядок: цель и схема очереди шагов — сделано, идёт, впереди; таблица итераций — время, шаг, длительность, исход, коммиты; текущее состояние; блок «Ждёт решения», пока вопрос пользователю открыт; история блокеров и кто ответил. Главное — сразу, подробности — в раскрывающихся блоках; вопрос, риски и неизвестное всегда на виду. Правила текста: обычные слова по `PROTOCOL.md` § Сообщения пользователю; у каждой вещи одно имя на всей странице, на схемах и в окне вопроса; у каждого действия назван исполнитель — движок, оркестратор, сессия, пользователь; шаги — по отдельности; короткие предложения, в абзаце одна тема — то, что автор поста берёт из ASD-STE100. Основания выводов — четырёх видов: факт с источником; оценка с диапазоном и базой; допущение и что изменится, если оно неверно; неизвестное, которое может поменять выбор. Без источника — «не проверено»; пустая категория — «не выявлено». Блок «Ждёт решения»: что строим и на чём остановились; откуда вопрос и почему решать сейчас; ограничения; риски и неизвестное; какой именно ответ нужен от пользователя; варианты — не меньше двух живых, у каждого цена и условие, при котором он лучше; рекомендация с основаниями рядом, при нехватке оснований — «рекомендации нет» и почему; варианты, отброшенные оркестратором, — причина и допущение, на котором держится отказ; вариант без условия, при котором он разумен, отбрасывается так же. Варианты в окне вопроса — полными фразами, теми же словами, что на странице. Формат под вопрос: меняется экран — картинка «как сейчас / после» с подписью, куда смотреть; меняется порядок действий — схема последовательности; меняются права и границы — схема границ и что будет при сбое; несколько критериев — таблица; простой выбор — пара строк текста. Правила схем: схема — SVG, нарисованный прямо в HTML страницы, без внешних библиотек; очередь шагов задачи — схемой всегда; схема строится из блоков, стрелок и подписей обычными словами; рядом со схемой — текст: порядок, направление, границы, что будет при сбое; предел числа блоков на схеме; цвета со смыслом, одинаковые на всех схемах; схема читается на экране телефона, в светлой и тёмной теме. Примеры — две страницы вымышленной задачи: в работе и с открытым вопросом. Проверка — пользователь: примеры, опубликованные страницами, открываются на телефоне и компьютере, задача и вопрос понятны по странице без таск-файла. Падение без истории — конец «итога JSON нет» и остановка за секунду. Ctrl+C группе процессов движка — конец с кодом 130 и остановка, метка и `tail` не остаются (`AGENTS.md` § Грабли — как подать сигнал из инструмента Bash). ## Блокер

Вопрос: журнал цикла готов — подходят ли его место и состав?

Место сейчас — служебная папка git самого проекта, рядом с файлом-замком движка (`.git/agent-loop.log`). У каждого проекта свой журнал, и проекты с одинаковым именем папки не смешиваются; сессия-оркестратор читает журнал, не выходя из папки проекта. Агент в контейнере может этот файл переписать — так же, как может переписать файл задачи. Другой вариант из прошлой беседы — общая папка журналов в домашней папке (`~/.local/state/agent-loop/<проект>.log`): журналы всех проектов в одном месте, агенту контейнера недоступны, но два проекта с одинаковым именем папки пишут в один файл.

Состав: запуск движка; начало каждой итерации — время, номер шага и начало его названия; ход — по строке на действие агента: что он пишет, какой файл читает или правит, какую команду запускает; конец итерации — сколько шла, чем кончилась, статус задачи и коммиты; остановка с причиной. Рассуждения агента и вывод команд в журнал не идут. Следить вживую — `tail -f .git/agent-loop.log` в папке проекта.

Предложение: оставить как сделано — журнал в служебной папке git проекта, состав как выше.

Как ответить: допиши в конец файла docs/tasks/orchestrator.md строку, которая начинается с «ответ:», — «ответ: ок» или «ответ:» и свой вариант. Потом запусти в Claude /box-next orchestrator или в терминале agent-loop.sh --host orchestrator.
