# orchestrator

## Постановка

Цель: в проекте под обвязкой пользователь одной командой делает интерактивную сессию Claude Code на хосте оркестратором задачи. Оркестратор ведёт задачу движком: шаги идут без остановок; блокер, который снимается проверкой без решения или сведениями, недоступными контейнеру, снимает сам и помечает ответ как свой; вопрос, требующий решения пользователя, задаёт инструментом вопроса — при Remote Control он приходит пушем в приложение Claude; ответ пользователя записывает для цикла его словами; к другой задаче переходит только с согласия пользователя. Под оркестратором движок по умолчанию не шлёт уведомлений в Telegram. Ход цикла виден: движок пишет журнал в постоянное место на хосте, оркестратор ведёт на claude.ai приватную страницу задачи со схемами по описанным правилам страниц, копия страницы — в `my_local/pages/` проекта. `README.md` описывает подключение Remote Control и запуск оркестратора.

Читает: `template/docs/PROTOCOL.md`, `template/.claude/skills/box-next/SKILL.md`.
- [x] Скилл оркестратора: `template/.claude/skills/box-orchestrate/SKILL.md`, вызов `/box-orchestrate [задача]`; без аргумента — предложение задачи первой незакрытой вехи, старт после согласия. Шаги скилла: запуск движка в фоне в тихом режиме, уведомления Telegram — по просьбе в аргументе; разбор каждой остановки по выводу движка, журналу цикла и таск-файлу. Блокер: вопросы шага, снимаемые проверкой без решения или поиском сведений вне сети контейнера, — ответ оркестратора по правилу предыдущего шага; требующие решения — одним вызовом инструмента вопроса, ответ пользователя — строкой «ответ:» его словами; затем перезапуск. Падение, алерт таймера, три итерации без прогресса — разбор по журналу, перезапуск, когда причина снимается без решения, иначе вопрос. «Готово» — вопрос о следующей задаче. Явный пуш инструментом пуша — на «готово», вопрос пользователю, остановку. Цель, проверку и очередь задачи оркестратор не правит (`PROTOCOL.md` § Таск-файлы). Раздел об оркестраторе — `ARCHITECTURE.md`, термин — `GLOSSARY.md`. Проверка: скилл по `RULES.md` § Конвенции кода; поведение — живой прогон. Читает: `template/docs/PROTOCOL.md`, `template/.claude/skills/box-next/SKILL.md`, `agent-loop.sh`, `ARCHITECTURE.md`, `GLOSSARY.md`, `researches/2026-10-10-orchestrator-remote.md`, `my_local/box-task-orchestrated-2026-10-06.md`.
- [x] Правила страниц: документ `template/.claude/skills/box-orchestrate/pages.md` и примеры в `template/.claude/skills/box-orchestrate/examples/`; основа — пост https://t.me/llm_notes/314 и навык decision-mockups из него. Документ описывает структуру страницы задачи — разделы и их порядок: цель и схема очереди шагов — сделано, идёт, впереди; таблица итераций — время, шаг, длительность, исход, коммиты; текущее состояние; блок «Ждёт решения», пока вопрос пользователю открыт; история блокеров и кто ответил. Главное — сразу, подробности — в раскрывающихся блоках; вопрос, риски и неизвестное всегда на виду. Правила текста: обычные слова по `PROTOCOL.md` § Сообщения пользователю; у каждой вещи одно имя на всей странице, на схемах и в окне вопроса; у каждого действия назван исполнитель — движок, оркестратор, сессия, пользователь; шаги — по отдельности; короткие предложения, в абзаце одна тема — то, что автор поста берёт из ASD-STE100. Основания выводов — четырёх видов: факт с источником; оценка с диапазоном и базой; допущение и что изменится, если оно неверно; неизвестное, которое может поменять выбор. Без источника — «не проверено»; пустая категория — «не выявлено». Блок «Ждёт решения»: что строим и на чём остановились; откуда вопрос и почему решать сейчас; ограничения; риски и неизвестное; какой именно ответ нужен от пользователя; варианты — не меньше двух живых, у каждого цена и условие, при котором он лучше; рекомендация с основаниями рядом, при нехватке оснований — «рекомендации нет» и почему; варианты, отброшенные оркестратором, — причина и допущение, на котором держится отказ; вариант без условия, при котором он разумен, отбрасывается так же. Варианты в окне вопроса — полными фразами, теми же словами, что на странице. Формат под вопрос: меняется экран — картинка «как сейчас / после» с подписью, куда смотреть; меняется порядок действий — схема последовательности; меняются права и границы — схема границ и что будет при сбое; несколько критериев — таблица; простой выбор — пара строк текста. Правила схем: схема — SVG, нарисованный прямо в HTML страницы, без внешних библиотек; очередь шагов задачи — схемой всегда; схема строится из блоков, стрелок и подписей обычными словами; рядом со схемой — текст: порядок, направление, границы, что будет при сбое; предел числа блоков на схеме; цвета со смыслом, одинаковые на всех схемах; схема читается на экране телефона, в светлой и тёмной теме. Примеры — две страницы вымышленной задачи: в работе и с открытым вопросом. Проверка — пользователь: примеры, опубликованные страницами, открываются на телефоне и компьютере, задача и вопрос понятны по странице без таск-файла. Читает: `template/docs/PROTOCOL.md` § Сообщения пользователю, скилл оркестратора, скиллы страниц Claude Code `artifact-design` и `artifact-diagramming`, навык decision-mockups https://github.com/djd1m/dz-harness/tree/main/packages/skills-decision-mockups/decision-mockups — `SKILL.md`, `references/language-guide.md`, `references/mockup-kit.md`, `examples/context-cases.md`.

Страница — файл `my_local/pages/<задача>.html` проекта, обновление — повторной публикацией файла; ссылки — список `my_local/pages/links.md`: по нему сессия следующего дня обновляет страницу по прежней ссылке. Ссылка на страницу — в чате оркестратора, при вопросе пользователю — сообщением рядом с вопросом. Правка — скилл оркестратора и `ARCHITECTURE.md`. Проверка — живой прогон. Ожидание: первый блокер оркестратор снимает сам, ответ помечен; второй вопрос приходит пушем, ответ из приложения доходит до цикла; задача доходит до «готово», оркестратор спрашивает о следующей; страница задачи открывается с телефона, обновляется после каждой итерации, при вопросе показывает блок «Ждёт решения» со схемой вариантов, копия лежит в `my_local/pages/`; журнал показывает ход итераций; в Telegram за прогон ничего не приходит.

Проверка шага: правка движка — проба в тестовом git-репозитории с заглушками `claude` и `curl`, как у задачи agent-loop (`tasks/agent-loop.md` § Постановка); правка скилла, протокола и образца — живая проверка пользователем по `RULES.md` § Конвенции работы.

Блокер: граница «проверка без решения» на конкретном случае; место журнала и что в него попадает из хода итерации; поведение Remote Control, пушей или страниц, разошедшееся с докой и описаниями инструментов; отказ классификатора режима auto на хосте при запуске движка из оркестратора — смежная задача sandbox-rule.

## Контекст

Задача готова: все шаги очереди закрыты, последний — живой прогон 2026-10-11 на тестовом проекте, ответ оркестратора «работает» — `DECISIONS.md` § 2026-10-11 — живой прогон оркестратора. Проверка пользователем — по записям `JOURNAL.md` и хвостам ниже, затем чекбокс строке задачи в `ROADMAP.md`.

Среда: тестовый проект прогона, его сеть Docker и истории сессий убраны. Скрипт сборки тестового проекта `my_local/orchestrator-probe.sh` (вне git) — для повторного прогона. Хвосты:

- ожидание в оркестраторе: в прогоне сессия сделала одну паузу обычной командой `sleep 45`, оболочка Claude Code её заблокировала, сессия перешла на ожидание по журналу; скилл ждёт фоновыми командами, но прямо об этом не говорит; предложение — фраза в шаге 2 скилла: пауза — только фоновой командой, обычный `sleep` оболочка блокирует;
- обращение к пользователю: итог сессии прогона обратился к пользователю в женском роде («Ответила ты»); предложение — правило в `PROTOCOL.md` § Сообщения пользователю: обращение без грамматического рода — настоящее время и безличные обороты («ответ пользователя — …»), правка оригинала и копии;
- предел времени фоновой команды Bash: описание инструмента с CLI 2.1.288 называет его, в пилотном проекте движок фоном без `timeout` шёл 3 ч 01 мин на CLI 2.1.292 и кончился своей остановкой; прогон 2026-10-11 — 4 итерации, длительность цикла в ответе не названа; цикл дольше — не проверен;
- контекст оркестратора: сессия идёт часами, каждое пробуждение добавляет вывод движка и журнала, правку и публикацию страницы на каждой итерации; сигнал context-guard в интерактивной сессии проекта предложит варианты (режим `rules`), что делает оркестратор на сигнале — скилл не описывает; предложение — пункт скилла: на сигнале итог пользователю и конец сессии, движок идёт дальше, продолжение — новой сессией `/box-orchestrate <задача>`;
- движок после конца сессии оркестратора — закрытый терминал, завершённый сервер Remote Control: идёт ли фоновая команда дальше в своей группе процессов, не проверено; README говорит условно — идущий движок держит lock, новый запуск завершается с именем его задачи;
