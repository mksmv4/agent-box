# page-rules

## Постановка

Цель: правила страниц задач оркестратора `template/.claude/skills/box-orchestrate/pages.md` и два примера рядом — `examples/question.html` (вопрос открыт) и `examples/running.html` (шаг идёт) — устроены по ресерчу `researches/2026-10-12-task-page.md` § Итог и макет: шапка с сутью задачи, оглавление «На этой странице», схема задачи и схема участников вопроса, блок вопроса без повторов, одна мысль — одно предложение, цвет только у состояния, история под чертой. Пользователь, открыв пример или живую страницу задачи через несколько часов, на телефоне и компьютере сразу понимает, что за задача, где она стоит и какое решение от него ждут, а подробности находит по оглавлению. Схема и картинка страницы открывается по нажатию поверх страницы, с увеличением, уменьшением и закрытием: отдельной вкладкой картинка опубликованной страницы claude.ai отвечает ошибкой `ERR_BLOCKED_BY_RESPONSE` (наблюдение пользователя 2026-10-13). Образец устройства страницы — принятый макет `my_local/page-research/mockup.html`, вне git (`DECISIONS.md` § 2026-10-12 — вторая версия макета: снимает ли жалобу); данные примеров — прежняя вымышленная задача примеров.

Вопрос — понятно ли, что за задача, где она стоит и какое решение ждут, находятся ли подробности, работают ли на claude.ai отметка раздела в оглавлении, кнопка «Наверх» и просмотр схемы поверх страницы с увеличением и уменьшением. Чекбокс — по ответу пользователя, что понятно.

Числа — в «Контекст», снимки — `my_local/page-rules/`, служебные файлы Playwright после проверки уносятся из репозитория. Шаг «Проверка пользователем» — взгляд пользователя, блокером.

Блокер: строка списка ресерча расходится с принятым макетом или решением `DECISIONS.md`; правило ложится в пример только с отступлением от макета, которое меняет вид страницы; итог шага «Проверка пользователем».
