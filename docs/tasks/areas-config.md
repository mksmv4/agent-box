# areas-config

## Постановка

Цель: проект с несколькими разработчиками и с разросшейся документацией ведётся обвязкой без лишнего контекста и без конфликтов при слиянии веток. Архитектура и правила делятся по областям кода — частям проекта со своими папками, например фронт и бэк, — когда в документации проекта раздел уже есть или документ перерос порог; правила области подгружаются сессии, которая трогает код области, и не подгружаются остальным. Журнал и реестр решений сливаются между ветками без конфликта. Пределы движка и порог раздела живут в одном конфиге agent-box — `config.yml` в корне клона agent-box, общем для всех проектов. Одиночный проект без раздела работает как раньше.

Повод — беседа 2026-10-14 о пилотном проекте с двумя разработчиками, фронт и бэк: в документации проекта раздел по областям уже есть, архитектура фронта — около 75 тыс. знаков.

Раскладка раздела — по ответу пользователя: у разделённого документа своя папка, основной файл — в ней же под прежним именем. Архитектура — `docs/architecture/ARCHITECTURE.md`: общая часть — сервисы, связи между областями, деплой — и список областей со ссылками; область — `docs/architecture/<область>.md`. Правила — `docs/rules/RULES.md`, общие, хаб подключает их на старте; область — `docs/rules/<область>.md`. Ссылки протокола и скиллов по голому имени `ARCHITECTURE.md` и `RULES.md` верны при обеих раскладках. Тексты правил области лежат в `docs/rules/`, а Claude Code их подгружает через указатель: папка `.claude/` — защищённый путь Claude Code, запись в неё в режиме auto идёт классификатору, в интерактивном режиме — вопросом (code.claude.com/docs/en/permission-modes § Protected paths, 2026-10-14), а сессии пишут в правила грабли.

Конфиг — `config.yml` в корне клона agent-box, один на все проекты, плоский YAML «ключ: целое число»: пределы движка — итераций за запуск, пауза между итерациями, итераций подряд без прогресса, потолок ходов итерации, минут до алерта таймера — и порог раздела в знаках. Нынешние значения — по умолчанию: 10, 10 секунд, 3, 200, 60 минут; порог — 50 000 знаков. Решение пользователя 2026-10-15 в беседе с оркестратором: «общий .. один .. файл» — один конфиг agent-box; ответ 2026-10-14 («документ с конфигом… и тут бы не помешал», «в нашем конфиге», «ямл в корне») — про него же, а шаг «Файл настроек движка» прочитал его как файл в корне каждого проекта под git. Алерт таймера остаётся уведомлением, итерацию не останавливает. Режим запуска движка — контейнер, хост, открытая сеть — в файл не идёт: правка агентом вывела бы следующий запуск из песочницы.

Шаг «Один конфиг agent-box» сделан, кроме двух правок, которые сессия записать не может, и проверки на собранном образе.

1. Карточки документов проекта — описание файлов, которые `/box-init` кладёт в проект, — правятся только с твоего согласия. Файла настроек в корне проекта больше нет: из списка файлов проекта уходит его строка, а порог деления документации на части берётся из общего конфига agent-box. Правка:

```diff
@@ § Дерево

-├── agent-box.yml        # настройки обвязки под git: пределы движка, порог раздела документации; правит человек

@@ § Раздел по областям
-… Порог — ключ `split_chars` в `agent-box.yml` в корне проекта, без файла или ключа — 50 000 знаков; счёт — …
+… Порог — ключ `split_chars` конфига agent-box — в контейнере `/etc/claude-box/config.yml`, на хосте `config.yml` в папке, куда ведёт команда `agent-loop.sh`; без файла или ключа — 50 000 знаков; счёт — …
```

Предложение: записать карточки как в правке выше.

2. Просьба сделать руками. В настройках образца осталась строка, которая запрещает агенту править файл настроек в корне проекта, — файла больше нет. Убрать строку и закоммитить может только человек: защита Claude Code отклоняет сессии и правку, и коммит этого файла. В папке клона agent-box:

3. Сессиям в контейнере порог теперь доходит копией общего конфига: её кладёт скрипт запуска контейнера при каждом старте. Как она ложится, видно только на пересобранном образе. Предложение — добавить в очередь шаг:
