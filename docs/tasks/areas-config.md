# areas-config

## Постановка

Цель: проект с несколькими разработчиками и с разросшейся документацией ведётся обвязкой без лишнего контекста и без конфликтов при слиянии веток. Архитектура и правила делятся по областям кода — частям проекта со своими папками, например фронт и бэк, — когда в документации проекта раздел уже есть или документ перерос порог; правила области подгружаются сессии, которая трогает код области, и не подгружаются остальным. Журнал и реестр решений сливаются между ветками без конфликта. Пределы движка и порог раздела живут в файле настроек в корне проекта под git. Одиночный проект без раздела и без файла настроек работает как раньше.

Повод — беседа 2026-10-14 о пилотном проекте с двумя разработчиками, фронт и бэк: в документации проекта раздел по областям уже есть, архитектура фронта — около 75 тыс. знаков.

Раскладка раздела — по ответу пользователя: у разделённого документа своя папка, основной файл — в ней же под прежним именем. Архитектура — `docs/architecture/ARCHITECTURE.md`: общая часть — сервисы, связи между областями, деплой — и список областей со ссылками; область — `docs/architecture/<область>.md`. Правила — `docs/rules/RULES.md`, общие, хаб подключает их на старте; область — `docs/rules/<область>.md`. Ссылки протокола и скиллов по голому имени `ARCHITECTURE.md` и `RULES.md` верны при обеих раскладках. Тексты правил области лежат в `docs/rules/`, а Claude Code их подгружает через указатель: папка `.claude/` — защищённый путь Claude Code, запись в неё в режиме auto идёт классификатору, в интерактивном режиме — вопросом (code.claude.com/docs/en/permission-modes § Protected paths, 2026-10-14), а сессии пишут в правила грабли.

Файл настроек — `agent-box.yml` в корне проекта под git, плоский YAML «ключ: целое число»: пределы движка — итераций за запуск, пауза между итерациями, итераций подряд без прогресса, потолок ходов итерации, минут до алерта таймера — и порог раздела в знаках. Нынешние значения — по умолчанию: 10, 10 секунд, 3, 200, 60 минут; порог — 50 000 знаков. Пределы общие для всех разработчиков проекта. Алерт таймера остаётся уведомлением, итерацию не останавливает. Режим запуска движка — контейнер, хост, открытая сеть — в файл не идёт: правка агентом вывела бы следующий запуск из песочницы.

## Блокер

Вопрос: записать ли правку карточек документов — описания того, какие документы получает проект при сборке документации, — под раздел архитектуры и правил по частям кода, например фронт и бэк?

Что меняется:

- Документ делится, когда в старой документации проекта он уже поделён или когда он длиннее порога из файла настроек проекта, по умолчанию 50 000 знаков. Архитектура и правила решают это каждый сам за себя.
- Поделённый документ — папка: основной файл под прежним именем и по файлу на каждую часть кода. Список частей с их папками — в архитектуре.
- Правила части кода видит только сессия, которая читает или правит файлы этой части: в папке части лежит маленький файл-указатель для Claude Code. У части несколько папок — указатель в каждой; в папке уже есть такой файл проекта — строка дописывается в него.
- Хаб, карта документации и порядок чтения называют файлы раздела. Без раздела всё как раньше. В список файлов проекта добавлен файл настроек.

Правка целиком — в терминале из папки agent-box:

```
git diff --no-index --word-diff \
  skills/box-init/documents.md \
  my_local/areas-config/documents.md
```

Предложение: записать как в черновике.

Как ответить: допиши в конец файла docs/tasks/areas-config.md строку, которая начинается с «ответ:», — «ответ: ок» или «ответ:» и свой вариант. Потом запусти в Claude /box-next areas-config или в терминале agent-loop.sh areas-config.
