# areas-config

## Постановка

Цель: проект с несколькими разработчиками и с разросшейся документацией ведётся обвязкой без лишнего контекста и без конфликтов при слиянии веток. Архитектура и правила делятся по областям кода — частям проекта со своими папками, например фронт и бэк, — когда в документации проекта раздел уже есть или документ перерос порог; правила области подгружаются сессии, которая трогает код области, и не подгружаются остальным. Журнал и реестр решений сливаются между ветками без конфликта. Пределы движка и порог раздела живут в файле настроек в корне проекта под git. Одиночный проект без раздела и без файла настроек работает как раньше.

Повод — беседа 2026-10-14 о пилотном проекте с двумя разработчиками, фронт и бэк: в документации проекта раздел по областям уже есть, архитектура фронта — около 75 тыс. знаков.

Раскладка раздела — по ответу пользователя: у разделённого документа своя папка, основной файл — в ней же под прежним именем. Архитектура — `docs/architecture/ARCHITECTURE.md`: общая часть — сервисы, связи между областями, деплой — и список областей со ссылками; область — `docs/architecture/<область>.md`. Правила — `docs/rules/RULES.md`, общие, хаб подключает их на старте; область — `docs/rules/<область>.md`. Ссылки протокола и скиллов по голому имени `ARCHITECTURE.md` и `RULES.md` верны при обеих раскладках. Тексты правил области лежат в `docs/rules/`, а Claude Code их подгружает через указатель: папка `.claude/` — защищённый путь Claude Code, запись в неё в режиме auto идёт классификатору, в интерактивном режиме — вопросом (code.claude.com/docs/en/permission-modes § Protected paths, 2026-10-14), а сессии пишут в правила грабли.

Файл настроек — `agent-box.yml` в корне проекта под git, плоский YAML «ключ: целое число»: пределы движка — итераций за запуск, пауза между итерациями, итераций подряд без прогресса, потолок ходов итерации, минут до алерта таймера — и порог раздела в знаках. Нынешние значения — по умолчанию: 10, 10 секунд, 3, 200, 60 минут; порог — 50 000 знаков. Пределы общие для всех разработчиков проекта. Алерт таймера остаётся уведомлением, итерацию не останавливает. Режим запуска движка — контейнер, хост, открытая сеть — в файл не идёт: правка агентом вывела бы следующий запуск из песочницы.

## Контекст

Шаг «Живая проверка» начат: блокер с командами проверки и уборки — пересборка образа, два тестовых проекта, одна итерация движка, слияние двух веток, копия пилотного проекта в `/tmp/ac-live-pilot` с повторным `/box-init` и тестовыми правилами области. Проверка идёт на копии пилотного проекта: `/box-init` коммитит и правит `claude-box.yml` вне git, сам пилотный проект остаётся нетронутым. Тестовые сессии идут через `docker run` — функция `box` в блокере: у копии пилотного проекта `/box-init` переносит строку `name:` основного compose-файла, и сессии через `claude-box.yml` легли бы в историю самого пилотного проекта; у `docker run` путь в контейнере — от имени папки, `/workspace/ac-live-*`.

Следующее: ответ на блокер. Всё совпало — чекбокс шага, статус «готово»; расхождение — правка и новый круг блокером. Слияние кнопкой на площадке пилотного проекта — проба на частном тестовом репозитории площадки, её место в очереди — вопросом пользователю; слияние командой git — пробы нет, хвост снимается.

Поиск 2026-10-15 о `merge=union` при слиянии кнопкой: GitHub — github.com/rubocop-hq/rubocop/pull/3594 (2016): веб-слияние файла с конфликтом не прошло, слияние — локально; GitLab — gitlab.com/gitlab-org/gitlab-foss/-/issues/17325, заявка на `merge=union` в проверке конфликтов запроса на слияние; Bitbucket — jira.atlassian.com BCLOUD-21337, BSERV-19161. Свежих подтверждений поведения площадок нет.

Движок по этой задаче — с `--host` (`AGENTS.md` § Грабли).

Прочитано за шаг — около 45 тыс. символов.

Хвосты:

- README: файл настроек и раздел по областям — в `README.md` после переписывания задачей readme, там же строка о пределах движка «до 10 итераций за запуск с паузой 10 секунд» — теперь значения по умолчанию из `agent-box.yml`; пересечение с её шагом «Переписывание» — свериться с её «Контекстом».
- Собственная архитектура agent-box — около 61 тыс. знаков, выше порога: предложение — раздел `docs/ARCHITECTURE.md` по новой раскладке после задачи.
- Слияние кнопкой запроса на слияние на GitHub или GitLab — вопросом в блокере.
- `/box-update` строки `.gitattributes` не дописывает и `agent-box.yml` не кладёт: проект, обновлённый только им, пишет реестр одной строкой, а ветки сливает с конфликтом, как раньше; движок в нём работает на значениях по умолчанию. Предложение — `/box-update` дописывает недостающие строки `.gitattributes` образца и кладёт недостающий `agent-box.yml`, как `/box-init`.
- Мера текста документа в описи `/box-init` считает источник, отданный нескольким документам, целиком у каждого: большой общий источник, например `README.md` проекта, может дать раздел и архитектуре, и правилам. Сверка строк раздела описи пилотного проекта с его источниками — пункт 7 блокера.
- Уборка тестовых папок и историй сессий проб прошлых шагов, черновика `my_local/areas-config/` — команды в блокере.

## Блокер

Последний шаг задачи — живая проверка руками: деление документации по частям кода, файл настроек движка и слияние журнала между ветками. Сессии нужен для неё пересобранный образ и новые сессии Claude в контейнере, поэтому проверку ведёшь ты.

**Вопрос.** Пилотный проект сливает ветки кнопкой на GitHub или GitLab? Слияние журнала без конфликта проверено только командой git. По старым сообщениям пользователей площадки при слиянии кнопкой это правило не применяют и показывают конфликт; свежих подтверждений нет. Предложение: кнопкой — отдельная проба на частном тестовом репозитории площадки, команды подготовит следующая сессия; командой git — пробы не нужно.

**Сделать руками** — терминал на компьютере, по порядку:

1. Пересобрать образ — в папке клона agent-box:

   ```
   docker compose build claude
   ```

2. Команда запуска контейнера для тестовых папок — вставить один раз, живёт до закрытия окна терминала:

   ```
   box() {
     n=$(basename "$PWD")
     docker run --rm -it \
       -v "$PWD":/workspace/"$n" -w /workspace/"$n" \
       -v "$HOME"/.claude-box:/home/node \
       -v "$HOME":/root/host-home:ro \
       maksim44/claude-box "$@"
   }
   ```

3. Простой проект без своей документации:

   ```
   mkdir /tmp/ac-live-one && cd /tmp/ac-live-one
   git init -q && echo '# one' >README.md
   git add -A && git commit -qm init
   box
   ```

   В Claude — `/box-init`, на его вопросы — любые ответы, потом выйти. Проверка:

   ```
   ls docs; cat .gitattributes agent-box.yml
   ```

   Ждём: в `docs` — файлы `ARCHITECTURE.md` и `RULES.md`, папок `architecture` и `rules` нет; в `.gitattributes` — две строки про журнал и реестр; `agent-box.yml` есть; итог `/box-init` называет оба файла.

4. Одна итерация движка — там же:

   ```
   sed -i 's/^max_iterations:.*/max_iterations: 1/' \
     agent-box.yml
   git commit -qam 'one iteration'
   agent-loop.sh docs/tasks/docs-*.md
   ```

   Ждём: строка старта «пределы цикла из agent-box.yml: итераций за запуск 1, …», одна итерация и остановка «лимит 1 итераций за запуск» — или раньше, блокером задачи сборки.

5. Слияние двух веток — там же:

   ```
   git switch -qc ac-a
   sed -i '1a - ac-a' docs/JOURNAL.md docs/DECISIONS.md
   git commit -qam a && git switch -q -
   git switch -qc ac-b
   sed -i '1a - ac-b' docs/JOURNAL.md docs/DECISIONS.md
   git commit -qam b && git merge --no-edit ac-a
   grep -n 'ac-[ab]$' docs/JOURNAL.md docs/DECISIONS.md
   ```

   Ждём: слияние без слова `CONFLICT`, в каждом из двух файлов — обе строки.

6. Проект со своим `.gitattributes`:

   ```
   mkdir /tmp/ac-live-own && cd /tmp/ac-live-own
   git init -q && echo '*.png binary' >.gitattributes
   git add -A && git commit -qm init
   box
   ```

   В Claude — `/box-init`, потом выйти. Проверка — `cat .gitattributes`. Ждём: первая строка `*.png binary` на месте, за ней две строки про журнал и реестр.

7. Копия пилотного проекта — сам проект остаётся нетронутым. В первой строке — свой путь к пилотному проекту вместо `~/<пилотный проект>`:

   ```
   git clone -q ~/<пилотный проект> /tmp/ac-live-pilot
   cd /tmp/ac-live-pilot && box
   ```

   В Claude — `/box-init`; итог называет части кода, по которым делится документация; потом выйти. Проверка:

   ```
   grep -n -E 'docs/(architecture|rules)/' \
     docs/tasks/docs-*.md
   ```

   Ждём: в очереди задачи сборки — шаги деления архитектуры: общая часть `docs/architecture/ARCHITECTURE.md` и шаг на каждую часть кода, фронт и бэк. Если там же делятся правила, а их в проекте немного, — их могла раздуть мера: большой общий источник вроде README засчитан и архитектуре, и правилам; напиши об этом в ответе.

8. Правила части кода — на той же копии. В первой строке — папки фронта и бэка от корня проекта:

   ```
   f=<папка фронта>; b=<папка бэка>
   mkdir -p docs/rules
   echo 'Кодовое слово фронта: КОМЕТА.' >docs/rules/ac-test.md
   r=$(realpath -m --relative-to="$f" docs/rules/ac-test.md)
   echo "@$r" >>"$f"/CLAUDE.md
   q='Назови кодовое слово фронта из инструкций или НЕТ.'
   ff=$(git ls-files "$f" | head -1)
   bf=$(git ls-files "$b" | head -1)
   box -p "Прочитай $ff. $q" \
     --disallowedTools Grep,Glob,Bash
   box -p "Прочитай $bf. $q" \
     --disallowedTools Grep,Glob,Bash
   ```

   Ждём: первая сессия, по файлу фронта, отвечает «КОМЕТА», вторая, по файлу бэка, — «НЕТ».

9. Уборка — после проверки. Тестовые папки, истории их сессий и сеть Docker движка:

   ```
   cd ~
   rm -rf /tmp/ac-live-one /tmp/ac-live-own /tmp/ac-live-pilot
   rm -rf ~/.claude-box/.claude/projects/-workspace-ac-live-*
   docker network ls -q --filter name=ac-live \
     | xargs -r docker network rm
   ```

   Остатки проб прошлых шагов этой задачи; последняя строка — в папке клона agent-box:

   ```
   rm -rf /tmp/ac-probe /tmp/ac-conf.* /tmp/ac-union* \
     /tmp/ac-journal* /tmp/ac-decisions* /tmp/ac-rules \
     /tmp/ac-docs /tmp/ac-task-*.md
   rm -rf ~/.claude-box/.claude/projects/-workspace-ac-rules-*
   rm -rf my_local/areas-config
   ```

Как ответить: допиши в конец файла docs/tasks/areas-config.md строку, которая начинается с «ответ:», и после двоеточия — сам ответ: что совпало с ожидаемым, что нет, и как пилотный проект сливает ветки. Потом запусти в Claude /box-next areas-config или в терминале agent-loop.sh --host areas-config.
