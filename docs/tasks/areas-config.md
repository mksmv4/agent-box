# areas-config

## Постановка

Цель: проект с несколькими разработчиками и с разросшейся документацией ведётся обвязкой без лишнего контекста и без конфликтов при слиянии веток. Архитектура и правила делятся по областям кода — частям проекта со своими папками, например фронт и бэк, — когда в документации проекта раздел уже есть или документ перерос порог; правила области подгружаются сессии, которая трогает код области, и не подгружаются остальным. Журнал и реестр решений сливаются между ветками без конфликта. Пределы движка и порог раздела живут в файле настроек в корне проекта под git. Одиночный проект без раздела и без файла настроек работает как раньше.

Повод — беседа 2026-10-14 о пилотном проекте с двумя разработчиками, фронт и бэк: в документации проекта раздел по областям уже есть, архитектура фронта — около 75 тыс. знаков.

Раскладка раздела — по ответу пользователя: у разделённого документа своя папка, основной файл — в ней же под прежним именем. Архитектура — `docs/architecture/ARCHITECTURE.md`: общая часть — сервисы, связи между областями, деплой — и список областей со ссылками; область — `docs/architecture/<область>.md`. Правила — `docs/rules/RULES.md`, общие, хаб подключает их на старте; область — `docs/rules/<область>.md`. Ссылки протокола и скиллов по голому имени `ARCHITECTURE.md` и `RULES.md` верны при обеих раскладках. Тексты правил области лежат в `docs/rules/`, а Claude Code их подгружает через указатель: папка `.claude/` — защищённый путь Claude Code, запись в неё в режиме auto идёт классификатору, в интерактивном режиме — вопросом (code.claude.com/docs/en/permission-modes § Protected paths, 2026-10-14), а сессии пишут в правила грабли.

Файл настроек — `agent-box.yml` в корне проекта под git, плоский YAML «ключ: целое число»: пределы движка — итераций за запуск, пауза между итерациями, итераций подряд без прогресса, потолок ходов итерации, минут до алерта таймера — и порог раздела в знаках. Нынешние значения — по умолчанию: 10, 10 секунд, 3, 200, 60 минут; порог — 50 000 знаков. Пределы общие для всех разработчиков проекта. Алерт таймера остаётся уведомлением, итерацию не останавливает. Режим запуска движка — контейнер, хост, открытая сеть — в файл не идёт: правка агентом вывела бы следующий запуск из песочницы.

## Блокер

Проба показала: кнопкой на сайте GitHub журнал и реестр решений сами не сливаются — после слияния первого запроса второй сайт показывает с конфликтом и не сливает. Обход проверен там же: разработчик на своём компьютере вливает основную ветку в свою командой git — записи обеих веток ложатся без конфликта, — отправляет ветку, и кнопка срабатывает. GitLab не проверяли по твоему решению; обход годится и для него: сливает git на компьютере, а не сайт.

**Вопрос.** Как сливать журнал и реестр проектам, которые вливают ветки кнопкой на сайте?

**Предложение — А.** Журнал и реестр оставить как есть, а порядок записать: перед кнопкой — три команды в своей ветке, `main` — основная ветка проекта:

```
git fetch origin
git merge origin/main
git push
```

Сайт уже показал конфликт в журнале — те же команды его снимают. Порядок узнает агент каждого проекта — одной фразой в протоколе: любая сессия выполнит его по просьбе или подскажет, — а человек — в описании обвязки, при его переписывании задачей readme. Цена — лишняя команда перед кнопкой; забытая команда — конфликт на сайте и те же три команды.

При «ок» в очередь встаёт шаг:

```
- [ ] Порядок слияния кнопкой: фраза в протоколе образца рядом с шагами записи журнала и реестра — сайт GitHub при слиянии кнопкой правило слияния журнала не применяет, поэтому перед кнопкой в ветку вливается основная ветка командой git на компьютере и ветка отправляется; сайт показал конфликт в журнале или реестре — те же команды. Факт — `docs/ARCHITECTURE.md` § Образец проекта. Правка `template/` — часть образа: команда пересборки — в итог пользователю. Проверка: `grep -n 'git merge' template/docs/PROTOCOL.md` — фраза на месте. Читает: `template/docs/PROTOCOL.md`, `docs/ARCHITECTURE.md` § Образец проекта; около 30 тыс. символов.
```

**Другой вариант — Б.** Журнал и реестр — файл на каждую запись в папке: ветки не трогают одни и те же строки, и кнопка любого сайта сливает без конфликта и без команд. Цена — новый вид журнала и реестра: правка протокола, перенос старых записей при заведении и обновлении проекта, журнал читается списком файлов, а не одним документом; несколько шагов, их очередь предложит следующая сессия.

Не нужно ни то, ни другое — итог пробы уже записан в устройство обвязки, задача на этом закрывается.

**Сделать руками — уборка**, ответа не требует. Репозиторий пробы на GitHub уже удалён. Остались тестовые папки прошлых шагов, истории их сессий и сети Docker:

```
cd ~
rm -rf /tmp/ac-*
rm -rf ~/.claude-box/.claude/projects/-workspace-ac-*
docker network ls -q --filter name=ac-live \
  --filter name=ac-rules | xargs -r docker network rm
```

Черновик прошлых шагов — в папке клона agent-box:

```
rm -rf my_local/areas-config
```

Как ответить: допиши в конец файла docs/tasks/areas-config.md строку, которая начинается с «ответ:», — «ответ: ок» или «ответ:» и свой вариант. Потом запусти в Claude /box-next areas-config или в терминале agent-loop.sh --host areas-config.
