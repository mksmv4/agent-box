Как работает оркестратор и всё, что он вызывает

Оркестратор — Claude на компьютере, который ведёт задачу проекта до «готово». Сам шаги он не делает: их делают итерации — сессии Claude, которые по очереди запускает движок. Оркестратор будит движок, разбирает его остановки, снимает вопросы проверкой, остальные приносит пользователю и показывает ход на странице задачи.

Схема — по текстам до шага правок по находкам полной проверки.

Что будит оркестратор

Оркестратор спит, пока идёт движок. Будит его выход сторожа или движка; по исходу он выбирает следующий шаг скилла.

Проснулся: что пришлоскилл, шаг 3
Сторож: началась итерация→ новый сторож, страница iteration и публикация, та же фраза в чатскилл, шаги 3 и 7
Код 0, «готово»→ страница done, итог одним сообщением, вопрос о следующей задаческилл, шаг 6
Код 0, предел итераций за запуск→ перезапуск без вопроса и без пушаскилл, шаг 3
Код 1, блокер→ разбор вопросов: проверка или решение пользователяскилл, шаг 4
Код 1: итерация упала, правки без коммита, итерации без прогресса, статус вне протокола→ разбор сбояскилл, шаг 5
Вывод без строки остановки — движок оборван снаружи→ разбор сбояскилл, шаг 5
Сторож на алерте: итерация идёт дольше предела→ живой ход в журнале — ожидание; иначе разбор сбояскилл, шаг 5
Код 2 — движок не запустился→ вопрос пользователю: причина из вывода движкаскилл, шаг 3
Код 130 — остановка по «останови»→ итог пользователю; перезапуск — по его словускилл, шаги 3 и 8

Вопрос блокера

Итерация остановилась на вопросе. Оркестратор делит вопросы на две группы до того, как спросить пользователя.

Снимает проверка — агент проверок

команда, тест; чтение кода, документов, ресерчей, истории git; запрос к локальной базе и запись её данных; осмотр контейнеров проекта; поиск в интернете и документации; чтение консоли площадки; публичное значение из сервиса — в файл вне git

скилл, шаг 4

Решает пользователь — окно вопроса

Сбой и остановки

Движок вышел не на «готово» и не на вопросе. Оркестратор разбирает журнал цикла, git status и «Контекст».

Сбой: что видноскилл, шаг 5
Сбой сети или API→ перезапускскилл, шаг 5
Лимит подписки→ ожидание сброса фоновым sleep, время — из текста ошибки; перезапускскилл, шаг 5
Шаг длиной в несколько сессий: живой ход, точка продолжения в «Контексте»→ перезапускскилл, шаг 5
Сбой сети, API или лимит оставил правки без коммита→ перезапуск с --resume <id>: та же сессия доделывает и коммититскилл, шаг 5
Прочие правки без коммита→ вопрос: принять коммитом или откатить; делает оркестратор по ответускилл, шаг 5
Остальное→ вопрос пользователю: что видно в журнале и что предлагает оркестраторскилл, шаг 5

Ответ на вопрос этого шага живёт в беседе и на странице: секции «Блокер» у него нет.

Слова пользователя в чате

Пользователь пишет между событиями движка. Оркестратор отвечает, а задачу, разошедшуюся с задумкой, останавливает.

Вопрос пользователя в чате→ ответ первым же сообщением из известного: свои действия за сессию, таск-файл, журнал цикла, ответы скриптаскилл, шаг 8
«Почему»→ первой фразой — причина: правило, решение пользователя или своё действиескилл, шаг 8
«Что происходит»→ положение задачи и следующее действие оркестратора; ждёт решения — вопрос ещё раз, ждёт шага — этот шаг ещё разскилл, шаг 8
Ответа в известном нет→ чтение файла с фразой перед ним, что и зачем читается; «не знаю» — после проверкискилл, шаг 8
Пока пользователь ждёт ответа→ ни агентов, ни движка: события этого времени — после ответаскилл, шаг 8
«Отменяй», «стоп», «хватит»→ вопрос, что отменить; движок идёт до ответаскилл, шаг 8
Расхождение с задумкойскилл, шаг 8

Что оркестратор делает сам и что отдаёт

Граница на всю сессию. Просьба сессии, пересланная целиком, и ответ о намерении вместо дела — срыв.

Делает сам

  • отвечает на вопросы пользователя и выполняет поручения
  • проверки — агентом проверок: код, документы, git, тесты, локальная база, интернет, консоли площадок на чтение
  • контейнеры и образы проекта: журнал, команды проверки, остановка и удаление поднятых по ошибке
  • файлы вне git
  • запуск, перезапуск и остановка движка по «останови»
  • страница задачи и её публикация
  • строки ответ:; коммит по ответу о правках без коммита; правка «Постановки» после «да»
скилл, шаг 8

Отдаёт пользователю

  • решения с разными последствиями, согласие на очередь шагов
  • цель и способ проверки задачи
  • миграции, правка compose-файла и настроек Claude Code
  • отправка на GitHub, вход в сервис, действия в браузере
  • рабочий сервер — ssh только по явному разрешению на этот заход
  • переход к другой задаче
