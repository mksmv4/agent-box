3. `/box-update` сервис не переносит: скилл сверяет и копирует только `docs/PROTOCOL.md`, `/box-next` и `/box-orchestrate` (`skills/box-update/SKILL.md:11–13`). Клон на другой машине и вторая рабочая копия получают файл своим `/box-init`.

Найдено сверх беседы:

5. Повторный `/box-init` в проекте с законченной сборкой заводит новую задачу сборки документации с полной очередью и вехой (`skills/box-init/SKILL.md:36`): кому нужен только перенос сервиса или `claude-box.yml` во второй копии, тот получает и её. README говорит это (строка 144), но не в связи с обновлением; обхода в скилле нет. Вариант для шага «Итог и макет» — копия `claude-box.yml` из другой копии того же репозитория на этой машине: пути в файле относительные и через `~`, кроме абсолютного пути `.git` у рабочей копии; не проверено.
6. Движок обновляется вместе с клоном: команда `agent-loop.sh` — ссылка на скрипт клона (`agent-loop.sh:110`), в образ он не входит (`container/Dockerfile:11–17`); `git pull` в клоне меняет движок сразу, без пересборки.
7. Правило песочницы: текст живёт в `agent-loop.sh:73`, в `~/.claude/settings.json` лежит копия на день записи; новый текст доходит до Claude Code только повторным `agent-loop.sh --sandbox-rule` руками (`:86–92` — запись заменяется).
8. Старые контейнеры: скиллы образа ложатся копией только при старте контейнера (`container/entrypoint.sh:32–38`), и `/box-update` в контейнере, открытом до пересборки, находит «совпадение» и заканчивает без правок (`skills/box-update/SKILL.md:11`); README говорит «в новом контейнере» (строка 144), но шага «выйти из открытых сессий Claude в контейнерах» в порядке нет.

Порядок обновления по коду — материал шага «Переписывание»; вживую целиком не прогонялся:

1. В клоне agent-box — `git pull`, затем `docker compose build claude`.
2. Кто ставил правило песочницы — снова `agent-loop.sh --sandbox-rule` в терминале.
3. Открытые сессии Claude в контейнерах проектов — закрыть.
4. В каждой копии каждого заведённого проекта, по виду:
   - `claude-box.yml` есть — `docker compose -f claude-box.yml run --rm claude`, в сессии `/box-update`: свежие протокол и скиллы; или `/box-init`: ещё правила запрета, адреса и сверка сборки, а строки для `claude-box.yml` — в итог, их дописывает человек;
   - `claude-box.yml` нет, сервис `claude` в основном compose-файле — `docker compose run --rm claude`, в сессии `/box-init`; строки старого сервиса из основного compose-файла убрать руками по итогу;
   - рабочая копия git без `claude-box.yml` — команда первого запуска рабочей копии, в сессии `/box-init`.
5. Сборка документации проекта закончена — повторный `/box-init` заведёт новую (п. 5 выше).
