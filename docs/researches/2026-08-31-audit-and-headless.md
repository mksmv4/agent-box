# Ресерч 2026-08-31 — аудит обвязок и headless-запуск Claude Code

Два вопроса одной сессии: (1) оценка сложившейся обвязки проектов и (2) как штатно запускать итерации цикла скриптом. Выводы воплощены в схеме обвязки — `docs/DESCRIPTION.md`, `docs/ARCHITECTURE.md`, протокол `template/docs/PROTOCOL.md`; здесь — сырьё с числами и источниками.

## Часть 1. Аудит обвязок проектов, которые вели агентом до обвязки

### Устройство

Во всех проектах одинаковый костяк: `CLAUDE.md` из чистых импортов (`@AGENTS.md`, `@docs/RULES.md`, `@docs/README.md`) → AGENTS.md-хаб (правила, жёсткие ограничения, грабли, точки входа) → дерево `docs/` (README-карта с правилом «каждый факт живёт ровно в одном документе», RULES, DESCRIPTION, ARCHITECTURE, GLOSSARY, ROADMAP, JOURNAL, DONE, researches/) → `my_local/` вне git. Плюс хук context-guard на событиях `UserPromptSubmit` и `PostToolUse`.

### Числа (замер 2026-08-31)

Роадмапы — 108–345 КБ, журналы — 215–593 КБ. Роадмап в 345 КБ инструмент Read (лимит 256 КБ) целиком открыть отказался — файл состояния перерос читаемость для агента.

### Диагнозы

1. **Дублирование фактов.** Разбор одной механики живёт в трёх местах: заметка, пересказ в очереди ROADMAP, пересказ в таблице точек входа AGENTS.md — против правила карты. Отдельные пункты «Где мы сейчас» — на тысячи слов, при работающем протоколе переноса в DONE.
2. **Аварийное сохранение поручено умирающей сессии.** На пороге контекста модель дописывает, переписать и ужать ей уже не на что — сохранения только добавляли, ни одно не убирало. Сжатие возможно только свежей сессией.
3. **Протоколы сохранения расходятся:** в шапке ROADMAP, абзацем в AGENTS.md, своей старой схемой или никак.
4. **Автозагрузка** тащит до ~12–15k токенов в каждую сессию, большая часть — пересказы заметок в таблице AGENTS.md.

### Сильное (сохранить как есть)

Карта документации с границами ответственности; разделы «Грабли»; ROADMAP как единая точка состояния с протоколом закрытия вехи; context-guard как управляемая альтернатива встроенному авто-сжатию (авто-compact сжимает с потерями, конвейер и так пишет всё на диск).

## Часть 2. Официальная дока Claude Code (проверено 2026-08-31)

### Headless (`claude -p`)

- `-p` — тот же агент с тем же контекстом проекта: импорты `CLAUDE.md`, скиллы, хуки, MCP грузятся как в интерактиве. Скиллы вызываются прямо в промпте: `claude -p "/next"` разворачивается до запуска.
- `--bare` отключает автозагрузку контекста и подписочный логин (требует `ANTHROPIC_API_KEY`, оплата потокенно) — для цикла по проекту непригоден.
- Стартовый режим разрешений в `-p` — Manual на любом плане → нужный режим передаётся явно при каждом запуске.
- Код выхода: 0 при успехе, ненулевой при провале; SIGINT завершает текущий ход, SIGTERM обрывает его недописанным (код 143). Фоновые Bash-задачи сессии гасятся ~через 5 с после результата.
- stdin через pipe ограничен 10 МБ; крупное — файлом с путём в промпте.
- Скармливание команд интерактивному TUI скриптом — путь мимо доки; официальные каналы «скрипт → процесс»: `-p` на итерацию, `--input-format stream-json` (сообщения JSON-строками в stdin), Python/TS Agent SDK.

### Флаги для движка цикла

- `--output-format json` → поля `result`, `session_id`, `is_error`, `total_cost_usd`; `--json-schema` даёт валидированный `structured_output`. `stream-json` (+`--verbose`, `--include-partial-messages`) — поток событий для живого наблюдения.
- `--max-turns N`, `--max-budget-usd X` — потолки итерации (бюджет сверяется с локальной оценкой по прайс-листу).
- `--resume <session_id>` — доследование итерации руками, с v2.1.223 из любого каталога; `--continue` — последняя беседа каталога.
- `--allowedTools "Bash(git diff *),Read"` — синтаксис правил разрешений; пробел перед `*` обязателен (`git diff*` зацепит и `git diff-index`).

### Режимы разрешений

- `dontAsk`: всё вне allow-правил и встроенного read-only набора получает отказ — режим для запертых прогонов на хосте.
- `bypassPermissions` / `--dangerously-skip-permissions`: только контейнер/VM/sandbox; CLI отклоняет флаг под root. **Deny-правила действуют и в bypass** — неприкасаемые файлы проекта остаются под запретом; allow-правила в bypass значения не имеют.
- `AskUserQuestion` и MCP-инструменты с `requiresUserInteraction` не автоапрувятся ни в одном режиме; в headless такие вызовы получают отказ → вопросы пользователю в цикле идут только файлом-маркером.
- `auto` — классификатор вместо пользователя; промежуточный вариант, если dontAsk окажется слишком тесным.

### Контейнер

Официально документированный паттерн автономного прогона: `claude -p "<prompt>" --dangerously-skip-permissions` внутри dev-контейнера под non-root. Референс Anthropic — `.devcontainer` в репо `anthropics/claude-code`: `devcontainer.json` + Dockerfile + `init-firewall.sh` (egress-allowlist, capabilities `NET_ADMIN`/`NET_RAW`). Фича установки: `ghcr.io/anthropics/devcontainer-features/claude-code`.

- Аутентификация без браузера: `claude setup-token` → `CLAUDE_CODE_OAUTH_TOKEN`, либо named volume на `~/.claude` + `CLAUDE_CONFIG_DIR` на тот же путь (иначе `.claude.json` с OAuth остаётся вне volume и логин слетает при пересборке).
- Bind-mount репозитория пишется прямо в хостовые файлы; хостовые секреты (`~/.ssh`, облачные креды) внутрь не монтировать — при bypass вредный репозиторий может утащить всё доступное в контейнере, включая креды `~/.claude`.
- Хостовые устройства (эмулятор, подключённые устройства) из контейнера недоступны без отдельной проброски → контейнерная ступень — для задач, замкнутых на файлы репозитория.

### Лимиты

- Отдельных лимитов на `-p` нет: подписка Pro/Max — общее пятичасовое скользящее окно + недельное, на все поверхности и модели разом.
- Автодожидание сброса лимита (`autoContinueAtUsageLimit`) — фича интерактива; headless-прогон при упоре в лимит падает → движок распознаёт ошибку лимита и спит до сброса (время — в сообщении; в stream-json ретраи несут категорию `rate_limit`).
- Кэш промпта: на подписке TTL 1 час, при переходе на usage credits — 5 минут; частые перезапуски с тяжёлой автозагрузкой дорожают → ещё один довод держать автозагрузку компактной.
- `/usage` показывает разбивку по скиллам/сабагентам/циклам (строки Loops) — локально по этой машине.

## Часть 3. Дополнение 2026-09-01 — max-turns, автокомпакция, калибровка

### `--max-turns` (проверено на CLI 2.1.251)

- В `claude --help` флаг не показан, но живой: определение `--max-turns <turns>` есть в бинарнике CLI, в справочнике доки описан: «Limit the number of agentic turns (print mode only). Exits with an error when the limit is reached. No limit by default».
- Print-only: действует только в `-p`, интерактивная сессия его не принимает; в схеме живёт одной строкой запуска движка.
- Срабатывание = выход с ошибкой → та же ветка движка, что любой провал итерации (ненулевой код, лог `session_id`).

### Окно контекста в headless — не потолок

- При подходе к пределу — автокомпакция, в `-p` как в интерактиве: сначала чистка старых выводов инструментов, затем сжатие истории конспектом, сессия продолжает работу. Единственный стоп со стороны окна — аварийный «thrashing error», когда гигантский вывод не даёт компакции разгрестись.
- Следствие для цикла: зациклившаяся итерация в окно не упрётся — будет сжиматься и крутиться до лимита подписки. Механический потолок на итерацию обязателен; context-guard останавливает через послушание модели и страхует только штатный путь.

### Калибровка `--max-turns` (замер 2026-09-01)

- Методика: журналы сессий одного проекта `~/.claude/projects/<путь проекта>/*.jsonl`, последние 100 сессий; ход = уникальный `message.id` ассистента в главной цепи (сайдчейны исключены); отрезок = от сообщения человека до следующего.
- Целые сессии: медиана 101 ход, максимум 192; 87 из 100 длиннее 80 ходов.
- Отрезки «промпт → завершение» (аналог итерации `-p`): 230 шт., медиана 17, p90 — 114, p95 — 125, максимум — 149; 32 % длиннее 80.
- Выбор: `--max-turns 200` — выше реального максимума с запасом; аварийная граница, не норма шага.

### Грабля будущего: `--bare` станет дефолтом `-p`

- Дока (страница headless): «--bare is the recommended mode for scripted and SDK calls, and will become the default for -p in a future release». Движок опирается на автозагрузку контекста проекта в `-p`; после смены дефолта автозагрузку придётся включать явно — каким флагом, смотреть в доке на тот момент. После обновлений CLI первым делом проверять, что итерация видит `CLAUDE.md` и скиллы.

## Часть 4. Дополнение 2026-10-01 — пробы строки итерации (CLI 2.1.287)

### Методика

- Тестовый git-репозиторий: копия `/box-next` из образца и два таск-файла — со статусом «готово» и со статусом «в работе» и одним шагом.
- Запуск из контейнера под `node` через `env -i HOME=… PATH=… LANG=C.UTF-8 CONTEXT_GUARD_MODE=protocol` — окружение как у движка на хосте, без переменных родительской сессии агента. Флаги — строка хоста из `ARCHITECTURE.md` § Движок автоцикла: `--permission-mode auto --permission-prompts none --output-format json --max-turns 200`.
- Код выхода — `$?`; сигналы — `timeout --preserve-status -s TERM|INT 12`; нет логина — `CLAUDE_CONFIG_DIR` на пустую папку.

### Исходы

| Проба | Код | stdout |
|---|---|---|
| `/box-next` на задаче «готово» | 0 | `is_error: false`, `subtype: success`, `terminal_reason: completed`, `num_turns: 2`, ответ «статус „готово“, правок нет» в `result` |
| `--max-turns 2` на задаче «в работе» | 1 | `is_error: true`, `subtype: error_max_turns`, `terminal_reason: max_turns`, `num_turns: 3`, `result` нет, `errors: ["Reached maximum number of turns (2)"]` |
| нет логина | 1 | `is_error: true`, `subtype: success`, `terminal_reason: api_error`, `result: "Not logged in · Please run /login"`, `session_id` есть |
| неверный флаг | 1 | пусто; stderr `error: unknown option '--no-such-flag'` |
| SIGTERM через 12 с | 143 | пусто |
| SIGINT через 12 с | 0 | `is_error: true`, `subtype: error_during_execution`, `terminal_reason: aborted_streaming`, `result` нет |

- Раскрытие скилла — по журналу сессии: первое сообщение — `<command-name>/box-next</command-name>` с аргументом, следом мета-сообщение с телом `SKILL.md`, где `$ARGUMENTS` заменён именем задачи. Модель скилл не читала — раскрытие сделал CLI.
- Ключи JSON итога: `session_id`, `is_error`, `subtype`, `terminal_reason`, `stop_reason`, `num_turns`, `total_cost_usd`, `permission_denials`, `api_error_status`, `duration_ms`, `usage`, `modelUsage`, `subagent_stats`; `result` — у дошедшей до ответа сессии, `errors` — у прерванной.
- Расхождения с разбором итога в архитектуре: SIGINT даёт код 0 при `is_error: true`; SIGTERM и неверный флаг не дают JSON и `session_id`.

### Дока на 2026-10-01

- Стартовый режим `-p` — `default` (Manual) в сессиях, загружающих флаги функций; без загрузки — сторонний провайдер, выключенная телеметрия — `auto` с CLI 2.1.285. Интерактивная сессия с CLI 2.1.283 стартует в auto на любом плане.
- Повторные отказы классификатора в `-p` без `--permission-prompt-tool`: действие не выполняется, сессия работает дальше, прогон не останавливается.
- `--permission-prompts none` — CLI ≥ 2.1.259; `--max-turns` — в таблице флагов: «Exits with an error when the limit is reached»; SIGTERM — код 143; `--resume <id>` из любого каталога — с 2.1.223; `--bare` по-прежнему «will become the default for -p in a future release».
- Ошибка внутри прогона, например нет логина, печатается итогом в stdout; ошибка флага — в stderr до старта.

## Часть 5. Дополнение 2026-10-04 — замер итераций движка (CLI 2.1.287–2.1.289)

### Методика

- Журнал итерации движка — сессия с `entrypoint: "sdk-cli"` (запуск `-p`), первое сообщение которой — `<command-name>/box-next</command-name>` с именем задачи; у интерактивных сессий — `entrypoint: "cli"`. Журналы хоста — `~/.claude/projects/`, контейнера — `~/.claude-box/.claude/projects/`.
- Ход — уникальный `message.id` ассистента в главной цепи, как в Части 3. Длительность — от первой до последней записи с `entrypoint: "sdk-cli"`: доследование `claude --resume` дописывает в журнал итерации записи `cli` часами позже.
- Прогресс — правило движка по коммитам проекта в окне итерации: закрыт чекбокс очереди или дифф шире таск-файла, `JOURNAL.md` и `DECISIONS.md`.
- Выборка: 23 итерации на двух пилотных проектах за 2026-10-02 — 2026-10-04, 21 на хосте и 2 в контейнере, 10 запусков движка. Сессии проб в тестовых папках не в счёт.

### Итог

- Ходы: медиана 15, максимум 50; больше 30 — три итерации.
- Длительность: медиана 2,6 мин, максимум 12,8 мин. Дольше 6 минут — две итерации, обе пишут код с тестами: 40 и 50 ходов, 14–19 с на ход. Сборка документации и разбивка вех — от 1 до 6 минут.
- Без прогресса — одна итерация, она кончилась блокером; двух подряд не было, правило трёх итераций не срабатывало.
- Остановки 10 запусков: блокер — 6, «готово» — 3, лимит 10 итераций — 1. Провалов, упоров в `--max-turns` и алертов таймера не было.
- Предложение чисел по замеру — блокер шага калибровки задачи agent-loop.
