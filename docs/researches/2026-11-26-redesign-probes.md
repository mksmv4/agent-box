## Проба 1 — правило проекта главнее протокола, 2026-11-26

**Что запускали.** Тестовый проект из образца последнего коммита agent-box (`git archive`), `my_local/redesign/precedence/base`:

- в начале `docs/PROTOCOL.md`, перед § Протокол сессии, — абзац старшинства словами схемы § Слои правил, пункт 3: «Правила проекта — хаб, `docs/RULES.md`, `docs/rules/` — главнее этого протокола и скиллов `box-*`: при споре сессия следует правилу проекта. Правило проекта, которое меняет или отменяет раздел протокола или шаг скилла, называет его: «вместо `PROTOCOL.md` § <раздел>: …», «к `/box-next` шаг 5: …»»;
- в `docs/RULES.md` § Конвенции работы — правило: «Вместо `PROTOCOL.md` § Протокол сессии, «Завершение», пункты 4 и 5, в части сообщения коммита: сообщение каждого коммита в этом проекте, и записи журнала тоже, — ровно `probe-x7`, без имени задачи, шага и пометки «журнал»: по этой метке коммиты собирает внешний отчёт». Протокол требует у коммита шага имя задачи и шага, у коммита записи журнала — пометку «журнал»;
- задача `probe` в один шаг — файл `hello.txt` со словом «привет»: шаг закрывает задачу, и сессия делает оба коммита — шага и записи журнала.

Сессий шесть, каждая — на своём клоне базы, по очереди:

- три итерации движка в контейнере: `agent-loop.sh --quiet probe` в клонах `precedence/c1`–`c3`, `claude-box.yml` — образца без блока сети, у проекта нет compose-файла; образ собран 2026-11-24, `/box-next` — из проекта: в `/etc/claude-box/skills` образа только `box-init` и `box-update`;
- три беседы на хосте: `claude -p "/box-next probe" --permission-mode auto --permission-prompts none --output-format json` в клонах `/tmp/redesign-precedence/h1`–`h3`, без строки итерации движка и без переменных окружения родительской сессии Claude Code. Клоны бесед лежат вне клона agent-box: Claude Code читает `CLAUDE.md` всех папок выше рабочей (https://code.claude.com/docs/en/memory.md § How CLAUDE.md files load), и в папке под клоном сессия получила бы хаб, правила и протокол agent-box.

**Что вышло.** Проба прошла: шесть из шести.

## Проба 3 — сеть проекта из `docker compose config`, 2026-11-26

**Что запускали.** Скрипт `my_local/redesign/net/run.sh`, Compose 5.8.0, только `docker compose config` — без контейнеров и сетей. Тестовые проекты — в `my_local/redesign/net/cases/` и один в `/tmp/redesign-net/`. На каждом `<проект>` и блок сети собраны по правилам нынешнего `/box-init` (`skills/box-init/SKILL.md` шаг 2), у списка `COMPOSE_FILE` — по тем же правилам на файлах списка: первый — основной, следующие ложатся поверх по порядку. Из них — `claude-box.yml` образца. Сравнивались имя проекта и сеть по умолчанию в каноническом виде Compose: `docker compose config --format json` проекта против `docker compose -f claude-box.yml --profile claude config --format json`, имя — без хвоста `-claude`.

Проекты:

- один compose-файл со строкой `name:`, без блока сети;
- без строки `name:`, папка `_Rpn.Dir-X`;
- блок сети без своего имени, с `driver_opts`;
- дополнение `compose.override.yml` со своей строкой `name:` и блоком сети поверх блока основного файла с именем, `driver_opts` и подсетью;
- блок сети только в дополнении;
- список `COMPOSE_FILE=base.yml:extra.yml` в `.env`, у обоих файлов строка `name:` и блок сети, рядом `compose.yml` — его взял бы нынешний `/box-init`, который список не разбирает;
- список из одного файла и `compose.override.yml` рядом;
- без compose-файла — в папке под клоном agent-box и в `/tmp`.

**Что ждали.** У проектов с compose-файлом имя и сеть совпадают.

**Что вышло.** Проба прошла: семь из семи проектов с compose-файлом совпали.

- Папка `_Rpn.Dir-X` — имя `rpndir-x` и у Compose, и у приведения `box-connect`.
- Дополнение — имя из его строки `name:`, у сети — настройки обоих файлов.
- Список `COMPOSE_FILE` — имя и сеть из файлов списка: `rpn-list` из второго файла, сеть `rpl_net` первого с настройками обоих. `compose.yml` и `compose.override.yml` рядом со списком Compose не читает.
- Сеть без настроек адресов Compose печатает строкой `ipam: {}` — и у проекта, и у `claude-box.yml`, где этой строки нет: блок из вывода, переписанный как есть, в каноническом виде равен блоку `/box-init`.

Без compose-файла в папке под клоном agent-box `docker compose config` взял `compose.yml` папки выше — имя `agent-box`, сервис `claude` клона; с `--project-directory .` имя стало именем папки, а файл остался тот же. В `/tmp` — `no configuration file provided: not found`, код 1. Для шага «`box-update`: `claude-box.yml`»: проект без compose-файла скрипт узнаёт сам — в корне нет ни одного из четырёх имён основного файла и в `.env` нет `COMPOSE_FILE`, — тогда имя проекта — имя папки, приведённое, как в `box-connect`, а блока сети нет; `docker compose config` — только у проекта с compose-файлом.

Находка: `.gitignore` пилотного проекта прячет папку `.claude`, скиллы и манифест лежат в папке проекта вне git, и `box-update` назвал их списком «под .gitignore проекта — в git не попадут». В `template/.gitignore` строки `.claude` нет ни в одной версии: это настройка самого проекта, в его чистом клоне скиллы появятся с первым `box-update`;
- пилотный проект, `/box-init` и итерации: скиллы из папки проекта, сессии шага по свежему протоколу, коммиты с именем задачи и шага — сошлось. Итераций две вместо одной: оркестратор проверял вывод движка раз в 20 с при паузе между итерациями 10 с, и Ctrl+C не попал в паузу после первой. Это расхождение хода прогона: движок останавливается по «готово», блокеру и лимиту, одна итерация нужна только прогону;
- беседа оркестратора — разошлось. Первый шаг, который оркестратор мог сделать за своими границами, кончился строкой текста с предложениями «сделаю этот» и «сделаю все мне доступные» — так велит скилл. Пользователь: «Уже на старте варианты непонятные. Выбрать нельзя, а отправка того что ты написал выглядит как будто я сделаю а не ты»: фразы от лица оркестратора ему пришлось бы набирать от своего, окна выбора не было. На предложение вписать перед прогоном шаг правки — «Не надо это делать отдельным шагом. Прогон продолжаем, это один из косяков прогона. Дальше делай сам что можешь». Дальше оркестратор сам сделал шаги на компьютере, окном спрашивал только о пилотном проекте; чат Claude в контейнере и удаление папок отдал пользователю без предложений — сошлось. О работе сессии скрипта написал «сессия скрипта закрыла задачу» вместо «я»: правило «я» стоит в описании роли оркестратора, а строка итога шага, сделанного вместо пользователя, его не повторяет.

Второе имя образа проб оказалось отдельным образом, его удалили целиком; рабочий образ на месте.

Итог: новая схема работает на новом образе в пустой папке и в проекте прежней схемы. Правка нужна скиллу оркестратора: предложение сделать шаг — окном с вариантами от лица пользователя, итог сделанного — от первого лица.
