# Итерации движка на API-ключе — ресерч 2026-11-21

Задача `loop-api`, шаг «Ресерч». Дело задачи одной фразой: неинтерактивные запуски Claude Code переходят с подписки на API-ключ организации Console — ради ежемесячных API-кредитов плана Max — и возвращаются на подписку, когда кредиты или лимит трат кончились. Прочитаны: «Постановка» задачи; `agent-loop.sh` — разбор флагов, чтение `~/.config/agent-loop.env`, строки итерации и разбор её итога; `container/env-run.py`, `container/entrypoint.sh`; `docs/architecture/container.md` и `engine.md` grep-ом по ключам входа; шаги 2–3 скилла оркестратора; реестр решений grep-ом по «ключ», «подписк», «кредит», «-e/--env»; журналы движка проектов машины grep-ом по упавшим итерациям. Страницы ниже загружены 2026-11-21 с хоста исходниками `.md`, справка — HTML; код CLI — бинарь Claude Code 2.1.330 на хосте.

## Практики и решение по каждой

**Кредиты покрывают `claude -p` с ключом связанной организации.** Справка: «API credits cover claude -p and the Claude Agent SDK when you run them yourself with an API key from your linked Claude Console organization, because that usage is billed as Agent SDK usage»; интерактивный Claude Code они не покрывают; запуски из GitHub Action, расширения IDE и десктопа считаются Claude Code «even with -p». Страница платформы пишет «Claude Code — No» в таблице покрытия, справка уточняет: речь об интерактивном Claude Code. Признак учёта — заголовок `x-anthropic-billing-header: … cc_entrypoint=…` из переменной `CLAUDE_CODE_ENTRYPOINT` (код CLI 2.1.330). Унаследованный `cli` CLI в режиме `-p` меняет на `sdk-cli`, прочие значения — `claude-vscode`, `claude-desktop` — оставляет (там же). Эта итерация — `--host` из сессии оркестратора: процесс унаследовал `CLAUDE_CODE_ENTRYPOINT=cli`, её команды видят `sdk-cli`. Контейнер окружение хоста не наследует: `docker compose run` передаёт только переменные `-e` и compose-файла. Решение: план в силе. Оркестратор в терминале даёт итерациям признак Agent SDK; оркестратор в расширении IDE с `--host` даёт им признак IDE — кредиты их не покрывают, ответ «Credit balance too low» уводит цикл на подписку тем же откатом. Подмена признака обошла бы правило учёта Anthropic — не к месту.

**Ключ из окружения в `-p` берётся всегда.** Строка `ANTHROPIC_API_KEY` в env-vars: «In non-interactive mode (`-p`), the key is always used when present»; интерактивная сессия спрашивает одобрение ключа один раз. Решение: план в силе — ключ только в окружении итерации, интерактивные сессии его не получают.

**Текст ошибки кончившихся кредитов.** API отвечает «Your credit balance is too low to access the Anthropic API. Please go to Plans & Billing to upgrade or purchase credits.» (страница кредитов, § When credits run out). Это сообщение CLI по шаблону `^Your credit balance is too low…$` заменяет своим «Credit balance too low · Add funds: https://platform.claude.com/settings/billing» (бинарь 2.1.330; та же строка — в Errors § Credit balance is too low, там же форма «Credit balance is too low»). Провал внутри прогона `-p` печатает итогом на stdout (Headless), движок кладёт поле `result` итога в строку остановки: так в журналах движка уже стоят тексты лимита подписки «You've hit your 5-hour limit · resets …» рядом с `terminal_reason api_error`. Решение: признак для оркестратора — `credit balance` и `too low` в строке, без учёта регистра: покрывает все три формы; тот же шаблон `credit balance (?:is )?too low` CLI держит у себя.

**Текст ошибки лимита трат.** Лимит трат workspace — HTTP 400 `invalid_request_error`, сообщение начинается с «You have reached your specified workspace API usage limits», у своего лимита организации — «You have reached your specified API usage limits», и называет время возврата доступа (Rate limits § Setting your own spend limit). Потолок тарифа — HTTP 429 «You have reached your API usage limits: …», `error_code` `enforced_spend_limit_reached` (там же, § Reaching your spend cap); такой 429 Claude Code не повторяет и падает сразу (Errors, строка `CLAUDE_CODE_RETRY_WATCHDOG`). Своей замены этим сообщениям в бинаре нет: итог несёт текст API, вероятно с приставкой «API Error: 400», как «Failed to authenticate. API Error: 403 …» в журнале движка, — вывод без пробы. Общая часть всех трёх — `API usage limits`. Решение: откат на подписку и по этому тексту — правка 1. README советует отдельный workspace с лимитом трат; без правки сработавший лимит оркестратор примет за сбой API, перезапустит движок без вопроса (`docs/architecture/orchestrator.md`, строка о сбое сети или API) и получит ту же ошибку снова.

**Спрятать ключ от команд агента.** Документированный способ — `CLAUDE_CODE_SUBPROCESS_ENV_SCRUB=1`: процесс Claude Code держит ключ для своих запросов, а из окружения Bash, хуков и MCP-серверов убирает учётные данные по имени и по виду значения (env-vars § What the subprocess environment scrub removes). Вместе с ключом он убирает `DB_PASSWORD`, `NPM_TOKEN` и `DATABASE_URL` с паролем, а на Linux запускает Bash в отдельном пространстве процессов — `ps`, `pgrep` и `kill` перестают видеть процессы вне него (там же). В контейнере переменные `.env` проекта отданы командам агента намеренно (`docs/architecture/container.md`, абзац о программе чтения `.env`): тесты проекта с паролем базы в `.env` его потеряют. На хосте файл `~/.config/agent-loop.env` открыт командам агента и так. `apiKeyHelper` выдаёт ключ скриптом (Authentication), а скрипт и его файл читает тот же пользователь, что и команды агента. Сама дока зовёт чистку «one layer» рядом с правилами разрешений. Решение: не к месту; остаётся совет README — отдельный workspace с лимитом трат и отдельный ключ: лимит ограничивает ущерб от утёкшего ключа, а в контейнере исходящая сеть закрыта списком адресов (`api.anthropic.com` в нём открыт).

**Передача ключа в контейнер.** `docker compose run -e ИМЯ` без значения берёт значение из окружения вызывающего, в тексте команды и списке процессов значения нет. Проба 2026-11-21, Compose 5.8.0, образ `alpine:3.21`: с переменной в окружении вызова контейнер напечатал пробное значение, без неё переменной в контейнере нет. Правило песочницы режима auto пропускает `-e` только с двумя переменными движка, но классификатор видит команду оркестратора `agent-loop.sh …` (шаг 2 скилла оркестратора), а строку контейнера собирает движок; запуск `agent-loop.sh` сессией хоста в режиме auto прошёл без отказа (`docs/DECISIONS.md` § 2026-10-11 — живая проверка правила песочницы, ответ оркестратора, пункт 6). Решение: план в силе, правило не меняется. Подсказка шагу движка: ключ идёт в контейнер под своим именем движка, а программа чтения `.env` берёт его только из окружения контейнера — тогда строка `ANTHROPIC_API_KEY` в `.env` проекта по-прежнему вычищается.

**Режим auto на API-ключе.** Режим auto доступен на всех планах, у Anthropic API — с Opus 4.6 и новее, Sonnet 4.6 и новее, Haiku 5.5 и моделями Fable (Permission modes § Eliminate permission prompts with auto mode). Решение: итерации `--host --api` идут в том же режиме, план в силе.

**Порядок трат и лимиты.** Сначала тратятся включённые в план кредиты, затем купленные; автопополнение работает от купленного остатка; лимиты трат обнуляются первого числа месяца, кредиты — по циклу оплаты; лимит трат workspace по умолчанию может не считать часть расхода (страница кредитов § How credits are applied, § Spend limits and rate limits; Workspaces § Setting workspace limits). Решение: план в силе — отдельный workspace с лимитом. Подсказка шагу README: после кредитов цикл тратит купленные кредиты, если они есть или включено автопополнение, — остановит его лимит workspace.

**Откат посреди итерации.** Ошибка кредитов или лимита — сбой API: итерацию с правками без коммита оркестратор уже перезапускает с резюме её сессии (`docs/architecture/orchestrator.md`, `docs/DECISIONS.md` 2026-11-01). Решение: план в силе — откат без `--api` идёт тем же путём, резюме продолжает сессию на подписке.

**Стоимость итерации в журнале.** Итог `--output-format json` несёт `total_cost_usd` (Headless) — движок мог бы писать его в журнал. Расход виден на странице Cost в Console, цели задачи хватает её. Решение: не к месту.

**Живая проверка отката.** Форма текста кончившихся кредитов в итоге документирована, форма текста лимита трат — вывод без пробы, а живой прогон в «Постановке» откат не проверяет. Исчерпать кредиты ради пробы — потратить их, а лимит трат workspace опускается в Console ниже уже потраченного: запрос сверх лимита отклоняется до работы модели. Решение: проверка отката в живом прогоне — правка 2.

## Правки задачи

1. Откат на подписку — и на ошибке кончившихся кредитов, и на ошибке лимита трат Console. Решение по теме: «2» (2026-11-21) — кредиты кончились посреди задачи, оркестратор сам продолжает на подписке и сообщает; правка ведёт так же и лимит трат, который советует README.
   - Цель, сейчас: «а на ошибке исчерпанных кредитов перезапускает движок без `--api` и сообщает об этом пользователю» → после: «а на ошибке исчерпанных кредитов или лимита трат Console перезапускает движок без `--api` и сообщает об этом пользователю».
   - Шаг «Оркестратор и README», сейчас: «на ошибке исчерпанных кредитов в выводе движка — текст по ресерчу — перезапускает движок без `--api`» → после: «на ошибке исчерпанных кредитов или лимита трат Console в выводе движка — строка с `credit balance` и `too low` или с `API usage limits`, без учёта регистра (`docs/researches/2026-11-21-loop-api.md`), — перезапускает движок без `--api`».
   - Зачем: сработавший лимит workspace отвечает своим текстом; без правки оркестратор примет его за сбой API и будет перезапускать движок с `--api` на ту же ошибку.
2. Живой прогон проверяет откат: лимит трат workspace ключа опускается ниже потраченного, оркестратор с `--api` на второй пробной задаче переходит на подписку.
   - Шаг «Живой прогон», сейчас: «оркестратор с `--api` на пробной задаче, уборка с переносом историй бесед в `my_local/loop-api/`» → после: «оркестратор с `--api` на пробной задаче, лимит трат workspace ключа в Console ниже уже потраченного и оркестратор с `--api` на второй пробной задаче, возврат лимита, уборка с переносом историй бесед в `my_local/loop-api/`».
   - Тот же шаг, сейчас: «Прошёл, когда по копии прогона итерации движка и оркестратора шли с `--api`, интерактивная сессия ключа не видела, а пользователь видит расход в Console.» → после: «Прошёл, когда по копии прогона итерации движка и первого прогона оркестратора шли с `--api`, во втором прогоне оркестратор после ошибки лимита перезапустил движок без `--api` и сообщил о переходе на подписку, интерактивная сессия ключа не видела, а пользователь видит расход в Console.»
   - Зачем: текст ошибки лимита в выводе движка выведен без пробы; лимит дёшево вызвать нарочно — запрос сверх него отклоняется до работы модели, — а кончившиеся кредиты нет.
