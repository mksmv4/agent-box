## 1. Ответ на вопрос в чате нельзя проверить

Где: строка 114 — «пока пользователь ждёт ответа в чате, оркестратор не запускает ни агентов, ни движка»; там же и в строке 107 — реестр решений и переписку бесед ради ответа читает агент проверок.

Что увидит пользователь: на «почему» или возражение оркестратор либо нарушает одно из правил, либо отвечает по памяти — догадкой.

Правка: «Пока пользователь ждёт ответа в чате, оркестратор не запускает движок и не ведёт события шагов 2–7 — команды страницы, агентов проверок блокера: они — после ответа. Агент проверок ради самого ответа идёт, перед ним — фраза, что он проверяет».

Защита: срыв (12) задачи `orchestrator-context` — агент страницы запущен на остановке, пока пользователь ждал ответа. События по-прежнему ждут.

## 2. Задание агента проверок для вопроса из чата не собрано

Где: строка 107 — «первая строка задания — «Проверь вопрос пользователя по задаче <задача>»»; строка 61 — первая строка задания длинная и несёт все запреты агента; строка 59 — итог сделанного руками агент проверяет «по истории беседы».

Что увидит пользователь: агент без запретов о секретах и миграциях или без переписки, которую ему велено читать. Где лежит переписка бесед, задание не говорит, номера файла хода у вопроса из чата нет.

Правка: в строке 61 первое предложение задания — отдельно: «Проверь вопрос блокера задачи <задача>, таск-файл docs/tasks/<задача>.md, секция «Блокер».», остальное — общая часть. Для вопроса из чата и итога сделанного руками первое предложение — «Проверь вопрос пользователя по задаче <задача>: сверь с docs/DECISIONS.md и перепиской бесед проекта — файлы .jsonl в <папка>.». Папка — та, где лежит файл переписки этой беседы из шага 2. Файл хода — `my_local/checks/<задача>-chat.md`.

Защита: запреты агента — секреты, миграции, консоли только на чтение — остаются в общей части для всех вызовов.

## 3. Предложение против решения пользователя оркестратор не ловит

Где: строка 107 — расхождение с задумкой, в том числе предложение сессии против решения без пометки «против решения от <дата>». Шага, который сверяет предложение с реестром, нет: вопросы с решением уходят пользователю без агента проверок.

Правка: в шаге 4, у вопросов с решением, — перед вопросом пользователю один агент проверок на блокер: «Сверь предложения сессии в вопросах <номера> с docs/DECISIONS.md grep-ом по словам темы: решение по теме без пометки «против решения от <дата>» — его цитата и дата». Расхождение — путь строки 107: готовая правка одним вопросом.

Цена: агент на каждый блокер с вопросами с решением, абзац в контексте оркестратора.

## 4. Границы дел оркестратора — четырьмя разными списками

Защита: правило о скрытых настройках — задача `sandbox-rule`, 2026-10-12–13; секрет кладёт пользователь — строка 54.
