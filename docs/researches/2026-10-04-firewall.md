# Ресерч 2026-10-04 — egress-firewall контейнерной ступени

Вопрос сессии: как ограничить сеть контейнера проекта списком разрешённых адресов по образцу `init-firewall.sh` из референса Anthropic `.devcontainer` и какие адреса нужны контейнеру agent-box. Шаг задачи `agent-loop` «Egress-firewall контейнерной ступени»; список адресов — блокер шага.

## Референс — снимок 2026-10-04, последний коммит скрипта `d945a61b` от 2026-06-30

- Права: `--cap-add=NET_ADMIN --cap-add=NET_RAW` в `runArgs`; скрипт запускает `postStartCommand` через `sudo`, в sudoers у `node` — только этот скрипт. Пакеты под скрипт: `iptables`, `ipset`, `iproute2`, `dnsutils`, `aggregate`.
- Порядок скрипта: сохранение NAT-правил встроенного DNS Docker (`127.0.0.11`) → сброс всех таблиц → возврат DNS-правил → разрешены DNS (udp 53) и SSH (tcp 22) на любой адрес и loopback → ipset `allowed-domains`: диапазоны GitHub `web`, `api`, `git` из `api.github.com/meta` и IPv4 доменов списка через `dig` на момент запуска → подсеть /24 шлюза по умолчанию открыта в обе стороны → политики INPUT, OUTPUT, FORWARD — DROP, установленные соединения разрешены, исходящие на ipset разрешены, прочие исходящие — REJECT `icmp-admin-prohibited`: отказ приходит сразу → самопроверка: `example.com` недоступен, `api.github.com` доступен, иначе выход с ошибкой.
- Домены: `registry.npmjs.org`, `api.anthropic.com`, `sentry.io`, `statsig.com`, три домена VS Code. Последний коммит убрал `statsig.anthropic.com`.
- IPv6 скрипт не настраивает.

## Документация Claude Code — снимок 2026-10-04

- Firewall и права `NET_ADMIN`/`NET_RAW` самому Claude Code не нужны. Bypass в dev-контейнере дока советует сочетать с ограничением сети; и с ним вредный проект в bypass выносит всё, что доступно в контейнере, включая креды `~/.claude`.
- Адреса Claude Code (`network-config` § Network access requirements): `api.anthropic.com` — модель, проверка домена WebFetch, флаги функций, телеметрия событий; `claude.ai` — вход аккаунтом claude.ai; `platform.claude.com` — обмен и продление OAuth-токена, нужен и при входе через claude.ai; `downloads.claude.ai` — нативный установщик, автообновление, проверка версий; `mcp-proxy.anthropic.com` — коннекторы claude.ai, при входе через claude.ai включены по умолчанию, выключаются `ENABLE_CLAUDEAI_MCP_SERVERS=false`; `registry.npmjs.org` — MCP-серверы через `npx`, плагины; `code.claude.com` — поиск по документации Claude Code; `http-intake.logs.us5.datadoghq.com` и `browser-intake-us5-datadoghq.com` — необязательная телеметрия, выключается `DISABLE_TELEMETRY` и `DISABLE_ERROR_REPORTING`; `github.com`, `raw.githubusercontent.com`, `storage.googleapis.com` — плагины и changelog.
- Списку референса недостаёт `claude.ai`, `platform.claude.com`, `downloads.claude.ai`; `sentry.io` и `statsig.com` в текущей доке не значатся.
- `https://claude.ai/install.sh` отвечает 302 на `downloads.claude.ai/claude-code-releases/bootstrap.sh`.
- WebSearch идёт через поисковый бэкенд Anthropic и возвращает заголовки и адреса страниц; страницу читает WebFetch — запросом из самого контейнера после проверки домена на `api.anthropic.com`.
- `DISABLE_TELEMETRY` и `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` выключают заодно загрузку флагов функций.

## Пробы 2026-10-04 — образ `maksim44/claude-box`, Compose 5.6.0

- В образе нет `iptables`, `ipset`, `ip`, `dig`, `sudo`; `gcc` есть.
- `setpriv` (util-linux 2.38.1) при переходе от root к `node` обнуляет действующие и разрешённые права процесса, `NET_ADMIN` остаётся в ограничивающем наборе; с `--bounding-set -all --no-new-privs` ограничивающий набор пуст и повышение прав запрещено. Setuid-программы образа: `su`, `mount`, `umount`, `passwd`, `chsh`, `chfn`, `gpasswd`, `newgrp`, `ssh-keysign`.
- Переменные окружения контейнера доходят до скрипта запуска, который работает от root: с `PATH=/nonexistent:/usr/local/bin` скрипт падает на `chown: not found`; `LD_PRELOAD` загрузчик применяет к `sh` скрипта и к его командам.
- Compose-сервис с `env_file: .env` и `environment:`: значение из `environment:` перекрывает то же имя из `.env`; `PATH` из `.env` перекрывает `PATH` образа и доходит до процесса запуска.

## Пробы 2026-10-04 — скрипт ограничения сети, образ с `iptables` 1.8.9 (nf_tables)

- Адреса доменов с хоста: `api.anthropic.com`, `mcp-proxy.anthropic.com`, `claude.ai`, `platform.claude.com`, `code.claude.com` — один адрес 160.79.104.10; `downloads.claude.ai` — 35.190.46.17; `registry.npmjs.org` — двенадцать адресов 104.16.0.34–104.16.11.34 (Cloudflare); `pypi.org` и `files.pythonhosted.org` — четыре общих адреса 151.101.x.223 (Fastly). Подключения аккаунта claude.ai по адресу от модели не отделить.
- Контейнер в сети Compose с правами `NET_ADMIN`, `NET_RAW`: открыты все восемь доменов списка, `github.com`, `api.github.com`, сервис проекта по имени в той же сети; закрыты `example.com`, `www.google.com`, приём телеметрии Datadog, `github.com:22`; в `ip6tables` — только loopback. Домены и адреса из `CLAUDE_BOX_ALLOW` открыты, домен без адреса останавливает старт.
- `getent ahostsv4` в образе работает; сеть контейнера из `/proc/net/route` — подсеть сети Compose (`172.27.0.0/255.255.0.0`); правил вместе с GitHub — 96 адресов.
- Без `cap_add`: `iptables -S` — «Permission denied (you must be root)», старт останавливается.
- `setpriv … --bounding-set -all --no-new-privs`: у процесса `node` `CapBnd` 0, `NoNewPrivs` 1, `iptables -F` — отказ, `su` — отказ.
- Полный старт за ограничением в пустой домашней папке: установщик Claude Code проходит, `claude --version` от `node` — 2.1.289. Старт с установленным Claude Code — 1,4–2,2 с против 0,3 с без ограничения.
- Живая проверка пользователем на пересобранном образе: `claude -p` через точку входа ограничения сети с `--permission-mode bypassPermissions --permission-prompts none` выполнил обе команды — `registry.npmjs.org` ответил 200, `example.com` — ошибкой соединения.
- Не проверено: доступны ли чужие сайты Cloudflare и Fastly через адреса npm и PyPI.

## Выводы для шага

- Скрипт запуска выполняет от root программы, найденные по `PATH` из `.env` проекта, и подгружает библиотеки из `LD_PRELOAD`. Агент контейнера пишет `.env` скриптом в обход правил запрета и кладёт рядом свою программу — следующий запуск контейнера выполняет её от root: такой код читает всю домашнюю папку хоста в `/root/host-home`, а с правом `NET_ADMIN` снимает firewall. Firewall держится, пока часть скрипта запуска от root работает без переменных `.env`.
- Процесс агента прав firewall не получает: `setpriv` их обнуляет, ограничивающий набор и запрет повышения прав закрывают возврат через setuid-программы.
- Контейнер стартует заново на каждый запуск (`--rm`): правила ложатся один раз в чистые таблицы, DNS-правила Docker в таблице NAT остаются на месте.
- Адреса доменов разрешаются один раз при старте: домен за CDN, сменивший адрес за время сессии, получает отказ.
- Разрешённый адрес, где посторонний держит свой аккаунт, — канал утечки: API Anthropic с чужим ключом, push на GitHub с чужим токеном, публикация в npm или PyPI, приём телеметрии Datadog и Sentry с чужим ключом. Открытый порт DNS — тоже канал: запрос имени в своём домене доносит данные до его DNS-сервера. Firewall закрывает прямую отправку на произвольный сервер, эти каналы остаются.
- Коннекторы claude.ai (почта, диск) идут через `mcp-proxy.anthropic.com`: с открытым адресом агент в bypass пользуется ими без вопросов.
- Свои адреса проекта — переменная в `environment:` сервиса `claude` со значением, вписанным в compose-файл: compose-файл агенту закрыт, `.env` значение не перекрывает. Переменная объявлена в сервисе всегда, хотя бы пустой: необъявленную задаёт `.env`.
