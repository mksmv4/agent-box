# Итерации движка на API-ключе — проверка постановки 2026-11-21

Задача `loop-api`, шаг «Проверка постановки». Сверены: «Постановка» задачи — слова пользователя, цель, шаги, способы проверки; решения по теме в `docs/DECISIONS.md` от 2026-11-21 и grep-ом по «ANTHROPIC_API_KEY», «по подписке», «секрет», «креды»; ресерч `docs/researches/2026-11-21-loop-api.md` и его две правки; `docs/RULES.md`, `docs/architecture/ARCHITECTURE.md`, `docs/architecture/engine.md`, `docs/architecture/container.md`, `docs/architecture/orchestrator.md`; `docs/DESCRIPTION.md` и `README.md` grep-ом по «подписк» и «API»; `container/env-run.py`, `container/entrypoint.sh` и строки чтения `~/.config/agent-loop.env` в `agent-loop.sh`; упоминания движка в скиллах `/box-review`, `/box-qa`, `/box-task`, `/box-next`; страницы документации, загруженные ресерчем: Rate limits § Setting your own spend limit, Workspaces § Claude Code workspace и § Setting workspace limits, страница кредитов § Spend limits and rate limits.

## Находки

1. **Откат на подписку живёт один запуск.** Где: цель — «`/box-orchestrate <задача> --api` передаёт флаг движку на каждом запуске, а на ошибке исчерпанных кредитов перезапускает движок без `--api`»; шаг «Оркестратор и README» — то же. Решение пользователя «2» (2026-11-21) — оркестратор «сам продолжает на подписке и сообщает». Что сломается: следующий запуск той же беседы — после ответа на блокер, лимита итераций, сбоя сети — по словам «на каждом запуске» снова идёт с `--api`, первая же итерация падает на той же ошибке, оркестратор перезапускает без флага и повторяет сообщение о переходе; кредиты возвращаются только с новым циклом оплаты, лимит трат — первого числа месяца (страница кредитов § Spend limits and rate limits). Правка: после отката беседа до конца запускает движок без флага; новая беседа с `--api` пробует ключ снова. Слито с правкой 1 ресерча — то же место «Постановки».

2. **Признак отката не привязан к сбою.** Где: правка 1 ресерча — «в выводе движка — строка с `credit balance` и `too low` или с `API usage limits`». Что сломается: строка остановки движка на блокере несёт текст секции «Блокер» (`docs/architecture/engine.md`, разбор итога), а в задаче о самих этих ошибках те же слова стоят в вопросах блокера — так в блокере этого шага. Оркестратор, ищущий слова во всём выводе, переключит цикл на подписку на обычном блокере. Правка: признак — итерация упала на сбое API (`terminal_reason api_error` в строке остановки, `engine.md`), и слова стоят в тексте её ошибки. Слито с правкой 1 ресерча.

3. **Документы говорят, что в контейнере вход только по подписке.** Где: `docs/DESCRIPTION.md` § Стек — «Работа рассчитана на подписку Claude; в контейнере вход только по ней»; антипаттерн `docs/architecture/ARCHITECTURE.md` — «Секреты хоста в контейнере (`~/.ssh`, облачные креды, креды `~/.claude`). В bypass агент читает всё, что видит его пользователь»; `README.md` § Если что-то пошло не так — «Ключи входа Claude Code убраны из окружения контейнера, тесты ключа не получат». Шаг «Движок и контейнер» правит только документы движка и контейнера в `docs/architecture/`, шаг «Оркестратор и README» — только строку о флаге. Что сломается: после задачи три места говорят неправду о `--api`; ревью задачи и следующие сессии по антипаттерну примут ключ в контейнере за нарушение, а пользователь по README не ждёт, что тесты проекта в итерации с `--api` получат ключ и тратят кредиты организации. Пользователь знал, что ключ видят команды агента, — пункт «дописала сессия» при заведении задачи; решения против ключа в контейнере в реестре нет. Правка: шаг движка и контейнера — исключение для ключа `--api` в антипаттерне и строке `DESCRIPTION.md`, шаг README — строка о тестах в лад с флагом.

## Правки ресерча

1. Откат и по ошибке лимита трат — прошла, с уточнениями находок 1 и 2. Лимит трат workspace советует сама «Постановка» (README), а сработавший лимит отвечает HTTP 400 со своим текстом (Rate limits § Setting your own spend limit) — без правки оркестратор принял бы его за сбой API и перезапускал бы движок с `--api` без вопроса (`docs/architecture/orchestrator.md`, остановки). Ключ под флаг создаётся в своём workspace: в workspace Claude Code ключи вручную не создаются (Workspaces § Claude Code workspace), поэтому 429 с `retry-after` этого workspace сюда не относится. С решением «2» (2026-11-21) правка сходится: сработавший лимит — тоже конец API-денег под флаг.
2. Живой прогон проверяет откат — прошла. Без неё форма ошибки лимита в итоге итерации остаётся выводом без пробы, а неверный признак даёт тихий круг перезапусков с `--api`. Расход идёт и с кредитов, и он считается в лимит workspace (страница кредитов: «To cap spending on a project, give it its own workspace and set that workspace's spend limit»). Наименьшее значение лимита дока не называет: вызвать ошибку выйдет, когда расход первых прогонов выше него; не вышло — пользователь назовёт это в ответе на блокер прогона.

## Без находок

- Слова пользователя: флаг для неинтерактивных сессий — итерации движка; циклы из скиллов запускает только `/box-orchestrate`, `/box-review` и `/box-qa` команду движка только называют (их `SKILL.md`, шаг итога); несколько флагов вместе — пункт цели.
- Код 2 отказа без ключа — тот же класс, что прочие отказы запуска (`engine.md`, коды выхода); оркестратор на коде 2 спрашивает пользователя (`SKILL.md` оркестратора, шаг 3).
- Переменные окружения доходят до программы чтения `.env`: скрипт запуска передаёт окружение через `setpriv … env HOME=… USER=…` без очистки (`container/entrypoint.sh`); правку ждут только `agent-loop.sh` и `container/env-run.py`.
- Порядок шагов выполним: оркестратор передаёт флаг, который движок уже знает; живой прогон — после пересборки образа (`docs/RULES.md` § Конвенции работы).
- Размер шагов: «Движок и контейнер» с правкой 3 — около 130 тыс. знаков чтения вместе с задачей, ресерчем и этой проверкой, «Оркестратор и README» — около 120 тыс.; предел шага — 150 тыс. (`docs/PROTOCOL.md` § Таск-файлы).
- Правило песочницы: классификатор видит команду `agent-loop.sh`, строку контейнера собирает движок (ресерч, «Передача ключа в контейнер»); запуск оркестратора с `--api` в режиме auto проверяет живой прогон.
