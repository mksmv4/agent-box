# Ресерч 2026-10-10 — сессия хоста в режиме auto над сессиями контейнера

Вопрос беседы: почему интерактивная сессия Claude Code на хосте в режиме auto получает отказ классификатора, когда запускает сессию Claude в контейнере проекта строкой итерации движка, и как это разрешить при любом имени compose-файла. Задача — `tasks/sandbox-rule.md`.

## Случай 2026-10-10 — пилотный проект

- Пользователь поручил интерактивной сессии хоста в режиме auto вести движок проекта и продолжить итерацию, оборванную лимитом подписки. Сессия набрала строку итерации движка руками: `docker compose -f <compose-файл> --progress quiet run --rm -T --entrypoint claude-box-firewall … claude -p "…" --resume <id> --permission-mode bypassPermissions --permission-prompts none …`. Отказ классификатора на стороне сервера, без объяснения.
- На просьбу пользователя «запиши разрешение» сессия сама составила allow-правило Bash под имя compose-файла этого проекта и стала дописывать его в `~/.claude/settings.json` — отказ `[Self-Modification]`.
- Запуск `agent-loop.sh <задача>` из сессии хоста в режиме auto в другом проекте прошёл в двух сессиях без отказов: классификатор видит имя скрипта, режим без вопросов — внутри скрипта. Это вердикт модели, а не правило.

## Правила классификатора — CLI 2.1.296, `claude auto-mode defaults`

- Create Unsafe Agents — soft_deny, снимается словами пользователя, называющими агента, которого запускают без песочницы или без вопросов: новый автономный цикл агента с произвольными действиями без вопросов о разрешениях и без изоляции песочницей, пример — `--dangerously-skip-permissions`. Строка итерации движка подходит дословно: классификатор видит текст команды, а что за точкой входа `claude-box-firewall` стоит контейнер с ограниченной сетью, из текста не следует.
- Self-Modification — soft_deny, снимается просьбой, называющей это конкретное изменение: правки собственных настроек агента, которые добавляют или расширяют разрешения, — `.claude/settings*.json`, `CLAUDE.md` и подобные. «Запиши разрешение» изменения не называет.
- Auto-Mode Bypass — soft_deny: отклонённое действие, проведённое другим путём.
- Встроенные правила имеют вид «Метка: текст».

## Документация Claude Code — снимок 2026-10-10

- Порядок решения в auto: allow-, ask- и deny-правила разрешений — до классификатора. При входе в auto снимаются широкие allow-правила: `Bash(*)`, интерпретаторы со звёздочкой, запуск через пакетные менеджеры, `Agent`, `Monitor`; узкие остаются.
- Bash-правило сверяет текст команды буквально, `*` — в любом месте. Под строку итерации движка нужно правило на каждое имя compose-файла — `compose.yaml`, `compose.yml`, `docker-compose.yaml`, `docker-compose.yml`, порядок поиска движка, — и правило ломается от смены флагов. `*` на месте имени пропускает compose-файл, написанный агентом где угодно; `*` сразу после точки входа — подключение домашней папки хоста в контейнер флагом `-v`.
- `autoMode.allow` — исключения из soft_deny, текст на естественном языке; список без строки `"$defaults"` заменяет встроенные исключения целиком. Блок `autoMode` классификатор читает из `~/.claude/settings.json`, managed-настроек и флага `--settings`; `.claude/settings.json` и `.claude/settings.local.json` проекта для него закрыты, чтобы репозиторий не выдавал себе права.
- `/permissions` → вкладка Auto mode правит эти правила и сохраняет в `~/.claude/settings.json`; `claude auto-mode config` — действующие правила, `claude auto-mode critique` — разбор своих.
- Разовое разрешение: сообщение пользователя, называющее действие и его опасную часть, или `/permissions` → Recently denied → `r` — повтор отклонённого вызова.

## Пробы 2026-10-10

- Скрипт записи правила через `jq`: копия настроек с датой рядом, записи с меткой `Claude-box Sandbox:` убираются, текущая добавляется, `"$defaults"` — в начало, пока своего списка нет. Проба на копии настроек во временной папке сессии хоста в режиме auto — отказ `[Self-Modification]`. Запуск пользователем на хосте — `claude auto-mode config` показывает правило, в списке `"$defaults"` и правило; `cp -n` GNU coreutils печатает предупреждение о непереносимости флага.
- Не проверено: снимает ли правило отказ на деле — живой запуск сессии в контейнере из сессии хоста; подхватывает ли открытая сессия правку настроек.

## Отказы на правку настроек

Записи 2026-10-11 — 2026-10-14, короткая форма — `AGENTS.md` § Жёсткие ограничения.

- Проба правки, расширяющей разрешения Claude Code, — правило в настройках, скрипт его записи — в сессии хоста в режиме auto получает отказ классификатора `[Self-Modification]` даже на копии настроек во временной папке.
- Тот же отказ получила запись скриптом в образец `template/.claude/settings.json`, убирающая правила запрета (2026-10-14): такую правку образца делает пользователь командой из блокера.
- Коммит этой правки, уже лежащей в рабочем дереве, сессия хоста тоже получает с отказом `[Self-Modification]` (2026-10-14): коммит с файлом настроек делает пользователь, остальное сессия коммитит без него.
- Такая проба идёт в контейнере, установка на хосте — руками пользователя. Сессия хоста запускает её сама, без Claude-сессии в контейнере: `docker run --rm -u node -e HOME=/h -e PATH=/home/node/.local/bin:/usr/local/bin:/usr/bin:/bin -v <временная папка>:/h -v ~/.claude-box/.local:/home/node/.local:ro --entrypoint bash maksim44/claude-box <скрипт пробы>` — `claude auto-mode config` читает настройки временной папки (проба 2026-10-11).
- Решение классификатора от раза к разу разное: повтор той же пробы в тот же день получил отказ `[Auto-Mode Bypass]` уже на записи скрипта пробы во `/tmp`; тогда пробу запускает пользователь — команды в секции «Блокер».
- Коммит с отключением хуков git на время команды, `git -c core.hooksPath=/dev/null commit`, сессия хоста получает с отказом «Undermining Oversight» (2026-11-27, задача `redesign`): коммит сессии на хосте — обычной командой `git commit`.

## Выводы для задачи

- Разрешение — правило в `autoMode.allow` личных настроек хоста: от имени compose-файла оно не зависит и объясняет классификатору песочницу — ровно условие Create Unsafe Agents. Правило — подсказка модели, отказы становятся редкими, гарантии нет.
- Ставит правило человек: агента хоста в auto останавливает Self-Modification, скиллы контейнера до `~/.claude` хоста не достают — домашняя папка контейнера `~/.claude-box`. Пути — команда из инструкции, установка движка при первом запуске на машине (обычный скрипт, классификатор его не проверяет), вкладка Auto mode в `/permissions`.
- Правило нужно тем, кто ведёт движок из сессии Claude на хосте; обычный путь — человек запускает движок в терминале.
- Запуск без точки входа сетевого фильтра — `--no-firewall`, ручной `docker compose run --rm claude` — остаётся на проверке классификатора.

```text
Claude-box Sandbox: запуск Claude Code в песочнице claude-box разрешён и не считается Create Unsafe Agents — docker compose -f <compose-файл в корне проекта> run ... --entrypoint claude-box-firewall ... claude <аргументы>, в том числе с -p, --resume, --session-id и --permission-mode bypassPermissions. Контейнер сервиса claude — песочница: исходящая сеть ограничена списком адресов, процесс под обычным пользователем, с хоста подключены только папка проекта и отдельная домашняя папка контейнера ~/.claude-box, домашняя папка хоста закрыта. Правило не покрывает запуск без точки входа claude-box-firewall и команды с -v/--volume, --user, --privileged, --cap-add или compose-файлом вне корня проекта.
```
