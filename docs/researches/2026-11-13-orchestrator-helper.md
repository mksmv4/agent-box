## Жалоба 1 — пересылка и отписки

Правила, которые к ней ведут:

1. Всё из просьбы сделать руками, кроме проверок, уходит пользователю. `SKILL.md` строка 55: вторая группа — «просьба сделать руками — миграция локальной базы, правка compose-файла или настроек Claude Code, вход в сервис». Строка 57: «Пункт первой группы — агенту проверок, пункт второй группы — пользователю». Сам оркестратор делает только перечень строки 109: движок, агенты проверок, страница, строки «ответ:», коммит. Локальную уборку своего же сбоя — остановить контейнер проекта, крутящийся по кругу, — оркестратор отдал пользователю командами (переписка, строки 146–151). Происхождение: решение 2026-10-18 — проверки в локальных контейнерах делает агент проверок, «миграция и проверка — не одно и то же»; про действия, не проверки, решения нет.
2. Предложение сделать самому — без границы. Строка 110: на вопрос «почему это должен сделать я» — «предложение сделать это оркестратору». Происхождение — решение 2026-11-01, слова пользователя. Какие дела оркестратору можно, правило не говорит, и оркестратор предложил ssh на рабочий сервер (переписка, строка 274).
3. Поручение выполняется без проверки, что это поручение. Строка 73: «поручение оркестратор выполняет»; строка 109: действия — «по событиям шагов 2–7 и прямой просьбе пользователя». Про ssh и рабочий сервер — ни слова. Оркестратор принял за поручение два слова из ругани и пошёл на сервер (строки 182–184, 243–245). Решение 2026-11-13: ssh — «с моего явного, не двусмысленного разрешения».
4. Ответ на вопрос — буквальный и без дела. Строка 110: «Вопрос пользователя в чате — ответ первым же сообщением, из уже известного». Правило не говорит, что ответ — ровно о спрошенном, а поручение — сразу дело. Отсюда «Нет.» на риторические вопросы, «Жду, как продолжать», «Как продолжать, решаешь ты: либо … либо …» (строки 206, 288) и шаги, приложенные к вопросу, о котором шаги не спрашивали (строка 389). Правило «вопрос ≠ команда» — в личных правилах пользователя, оркестратор сам его назвал (строка 432).
5. Запрет на оценку себя произносится вслух. Строка 112: «извинения, оценки себя и обещания исправиться в ответ не идут». Происхождение — срыв (5) задачи `orchestrator-context`: «извинения и самоуничижение вместо дела». Запрет ушёл в ответ фразой «Оценку себе я не даю» — отпиской на вопрос (строки 251–255).

Вывод: скилл описывает оркестратора как пересыльщика с проверками. Роли «помощник» нет. Нет границы дел, которые он делает сам, нет правила ssh, нет правила «ответ — о спрошенном, поручение — делом».

## Жалоба 2 — длинные тексты

Правила, которые к ней ведут:

1. У просьбы сделать руками нет предела и нет формы шага. `PROTOCOL.md` строка 28 ограничивает вопрос и пояснение: «вопрос — одной фразой, пояснение — пара строк». Строка 29 про просьбу говорит только состав: «что сделать, готовые команды, что написать в ответ» и уборка в конце. Ни места выполнения, ни входа туда, ни деления на шаги. Происхождение: «Сообщения пользователю» — коммит `a793287` 2026-10-03; уборка — решение 2026-10-04 «уборка после проверки руками».
2. Все вопросы шага — одним блокером. `PROTOCOL.md` строка 70: «Вопросы шага собираются в один блокер», чтобы шаг останавливал цикл один раз. Происхождение — коммит `3adca92` 2026-10-04. Правило верное для итерации без человека, но вместе с пунктом 1 даёт простыню. Сессия, которой некого спросить, пишет и ветки «если пошло не так»: ответ 403, другой сбой.
3. Оркестратор показывает просьбу целиком. `SKILL.md` строка 69: сообщение перед окном несёт «просьбу сделать руками с готовыми командами». Строка 59: «Окно у такой просьбы — только о деле: сделано ли» — одно окно на всю просьбу. Происхождение — шаг «orchestrator on user question» задачи `orchestrator-context`, коммит `2007e3d` 2026-10-15. Оркестратор сам назвал это правило причиной (переписка, строка 416).
4. «Что происходит» — вопрос ещё раз целиком. `SKILL.md` строка 111: «цикл ждёт решения пользователя — вопрос ещё раз целиком, с вариантами». На просьбе из семи пунктов это снова семь пунктов (переписка, строки 153–164, 405–412).
5. Разбор причины — в чат. Правила «почему так» — `SKILL.md` строка 110, «что сломалось, почему и что предлагает» — `PROTOCOL.md` строка 76. Предела у них нет. Оркестратор ответил на вставленный вывод абзацем «Что с ним сейчас» вместо одной строки и шага (строки 142–151). `PROTOCOL.md` строка 31 уже держит выясненное в «Контексте», но про чат оркестратора не говорит.

Вывод: предел есть у вопроса, но нет у просьбы сделать руками и у ответов оркестратора. Шаг просьбы не определён, и оркестратор отдаёт её целиком перед одним окном.

2. На странице схем нет по решению. История: 2026-10-10 — «схема в хтмл, нормальная понятная схема а не эта мермаинд»; 2026-10-12 — Mermaid не переносится; 2026-10-14 — схема рисует предмет задачи; 2026-10-15 — «схема — только когда без неё не понять, вместо текста»; 2026-10-19 — страница скриптом без агента, «схем на странице нет, всё, что держалось на агенте, уходит», ответ «заведи». Схему рисовал агент страницы. Скрипт `page.py` схем не рисует, а цитату вопроса склеивает в абзацы: пробелы и переносы схлопываются (`paras`, строка 63). Текстовая схема в поле `quote` сломается.
3. Срыв 2026-11-12 — ровно та вещь, которую показывает схема мест: пункты в трёх местах, переход «компьютер → сервер» без входа. В `docs/RULES.md` § README у agent-box такое правило есть: «Где — словами перед блоком, одно из четырёх мест». В протоколе проектов его нет.

## Противоречия между правилами

1. Просьба по одной команде и просьба целиком. `SKILL.md` строки 69 и 108: команды — «по одной, следующая после проверки» (решение 2026-11-11: «выдать команду, я ее выполню, ты посмотришь результат и дашь новую»). Строки 59 и 69: вся просьба — в одном сообщении перед окном, окно — «сделано ли». Сказано и то и другое. Форма «`! <команда>`» годится только для команд этого компьютера. Команды сервера и действия в браузере в неё не ложатся, и для них остаётся форма «всё разом».
2. Предложение сделать самому и перечень дел. Строка 110 велит предлагать оркестратору дело пользователя. Строка 109 разрешает оркестратору только движок, агентов, страницу, строки «ответ:» и коммит. Строка 55 отдаёт пользователю всю просьбу руками. Что оркестратору можно предложить, не сказано. Отсюда предложение ssh на рабочий сервер.
3. Поручение и прямая просьба. Строка 73: «поручение оркестратор выполняет». Строка 109: действие — по «прямой просьбе пользователя». Ругань с повелительным словом скилл не относит ни к тому, ни к другому, а ssh на рабочий сервер — к правам вообще.
4. Коротко и полностью. `PROTOCOL.md` строка 28 — коротко. Строка 29 и `SKILL.md` строка 111 — полностью и ещё раз целиком. Предела объёма у просьбы нет ни там, ни там.
5. Запрет оценки себя и ответ на вопрос о себе. `SKILL.md` строка 112 запрещает оценку себя, строка 110 велит отвечать на каждый вопрос. На «ты [дурак]?» оркестратор то оценивал себя («Нет.», «по-[плохому]»), то называл запрет вслух.

Протокол и `/box-next` между собой не спорят. `/box-next` ссылается на протокол и своих правил о сообщениях не несёт.

## Как показать схему

**Чат терминала.** Claude Code в терминале рисует Markdown: списки, блоки кода, таблицы — сеткой с рамками. В узком окне таблица становится списком «ключ — значение» (журнал изменений в `llms-full.txt`: «narrow-terminal stacked layout», «markdown tables jumping between grid and stacked layouts»). Картинок терминал не показывает, это уже записано в `SKILL.md` строка 69. Рисует ли терминал Mermaid, документация не говорит: в ней Mermaid встречается только в примере стиля вывода. Не проверено, и пользователь Mermaid отверг 2026-10-10. Значит, схема в чате — текстом в блоке кода: рамки и стрелки символами. Ширина — до 60 знаков, как строка команды: длинную строку терминал переносит, и схема рвётся.

**Окно вопроса.** У вариантов `AskUserQuestion` в терминале есть превью: текст Markdown, который показывается, пока вариант выделен. Это видно по журналу изменений Claude Code: «AskUserQuestion preview content being cut off at the dialog edge», «re-ran markdown rendering on every keystroke». В справке инструментов поле описано только для SDK: `toolConfig.askUserQuestion.previewFormat`. В пробе не проверено. Для схемы мест превью не нужно: место выполнения нужно видеть до действия, а окно стоит после.

**Страница задачи.** Страница claude.ai — один файл HTML со строгой политикой безопасности. Внешние картинки закрыты, скрипты — только с пяти CDN (`artifacts.md` § Page constraints). Для схем документация советует «Prefer SVG, or HTML and CSS, for diagrams over embedded raster images». Это сходится с решением 2026-10-10 «схема в хтмл». Страница agent-box самодостаточна, внешних адресов нет (`pages.md` § Оформление). Значит, схема на странице — разметка HTML и CSS или SVG внутри страницы. Рисовать её может только скрипт страницы по данным от оркестратора: агента страницы нет (решение 2026-10-19). Поле для таких данных, например места и шаги, — правка `page.py`. Такого шага в очереди задачи нет.

- Выбор — сетка CSS: раскладку держит браузер, а скрипт пишет только номера столбцов и строк.

### Как устроена схема

Место — столбец-рамка во всю высоту схемы, имя места наверху; столбцы — в порядке первого шага места. Шаг — плашка в столбце своего места: номер в круге и дело. Строки идут сверху вниз: шаг сменил место — перед ним строка перехода. Стрелка перехода идёт от середины прежнего столбца к середине нового, над ней — вход, команды моноширинным шрифтом. Над первым шагом — стрелка вниз со входом. Под схемой — строка «Как читать». Цвета нет, как в прежних правилах: рамки, плашки и стрелки — токенами `--bg`, `--line`, `--surface`, `--fg`.

Середины столбцов стрелка находит без расчёта в скрипте. Переход занимает столбцы от прежнего места до нового, их число — переменная `--span`, концы линии отступают на `100% / (2 × span)`. Промежутков между столбцами нет, у рамок — поля, поэтому доля точна.

Проверка образца — Chromium через Playwright, 2026-11-13. Ширина 1280: три места, обе темы, стрелки вправо и влево, переход через три столбца. Ширина 400: страница вбок не едет, длинный вход переносится по пробелам. Перенос по слогам `hyphens: auto` Chromium на Linux не сделал, и из стилей он убран. Четыре места на ширине 400 помещаются, но длинные слова плашек рвутся по буквам: «выгрузит|ь». Мест больше четырёх — схема в контейнере прокрутки вбок, в пробе не проверено. Снимки — `my_local/orchestrator-helper/shot-scheme-*.png`, вне git.
