# Спецификация

## Цели

agent-box — обвязка проектов под работу с AI-агентом Claude Code: состояние проекта живёт в файлах репозитория, каждая сессия агента делает один шаг задачи и сохраняет итог по общему протоколу. Схема — выжимка из опыта нескольких проектов, которые вели агентом до обвязки: там факты дублировались по документам, файлы состояния разрастались до нечитаемых агентом размеров, а аварийное сохранение на пороге контекста поручалось сессии, которой уже не хватало места ужать написанное (`researches/2026-08-31-audit-and-headless.md` § Часть 1).

- **Релиз для любого проекта.** Обвязкой пользуется любой человек в любом проекте — пустом, с кодом, со своей документацией любой раскладки: проект заводится одной командой в контейнере, документация собирается из того, что в проекте уже есть.
- **Задача идёт шагами без присмотра.** Задача из серии однотипных шагов идёт автоциклом — итерация за итерацией, без ручного сообщения на каждую сессию; человек вмешивается по уведомлениям: блокер, остановка, «готово».

## Стек

- Claude Code — агент: интерактивная сессия и headless-запуск `claude -p` на итерацию автоцикла. Поведение обвязки задают скиллы Claude Code — `/box-init`, `/box-task`, `/box-next` — и хук context-guard. Работа рассчитана на подписку Claude; в контейнере вход только по ней.
- Docker и Docker Compose — контейнер `claude-box` с Claude Code: образ на `node:20` с `jq` и `python3-venv`, сам Claude Code ставится официальным установщиком при первом старте. Запуск — сервис `claude` в compose-файле проекта. Образ собирается под amd64; публикация на Docker Hub публичным образом `maksim44/claude-box` — задача релиза.
- Shell — скрипт запуска контейнера; движок автоцикла — bash-скрипт на хосте с разбором итога итерации через `jq` и уведомлениями через Telegram Bot API.
- Markdown и git — документы и состояние проекта. Документы и заготовки — на русском.

## Ключевые решения

Принципы:

- **Состояние на диске, сессии одноразовые.** Любая сессия может оборваться в любой момент; всё, что нужно следующей, лежит в файлах репозитория. Сессия делает не больше одного шага задачи.
- **Каждый факт живёт ровно в одном документе**, остальные ссылаются; у каждой части решения — факта, пути к нему, ответа пользователя — тоже один дом (маршрутизация — `docs/README.md`).
- **Сохранение — часть каждого завершения.** Конец по сигналу context-guard идёт тем же протоколом, что и штатный, только раньше; так длинная сессия сохраняется по протоколу до встроенного автосжатия, которое сжимает историю с потерями.
- **Перезапись против дописывания.** Состояние задачи — «Контекст» таск-файла — перезаписывается целиком; журнал и архив вех дописываются.
- **Архив дешёвый, контекст дорогой.** Писать на диск можно сколько угодно, на старте сессии читается мало. От разрастания защищает раздельность файлов: «Контекст» перезаписывается, журнал на старте не читается. Потолков размеров, ротации журнала и скриптов проверки размеров в схеме нет.
- **Один агент, последовательно.** Итерация — одна сессия, в репозитории одновременно идёт один цикл; подагенты и параллельные запуски — только когда их предусматривает скилл или по явному решению пользователя.
- **Порядок на месте.** Грабля уходит в постоянный дом той же сессией, что её нашла; отдельной уборочной сессии нет.
- **Каркас целиком со старта.** Проект получает весь набор документов сразу, при заведении.

Работа:

- Итерация автоцикла — свежая сессия `claude -p "/box-next <задача>"` со свежим контекстом. Движок — внешний процесс: перезапуск сессии со свежим контекстом доступен только снаружи неё, а скрипт детерминирован и работает без расхода токенов.
- Задачи проекта ведутся каждая своим таск-файлом: блокер одной останавливает только её цикл, циклы задач одного репозитория идут по очереди.
- Вопрос пользователю из цикла — статус «блокер» с секцией «Блокер» в таск-файле: инструмент вопроса пользователю в headless получает отказ. Уведомление о блокере — в Telegram-бот; токен и chat_id — в файле хоста вне репозиториев (`ARCHITECTURE.md` § Движок автоцикла).
- Человек проверяет задачу целиком, по уведомлению «готово» — по журналу, где на каждый шаг запись с хэшами его коммитов, и хвостам «Контекста»; ревью каждого шага и механической проверки итерации в схеме нет.
- Две ступени изоляции итераций: хост — для задач, завязанных на окружение хоста (эмулятор, устройства, хуки); контейнер — полная автономия для задач, замкнутых на файлы репозитория и сервисы его compose-файла. Режимы разрешений ступеней — `ARCHITECTURE.md`.
- Контейнер — своя простая сборка под терминал (`researches/2026-09-24-container.md`): одна команда `docker compose run --rm claude` на любой ОС; Claude Code обновляется сам; логин и история сессий — в домашней папке контейнера, общей для проектов машины; личные настройки хоста приезжают при каждом старте копией, если они есть, а сама домашняя папка хоста агенту закрыта.
- Проект заводится в обвязку `/box-init`: заготовки из образца и задача сборки документации. Сборка переносит прежнюю историю проекта — журналы, архивы вех, логи разведки — без правок и выбирает из неё решения пользователя в `DECISIONS.md`; разобранные старые файлы уходят в архив с картой исходных путей, место хранения архива — в git или на диске вне git — выбирает пользователь. Повторный `/box-init` обновляет протокол и `/box-next`, незаконченную сборку дорабатывает под свежий шаблон с согласия пользователя, после законченной заводит новую задачу сверки с текущим кодом.
- Задачи заводит генератор `/box-task`. Очередь шагов, не согласованная за его сессию, становится первым шагом самой задачи — «разбивкой»: `/box-next` присылает предложение очереди блокером, в «Постановку» её дописывает пользователь.
- Решения пользователя копятся в `DECISIONS.md` проекта — база прецедентов для авторешения блокеров, следующей ступени автоцикла: классификатор выбирает, кого звать на блокер, — модель авторешения или пользователя; последнее слово за моделью, она вправе отказаться. План внедрения — `ROADMAP.md`.
- AI Factory в схему не входит; отдельные её скиллы могут браться позже.
