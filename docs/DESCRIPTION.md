# Спецификация

## Цели

agent-box — обвязка проектов под работу с AI-агентом Claude Code: состояние проекта живёт в файлах репозитория, каждая сессия агента делает один шаг задачи и сохраняет итог по общему протоколу. Схема — выжимка из опыта нескольких проектов, которые вели агентом до обвязки: там факты дублировались по документам, файлы состояния разрастались до нечитаемых агентом размеров, а аварийное сохранение на пороге контекста поручалось сессии, которой уже не хватало места ужать написанное (`researches/2026-08-31-audit-and-headless.md` § Часть 1).

- **Релиз для любого проекта.** Обвязкой пользуется любой человек в любом проекте — пустом, с кодом, со своей документацией любой раскладки: проект заводится командой `box-connect` в терминале хоста и `/box-init` в Claude, документация собирается из того, что в проекте уже есть; обновление обвязки доходит до проекта скриптом, а правила проекта его переживают.
- **Задача идёт шагами без присмотра.** Задача из серии однотипных шагов идёт автоциклом — итерация за итерацией, без ручного сообщения на каждую сессию; человек вмешивается по уведомлениям: блокер, остановка, «готово».

## Стек

- Claude Code — агент: интерактивная сессия и headless-запуск `claude -p` на итерацию автоцикла. Поведение обвязки задают скиллы Claude Code — `/box-init`, `/box-task`, `/box-next` — и хук context-guard; файлы обвязки в проект кладёт скрипт `box-update`, при подключении — под именем `box-connect`. Работа рассчитана на подписку Claude: интерактивные сессии и итерации автоцикла идут по ней; исключение — итерации движка с флагом `--api`, они идут на ключе Console и тратят API-кредиты организации (`architecture/engine.md`).
- Docker и Docker Compose — контейнер `claude-box` с Claude Code: образ на `node:20` с `jq`, `python3-venv` и `iptables`, сам Claude Code ставится официальным установщиком при первом старте. Запуск — сервис `claude` в файле `claude-box.yml` в корне проекта под `.gitignore`: в git и деплой проекта он не попадает. Образ собирается под amd64; публикация на Docker Hub публичным образом `maksim44/claude-box` — задача релиза.
- Shell — скрипт запуска контейнера; движок автоцикла — bash-скрипт на хосте с разбором итога итерации через `jq` и уведомлениями через Telegram Bot API; подключение и обновление обвязки в проекте `box-connect` и `box-update` — один bash-скрипт на хосте с `git archive`, `sha256sum`, `jq` и `docker compose config`.
- Markdown и git — документы и состояние проекта. Документы и заготовки — на русском.

## Ключевые решения

Принципы:

- **Состояние на диске, сессии одноразовые.** Любая сессия может оборваться в любой момент; всё, что нужно следующей, лежит в файлах репозитория. Сессия делает не больше одного шага задачи.
- **Каждый факт живёт ровно в одном документе**, остальные ссылаются; у каждой части решения — факта, пути к нему, ответа пользователя — тоже один дом (маршрутизация — `docs/README.md`).
- **Сохранение — часть каждого завершения.** Конец по сигналу context-guard идёт тем же протоколом, что и штатный, только раньше; так длинная сессия сохраняется по протоколу до встроенного автосжатия, которое сжимает историю с потерями.
- **Перезапись против дописывания.** Состояние задачи — «Контекст» таск-файла — перезаписывается целиком; журнал и архив вех дописываются.
- **Архив дешёвый, контекст дорогой.** Писать на диск можно сколько угодно, на старте сессии читается мало. От разрастания защищает раздельность файлов: «Контекст» перезаписывается и держит только нужное открытым шагам, закрытые шаги таск-файла и журнал на старте не читаются. Потолков размеров, ротации журнала и скриптов проверки размеров в схеме нет. Исключение — порог раздела: архитектура или правила длиннее порога из конфига agent-box `config.yml` в клоне — один конфиг на все проекты машины держит и порог, и пределы движка; по умолчанию 50 000 знаков, треть бюджета шага на чтение, — делятся по областям кода, частям проекта со своими папками; правила области получает только сессия по её коду. Раздел делает сборка документации, позже его предлагает сессия, после записи которой документ перерос порог; раскладка и условие — карточки документов `template/.claude/skills/box-init/documents.md`.
- **Один агент, последовательно.** Итерация — одна сессия, в репозитории одновременно идёт один цикл; подагенты и параллельные запуски — только когда их предусматривает скилл или по явному решению пользователя.
- **Порядок на месте.** Порядок держат правила записи в момент появления данных: у факта один дом, документ больше порога делится по областям; отдельной уборочной сессии нет.
- **Каркас целиком со старта.** Проект получает весь набор документов сразу, при заведении.

Работа:

- Итерация автоцикла — свежая сессия `claude -p "/box-next <задача>"` со свежим контекстом. Движок — внешний процесс: перезапуск сессии со свежим контекстом доступен только снаружи неё, а скрипт детерминирован и работает без расхода токенов.
- Задачи проекта ведутся каждая своим таск-файлом: блокер одной останавливает только её цикл, циклы задач одного репозитория идут по очереди.
- Вопрос пользователю из цикла — статус «блокер» с секцией «Блокер» в таск-файле: инструмент вопроса пользователю в headless получает отказ. Уведомление о блокере — в Telegram-бот; токен и chat_id — в файле хоста вне репозиториев (`architecture/engine.md`).
- Человек проверяет задачу целиком, по уведомлению «готово» — по записи журнала о задаче с хэшами всех её коммитов и хвостам «Контекста» или ревью задачи по его команде `/box-review`: шаги ревью идут циклом задачи, а находки приходят блокером с шагами правок, и каждое ревью видит всю задачу; после ревью — QA по команде `/box-qa`: сценарии глазами пользователя `/box-qa` согласует с человеком до прогона, прогон в браузере идёт циклом задачи на хосте, провалы приходят блокером; ревью каждого шага и механической проверки итерации в схеме нет.
- Две ступени изоляции итераций: хост — для задач, завязанных на окружение хоста (эмулятор, устройства, хуки); контейнер — полная автономия для задач, замкнутых на файлы репозитория и сервисы его compose-файла. Режимы разрешений ступеней — `architecture/container.md` § Ступени изоляции.
- Контейнер — своя простая сборка под терминал (`researches/2026-09-24-container.md`): одна команда `docker compose -f claude-box.yml run --rm claude` на любой ОС; Claude Code обновляется сам; логин и история сессий — в домашней папке контейнера, общей для проектов машины; личные настройки хоста приезжают при каждом старте копией, если они есть, а сама домашняя папка хоста агенту закрыта.
- Проект заводится в обвязку командой `box-connect`, обновляется командой `box-update` — в терминале хоста в папке проекта: файлы agent-box — протокол, скиллы `box-*`, режим сигнала context-guard — ложатся свежей копией из последнего коммита клона, их суммы и версия — в манифесте `.claude/agent-box.sha256`; заготовки документов — только при подключении, дальше это документы проекта; недостающие строки `.gitignore`, `.gitattributes` и правила запрета дописываются; `claude-box.yml` собирается под проект и машину. Обновление детерминировано — файлы кладёт скрипт, а правка проекта в файле agent-box останавливает скрипт до правок со списком файлов и советом перенести её в правила проекта. Итог печатает, что изменилось в agent-box, записями его журнала (`architecture/template.md` § Обновление проекта). Три команды — три дела: `box-connect` подключает, `box-update` обновляет, `box-claude` запускает Claude в контейнере проекта; сборку документации `/box-init` запускает человек по подсказке в конце подключения (решение пользователя 2026-11-28 в `DECISIONS.md`).
- Правила проекта — хаб, `docs/RULES.md`, `docs/rules/` — главнее протокола и скиллов `box-*`: так говорит абзац в начале протокола, а правило, которое меняет раздел протокола или шаг скилла, называет его — «вместо `PROTOCOL.md` § <раздел>: …». Claude Code склеивает файлы правил и при споре двух строк берёт любую, поэтому старшинство записано текстом; `box-update` печатает такие правила в итоге и останавливается, когда названный раздел или скилл в новой версии пропал. Локальный протокол проекта — `docs/RULES.md`, дом его правил работы (`researches/2026-11-26-redesign-scheme.md` § Слои правил).
- Сборку документации заводит `/box-init` в проекте, подключённом `box-connect`: он же собирает адреса интернета проекта для ограничения сети. Сборка переносит прежнюю историю проекта — журналы, архивы вех, логи разведки — без правок и выбирает из неё решения пользователя в `DECISIONS.md`; разобранные старые файлы уходят в архив с картой исходных путей, место хранения архива — в git или на диске вне git — выбирает пользователь. Повторный `/box-init` незаконченную сборку дорабатывает под свежий шаблон с согласия пользователя, после законченной заводит новую задачу сверки с текущим кодом.
- Задачи заводит генератор `/box-task` — командой пользователя или сессией по его просьбе. Очередь шагов, не согласованная за сессию генератора, становится первым шагом самой задачи — «разбивкой»: `/box-next` присылает предложение очереди блокером, по согласию пользователя в «Постановку» её вписывает сессия, свой вариант — пользователь. При заведении сессия предлагает ресерч — как такое дело обычно делают и где оно ломается — и проверку постановки — сходится ли задача со словами пользователя, его решениями и проектом; выбранные встают первыми этапами очереди, а правки задачи от них приходят блокером один раз (`/box-task`, `PROTOCOL.md` § Ресерч и проверка постановки).
- Решения пользователя копятся в `DECISIONS.md` проекта — база прецедентов для авторешения блокеров, следующей ступени автоцикла: классификатор выбирает, кого звать на блокер, — модель авторешения или пользователя; последнее слово за моделью, она вправе отказаться. План внедрения — `ROADMAP.md`.
- AI Factory в схему не входит; отдельные её скиллы могут браться позже.
