# Архитектура

## Устройство системы

Продукт — три папки репозитория и скрипт: образец проекта `template/`, скиллы контейнера `skills/`, образ `container/`, который несёт образец и скиллы, и движок автоцикла `agent-loop.sh` в корне. В проект обвязка попадает через `/box-init` в контейнере: заготовки из образца, скиллы `/box-next` и `/box-orchestrate` и протокол ложатся в репозиторий проекта и дальше живут в его git. Вне репозитория — хук context-guard в `~/.claude` хоста. Движок работает на хосте из клона agent-box и ведёт итерации в контейнере проекта или на хосте (§ Движок автоцикла); защита контейнерной ступени — `ROADMAP.md`. Набор документов проекта, их границы, дерево и слои чтения — `skills/box-init/documents.md`.

### Круг задачи

1. Задачу заводит `/box-task` или сессия по просьбе пользователя: таск-файл со статусом «в работе» и строка задачи под вехой в `ROADMAP.md`. Очередь, не согласованная за сессию генератора, — первый шаг задачи «разбивка»: её предложение приходит блокером.
2. Пробный прогон руками: `/box-next <задача>` в интерактивной сессии проверяет шаг и завершение; одна-две итерации строкой движка, запущенной руками, проверяют работу без присмотра — блокер через файл, отказ в разрешениях, коммит и код выхода.
3. Движок захватывает lock репозитория и крутит итерации, пока статус в шапке таск-файла «в работе» или «блокер» с ответом пользователя.
4. Итерация — свежая сессия `/box-next`: один шаг очереди и завершение по `docs/PROTOCOL.md` § Протокол сессии. Сигнал context-guard запускает то же завершение раньше; начатый шаг продолжает следующая итерация от точки в «Контексте».
5. Движок разбирает итог итерации и останавливается на блокере, «готово», падении или трёх итерациях без прогресса (§ Движок автоцикла); пользователь вмешивается по уведомлению или ведёт цикл оркестратором (§ Оркестратор).
6. «Готово» — пользователь проверяет задачу по журналу и хвостам «Контекста» или ревью `/box-review`: замечания — новые шаги в очередь и статус «в работе»; принято — чекбокс строке задачи в `ROADMAP.md`. Закрытие вехи — `docs/PROTOCOL.md` § Протокол закрытия вехи.

Тот же круг идёт руками: каждая итерация — `/box-next <задача>` в интерактивной сессии.

Состояние между сессиями — таск-файл задачи: итерация стартует со свежим контекстом и берёт из него шаг и точку продолжения, движок читает его первую строку. Правила таск-файла — `docs/PROTOCOL.md` § Таск-файлы.

### Итерация — `/box-next`

Скилл лежит в проекте, `.claude/skills/box-next/`, копией образца и уезжает в git вместе с проектом; имя задачи приходит аргументом. Вызов без аргумента — в интерактиве: скилл спрашивает пользователя, какую задачу взять, из задач первой незакрытой вехи роадмапа. Четыре действия: открыть таск-файл и сверить статус («блокер» со строкой «ответ:» — статус «в работе»; иной не «в работе» — назвать его и закончить без правок), сделать первый незакрытый шаг очереди, завершить сессию по протоколу, последним сообщением назвать пользователю сделанное и его следующее действие по исходу — новая сессия `/box-next`, ответ на блокер, проверка готовой задачи, закрытие вехи или новая задача. Правила таск-файла, статусов и завершения сессия берёт из `docs/PROTOCOL.md`, который приходит автозагрузкой хаба. `disable-model-invocation: true` — скилл вызывается только командой. Имя `box-next` принадлежит обвязке: скиллы проекта под другими именами, включая `next` прежней обвязки, остаются на своих местах.

Итерация автоцикла — `claude -p "/box-next <задача>"`. Headless-запуск — тот же агент с тем же контекстом проекта: импорты `CLAUDE.md`, скиллы, хуки, MCP; скилл разворачивается прямо из промпта. В headless инструмент вопроса пользователю (`AskUserQuestion`) получает отказ в любом режиме разрешений, поэтому спросить пользователя итерация может только статусом «блокер» с секцией «Блокер» в таск-файле. В интерактиве `/box-next` — одна команда на сессию, и без движка.

### Движок автоцикла

Шелл-скрипт `agent-loop.sh [--host | --no-firewall] [--quiet] <задача>` в корне agent-box, один на все проекты машины; работает на хосте для обеих ступеней изоляции. Задача — имя или путь к таск-файлу, аргумент с `/` или на `.md`: по имени скрипт запускается из папки проекта, по пути — из любой папки, проект — git-репозиторий файла, подсказки движка повторяют запуск тем же путём; файл вне `docs/tasks/` своего репозитория — отказ запуска. Команды `agent-loop.sh` и `box-connect` скрипт ставит сам: на каждом запуске, когда одной из них нет, а `~/.local/bin` есть в `PATH`, кладёт туда ссылки на себя и на `box-connect` из своей папки клона; запуск без аргументов ставит команды и печатает строку запуска. `box-connect` в папке проекта — первый запуск Claude в контейнере до `/box-init`: `docker run` образа с подключениями папки проекта и домашних папок, как у сервиса `claude` (§ Образ и скрипт запуска), путь в контейнере — от имени папки, приведённого к имени проекта Compose, у рабочей копии git — с подключениями `.git` основного репозитория. `agent-loop.sh --sandbox-rule` вместо цикла пишет правило песочницы в личные настройки Claude Code хоста (§ Ступени изоляции — сессия хоста над контейнером). Без `~/.local/bin` в `PATH` подсказки движка дают полный адрес скрипта. Итерации идут в контейнере — сервисе `claude` проекта — за ограничением сети и без вопросов о разрешениях; с `--no-firewall` — в контейнере с открытой сетью в режиме auto, с `--host` — на хосте (§ Ступени изоляции). Нужны `git` и `jq`; контейнерной ступени — Docker с Compose и сервис `claude` в `claude-box.yml` проекта, хостовой — `claude` хоста; для уведомлений — `curl`. Цикл: захват lock-файла репозитория → статус из шапки `docs/tasks/<задача>.md` → фиксация HEAD → итерация свежей сессией под таймером → разбор итога: код выхода, чистота рабочего дерева, статус, дифф итерации → пауза → снова. Lock-файл `.git/agent-loop.lock` лежит вне рабочего дерева и несёт имя задачи и PID цикла; второй запуск движка в том же репозитории сразу завершается с именем задачи идущего цикла. Lock процесса, которого уже нет, — после `kill -9` или сбоя питания — следующий запуск перехватывает. Git хоста движок запускает с `-c core.fsmonitor=false -c core.hooksPath=/dev/null`: команда fsmonitor и хуки из `.git` проекта не выполняются — их может подложить агент контейнера. Сервис `claude` движок берёт из `claude-box.yml` в корне проекта явным `-f`: контейнер собирается только по нему — основной compose-файл проекта, дополнение `compose.override.yml` и строка `COMPOSE_FILE` в `.env` в сборку не входят (проба 2026-10-03). Контейнеры сервисов основного compose-файла для `claude-box.yml` с тем же именем проекта Compose чужие, и каждый запуск пишет о них строку в stderr; переменная `COMPOSE_IGNORE_ORPHANS=true` в строке итерации её убирает (проба 2026-10-14).

Код выхода движка: 0 — «готово» или лимит итераций; 1 — остановка, ждущая пользователя: блокер, провал итерации, правки без коммита, итерации без прогресса, статус вне протокола; 2 — движок не запустился: второй цикл в репозитории, нет таск-файла, нужной команды, `claude-box.yml` в корне проекта или сервиса `claude` в нём перед первой итерацией в контейнере, ошибка в `config.yml`; 130 — Ctrl+C.

Пределы цикла — конфиг agent-box `config.yml` в корне клона, рядом с движком, один на все проекты машины: итераций за запуск `max_iterations`, секунд паузы между итерациями `pause_seconds`, итераций подряд без прогресса `max_idle_iterations`, потолок ходов итерации `max_turns`, минут итерации до алерта таймера `alert_minutes`; там же порог раздела документации по областям `split_chars` — его движок принимает и пропускает, сессиям в контейнере копию конфига кладёт скрипт запуска (§ Образ и скрипт запуска), — и модель агента проверок оркестратора `check_agent_model` — алиас модели параметра `model` инструмента `Agent`: `opus`, `sonnet`, `haiku` или `fable`; движок её пропускает, проверив вид значения, оркестратор читает при старте сессии (§ Оркестратор). Конфиг движок находит рядом с собой — по пути скрипта с развёрнутыми ссылками: команда `agent-loop.sh` ведёт в клон ссылкой из `~/.local/bin`. Движок читает файл один раз при старте запуска, построчно: строка — «ключ: значение», у пределов и порога — целое число, у модели — строчные латинские буквы; комментарии `#` и пустые строки пропускаются; нет файла или ключа — значение по умолчанию: 10, 10 секунд, 3, 200, 60 минут. Неизвестный ключ, значение не того вида или строка другого вида — отказ запуска с путём конфига и номером строки. Строка старта называет действующие пределы и их источник — путь конфига или значение по умолчанию; правка файла действует со следующего запуска. Режим запуска — контейнер, хост, открытая сеть — живёт только во флагах строки запуска: конфиг правят сессии по задачам самого agent-box, где он в рабочем дереве, и ключ режима в нём вывел бы следующий запуск из песочницы. До решения пользователя 2026-10-15 (`DECISIONS.md`) — один конфиг на все проекты — те же ключи жили файлом образца в корне каждого проекта под git. Проба 2026-10-15 файла в корне проекта на тестовом проекте с заглушкой `claude` вместо сессии: без файла — значения по умолчанию; файл образца и файл с частью ключей — значения файла и источник каждого в строке старта; `max_iterations: 1` — одна итерация, `pause_seconds: 01` — пауза 1 с, `max_turns: 7` — `--max-turns 7` в строке итерации, `alert_minutes: 1` — алерт через минуту; буквы в значении, отрицательное число, неизвестный ключ, строка без двоеточия — отказ с кодом 2 и номером строки. Живая проверка 2026-10-15 на пересобранном образе, файл в корне проекта с `max_iterations: 1` — одна итерация сессии в контейнере и остановка по лимиту. Проба 2026-10-15 конфига клона: копия движка во временной папке на тестовом проекте, запуск путём к скрипту и по имени через ссылку из папки в `PATH` — без `config.yml` рядом строка старта называет значения по умолчанию и путь отсутствующего файла; с `max_iterations: 1` — значение и путь файла; неизвестный ключ и буква в значении — отказ с кодом 2, путём и номером строки.

Строка итерации на хосте:

```bash
CONTEXT_GUARD_MODE=protocol CLAUDE_CODE_PROMPT_CACHE_TTL=5m claude -p "/box-next <задача>" --session-id <uuid> \
  --permission-mode auto --permission-prompts none --output-format json --max-turns 200
```

Строка итерации в контейнере — тот же запуск через сервис проекта, через точку входа ограничения сети и в bypass:

```bash
COMPOSE_IGNORE_ORPHANS=true docker compose -f claude-box.yml --progress quiet run --rm -T --entrypoint claude-box-firewall \
  -e CONTEXT_GUARD_MODE=protocol -e CLAUDE_CODE_PROMPT_CACHE_TTL=5m claude -p "/box-next <задача>" --session-id <uuid> \
  --permission-mode bypassPermissions --permission-prompts none --output-format json --max-turns 200 </dev/null
```

С `--no-firewall` — без `--entrypoint` и с `--permission-mode auto`. Флаги после имени сервиса уходят в Claude Code. Образ, собранный до ограничения сети, точки входа `claude-box-firewall` не несёт: контейнер не стартует, итерация падает, и движок останавливается — bypass без ограничения сети не запускается. Поведение Compose 5.6.0 по пробам 2026-10-03:

- код выхода процесса контейнера `docker compose run` возвращает движку;
- `-T` выключает терминал сервиса (`tty: true`): stdout с JSON итога идёт отдельно от stderr;
- при `-T` ввод контейнера — открытый канал без конца, а `-p` добавляет поданный ввод к промпту: ввод — `/dev/null`;
- `--progress quiet` оставляет в stderr только ошибки — их хвост уходит в уведомление о провале;
- SIGINT Compose отдаёт процессу контейнера и сам сразу выходит с кодом 130, не дожидаясь итога.

Сессии контейнера лежат в его домашней папке: доследование — `docker compose -f claude-box.yml run --rm claude --resume <id>` из папки проекта, с открытой сетью.

Флаги и поведение CLI, на которые опирается строка; сверено с докой и пробами на CLI 2.1.287 — `researches/2026-08-31-audit-and-headless.md` § Часть 4:

- `/box-next <задача>` в промпте `-p` раскрывается до запуска и при `disable-model-invocation: true`: тело скилла с подставленным именем задачи приходит первым сообщением сессии.
- `-p` стартует в Manual; сессия без загрузки флагов функций с сервера — сторонний провайдер, выключенная телеметрия — с CLI 2.1.285 стартует в auto. Режим разрешений передаётся явно при каждом запуске (§ Ступени изоляции).
- `--permission-prompts none` (CLI ≥ 2.1.259): запрос, который ждал бы ответа человека, получает отказ с указанием его не повторять, инструменты вопроса пользователю убраны, прогон продолжается — отказ ведёт сессию к блокеру.
- `--output-format json` — один JSON-объект на stdout: `session_id`, `is_error`, `subtype`, `terminal_reason`, `num_turns`, `total_cost_usd`, `permission_denials`; итоговый текст `result` — у дошедшей до ответа сессии, текст ошибки — в `result` или массиве `errors`. Исходы по пробам:
  - штатное завершение — код 0, `is_error: false`, `subtype: success`, `terminal_reason: completed`;
  - упор в `--max-turns` — код 1, `is_error: true`, `subtype: error_max_turns`, `terminal_reason: max_turns`, `result` нет;
  - ошибка API (проба — нет логина) — код 1, `is_error: true` при `subtype: success`, `terminal_reason: api_error`, ошибка в `result`;
  - SIGINT — ход обрывается, итог записан: код 0 при `is_error: true`, `subtype: error_during_execution`, `terminal_reason: aborted_streaming`;
  - SIGTERM — ход обрывается без итога: код 143, stdout пуст;
  - неверный флаг — код 1, stdout пуст, ошибка в stderr.
- `--session-id <uuid>` — идентификатор сессии задаёт движок до запуска: алерт таймера называет сессию, пока она идёт, и сообщение о провале без JSON — тоже; в итоге JSON `session_id` тот же (проба 2026-10-01).
- `--max-turns 200` — потолок ходов итерации против зацикливания, только для `-p`; 200 — значение по умолчанию, оставлено пользователем после замера обкатки 2026-10-04 — вчетверо выше самой длинной итерации, 50 ходов (`researches/2026-08-31-audit-and-headless.md` § Часть 5); пересматривается, когда наберутся итерации с кодом. Окно контекста итерацию не ограничивает: у предела автосжатие продолжает сессию, а context-guard останавливает её только через послушание модели.
- `CLAUDE_CODE_PROMPT_CACHE_TTL=5m` в окружении итерации (CLI ≥ 2.1.242) — кэш промпта на пять минут вместо часового, который Claude Code на подписке берёт для `-p` по умолчанию: отсчёт идёт от последнего вызова, вызовы внутри итерации идут чаще, а следующая итерация — новая сессия с другим снимком git, то есть с другим началом кэша; запись в кэш на час стоит 2× входа, на пять минут — 1,25× (https://code.claude.com/docs/en/prompt-caching). Пауза между вызовами дольше пяти минут — одна перезапись кэша. Проверка — `usage.cache_creation` в JSON итога: записи в `ephemeral_5m_input_tokens` (проба 2026-10-06 на CLI 2.1.291).
- Лимит подписки общий для всех поверхностей — пятичасовое окно и недельное; headless-прогон при упоре в лимит падает.
- Живое наблюдение — `--output-format stream-json --verbose --include-partial-messages` с `tee` в лог.

Разбор итога итерации:

- провал итерации — ненулевой код выхода, `is_error: true` или stdout без JSON: падение, `--max-turns`, лимит подписки, SIGINT итерации — стоп с уведомлением: `session_id`, `terminal_reason`, текст ошибки из `result` или `errors`; без JSON — код выхода и хвост stderr. Сессия умерла до шагов завершения, в рабочем дереве могут лежать правки, которых «Контекст» не знает; доследование руками — `claude --resume <id>` из любого каталога, у контейнера — через сервис `claude`. SIGINT итерации даёт код 0 при `is_error: true`, и правило по `is_error` останавливает движок вместе с ней: вмешательство пользователя по алерту таймера кончает цикл;
- код 0 и незакоммиченные правки в дереве — та же остановка: сессия не дошла до коммита;
- статус «блокер» без строки «ответ:» в секции «Блокер» — стоп, секция в терминал и уведомлением; пользователь пишет строку «ответ:» и запускает движок снова. Блокер с ответом движок снимает сам: статус «в работе» в рабочем дереве — его забирает коммит итерации — и итерация; регистр слова «ответ» любой — в UTF-8 локали хоста;
- статус «готово» — стоп, уведомление с именем задачи;
- три итерации подряд без прогресса — стоп с уведомлением. Прогресс — закрыт чекбокс очереди либо дифф итерации затронул что-то кроме служебных файлов завершения: таск-файла, `JOURNAL.md`, `DECISIONS.md`. Правило — алерт, не приговор: шаг длиной в несколько сессий чтения или дебага пишет только в «Контекст» и остановит цикл при живой работе, а три сессии с одной граблей в `AGENTS.md` пройдут как прогресс; в обоих случаях пользователь смотрит журнал цикла и перезапускает движок. Три — значение по умолчанию, оставлено пользователем после замера 2026-10-04: правило не срабатывало ни разу;
- лимит итераций за запуск, по умолчанию 10; Ctrl+C;
- иначе — пауза, по умолчанию 10 секунд, и следующая итерация. Пауза — окно чистой остановки Ctrl+C: прошлая итерация закоммичена, следующая не начата; Ctrl+C в терминале доходит и до идущей сессии `claude` и обрывает её ход.

Таймер итерации — алерт без остановки: порог превышен → уведомление с `session_id` и длительностью, итерация продолжается; вмешательство — лог, `claude --resume`, SIGINT. Порог по умолчанию — час: оставлен пользователем после замера 2026-10-04 по jsonl-журналам сессий — самая длинная итерация шла 13 минут; пересматривается вместе с потолком ходов.

Журнал цикла — файл `.git/agent-loop.log` проекта рядом с lock-файлом, вне рабочего дерева, у дополнительной рабочей копии git — в её папке `.git/worktrees/<имя>` основного репозитория (`git rev-parse --absolute-git-dir`); путь движок печатает при старте, файл копится от запуска к запуску. Строка — дата, время и событие: запуск — строкой повтора с флагами; начало итерации — номер, шаг очереди (первый незакрытый чекбокс «Постановки», его номер из их числа и начало текста до 80 символов) и сессия; ход итерации — строки с отступом; конец итерации — длительность, код выхода, `terminal_reason` и число ходов из итога или «итога JSON нет», статус задачи, коммиты итерации с сообщениями; алерт таймера; остановка — текст терминала, включая отказ запуска после захвата lock. Ход берётся из истории сессии Claude Code — файла `<session_id>.jsonl` в `~/.claude-box/.claude/projects/<папка проекта>/` у контейнера и в `~/.claude/projects/<папка проекта>/` у `--host`; движок ищет файл по `session_id`, он появляется со стартом сессии. Из ответов агента основной сессии идут текст, чтение и правка файлов с путями от корня проекта, команды, поиск и прочие инструменты именем и вводом; длинное обрезается до 200 символов. Ход пишется вживую: на время итерации движок держит процесс-метку `sleep`, фоновый `tail -f` с `jq` переводит новые строки истории в журнал, а по снятию метки `tail --pid` дочитывает файл и выходит — строка конца итерации ложится после всего хода. Формат истории сверен на образцах CLI 2.1.287 и 2.1.296 (2026-10-10); строка другого формата пропускается, и журнал остаётся без хода — строки событий движок пишет сам.

Уведомления — Telegram Bot API `sendMessage` и `sendDocument` через `curl`. Токен и chat_id — строки `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` в `~/.config/agent-loop.env` хоста, вне репозиториев; движок берёт из файла только их, в окружение сессий они не попадают. chat_id, которого в файле нет, движок при старте берёт из последнего сообщения боту (`getUpdates`) и дописывает в файл; Telegram хранит входящие бота 24 часа — годится только свежее сообщение. Уведомление уходит на каждой остановке цикла и на алерте таймера: текст терминала с именем папки проекта впереди — движок один на все проекты машины; отказ запуска (код 2) остаётся в терминале — пользователь в этот момент у терминала. Последняя строка текста — «дальше:» со следующим шагом пользователя: проверка готовой задачи, `claude --resume`, повторный запуск; у блокера это строка «Как ответить:», которой секцию «Блокер» заканчивает сессия (`PROTOCOL.md` § Таск-файлы). Текст до 4000 символов уходит сообщением — предел сообщения Telegram 4096; длиннее — файлом `<проект>-<задача>.md` целиком, в подписи — первые 600 символов и строка «дальше:»: подпись Telegram ограничивает 1024 символами. Токен уходит в `curl` через stdin и в списке процессов не виден. Сбой отправки — строка в терминале с ответом Telegram, код выхода остановки прежний. Токен движок проверяет при старте запросом `getMe` — до поиска chat_id и первой итерации, пока пользователь у терминала. Неверный токен вида `<число>:<ключ>` Telegram отклоняет ответом 401 «Unauthorized», токен другого вида — без двоеточия, с пустой или нецифровой частью до него — ответом 404 «Not Found» (проба 2026-10-04); на оба движок стартует со строкой «уведомления выключены: неверный токен», ответом Telegram и подсказкой, где поправить токен. Проверка, на которую Telegram не ответил, — строка с ошибкой, уведомления остаются включены. Без токена или chat_id движок стартует со строкой «уведомления выключены» и причиной и сообщает только в терминал. Флаг `--quiet` выключает Telegram на запуск целиком, вместе с проверкой токена: строка старта называет флаг, остановки и алерт таймера идут только в терминал, подсказки «дальше:» повторяют запуск с флагом. Режим для сессии, которая ведёт движок и читает его вывод сама.

### Оркестратор — `/box-orchestrate`

Оркестратор — интерактивная сессия Claude Code на хосте, которая ведёт задачу движком за пользователя: скилл проекта `/box-orchestrate <задача>`, рабочий оригинал — `template/.claude/skills/box-orchestrate/`, шаги — в его `SKILL.md`, скрипт страницы задачи — `page.py` рядом, устройство страницы и метки — в `pages.md`, образцы вопросов пользователю «плохо → понятно» — в `questions.md`, две страницы-примера вымышленной задачи — в `examples/`. Скилл лежит в проекте рядом с `/box-next`: скиллы контейнера сессия хоста не видит. Папку скилла целиком кладут в проект `/box-init` и `/box-update`, как `/box-next` (§ Скиллы контейнера). Канал к пользователю — Remote Control: сессия на проект в приложении Claude, вопросы и пуши приходят на телефон (`researches/2026-10-10-orchestrator-remote.md`).

Движок — фоновая команда Bash сессии `env --default-signal=INT setsid -w agent-loop.sh --quiet <задача>`: завершение команды будит сессию; своя группа процессов и снятый игнор Ctrl+C дают остановку по просьбе пользователя сигналом `kill -INT -- -<PID>`, PID — из lock-файла движка, — тот же путь, что Ctrl+C в терминале (проба 2026-10-11 заглушкой с обработчиком движка: выход 130). Тихий режим — по умолчанию, Telegram — словом `telegram` в аргументе (`DECISIONS.md` 2026-10-10 — уведомления движка под оркестратором). Начало итерации и алерт таймера ловит сторож — вторая фоновая команда, поставленная раньше движка: опрос журнала цикла раз в 30 секунд, выход на первой строке начала итерации или алерта после его старта. Шаблон сторожа берёт только строки событий движка — время и через один пробел «задача»: в строках хода итерации бывают те же слова — поиск по одним словам «идёт дольше» нашёл в журнале 2026-10-11 две строки хода, команды агента. Сессия просыпается по событиям — остановка движка, начало итерации, алерт, сообщение пользователя; в ожидании ходов модели нет.

Страница задачи — приватная страница claude.ai, которую оркестратор ведёт по событиям цикла (`DECISIONS.md` 2026-10-10 — ход цикла: журнал и страница статуса). Её файл — `my_local/pages/<задача>.html` проекта, вне git: он же копия страницы (`DECISIONS.md` 2026-10-10 — копии страниц задач); адреса страниц — `my_local/pages/links.md`, строка на задачу. Обновление — на выходе сторожа, вопросе пользователю, ответе, остановке движка без перезапуска и «готово». Строка начала итерации ложится в журнал после строки конца прошлой, и одно пробуждение на итерацию даёт странице и исход прошлой итерации, и идущую. Копия, открытая из файла: Chrome 155 показывает кириллицу примера без `<meta charset>` верно — распознаёт UTF-8 (проба 2026-10-11).

Скрипт страницы — `page.py` на Python 3 со стандартной библиотекой (задача page-script): файл страницы он правит по 14 меткам-комментариям в разметке, всё вне меток — каркас примера `examples/running.html`. Шаги очереди скрипт берёт из таск-файла, итерации — из журнала цикла, сквозной нумерацией по всем запускам задачи; от оркестратора — только фразы события со stdin: заголовок, лид, цели и этапы очереди при создании, вопрос с вариантами и рекомендацией, ответы, итог итераций, причину остановки. Команды — `new`, `iteration`, `question`, `answer`, `stop`, `done` и `link` для адреса в `links.md`; ответ — одна строка: изменённые метки и адрес страницы или «первая публикация»; страницы или меток нет — код 3, и оркестратор создаёт страницу командой `new`. Публикует оркестратор инструментом `Artifact`, загрузив его `ToolSearch` один раз за беседу. Повод — беседа оркестратора пилотного проекта 2026-10-19: подагент, который вёл страницу до задачи page-script, запускался 10 раз, 6 на начала итераций и 4 на один вопрос с повторами; каждый стартовал с 56 тыс. токенов контекста и кончал на 90–113 тыс., а сама правка у него — одна команда по файлу и одна публикация (`DECISIONS.md` 2026-10-18 — агент на отметки, 2026-10-19 — задача page-script). До этого подагента оркестратор к первой публикации занимал 105–115 тыс. токенов из предельных 150 тыс.: правила страниц около 8,5 тыс., файл страницы 7–22 тыс., схема `Artifact` 13 тыс., отказ «не видел живую версию» с живой страницей 22 тыс. (задача orchestrator-context). Скрипт убирает из контекста оркестратора правила и файл страницы, схема `Artifact` и отказ остаются; сколько добавляет событие, меряет живой прогон задачи page-script. Вопрос пользователю идёт порядком страница, фоновая команда `sleep 5`, сообщение текстом, которым кончается ход, пуш на уведомление `sleep`, окно: текст ответа с вызовом инструмента сразу после результата другого Claude Code в половине случаев сворачивает, а текст, которым кончается ход, и ответ на уведомление фоновой команды видны всегда (`AGENTS.md` § Грабли).

Агент проверок — подагент общего назначения сессии оркестратора на вопрос блокера, снимаемый проверкой с однозначным итогом или сведениями вне сети контейнера (задача orchestrator-context): оркестратор передаёт ему вопрос и предложение сессии из секции «Блокер», агент читает код, документы, ресерчи и историю git, запускает команды и тесты, ищет в интернете и отвечает одним абзацем — что проверено, итог, источник. Ему же идут проверки из просьбы сделать руками, до которых сессии в контейнере не дотянуться: запрос на чтение к локальной базе, осмотр контейнеров проекта. Миграции и запись в локальную базу делает пользователь: схему базы меняет только он (`DECISIONS.md` 2026-10-18 — проверка из просьбы сделать руками). Строку «ответ: оркестратор —» оркестратор пишет по этому абзацу, а прочитанное остаётся в контексте агента: до задачи оркестратор читал ресерч задачи ради ответа на блокер, уже занимая 130–137 тыс. токенов из предельных 150 тыс. Задание агента — три строки прямо в скилле: вопрос, предложение сессии и поручение с формой ответа. Модель — ключ `check_agent_model` конфига agent-box, по умолчанию `opus`, параметр `model` вызова (`DECISIONS.md` 2026-10-15 — модель помощников оркестратора). Агенты нескольких вопросов идут разом — в проект они не пишут; вопрос пользователю ждёт отчётов всех: их итоги — ответы оркестратора на странице и в сообщении перед окном. Итог неоднозначен или агент упал — вопрос уходит пользователю с абзацем агента. Интерактивная сессия запускает подагентов фоном — режим форков в ней включён по умолчанию (code.claude.com/docs/en/sub-agents, 2026-10-15): ответ агента — его отчёт, сообщение, которое будит сессию; уведомление о конце приходит следом и сессию обычно не будит (`AGENTS.md` § Грабли), поэтому вопрос пользователю ждёт отчётов.

Остановку оркестратор разбирает по коду выхода и строке остановки движка (§ Движок автоцикла), журналу цикла и таск-файлу:

- блокер: вопрос, снимаемый проверкой с однозначным итогом или сведениями, закрытыми сети контейнера, оркестратор снимает своим ответом по итогу агента проверок — строкой «ответ: оркестратор —» (`docs/PROTOCOL.md` § Таск-файлы, `DECISIONS.md` 2026-10-10 — что оркестратор решает сам); вопрос с решением — выбор с разными последствиями, согласие на очередь, цель и проверка задачи, ручное действие, неясная граница — пользователю. Ответы ложатся в таск-файл разом, когда отвечен каждый вопрос блокера: первая строка «ответ:» снимает блокер для движка целиком. Коммитит их следующая итерация — в обкатке на пилотном проекте оркестратор закоммитил ответы до разбора всех вопросов, и пользователь его остановил;
- лимит итераций, сбой сети или API, лимит подписки после сброса, шаг на несколько сессий с живым ходом в журнале — перезапуск без вопроса; правки без коммита в рабочем дереве — всегда вопрос пользователю;
- «готово» — вопрос о следующей задаче: задачи переключаются только по согласию пользователя, шаги — сами (`DECISIONS.md` 2026-10-10 — переход оркестратора к следующей задаче).

Идущий движок оркестратор останавливает только по прямой просьбе «останови»: в обкатке он остановил идущий цикл на «не запускай», а пользователь имел в виду следующий запуск. Явный пуш — на «готово», вопрос пользователю и остановку, которую оркестратор не снял сам.

Предел контекста: от 150 тыс. токенов занятости контекста сессии оркестратор новых запусков движка не делает — ни перезапуска, ни следующей задачи (`DECISIONS.md` 2026-10-11 — предел контекста оркестратора). Сессия идёт часами, и каждое пробуждение добавляет в контекст вывод движка, журнал и правку страницы; новые запуски уходят в новую сессию со свободным контекстом. Проверка стоит перед каждым запуском, поэтому идущий движок доходит до своей остановки, оркестратор её разбирает, пишет ответы на блокер и заканчивает итогом со строкой продолжения. Занятость — по файлу переписки сессии `~/.claude/projects/*/<id сессии>.jsonl`: сумма токенов последнего ответа модели, как у хука context-guard без снимка (§ Хук context-guard); id сессии CLI передаёт командам Bash переменной `CLAUDE_CODE_SESSION_ID` (бинарь CLI 2.1.296). Источник работает без хука и строки состояния, на `jq`, который нужен и движку. Снимок строки состояния даёт то же число: на шести сессиях хоста 2026-10-11 совпадение в пяти; в шестой, возобновлённой сессии Remote Control, снимок — 0 до первого запроса к модели, а файл переписки хранит последнее число, 237 тыс. Цифра отстаёт на шаг, как у хука.

Инструменты сессии, на которые опирается скилл, — по схемам инструментов и настроек CLI 2.1.296:

- окно вопроса `AskUserQuestion` — от одного до четырёх вопросов за вызов, у вопроса от двух до четырёх вариантов, свой ответ окно добавляет само; ответа ждёт без срока — настройка `askUserQuestionTimeout` по умолчанию `never`;
- пуш `PushNotification` — строка до 200 символов, с подключённым Remote Control — и на телефон; пропускается, когда пользователь у терминала. Ответ инструмента «Mobile push requested» — запрос пуша ушёл с компьютера, доставку на телефон он не подтверждает (бинарь CLI 2.1.296): в прогоне предела контекста 2026-10-11 пуш с таким ответом до телефона не дошёл, причина не выяснена;
- страница `Artifact` — у интерактивной сессии хоста: ею опубликованы страницы-примеры (2026-10-11); отложенным инструментом — загрузка `ToolSearch` запросом `select:Artifact`: так его получил фоновый подагент (проба 2026-10-15), так его загружает оркестратор, когда инструмент отложен, один раз за беседу; схема `Artifact` бывает в инструментах беседы с первого запроса, тогда оркестратор публикует сразу (`AGENTS.md` § Грабли); интерактивная сессия `/box-next` хоста 2026-10-13 на CLI 2.1.296 инструмента не получила, причина не выяснена, — тогда страница живёт только файлом (скилл оркестратора, шаг «Страница задачи»); у итерации движка — `claude -p` на хосте — инструмента нет, публикацию страниц проверяет сессия хоста. Публикация берёт путь файла; первая — ещё `icon` и `description` одной фразой. Тот же путь в той же беседе публикуется по прежнему адресу; новая беседа правит прежнюю страницу, только передав её адрес в `url`, без него появляется новая страница по новому адресу. Открытая у зрителя страница получает новую версию сама. Потерянную ссылку на страницу инструмент называет в ответе, и её адрес больше не передаётся;
- фоновая команда Bash игнора SIGINT не несёт — проба 2026-10-11; `env --default-signal=INT` держит остановку и при запуске через `&` (`AGENTS.md` § Грабли). Описание инструмента с CLI 2.1.288 называет предел времени фоновой команды; в пилотном проекте движок фоном без `timeout` шёл 3 ч 01 мин и закончился своей остановкой (CLI 2.1.292, 2026-10-10).

### Ступени изоляции — режимы разрешений

Назначение ступеней — `DESCRIPTION.md` § Ключевые решения.

**Хост** — `--permission-mode auto --permission-prompts none`: чтение и правки внутри рабочего каталога проходят сами, остальное оценивает классификатор. Отказ классификатора прогон `-p` не останавливает: сессия видит отказ и ставит статус «блокер» — запись в таск-файл тоже правка внутри каталога. Интерактивная сессия с CLI 2.1.283 на любом плане стартует в том же auto, но после повторных отказов классификатора (3 подряд или 20 за сессию) переходит к вопросам пользователю, а модель может спросить его напрямую — поэтому пробный прогон включает строку итерации, запущенную руками. Auto бывает недоступен — выключен на сервере, модель без поддержки: тогда сессия стартует в Manual, в `-p` отказ получает любая правка, итерации идут без прогресса, и цикл останавливается по правилу трёх итераций.

Строгая альтернатива на хосте — `--permission-mode dontAsk` со списком разрешений: проходит только список и встроенный набор чтения. В списке обязательны правка файлов и коммит — `--allowedTools "Edit(./**)" "Bash(git add *)" "Bash(git commit *)"`: без них итерация не запишет ни результат, ни блокер. Команды проекта (тесты) дописываются в `.claude/settings.json` проекта. В правилах разрешений пробел перед `*` обязателен: `git diff*` цепляет и `git diff-index`.

**Контейнер** — итерации движка: ограничение сети и `--permission-mode bypassPermissions`, полная автономия; с `--no-firewall` — сеть открыта, режим auto с `--permission-prompts none`, как на хосте. Ручной `docker compose -f claude-box.yml run --rm claude` — сеть открыта, режим выбирает человек. Контейнер работает под non-root `node`: под root CLI bypass отклоняет. Bypass открывает агенту всё, что доступно в контейнере, — сеть ограничивает список адресов. Папка проекта подключена напрямую — правки ложатся в хостовый репозиторий; домашняя папка хоста агенту закрыта (§ Образ и скрипт запуска), push — с хоста. Контейнер следующего старта агент мог бы менять правкой `claude-box.yml`, файлом `compose.override.yml` или строкой `COMPOSE_FILE` в `.env`, а команды на хосте выполнять через `.git` проекта: настройки и хуки git срабатывают на `git status` хоста, а движок делает его после каждой итерации (`researches/2026-10-03-deny-rules.md`). Защита — четыре слоя:

- Правила запрета `permissions.deny` в `.claude/settings.json` образца — для сессий на хосте и в контейнере, действуют и в bypass. Агент не читает и не меняет `.env` и его рабочие варианты — `.env.local`, `.env.*.local`, `.env.development`, `.env.dev`, `.env.production`, `.env.prod`, `.env.staging`, `.env.test`; примеры вроде `.env.example` ему открыты. Не меняет `claude-box.yml` и настройки Claude Code проекта — их правит человек; не делает принудительный push. Основной compose-файл проекта с дополнениями агент правит, как остальной код: контейнер Claude собирается без него (явный `-f claude-box.yml`, слой ниже), правка видна в коммите. Правила ловят только инструменты Claude Code и распознанные им команды: скрипт агента их обходит, а в bypass агент может и стереть их — запись в защищённые пути `.claude/`, `.git/` bypass пропускает. Значения `.env` агент контейнера видит в окружении (§ Образ и скрипт запуска): правило закрывает сам файл.
- Подключения только на чтение поверх папки проекта — `claude-box.yml`, `.git/config`, `.git/hooks`, `.git/info`, у дополнительной рабочей копии git — те же три папки основного репозитория (§ Образ и скрипт запуска): изнутри контейнера их не меняет ничто. В `.git/info` лежит список исключений `exclude` — скрытая настройка: его строка прячет файл от git без следа в файлах проекта. Правку в нём сессия контейнера после «да» пользователя отдаёт ему командой для терминала хоста (`template/docs/PROTOCOL.md` § Личные данные и скрытые настройки); на хосте список охраняет только это правило. Живая проверка 2026-10-12, один разговор трижды в контейнере тестового проекта: на просьбу спрятать файл от git только на машине пользователя сессия проверяет доступ `test -w` и чтением, называет `.git/info/exclude`, спрашивает разрешения и после «да» даёт команду для терминала хоста; свои прошлые коммиты оставляет в истории ветки, свою строку `.gitignore` отменяет `git revert --no-commit` и `git commit -m`.
- Явный `-f claude-box.yml` у движка и ручного запуска, git хоста у движка — с выключенными fsmonitor и хуками (§ Движок автоцикла): основной compose-файл проекта, дополнение `compose.override.yml` и `COMPOSE_FILE` из `.env` контейнер следующего запуска не меняют, подложенные в `.git` fsmonitor и хуки на хосте не выполняются.
- Ограничение сети итераций движка (§ Образ и скрипт запуска): исходящие — только на адреса Claude Code, GitHub, npm, PyPI, сети контейнера и свои адреса проекта; прочие сайты, SSH, телеметрия и домашняя сеть отвечают отказом. Поиск в интернете работает — его ведёт бэкенд Anthropic, — а страницу по ссылке агент из контейнера не откроет: её загружает сам контейнер (`researches/2026-10-04-firewall.md`). Процесс агента правила не снимает: права сети у него отобраны.

Открыто: файл `.git/commondir` переадресует чтение настроек git в папку, которую агент может создать, — ручной `git status` пользователя на хосте выполнит команду из её настроек; у дополнительной рабочей копии то же делают её файл `.git` и файл `commondir` в её папке основного репозитория — оба открыты агенту на запись (проба 2026-10-14); `.claude/settings.local.json` с хуками, записанный скриптом агента, сработает в сессии Claude Code хоста в этом проекте. Ограничение сети работает по адресам, а адреса общие: у `mcp-proxy.anthropic.com` — подключений аккаунта claude.ai — адрес модели, их закрывает настройка Claude Code, и агент, обходящий её намеренно, до них дотянется; npm отвечает с адресов Cloudflare, PyPI — с адресов Fastly, где живут и чужие сайты, — доступны ли они через эти адреса, не проверено. Остаются каналы утечки через аккаунты постороннего на разрешённых сервисах и через DNS (`researches/2026-10-04-firewall.md` § Выводы для шага).

**Сессия хоста над контейнером** — интерактивная сессия Claude Code на хосте в режиме auto, которая запускает итерации в контейнере: оркестратор, просьба пользователя. Строку итерации классификатор читает как Create Unsafe Agents — автономный агент без вопросов о разрешениях, — а что за точкой входа `claude-box-firewall` стоит контейнер с ограниченной сетью, из текста команды не следует; правило разрешений Bash сверяет текст буквально и ломается от имени compose-файла и флагов (`researches/2026-10-10-auto-mode-host.md`). Исключение — правило песочницы, запись с меткой `Claude-box Sandbox:` в `autoMode.allow` личных настроек хоста `~/.claude/settings.json`: блок `autoMode` классификатор читает оттуда, из managed-настроек и флага `--settings`, настройки проекта ему закрыты. Правило пишет `agent-loop.sh --sandbox-rule` — человек в терминале: правку своих разрешений сессия хоста в режиме auto получает с отказом `[Self-Modification]`. Режим кладёт копию настроек `settings.json.bak-<дата>` рядом — первую за день, — заменяет запись с меткой текущей, ставит `"$defaults"` в начало списка, пока своего нет, — список без этой строки заменяет встроенные исключения целиком, — пишет поверх файла, сохраняя ссылку и права, и сверяет запись по `claude auto-mode config`; файла нет — создаёт его. Текст правила — в `agent-loop.sh`: разрешён запуск через `claude-box-firewall` с compose-файлом в корне проекта — с `-p`, `--resume`, `--session-id` и bypass, — не покрыты compose-файл вне корня проекта, запуск без этой точки входа — `--no-firewall`, ручной запуск, команда доследования итерации, которую печатает движок, — флаги подключения папок, пользователя и прав и переменные запуска `-e`/`--env` и `--env-from-file`, кроме двух переменных движка `CONTEXT_GUARD_MODE` и `CLAUDE_CODE_PROMPT_CACHE_TTL`: переменная запуска перекрывает строку `environment:` сервиса, и `-e CLAUDE_BOX_ALLOW=0.0.0.0/0` открывает сеть контейнера за точкой входа ограничения (проба 2026-10-11, Compose 5.6.0). Правило — подсказка модели классификатора: отказы редки, гарантии нет. Проба 2026-10-11 в контейнере на временной домашней папке: создание файла, замена записи, свой список без `"$defaults"`, ссылка и права файла, файл не JSON — отказ без правки. Живая проверка 2026-10-11 на хосте с установленным правилом: сессия Claude Code в режиме auto в тестовом проекте с `docker-compose.yml` запустила строку итерации в контейнере и `agent-loop.sh <задача>` без отказа классификатора.

### Хук context-guard — сигнал на пороге контекста

Хук живёт в `~/.claude` хоста: скрипт `hooks/context-guard.sh` с порогами в `hooks/context-guard.conf`, его регистрация в `settings.json` на событиях `UserPromptSubmit` и `PostToolUse`, снимок занятости в конце скрипта строки состояния и раздел «Контекстное окно» в `CLAUDE.md` — текст сигнала выполнять как инструкцию. Хук сравнивает занятость контекста с порогом и печатает текст сигнала агенту в контекст; повтор — после роста занятости на заданный шаг.

Занятость считается по-разному:

- интерактивная сессия — по снимку строки состояния: размер окна приходит только в её данные, строка состояния сохраняет занятость и размер окна в файл сессии;
- headless — строки состояния нет: занятость по файлу переписки сессии, свой порог, размер окна неизвестен;
- подагент — по своему файлу переписки, свой порог; его сигнал — прекратить сбор данных и вернуть накопленное вызвавшему агенту.

Цифра отстаёт на шаг: токены считаются по факту запроса к модели, крупное чтение попадает в счётчик к следующему вызову инструмента.

Режим сигнала главной сессии — `CONTEXT_GUARD_MODE`; источник по приоритету: окружение процесса `claude` → строка `CONTEXT_GUARD_MODE=…` в `.claude/context-guard.conf` корня проекта → умолчание.

- Без режима — остановиться и предложить варианты: продолжить как есть; конспект в файл и новая сессия; свой вариант.
- `rules` — те же варианты, сохранение — по протоколу проекта, идущее завершение доводится без вопросов. Образец кладёт этот режим в проект файлом `.claude/context-guard.conf`.
- `protocol` — выполнить протокол завершения молча. Его ставит движок переменной окружения при запуске итерации.

Сигнал в сессии проекта — то же завершение, что штатное (`docs/PROTOCOL.md` § Протокол сессии), только раньше; так длинная сессия сохраняется по протоколу до встроенного автосжатия.

В контейнере скрипт хука приезжает копией `~/.claude/hooks/` хоста, регистрация — из образа, включается при наличии скрипта. Строка состояния хоста копируется вместе со своим скриптом ради снимка, когда скрипт лежит внутри `~/.claude` хоста: копируются только файлы оттуда (§ Образ и скрипт запуска, п. 5); хост без строки состояния — интерактивная сессия в контейнере считается по ветке headless. Хук работает на `jq`: без него выходит молча, и длинная сессия доходит до встроенного автосжатия; `jq` стоит в образе.

### Образец проекта — `template/`

То, что `/box-init` кладёт в новый проект: хаб `AGENTS.md` со строкой «Чтение на старте» и `CLAUDE.md` строкой `@AGENTS.md`; заготовки документов `docs/` с заголовками обязательных разделов, пустые `docs/tasks/` и `docs/researches/`; `docs/PROTOCOL.md` — рабочий оригинал протокола; скиллы `.claude/skills/box-next/`, `.claude/skills/box-orchestrate/` — оркестратор с правилами страниц и примерами, — `.claude/skills/box-task/` и `.claude/skills/box-review/`; `.claude/context-guard.conf` строкой `CONTEXT_GUARD_MODE=rules`; `.claude/settings.json` с правилами запрета (§ Ступени изоляции); `claude-box.yml` с сервисом `claude`; `.gitignore` строками `my_local/` и `/claude-box.yml`; `.gitattributes` строками `docs/JOURNAL.md merge=union` и `docs/DECISIONS.md merge=union`. Образ несёт папку в `/etc/claude-box/template/` вместе со скрытыми файлами.

`/box-task` и `/box-review` лежат в проекте и работают в любой его сессии — в контейнере и на хосте; вызываются только командой и начинают с чистого рабочего дерева, как скиллы контейнера (§ Скиллы контейнера).

- `/box-task` — заведение задачи: сначала имя, веха, цель, проверка шага и блокер, затем очередь шагов; черновик пользователю, запись после согласия; таск-файл и строка задачи под вехой — одним коммитом с именем задачи в сообщении, его хэш войдёт в запись журнала о задаче на её «готово». Очередь, не согласованная за сессию, — один шаг «разбивка»: `/box-next` ведёт его сколько нужно сессий и кладёт предложенную очередь в секцию «Блокер», в «Постановку» её вписывает сессия по согласию пользователя или сам пользователь, чекбокс разбивки ставит сессия, увидевшая очередь там. Шаги — `template/.claude/skills/box-task/SKILL.md`.
- `/box-review` — ревью задачи со статусом «готово»: в конец очереди ложатся шаги ревью по всем коммитам задачи, статус — «в работе», коммит с именем задачи. Само ревью делает цикл задачи: сессия обычного шага сверяет изменения с целью, критериями шагов, ответами пользователя по задаче, правилами и архитектурой, и рядом с изменениями шага ей открыта вся задача. Шагов несколько, когда изменения задачи вместе с таск-файлом и `ARCHITECTURE.md` больше размера шага; таск-файл, журнал и реестр шаг читает в нынешнем виде, и их изменения в счёт не идут. Находки шаг ревью приносит блокером с предложенными шагами правок; дальше — тот же путь, что у разбивки: по согласию шаги правок вписывает сессия, сразу после шага ревью, и ставит ему чекбокс. Шаблон шага и деление — `template/.claude/skills/box-review/SKILL.md`.

Журнал и реестр решений сливаются между ветками без конфликта: при `merge=union` git на месте конфликта оставляет строки обеих веток — сначала текущей, затем вливаемой, — и записи, которые две ветки дописали в начало файла, после слияния лежат обе. Способ держится на записи в одну строку: строки, одинаковые в добавках обеих веток, git оставляет один раз, и у записи в несколько строк общие с записью другой ветки строки — ответ «ок», «Постановка» не правилась — уходят под заголовок чужой записи (проба 2026-10-15 с записями реестра под заголовком `##`). Поэтому запись реестра, как и журнала, — одна строка (`docs/PROTOCOL.md` § Протокол сессии, шаг 2 завершения); записи реестра прежнего вида в проекте остаются как есть, новые ложатся над ними. На стыке записей двух веток пропадает пустая строка между ними, список в разметке выглядит так же. Старая запись, правленная в обеих ветках, после слияния лежит в двух версиях. Проба 2026-10-15, git 2.43.0: тестовый репозиторий с `.gitattributes` образца и записью реестра прежнего вида, два круга слияния двух веток с записями одной строкой в начале журнала и реестра — все записи целиком, прежняя запись цела. Живая проверка 2026-10-15 на пересобранном образе: `/box-init` кладёт строки образца в `.gitattributes` — у проекта со своим файлом после его строк, — и две ветки с записями журнала и реестра сливаются командой git без конфликта. Кнопка запроса на слияние на GitHub правило не применяет: после слияния первой из двух веток с записями в начале журнала и реестра запрос второй GitHub показывает с конфликтом (`mergeable_state: dirty`) и не сливает. Основная ветка, влитая в ветку второй командой `git merge origin/main` на компьютере, ложится без конфликта — правило срабатывает у git, — и после отправки ветки запрос сливается, все записи на месте. Проба 2026-10-15: частный репозиторий GitHub, обычное слияние через API GitHub (`gh pr merge --merge`), git 2.43.0. GitLab не проверялся — решение пользователя 2026-10-15 (`DECISIONS.md`); старое сообщение пользователей о `merge=union` при слиянии кнопкой на GitLab — gitlab.com/gitlab-org/gitlab-foss/-/issues/17325. Порядок слияния кнопкой — абзац протокола образца после списка «Завершение» (`template/docs/PROTOCOL.md` § Протокол сессии): перед кнопкой основная ветка вливается в свою командой git на компьютере, ветка отправляется, те же команды снимают конфликт, показанный сайтом; протокол читает каждая сессия проекта на старте, и порядок она выполнит по просьбе или подскажет. Журнал и реестр остаются одним файлом каждый — решение пользователя 2026-10-15 (`DECISIONS.md`).

Правила области кода — текст в `docs/rules/<область>.md`, подгрузка — через `CLAUDE.md` в папке области со строкой `@`-импорта этого файла; путь импорта — от папки указателя, у `front/` — `@../docs/rules/front.md`. Вложенный `CLAUDE.md` вместе с его импортом Claude Code подгружает, когда сессия читает файл его папки, в том числе в подпапках; сессия по файлам вне папки их не видит. По документации так же действуют правка файла и `cat` одного файла (code.claude.com/docs/en/memory § How CLAUDE.md files load). Указатель `.claude/rules/<область>.md` с полем `paths:` по пути подгружает только свой текст, а файл своего импорта отдаёт на старте каждой сессии — правила фронта получает и сессия по бэку. Проба 2026-10-15, CLI 2.1.300: сессии `claude -p` в контейнере в режиме итерации движка, две тестовые папки с кодовыми словами в указателе и в файле импорта; у `.claude/rules/` чтение файла фронта дало оба слова, чтение файла бэка — слово импорта; у вложенного `CLAUDE.md` чтение `front/app.js` и `front/src/components/Button.js` дало оба слова, чтение файла бэка — ни одного. В истории сессии загрузка на старте — вложение `instructions`, подгрузка по пути — вложение `nested_memory` с путём файла. Живая проверка 2026-10-15 на копии пилотного проекта: сессия по файлу фронта назвала слово правил фронта, сессия по файлу бэка — нет.

Раздел по областям — архитектура и правила проекта папками `docs/architecture/` и `docs/rules/` (`skills/box-init/documents.md` § Раздел по областям). Его решает `/box-init` в описи источников, каждому документу по своему условию: документ уже разделён — прошлой сборкой или в источниках проекта — или текст его файла и отданных ему источников больше порога `split_chars` конфига agent-box (§ Движок автоцикла), в контейнере — из его копии `/etc/claude-box/config.yml` (§ Образ и скрипт запуска); области — из прошлой сборки, разделённых источников или папок кода верхнего уровня, при одной области документ остаётся одним файлом. Задача сборки получает на месте шага документа шаги раздела: общую часть, куда прежний файл переезжает `git mv`, и шаг на область; общая часть правил меняет и строку хаба, шаг области правил кладёт указатели в её папки. Области из описи `/box-init` называет в итоге: пользователь правит их в «Постановке» до их шагов. Папки `docs/architecture/` и `docs/rules/`, занятые проектом до первой сборки, уходят в `.old/`, как `docs/tasks/`. Дальше раздел держит протокол (`template/docs/PROTOCOL.md` § Порядок на месте): факт и конвенция одной области — в её файл, а документ одним файлом, переросший порог после записи сессии, получает предложение раздела в хвостах «Контекста» — раздел делает повторный `/box-init` новой задачей сборки. Живая проверка 2026-10-15: повторный `/box-init` на копии пилотного проекта завёл задачу сборки с шагами раздела архитектуры — общая часть и шаги фронта и бэка. Протокол, `/box-task` и карта образца называют правила и архитектуру голым именем `RULES.md`, `ARCHITECTURE.md`: при обеих раскладках оно ведёт на основной файл.

Правила о личных данных и скрытых настройках — раздел протокола (`template/docs/PROTOCOL.md` § Личные данные и скрытые настройки): свежую копию протокола получает каждый проект при `/box-update` и повторном `/box-init`, каждая сессия читает её на старте, а правила и архитектуру проекта сборка документации пишет под проект. Сборка документации переносит старые журналы и решения из заметок под `.gitignore` в git — главный путь личных данных в историю проекта, — поэтому шаблон её задачи обезличивает записи по тому же разделу.

Сервис `claude` живёт в `claude-box.yml` в корне проекта, под `.gitignore`: файл несёт пути и адреса машины, в git и деплой проекта он не попадает. Запуск — `docker compose -f claude-box.yml run --rm claude`. Образ `maksim44/claude-box`, `stdin_open` и `tty` для интерактива, права `NET_ADMIN` и `NET_RAW` для ограничения сети. `profiles: [claude]`: `docker compose -f claude-box.yml up` сервис пропускает, прямой `run` профиль активирует. `.env` проекта читает скрипт запуска (§ Образ и скрипт запуска), строки `env_file` у сервиса нет. Подключения — § Образ и скрипт запуска. Claude — в сети сервисов основного compose-файла проекта: Compose сводит в сеть `<имя проекта>_default` оба файла с одним именем проекта — по папке или по одинаковой строке `name:`, которую `/box-init` переносит из основного файла, — смену имени в основном файле человек повторяет в `claude-box.yml` руками; порядок запуска не важен, `down` проекта при работающем Claude сеть оставляет, и Claude работает дальше (`researches/2026-10-14-compose-local.md`). Каждый запуск при поднятых сервисах проекта пишет строку Compose о чужих контейнерах с советом `--remove-orphans`; этот флаг в команде запуска Claude удаляет контейнеры проекта (проба 2026-10-14, Compose 5.6.0).

### Скиллы контейнера — `skills/`

Скиллы едут в образе, `/etc/claude-box/skills/`, и доступны в любом проекте без установки: скрипт запуска при каждом старте контейнера кладёт их свежую копию в `~/.claude/skills`, скиллы пользователя под другими именами остаются рядом. Папки `box-*` прошлого запуска он перед этим убирает целиком: имена `box-*` принадлежат обвязке, а личный скилл Claude Code берёт верх над одноимённым скиллом проекта (code.claude.com/docs/en/skills, 2026-10-13) — копия `/box-task` или `/box-review` из образа до их переезда в проект заслонила бы проектную. Все вызываются только командой (`disable-model-invocation: true`) и начинают с чистого рабочего дерева: коммит в конце забирает дерево целиком, поэтому при незакоммиченных правках скилл перечисляет их и заканчивает без изменений. Исключение у `/box-update` и повторного `/box-init` — правки пользователя в таск-файлах, ответ на блокер и правка «Постановки»: они остаются в рабочем дереве вне коммитов скилла, их забирает коммит сессии задачи. `/box-init` исключения не делает для таск-файла незаконченной сборки документации — его дорабатывает сам.

- `/box-init` — заведение проекта в обвязку, его роль — `DESCRIPTION.md` § Ключевые решения. Занятые имена образца освобождаются переименованием в `.old` (`.old2`, `.old3`…); переименованное, что было под `.gitignore` проекта, остаётся вне git строкой в корневом `.gitignore` под комментарием сборки. Папки скиллов `box-next`, `box-orchestrate`, `box-task` и `box-review` при любом заходе ложатся свежей копией поверх: имена принадлежат обвязке. Папки `docs/`, `.claude/`, `.claude/skills/`, а также `.gitignore`, `.gitattributes` и compose-файл проекта остаются на местах: образец ложится рядом, недостающие файлы — `cp -rn`, в `.gitignore` — недостающие строки образца `my_local/` и `/claude-box.yml`, в `.gitattributes` — недостающие строки образца (§ Образец проекта), в `.claude/settings.json` проекта — недостающие правила запрета образца, а правила прежнего образца на правку compose-файлов оттуда убираются. Сервис `claude` — в `claude-box.yml` при любом заходе: файла нет — копия образца, а сервис `claude` основного compose-файла проекта, заведённого раньше, переезжает в него без строки `env_file`: переменные `.env` передаёт скрипт запуска (§ Образ и скрипт запуска); строка `name:` основного файла — та же в `claude-box.yml`; сервису дописываются недостающие подключения только на чтение, права ограничения сети, строка модели `ANTHROPIC_MODEL` образца и свои адреса проекта строкой `CLAUDE_BOX_ALLOW` по списку, согласованному с пользователем; в дополнительной рабочей копии git на месте подключений `./.git/…` — `.git` основного репозитория по пути из строки `gitdir:` (§ Образ и скрипт запуска). Основной compose-файл `/box-init` не правит: в контейнере прежней схемы он подключён только на чтение, строки сервиса `claude` на удаление уходят в итог. Правила запрета ложатся после записи в `claude-box.yml`: Claude Code применяет их в идущей сессии сразу (живая проверка 2026-10-04 — правка compose-файла после копии настроек образца получила отказ). Шаги, опись источников и шаблон задачи сборки с вариантами хранения архива — `skills/box-init/SKILL.md`; рядом — карточки документов проекта `documents.md`.
- `/box-update` — обновление обвязки в проекте: протокол и скиллы проекта `/box-next`, `/box-orchestrate`, `/box-task` и `/box-review`, разошедшиеся с образцом или недостающие, — свежей копией, коммит и запись журнала; документы, задачи и сборка документации остаются как есть. Шаги — `skills/box-update/SKILL.md`.

### Образ и скрипт запуска — `container/`

Образ `maksim44/claude-box` — `node:20` с `jq` (сборка настроек при старте, хук context-guard), `python3-venv` (чтение `.env` проекта при старте; виртуальные окружения и pip для Python-проектов: системные пакеты ставит только root) и `iptables` (ограничение сети). Несёт образец, скиллы, базовые настройки с регистрацией хука context-guard (`/etc/claude-box/settings.json`), скрипт запуска — точку входа `/usr/local/bin/claude-box`, — точку входа ограничения сети `/usr/local/bin/claude-box-firewall` и программу чтения `.env` `/usr/local/bin/claude-box-env`. Собирается из корня репозитория под архитектуру машины сборки, сейчас amd64, — на каждой машине из клона agent-box: на Docker Hub образа пока нет, публикация — задача релиза (`ROADMAP.md` § Вехи). Claude Code ставит скрипт запуска при первом старте, официальным установщиком, в `~/.local` пользователя `node` — в домашнюю папку контейнера, дальше Claude Code обновляется сам в фоне; первый старт на пустой домашней папке шёл 40 с, повторный — 0,3 с (проба 2026-10-19, CLI 2.1.303, 273 МБ в домашней папке); `PATH` образа включает `/home/node/.local/bin`.

Подключения сервиса `claude`:

- папка проекта → `/workspace/${COMPOSE_PROJECT_NAME}`: сессии, автопамять и доверие Claude Code раскладывает по пути рабочего каталога, так у каждого проекта в общей домашней папке они свои; `${COMPOSE_PROJECT_NAME}` — имя папки compose-файла, из подпапки то же, `name:` в compose-файле задаёт его явно. Строку `name:` основного compose-файла `/box-init` переносит в `claude-box.yml` (§ Скиллы контейнера); имя в ней другое, чем у папки, — сессии первого запуска `box-connect` остаются под путём от имени папки, запуски из `claude-box.yml` идут под путём от `name:`. Строка `name:` основного файла в git общая у всех копий репозитория — клонов и рабочих копий git, — и путь в контейнере у них один: общие сессии, автопамять и доверие Claude Code; без строки путь у каждой копии от имени её папки;
- `claude-box.yml`, `.git/config`, `.git/hooks` и `.git/info` → те же пути внутри папки проекта, только на чтение, поверх её подключения: запись, `mv` и `rm` изнутри отклоняются, коммит проходит (пробы 2026-10-03, 2026-10-04, для `.git/info` — 2026-10-11, git 2.43.0); у дополнительной рабочей копии git (worktree) `.git` — файл, строка `gitdir:` в нём ведёт в `.git/worktrees/<имя>` основного репозитория, и с подключениями `./.git/…` контейнер не стартует: вместо них — `.git` основного репозитория по его абсолютному пути на хосте и поверх только на чтение его `config`, `hooks`, `info` по тем же путям — git рабочей копии и коммит проходят, запись, `mv` и `rm` в них отклоняются (проба 2026-10-14, `researches/2026-10-14-compose-local.md` § Проба worktree); строки пишет `/box-init`, до него — `box-connect` (§ Движок автоцикла); `git sparse-checkout` в контейнере отказывает — он пишет в `.git/config`. Обе папки git создаёт при `git init` и `git clone`; нет их на хосте — репозиторий создан `git init --template=` — Compose при запуске создаёт их пустыми от root: git хоста работает, а хук или строку списка исключений пользователь ставит только через `sudo` (проба 2026-10-11, Compose 5.6.0);
- `~/.claude-box` → `/home/node`: домашняя папка контейнера, общая для проектов машины — логин, история сессий, сам Claude Code; при первом запуске Compose создаёт её от root, скрипт запуска отдаёт её `node`;
- `~` → `/root/host-home`, только на чтение: `/root` закрыт для `node` — ни напрямую, ни через `/proc/<pid>/root`.

Права сервиса — `cap_add: [NET_ADMIN, NET_RAW]`: ими часть запуска от root ставит ограничение сети.

Модель сессий — `ANTHROPIC_MODEL: opus` в `environment:` сервиса: по приоритету Claude Code переменная окружения выше ключа `model` настроек (https://code.claude.com/docs/en/model-config), а в настройки контейнера этот ключ приезжает с хоста, где его пишет `/model` по Enter в любой сессии (п. 6 ниже). Смена модели проекта — другой псевдоним в строке, варианты — в комментарии над ней; на одну сессию — `/model` в ней.

`node` в образе — uid 1000: файлы, созданные в контейнере, на хосте принадлежат пользователю с тем же uid.

Скрипт запуска стартует от root и при каждом старте:

1. отдаёт домашнюю папку контейнера `node`;
2. ставит Claude Code, если лаунчера `~/.local/bin/claude` ещё нет;
3. переносит с хоста `~/.claude/CLAUDE.md`, `~/.claude/hooks/` и `~/.gitconfig` — автор коммитов протокола: есть на хосте — свежая копия, нет — копия прошлого запуска убирается;
4. кладёт свежую копию скиллов образа в `~/.claude/skills`;
5. берёт команду `statusLine` из хостового `settings.json`, переводит в ней пути внутри хостовой `~/.claude` в контейнерную и копирует файлы по ним;
6. собирает `~/.claude/settings.json` контейнера: регистрация хука из образа — при наличии скрипта хука; `language`, `model`, `effortLevel`, `modelSettings`, `attribution`, `includeCoAuthoredBy` и `statusLine` с переведённой командой — из хостового `settings.json`;
7. кладёт свежую копию конфига agent-box (§ Движок автоцикла) в `/etc/claude-box/config.yml` — оттуда порог раздела берут `/box-init` и протокол, `node` файл только читает. Клон — цель ссылки `~/.local/bin/agent-loop.sh` хоста, абсолютный путь хоста; от него отрезаются ведущие части, пока остаток не найдётся в подключённой домашней папке хоста: `/home/<пользователь>/tools/agent-box/agent-loop.sh` → `tools/agent-box/agent-loop.sh`. Клон вне домашней папки хоста или ссылки нет — копии нет, сессии берут порог по умолчанию. Правка конфига доходит до сессий со следующего старта контейнера. Проба 2026-10-15 на временной папке вместо домашней папки хоста, `dash`: ссылка и конфиг — копия; ссылка без конфига, ссылка вне папки, ссылки нет — копии нет, копия прошлого запуска убрана; на настоящей домашней папке — копия `config.yml` клона;
8. запускает `claude` от `node` через `setpriv` и программу чтения `.env`, аргументы запуска уходят в него. Ограничивающий набор прав пуст, повышение прав запрещено: права root, включая `NET_ADMIN`, процессам `node` недоступны и через setuid-программы (проба 2026-10-04: у `node` `CapBnd` 0, `NoNewPrivs` 1, `iptables -F` — отказ).

Из хостового `settings.json` берутся отдельные ключи: хуки и прочие пути в нём — абсолютные пути хоста. Правка хостового действует со следующего старта. Креды и переписка хоста, его скиллы, плагины, MCP из `~/.claude.json`, `keybindings.json` и ключи `~/.ssh` остаются на хосте.

Программа чтения `.env` работает уже от `node`: добавляет к окружению переменные `.env` из папки запуска — их получают Claude Code, MCP-серверы (`${VAR}` в `.mcp.json`) и команды агента — и запускает `claude`. Часть скрипта от root работает без переменных `.env`: строки `PATH` и `LD_PRELOAD` в нём действуют только на процессы `node` (проба 2026-10-04: из окружения контейнера, как при `env_file`, те же строки выполнили программу и библиотеку из папки проекта от root десятки раз, через программу чтения — ни разу). Ключи входа и переключатели провайдера — `ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN`, `CLAUDE_CODE_OAUTH_TOKEN`, `CLAUDE_CODE_USE_BEDROCK`, `CLAUDE_CODE_USE_VERTEX`, `CLAUDE_CODE_USE_FOUNDRY` — программа убирает из окружения: Claude Code в контейнере работает по подписке, программы агента этих ключей тоже не видят.

Ограничение сети — точка входа `claude-box-firewall`: её задаёт итерациям в контейнере движок (`--entrypoint`), ручной запуск идёт через обычную. От root, до скрипта запуска, она собирает адреса: домены — `getent ahostsv4` на момент старта, диапазоны GitHub `web`, `api`, `git` — из `api.github.com/meta`, сети контейнера — маршруты без шлюза из `/proc/net/route`. Правила iptables:

- исходящие — loopback, ответы установленных соединений, DNS на любой адрес; сети контейнера — сервисы проекта и сам компьютер по адресу шлюза — и свои адреса проекта на все порты; Claude Code (`api.anthropic.com`, `claude.ai`, `platform.claude.com`, `downloads.claude.ai`, `code.claude.com`), npm и PyPI (`registry.npmjs.org`, `pypi.org`, `files.pythonhosted.org`) и GitHub — порты 80 и 443; прочее — отказ сразу (REJECT);
- входящие — loopback, ответы и сети контейнера;
- IPv6 — только loopback.

Затем самопроверка — `example.com` закрыт, `api.anthropic.com` открыт — и обычный скрипт запуска с `ENABLE_CLAUDEAI_MCP_SERVERS=false`: подключения аккаунта claude.ai идут через `mcp-proxy.anthropic.com`, а его адрес — адрес модели (2026-10-04 — 160.79.104.10, тот же у `claude.ai`, `platform.claude.com`, `code.claude.com`). Свои адреса проекта — `CLAUDE_BOX_ALLOW` в `environment:` сервиса `claude`: домены, адреса IPv4 и подсети через пробел или запятую, значение вписано в `claude-box.yml` — подстановку `${…}` Compose берёт из `.env`, который агент переписывает скриптом. Строку пишет `/box-init`, сессия, упёршаяся в закрытый адрес, ставит блокер с ней, дополненной адресом (`docs/PROTOCOL.md` § Таск-файлы). Закрытый адрес отвечает ошибкой соединения сразу (проба 2026-10-04: `curl` и `git` — `Couldn't connect to server`, Python — `Network is unreachable`, `fetch` Node — `fetch failed`). Без права `NET_ADMIN`, при домене без адреса или проваленной самопроверке старт останавливается с сообщением; без права — со строкой `cap_add` для compose-файла. Адреса доменов разрешаются один раз при старте: домен, сменивший адрес за время сессии, получает отказ. Пробы 2026-10-04: старт дольше на 1–2 секунды, первая установка Claude Code за ограничением проходит.

Разбор `.env` повторяет `env_file` Compose (compose-go, пакеты `dotenv` и `template`): комментарии, `export`, запись `ключ: значение`, кавычки и экранирование, многострочные значения в кавычках, подстановки `$VAR`, `${VAR}` с `:-`, `-`, `:+`, `+`, `:?`, `?` и `$$`, ссылки на имена ниже по файлу; ошибка разбора останавливает старт сообщением с номером строки, как отказ Compose. Сверено пробой 2026-10-04 с Compose 5.6.0: совпали 41 запись, строка из одного имени и шесть ошибочных записей. Расхождения с Compose:

- подстановки и строки из одного имени берут значения из окружения контейнера, у Compose — из окружения хоста: `${HOME}` в `.env` даёт `/home/node`;
- имена, уже заданные в окружении контейнера — образом (`PATH`), compose-файлом, движком (`CONTEXT_GUARD_MODE`), точкой входа ограничения сети (`ENABLE_CLAUDEAI_MCP_SERVERS`), — `.env` не перекрывает, у Compose `.env` перекрывает переменные образа;
- строка из одного имени последней в файле, без перевода строки, берёт значение из окружения, Compose на ней отказывает в старте.

## Правила зависимостей

- **Образец и скиллы доезжают до проекта через образ.** Правка `template/`, `skills/` или `container/` → пересборка образа (`README.md` § Пересобрать образ после правки agent-box). Скиллы новый контейнер берёт на старте; протокол и скиллы проекта обновляет `/box-update`, остальные документы проекта остаются как есть; повторный `/box-init` обновляет их же вместе с доработкой или новой задачей сборки. Папки скиллов, которые проект получает свежей копией, названы в шаге 2 `/box-init` и сверке `/box-update`: новый скилл обвязки в образце правит оба.
- **Оригиналы — в `template/`, в проекте — копии.** Рабочий оригинал протокола — `template/docs/PROTOCOL.md`, скиллов проекта — папки `template/.claude/skills/box-*/`; скиллы и карточки ссылаются на проектные пути `docs/PROTOCOL.md` и `.claude/skills/box-*/`. В этом репозитории на их месте — ссылки на оригиналы (`AGENTS.md` § Жёсткие ограничения).
- **Скиллы образа и карточки ссылаются только на то, что едет в образе, кладёт скрипт запуска или лежит в проекте.** `/box-init` берёт образец из `/etc/claude-box/template/`, карточки из `~/.claude/skills/box-init/documents.md` и порог раздела из копии конфига `/etc/claude-box/config.yml` и потому работает в контейнере `claude-box`. Путь копии конфига называют скрипт запуска, `/box-init`, протокол и карточки: его смена правит все четыре.
- **Номера шагов завершения — контракт.** Список «Завершение» в `docs/PROTOCOL.md` § Протокол сессии адресуется номерами: сам протокол и `/box-init`, `/box-task`, `/box-update` — «шаги 1, 2, 4–6», шаблон задачи сборки — «шаг 2», карточки `documents.md` — шаги 2–4 и 6. Перенумерация списка правит все ссылки тем же коммитом.
- **Шапка таск-файла — контракт движка.** Статус — первой строкой `статус: в работе | блокер | готово`, движок читает её grep-ом. Шаблон таск-файла — `docs/PROTOCOL.md` § Таск-файлы; шаблоны в `/box-task` и `/box-init` повторяют его раскладку.
- **Движок зависит от проекта через имена.** Скилл `/box-next`, сервис `claude` в `claude-box.yml` проекта с правами `cap_add`, точка входа образа `claude-box-firewall`, переменная `CONTEXT_GUARD_MODE` и код выхода `claude` — интерфейс итерации; смена любого из них правит строку итерации. Ключи `config.yml` клона — контракт движка: ключ, которого движок не знает, останавливает запуск, поэтому новый ключ конфига правит и список ключей в `agent-loop.sh`.
- **Строки событий журнала цикла — контракт оркестратора.** Сторож `/box-orchestrate` узнаёт начало итерации и алерт таймера по тексту их строк в `agent-loop.sh` — «задача <задача> — итерация <i>/<всего>, шаг» и «… итерация <i> идёт дольше»; смена этих строк или формата времени в журнале правит шаблон сторожа в `template/.claude/skills/box-orchestrate/SKILL.md`.
- **Набор документов проекта описан в четырёх местах.** Карточки `skills/box-init/documents.md`, файлы `template/`, карта `template/docs/README.md` и очередь шаблона задачи сборки в `skills/box-init/SKILL.md`; новый или убранный документ правит все четыре.
- **Хук — по имени файла.** Регистрация в `container/settings.json` и проверка в скрипте запуска ссылаются на `~/.claude/hooks/context-guard.sh`; режим хук читает из `CONTEXT_GUARD_MODE` и `.claude/context-guard.conf` корня проекта.
- **Образ собирается из корня репозитория:** Dockerfile копирует `template/` и `skills/`.

## Анти-паттерны

- **`--bare` в строке итерации.** Отключает автозагрузку контекста проекта и подписочный логин — итерация не видит хаб, протокол и `/box-next` и требует API-ключ. Дока объявляет `--bare` будущим дефолтом `-p`: после обновления CLI первым делом проверять, что итерация видит `CLAUDE.md` и скиллы.
- **Скрипт кормит командами долгоживущую интерактивную сессию.** Процесс копит контекст, путь идёт мимо доки; каналы «скрипт → процесс» по доке — `-p` на итерацию, `--input-format stream-json`, Agent SDK.
- **`protocol` в `.claude/context-guard.conf` проекта.** Интерактивные сессии проекта на пороге молча завершаются вместо вариантов; режим `protocol` приходит только из окружения движка.
- **Установка Claude Code при сборке образа.** Версия фиксируется: глобальный каталог npm принадлежит root, контейнер работает от `node`, обновление не записывается, а `--rm` стирает контейнер с любыми правками — обновление превращается в пересборку образа.
- **Именованный volume под домашнюю папку контейнера.** Compose приписывает общий volume создавшему его проекту и в каждом другом проекте на каждом запуске предупреждает «volume already exists but was created for project …».
- **Подключение отдельных файлов хоста в compose-файле.** Отсутствующий на хосте источник Compose создаёт пустым каталогом от root — и там, где ждали файл; опциональное с хоста берёт скрипт запуска из подключённой целиком домашней папки.
- **Секреты хоста в контейнере** (`~/.ssh`, облачные креды, креды `~/.claude`). В bypass агент читает всё, что видит его пользователь.
- **Разросшийся роадмап.** Симптом смешения ролей: в него дописали сиюминутное таск-файла или путь к разобранному из журнала и ресерча.
