# Архитектура

## Устройство системы

Продукт — три папки репозитория и скрипт: образец проекта `template/`, скиллы контейнера `skills/`, образ `container/`, который несёт образец и скиллы, и движок автоцикла `agent-loop.sh` в корне. В проект обвязка попадает через `/box-init` в контейнере: заготовки из образца, скилл `/box-next` и протокол ложатся в репозиторий проекта и дальше живут в его git. Вне репозитория — хук context-guard в `~/.claude` хоста. Движок работает на хосте из клона agent-box (§ Движок автоцикла); готова хостовая ступень, остальное — `ROADMAP.md`. Набор документов проекта, их границы, дерево и слои чтения — `skills/box-init/documents.md`.

### Круг задачи

1. `/box-task` заводит задачу: таск-файл со статусом «в работе» и строка задачи под вехой в `ROADMAP.md`. Очередь, не согласованная за сессию генератора, — первый шаг задачи «разбивка»: её предложение приходит блокером.
2. Пробный прогон руками: `/box-next <задача>` в интерактивной сессии проверяет шаг и завершение; одна-две итерации строкой движка, запущенной руками, проверяют работу без присмотра — блокер через файл, отказ в разрешениях, коммит и код выхода.
3. Движок захватывает lock репозитория и крутит итерации, пока статус в шапке таск-файла «в работе».
4. Итерация — свежая сессия `/box-next`: один шаг очереди и завершение по `docs/PROTOCOL.md` § Протокол сессии. Сигнал context-guard запускает то же завершение раньше; начатый шаг продолжает следующая итерация от точки в «Контексте».
5. Движок разбирает итог итерации и останавливается на блокере, «готово», падении или трёх итерациях без прогресса (§ Движок автоцикла); пользователь вмешивается по уведомлению.
6. «Готово» — пользователь проверяет задачу по журналу и хвостам «Контекста»: замечания — новые шаги в очередь и статус «в работе»; принято — чекбокс строке задачи в `ROADMAP.md`. Закрытие вехи — `docs/PROTOCOL.md` § Протокол закрытия вехи.

Тот же круг идёт руками: каждая итерация — `/box-next <задача>` в интерактивной сессии.

Состояние между сессиями — таск-файл задачи: итерация стартует со свежим контекстом и берёт из него шаг и точку продолжения, движок читает его первую строку. Правила таск-файла — `docs/PROTOCOL.md` § Таск-файлы.

### Итерация — `/box-next`

Скилл лежит в проекте, `.claude/skills/box-next/`, копией образца и уезжает в git вместе с проектом; имя задачи приходит аргументом. Вызов без аргумента — в интерактиве: скилл спрашивает пользователя, какую задачу взять, из задач первой незакрытой вехи роадмапа. Три действия: открыть таск-файл и сверить статус (не «в работе» — назвать его и закончить без правок), сделать первый незакрытый шаг очереди, завершить сессию по протоколу. Правила таск-файла, статусов и завершения сессия берёт из `docs/PROTOCOL.md`, который приходит автозагрузкой хаба. `disable-model-invocation: true` — скилл вызывается только командой. Имя `box-next` принадлежит обвязке: скиллы проекта под другими именами, включая `next` прежней обвязки, остаются на своих местах.

Итерация автоцикла — `claude -p "/box-next <задача>"`. Headless-запуск — тот же агент с тем же контекстом проекта: импорты `CLAUDE.md`, скиллы, хуки, MCP; скилл разворачивается прямо из промпта. В headless инструмент вопроса пользователю (`AskUserQuestion`) получает отказ в любом режиме разрешений, поэтому спросить пользователя итерация может только статусом «блокер» с секцией «Блокер» в таск-файле. В интерактиве `/box-next` — одна команда на сессию, и без движка.

### Движок автоцикла

Шелл-скрипт `agent-loop.sh <задача>` в корне agent-box, один на все проекты машины; работает на хосте для обеих ступеней изоляции, запускается из папки проекта. Нужны `git`, `jq` и `claude` хоста, для уведомлений — `curl`. Цикл: захват lock-файла репозитория → статус из шапки `docs/tasks/<задача>.md` → фиксация HEAD → итерация свежей сессией под таймером → разбор итога: код выхода, чистота рабочего дерева, статус, дифф итерации → пауза → снова. Lock-файл `.git/agent-loop.lock` лежит вне рабочего дерева и несёт имя задачи и PID цикла; второй запуск движка в том же репозитории сразу завершается с именем задачи идущего цикла. Lock процесса, которого уже нет, — после `kill -9` или сбоя питания — следующий запуск перехватывает.

Код выхода движка: 0 — «готово» или лимит итераций; 1 — остановка, ждущая пользователя: блокер, провал итерации, правки без коммита, итерации без прогресса, статус вне протокола; 2 — движок не запустился: второй цикл в репозитории, нет таск-файла или нужной команды; 130 — Ctrl+C.

Строка итерации на хосте:

```bash
CONTEXT_GUARD_MODE=protocol claude -p "/box-next <задача>" --session-id <uuid> --permission-mode auto \
  --permission-prompts none --output-format json --max-turns 200
```

В контейнере — тот же запуск через сервис проекта: `docker compose run --rm -e CONTEXT_GUARD_MODE=protocol claude -p "/box-next <задача>" …`; флаги после имени сервиса уходят в Claude Code, код выхода возвращается движку.

Флаги и поведение CLI, на которые опирается строка; сверено с докой и пробами на CLI 2.1.287 — `researches/2026-08-31-audit-and-headless.md` § Часть 4:

- `/box-next <задача>` в промпте `-p` раскрывается до запуска и при `disable-model-invocation: true`: тело скилла с подставленным именем задачи приходит первым сообщением сессии.
- `-p` стартует в Manual; сессия без загрузки флагов функций с сервера — сторонний провайдер, выключенная телеметрия — с CLI 2.1.285 стартует в auto. Режим разрешений передаётся явно при каждом запуске (§ Ступени изоляции).
- `--permission-prompts none` (CLI ≥ 2.1.259): запрос, который ждал бы ответа человека, получает отказ с указанием его не повторять, инструменты вопроса пользователю убраны, прогон продолжается — отказ ведёт сессию к блокеру.
- `--output-format json` — один JSON-объект на stdout: `session_id`, `is_error`, `subtype`, `terminal_reason`, `num_turns`, `total_cost_usd`, `permission_denials`; итоговый текст `result` — у дошедшей до ответа сессии, текст ошибки — в `result` или массиве `errors`. Исходы по пробам:
  - штатное завершение — код 0, `is_error: false`, `subtype: success`, `terminal_reason: completed`;
  - упор в `--max-turns` — код 1, `is_error: true`, `subtype: error_max_turns`, `terminal_reason: max_turns`, `result` нет;
  - ошибка API (проба — нет логина) — код 1, `is_error: true` при `subtype: success`, `terminal_reason: api_error`, ошибка в `result`;
  - SIGINT — ход обрывается, итог записан: код 0 при `is_error: true`, `subtype: error_during_execution`, `terminal_reason: aborted_streaming`;
  - SIGTERM — ход обрывается без итога: код 143, stdout пуст;
  - неверный флаг — код 1, stdout пуст, ошибка в stderr.
- `--session-id <uuid>` — идентификатор сессии задаёт движок до запуска: алерт таймера называет сессию, пока она идёт, и сообщение о провале без JSON — тоже; в итоге JSON `session_id` тот же (проба 2026-10-01).
- `--max-turns 200` — потолок ходов итерации против зацикливания, только для `-p`; стартовое значение с запасом над максимумом замера (`researches/2026-08-31-audit-and-headless.md` § Часть 3), пересматривается по обкатке. Окно контекста итерацию не ограничивает: у предела автосжатие продолжает сессию, а context-guard останавливает её только через послушание модели.
- Лимит подписки общий для всех поверхностей — пятичасовое окно и недельное; headless-прогон при упоре в лимит падает.
- Живое наблюдение — `--output-format stream-json --verbose --include-partial-messages` с `tee` в лог.

Разбор итога итерации:

- провал итерации — ненулевой код выхода, `is_error: true` или stdout без JSON: падение, `--max-turns`, лимит подписки, SIGINT итерации — стоп с уведомлением: `session_id`, `terminal_reason`, текст ошибки из `result` или `errors`; без JSON — код выхода и хвост stderr. Сессия умерла до шагов завершения, в рабочем дереве могут лежать правки, которых «Контекст» не знает; доследование руками — `claude --resume <id>` из любого каталога. SIGINT итерации даёт код 0 при `is_error: true`, и правило по `is_error` останавливает движок вместе с ней: вмешательство пользователя по алерту таймера кончает цикл;
- код 0 и незакоммиченные правки в дереве — та же остановка: сессия не дошла до коммита;
- статус «блокер» — стоп, секция «Блокер» в терминал и уведомлением; пользователь отвечает правкой таск-файла, возвращает «в работе» и запускает движок снова;
- статус «готово» — стоп, уведомление с именем задачи;
- три итерации подряд без прогресса — стоп с уведомлением. Прогресс — закрыт чекбокс очереди либо дифф итерации затронул что-то кроме служебных файлов завершения: таск-файла, `JOURNAL.md`, `DECISIONS.md`. Правило — алерт, не приговор: шаг длиной в несколько сессий чтения или дебага пишет только в «Контекст» и остановит цикл при живой работе, а три сессии с одной граблей в `AGENTS.md` пройдут как прогресс; в обоих случаях пользователь смотрит журнал и перезапускает движок. Три — стартовое значение, пересматривается по обкатке;
- лимит — 10 итераций за запуск; Ctrl+C;
- иначе — пауза 10 секунд и следующая итерация. Пауза — окно чистой остановки Ctrl+C: прошлая итерация закоммичена, следующая не начата; Ctrl+C в терминале доходит и до идущей сессии `claude` и обрывает её ход.

Таймер итерации — алерт без остановки: порог превышен → уведомление с `session_id` и длительностью, итерация продолжается; вмешательство — лог, `claude --resume`, SIGINT. Порог — максимум длительностей отрезков «промпт → завершение» по таймстемпам jsonl-журналов сессий с запасом; до замера — час.

Уведомления — Telegram Bot API `sendMessage` через `curl`. Токен и chat_id — строки `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` в `~/.config/agent-loop.env` хоста, вне репозиториев; движок берёт из файла только их, в окружение сессий они не попадают. chat_id, которого в файле нет, движок при старте берёт из последнего сообщения боту (`getUpdates`) и дописывает в файл; Telegram хранит входящие бота 24 часа — годится только свежее сообщение. Уведомление уходит на каждой остановке цикла и на алерте таймера: текст терминала с именем папки проекта впереди — движок один на все проекты машины; отказ запуска (код 2) остаётся в терминале — пользователь в этот момент у терминала. Текст режется до 4000 символов — предел сообщения Telegram 4096. Токен уходит в `curl` через stdin и в списке процессов не виден. Сбой отправки — строка в терминале с ответом Telegram, код выхода остановки прежний; неверный токен Telegram отклоняет ответом «Not Found». Без токена или chat_id движок стартует со строкой «уведомления выключены» и причиной и сообщает только в терминал.

### Ступени изоляции — режимы разрешений

Назначение ступеней — `DESCRIPTION.md` § Ключевые решения.

**Хост** — `--permission-mode auto --permission-prompts none`: чтение и правки внутри рабочего каталога проходят сами, остальное оценивает классификатор. Отказ классификатора прогон `-p` не останавливает: сессия видит отказ и ставит статус «блокер» — запись в таск-файл тоже правка внутри каталога. Интерактивная сессия с CLI 2.1.283 на любом плане стартует в том же auto, но после повторных отказов классификатора (3 подряд или 20 за сессию) переходит к вопросам пользователю, а модель может спросить его напрямую — поэтому пробный прогон включает строку итерации, запущенную руками. Auto бывает недоступен — выключен на сервере, модель без поддержки: тогда сессия стартует в Manual, в `-p` отказ получает любая правка, итерации идут без прогресса, и цикл останавливается по правилу трёх итераций.

Строгая альтернатива на хосте — `--permission-mode dontAsk` со списком разрешений: проходит только список и встроенный набор чтения. В списке обязательны правка файлов и коммит — `--allowedTools "Edit(./**)" "Bash(git add *)" "Bash(git commit *)"`: без них итерация не запишет ни результат, ни блокер. Команды проекта (тесты) дописываются в `.claude/settings.json` проекта. В правилах разрешений пробел перед `*` обязателен: `git diff*` цепляет и `git diff-index`.

**Контейнер** — `--dangerously-skip-permissions`, полная автономия. Контейнер работает под non-root `node`: под root CLI флаг отклоняет. Deny-правила действуют и в bypass — неприкасаемое (`.env`, `compose.yml`, `git push --force`) закрывается ими. Bypass открывает агенту всю сеть контейнера. Папка проекта подключена напрямую — правки ложатся в хостовый репозиторий; домашняя папка хоста агенту закрыта (§ Образ и скрипт запуска), push — с хоста. Правка агентом `compose.yml` своего проекта действует со следующего старта контейнера: итерация может расширить монтирования следующей итерации. Deny-правила образца и egress-firewall по образцу `init-firewall.sh` из референса Anthropic `.devcontainer` решаются вместе с движком — `ROADMAP.md`.

### Хук context-guard — сигнал на пороге контекста

Хук живёт в `~/.claude` хоста: скрипт `hooks/context-guard.sh` с порогами в `hooks/context-guard.conf`, его регистрация в `settings.json` на событиях `UserPromptSubmit` и `PostToolUse`, снимок занятости в конце скрипта строки состояния и раздел «Контекстное окно» в `CLAUDE.md` — текст сигнала выполнять как инструкцию. Хук сравнивает занятость контекста с порогом и печатает текст сигнала агенту в контекст; повтор — после роста занятости на заданный шаг.

Занятость считается по-разному:

- интерактивная сессия — по снимку строки состояния: размер окна приходит только в её данные, строка состояния сохраняет занятость и размер окна в файл сессии;
- headless — строки состояния нет: занятость по файлу переписки сессии, свой порог, размер окна неизвестен;
- подагент — по своему файлу переписки, свой порог; его сигнал — прекратить сбор данных и вернуть накопленное вызвавшему агенту.

Цифра отстаёт на шаг: токены считаются по факту запроса к модели, крупное чтение попадает в счётчик к следующему вызову инструмента.

Режим сигнала главной сессии — `CONTEXT_GUARD_MODE`; источник по приоритету: окружение процесса `claude` → строка `CONTEXT_GUARD_MODE=…` в `.claude/context-guard.conf` корня проекта → умолчание.

- Без режима — остановиться и предложить варианты: продолжить как есть; конспект в файл и новая сессия; свой вариант.
- `rules` — те же варианты, сохранение — по протоколу проекта, идущее завершение доводится без вопросов. Образец кладёт этот режим в проект файлом `.claude/context-guard.conf`.
- `protocol` — выполнить протокол завершения молча. Его ставит движок переменной окружения при запуске итерации.

Сигнал в сессии проекта — то же завершение, что штатное (`docs/PROTOCOL.md` § Протокол сессии), только раньше; так длинная сессия сохраняется по протоколу до встроенного автосжатия.

В контейнере скрипт хука приезжает копией `~/.claude/hooks/` хоста, регистрация — из образа, включается при наличии скрипта. Строка состояния хоста копируется вместе со своим скриптом ради снимка; хост без строки состояния — интерактивная сессия в контейнере считается по ветке headless. Хук работает на `jq`: без него выходит молча, и длинная сессия доходит до встроенного автосжатия; `jq` стоит в образе.

### Образец проекта — `template/`

То, что `/box-init` кладёт в новый проект: хаб `AGENTS.md` со строкой «Чтение на старте» и `CLAUDE.md` строкой `@AGENTS.md`; заготовки документов `docs/` с заголовками обязательных разделов, пустые `docs/tasks/` и `docs/researches/`; `docs/PROTOCOL.md` — рабочий оригинал протокола; скилл `.claude/skills/box-next/`; `.claude/context-guard.conf` строкой `CONTEXT_GUARD_MODE=rules`; `compose.yml` с сервисом `claude`; `.gitignore` строкой `my_local/`. Образ несёт папку в `/etc/claude-box/template/` вместе со скрытыми файлами.

Сервис `claude` — образ `maksim44/claude-box`, `stdin_open` и `tty` для интерактива. `profiles: [claude]`: обычный `docker compose up` проекта сервис пропускает, прямой `docker compose run` профиль активирует. `.env` проекта — `env_file` с `required: false`: его переменные уходят в окружение контейнера — MCP-серверам (`${VAR}` в `.mcp.json`) и командам агента. Подключения — § Образ и скрипт запуска. В проекте со своим compose-файлом `/box-init` вписывает сервис в его `services:` вместо образцового `compose.yml`; Claude тогда в одной сети с сервисами проекта, база доступна по имени сервиса.

### Скиллы контейнера — `skills/`

Скиллы едут в образе, `/etc/claude-box/skills/`, и доступны в любом проекте без установки: скрипт запуска при каждом старте контейнера кладёт их свежую копию в `~/.claude/skills`, скиллы пользователя под другими именами остаются рядом. Оба вызываются только командой (`disable-model-invocation: true`) и начинают с чистого рабочего дерева: коммит в конце забирает дерево целиком, поэтому при незакоммиченных правках скилл перечисляет их и заканчивает без изменений.

- `/box-init` — заведение проекта в обвязку, его роль — `DESCRIPTION.md` § Ключевые решения. Занятые имена образца освобождаются переименованием в `.old` (`.old2`, `.old3`…); переименованное, что было под `.gitignore` проекта, остаётся вне git строкой в корневом `.gitignore` под комментарием сборки. Папки `docs/`, `.claude/`, `.claude/skills/`, а также `.gitignore` и compose-файл проекта остаются на местах: образец ложится рядом, недостающие файлы — `cp -rn`, в `.gitignore` дописывается `my_local/`. Шаги, опись источников и шаблон задачи сборки с вариантами хранения архива — `skills/box-init/SKILL.md`; рядом — карточки документов проекта `documents.md`.
- `/box-task` — заведение задачи: сначала имя, веха, цель, проверка шага и блокер, затем очередь шагов; черновик пользователю, запись после согласия; таск-файл и строка задачи под вехой — одним коммитом, запись журнала с его хэшем — следующим. Очередь, не согласованная за сессию, — один шаг «разбивка»: `/box-next` ведёт его сколько нужно сессий и кладёт предложенную очередь в секцию «Блокер», в «Постановку» её дописывает пользователь, чекбокс разбивки ставит сессия, увидевшая очередь там. Шаги — `skills/box-task/SKILL.md`.

### Образ и скрипт запуска — `container/`

Образ `maksim44/claude-box` — `node:20` с `jq` (сборка настроек при старте, хук context-guard) и `python3-venv` (виртуальные окружения и pip для Python-проектов: системные пакеты ставит только root). Несёт образец, скиллы, базовые настройки с регистрацией хука context-guard (`/etc/claude-box/settings.json`) и скрипт запуска — точку входа `/usr/local/bin/claude-box`. Собирается из корня репозитория под архитектуру машины сборки, сейчас amd64. Claude Code ставит скрипт запуска при первом старте, официальным установщиком, в `~/.local` пользователя `node` — в домашнюю папку контейнера, дальше Claude Code обновляется сам в фоне; `PATH` образа включает `/home/node/.local/bin`.

Подключения сервиса `claude`:

- папка проекта → `/workspace/${COMPOSE_PROJECT_NAME}`: сессии, автопамять и доверие Claude Code раскладывает по пути рабочего каталога, так у каждого проекта в общей домашней папке они свои; `${COMPOSE_PROJECT_NAME}` — имя папки compose-файла, из подпапки то же, `name:` в compose-файле задаёт его явно;
- `~/.claude-box` → `/home/node`: домашняя папка контейнера, общая для проектов машины — логин, история сессий, сам Claude Code; при первом запуске Compose создаёт её от root, скрипт запуска отдаёт её `node`;
- `~` → `/root/host-home`, только на чтение: `/root` закрыт для `node` — ни напрямую, ни через `/proc/<pid>/root`.

`node` в образе — uid 1000: файлы, созданные в контейнере, на хосте принадлежат пользователю с тем же uid.

Скрипт запуска стартует от root и при каждом старте:

1. отдаёт домашнюю папку контейнера `node`;
2. ставит Claude Code, если лаунчера `~/.local/bin/claude` ещё нет;
3. переносит с хоста `~/.claude/CLAUDE.md`, `~/.claude/hooks/` и `~/.gitconfig` — автор коммитов протокола: есть на хосте — свежая копия, нет — копия прошлого запуска убирается;
4. кладёт свежую копию скиллов образа в `~/.claude/skills`;
5. берёт команду `statusLine` из хостового `settings.json`, переводит в ней пути внутри хостовой `~/.claude` в контейнерную и копирует файлы по ним;
6. собирает `~/.claude/settings.json` контейнера: регистрация хука из образа — при наличии скрипта хука; `language`, `model`, `effortLevel`, `modelSettings`, `attribution`, `includeCoAuthoredBy` и `statusLine` с переведённой командой — из хостового `settings.json`;
7. убирает из окружения ключи входа и переключатели провайдера — `ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN`, `CLAUDE_CODE_OAUTH_TOKEN`, `CLAUDE_CODE_USE_BEDROCK`, `CLAUDE_CODE_USE_VERTEX`, `CLAUDE_CODE_USE_FOUNDRY`: Claude Code в контейнере работает по подписке, программы агента этих ключей тоже не видят;
8. запускает `claude` от `node` через `setpriv`, аргументы запуска уходят в него.

Из хостового `settings.json` берутся отдельные ключи: хуки и прочие пути в нём — абсолютные пути хоста. Правка хостового действует со следующего старта. Креды и переписка хоста, его скиллы, плагины, MCP из `~/.claude.json`, `keybindings.json` и ключи `~/.ssh` остаются на хосте.

## Правила зависимостей

- **Образец и скиллы доезжают до проекта через образ.** Правка `template/`, `skills/` или `container/` → пересборка образа (`README.md`). Скиллы новый контейнер берёт на старте; протокол и `/box-next` в проекте обновляет повторный `/box-init`, остальные документы проекта остаются как есть.
- **Оригиналы — в `template/`, в проекте — копии.** Рабочий оригинал протокола — `template/docs/PROTOCOL.md`, скилла — `template/.claude/skills/box-next/`; скиллы и карточки ссылаются на проектные пути `docs/PROTOCOL.md` и `.claude/skills/box-next/`. Копии в этом репозитории — `AGENTS.md` § Жёсткие ограничения.
- **Скиллы образа и карточки ссылаются только на то, что едет в образе или лежит в проекте.** `/box-init` берёт образец из `/etc/claude-box/template/` и карточки из `~/.claude/skills/box-init/documents.md` и потому работает в контейнере `claude-box`.
- **Номера шагов завершения — контракт.** Список «Завершение» в `docs/PROTOCOL.md` § Протокол сессии адресуется номерами: сам протокол и `/box-init`, `/box-task` — «шаги 1, 2, 4–6», шаблон задачи сборки — «шаг 2», карточки `documents.md` — шаги 2–4 и 6. Перенумерация списка правит все ссылки тем же коммитом.
- **Шапка таск-файла — контракт движка.** Статус — первой строкой `статус: в работе | блокер | готово`, движок читает её grep-ом. Шаблон таск-файла — `docs/PROTOCOL.md` § Таск-файлы; шаблоны в `/box-task` и `/box-init` повторяют его раскладку.
- **Движок зависит от проекта через имена.** Скилл `/box-next`, сервис `claude` проекта, переменная `CONTEXT_GUARD_MODE` и код выхода `claude` — интерфейс итерации; смена любого из них правит строку итерации.
- **Набор документов проекта описан в четырёх местах.** Карточки `skills/box-init/documents.md`, файлы `template/`, карта `template/docs/README.md` и очередь шаблона задачи сборки в `skills/box-init/SKILL.md`; новый или убранный документ правит все четыре.
- **Хук — по имени файла.** Регистрация в `container/settings.json` и проверка в скрипте запуска ссылаются на `~/.claude/hooks/context-guard.sh`; режим хук читает из `CONTEXT_GUARD_MODE` и `.claude/context-guard.conf` корня проекта.
- **Образ собирается из корня репозитория:** Dockerfile копирует `template/` и `skills/`.

## Анти-паттерны

- **`--bare` в строке итерации.** Отключает автозагрузку контекста проекта и подписочный логин — итерация не видит хаб, протокол и `/box-next` и требует API-ключ. Дока объявляет `--bare` будущим дефолтом `-p`: после обновления CLI первым делом проверять, что итерация видит `CLAUDE.md` и скиллы.
- **Скрипт кормит командами долгоживущую интерактивную сессию.** Процесс копит контекст, путь идёт мимо доки; каналы «скрипт → процесс» по доке — `-p` на итерацию, `--input-format stream-json`, Agent SDK.
- **`protocol` в `.claude/context-guard.conf` проекта.** Интерактивные сессии проекта на пороге молча завершаются вместо вариантов; режим `protocol` приходит только из окружения движка.
- **Установка Claude Code при сборке образа.** Версия фиксируется: глобальный каталог npm принадлежит root, контейнер работает от `node`, обновление не записывается, а `--rm` стирает контейнер с любыми правками — обновление превращается в пересборку образа.
- **Именованный volume под домашнюю папку контейнера.** Compose приписывает общий volume создавшему его проекту и в каждом другом проекте на каждом запуске предупреждает «volume already exists but was created for project …».
- **Подключение отдельных файлов хоста в compose-файле.** Отсутствующий на хосте источник Compose создаёт пустым каталогом от root — и там, где ждали файл; опциональное с хоста берёт скрипт запуска из подключённой целиком домашней папки.
- **Секреты хоста в контейнере** (`~/.ssh`, облачные креды, креды `~/.claude`). В bypass агент читает всё, что видит его пользователь.
- **Разросшийся роадмап.** Симптом смешения ролей: в него дописали сиюминутное таск-файла или путь к разобранному из журнала и ресерча.
