# Движок автоцикла

Шелл-скрипт `agent-loop.sh [--host | --no-firewall] [--api] [--quiet] [--resume <id>] <задача>` в корне agent-box, один на все проекты машины; работает на хосте для обеих ступеней изоляции. Задача — имя или путь к таск-файлу, аргумент с `/` или на `.md`: по имени скрипт запускается из папки проекта, по пути — из любой папки, проект — git-репозиторий файла, подсказки движка повторяют запуск тем же путём; файл вне `docs/tasks/` своего репозитория — отказ запуска. Команды `agent-loop.sh`, `box-connect`, `box-update` и `box-claude` скрипт ставит сам: на каждом запуске, когда одной из них нет, а `~/.local/bin` есть в `PATH`, кладёт туда ссылки на себя и на `box-connect`, `box-update` и `box-claude` из своей папки клона; запуск без аргументов ставит команды и печатает строку запуска. Машина, где команды ставились раньше, получает недостающую первым же запуском движка (пробы с временной домашней папкой: 2026-11-26 — команд нет, ставятся все, нет одной `box-update` — она же, все на месте — строки установки нет; 2026-11-28 — при прежних трёх ссылках ложится `box-claude`, `researches/2026-11-26-redesign-probes.md` § Сценарии трёх команд). `box-connect` подключает проект, `box-update` обновляет — `template.md` § Обновление проекта. `box-claude` в папке проекта — Claude в контейнере проекта: `docker compose -f claude-box.yml run --rm claude`, тот же сервис, что у итераций, с подключениями и путём в контейнере из файла (`container.md` § Образ и скрипт запуска); `claude-box.yml` нет — код 1 с подсказкой: в подключённом проекте, с манифестом `.claude/agent-box.sha256`, — собрать файл командой `box-update`, как у рабочей копии git, без манифеста — подключить проект командой `box-connect`. `agent-loop.sh --sandbox-rule` вместо цикла пишет правило песочницы в личные настройки Claude Code хоста (`container.md` § Ступени изоляции — сессия хоста над контейнером). Без `~/.local/bin` в `PATH` подсказки движка дают полный адрес скрипта. Итерации идут в контейнере — сервисе `claude` проекта — за ограничением сети и без вопросов о разрешениях; с `--no-firewall` — в контейнере с открытой сетью в режиме auto, с `--host` — на хосте (`container.md` § Ступени изоляции). Нужны `git` и `jq`; контейнерной ступени — Docker с Compose и сервис `claude` в `claude-box.yml` проекта, хостовой — `claude` хоста; для уведомлений — `curl`. Цикл: захват lock-файла репозитория → статус из шапки `docs/tasks/<задача>.md` → фиксация HEAD → итерация свежей сессией под таймером → разбор итога: код выхода, чистота рабочего дерева, статус, дифф итерации → пауза → снова. Lock-файл `.git/agent-loop.lock` лежит вне рабочего дерева и несёт имя задачи и PID цикла; второй запуск движка в том же репозитории сразу завершается с именем задачи идущего цикла. Lock процесса, которого уже нет, — после `kill -9` или сбоя питания — следующий запуск перехватывает. Git хоста движок запускает с `-c core.fsmonitor=false -c core.hooksPath=/dev/null`: команда fsmonitor и хуки из `.git` проекта не выполняются — их может подложить агент контейнера. Сервис `claude` движок берёт из `claude-box.yml` в корне проекта явным `-f`: контейнер собирается только по нему — основной compose-файл проекта, дополнение `compose.override.yml` и строка `COMPOSE_FILE` в `.env` в сборку не входят (проба 2026-10-03). У `claude-box.yml` своё имя проекта Compose, и запуск итерации ресурсы основного compose-файла со своим файлом не сверяет: контейнеры и сеть проекта остаются как есть (`template.md` § Образец проекта). Сеть проекта в `claude-box.yml` каждый запуск отмечает безвредным предупреждением Compose о сети, созданной не этим проектом (`template.md` § Образец проекта): `--progress quiet` его оставляет, и в уведомлении о провале итерации оно стоит в хвосте stderr рядом с причиной (проба 2026-11-09, Compose 5.7.0).

Код выхода движка: 0 — «готово» или лимит итераций; 1 — остановка, ждущая пользователя: блокер, провал итерации, правки без коммита, итерации без прогресса, статус вне протокола; 2 — движок не запустился: второй цикл в репозитории, нет таск-файла, нужной команды, `claude-box.yml` в корне проекта или сервиса `claude` в нём перед первой итерацией в контейнере — подсказка называет `box-connect` и `box-update`, ошибка в `config.yml`, строки ключа API при `--api`; 130 — Ctrl+C.

Пределы цикла — конфиг agent-box `config.yml` в корне клона, рядом с движком, один на все проекты машины: итераций за запуск `max_iterations`, секунд паузы между итерациями `pause_seconds`, итераций подряд без прогресса `max_idle_iterations`, потолок ходов итерации `max_turns`, минут итерации до алерта таймера `alert_minutes`; там же порог раздела документации по областям `split_chars` — его движок принимает и пропускает, сессиям в контейнере копию конфига кладёт скрипт запуска (`container.md` § Образ и скрипт запуска), — и модель агента проверок оркестратора `check_agent_model` — алиас модели параметра `model` инструмента `Agent`: `opus`, `sonnet`, `haiku` или `fable`; движок её пропускает, проверив вид значения, оркестратор читает при старте сессии (`orchestrator.md`). Конфиг движок находит рядом с собой — по пути скрипта с развёрнутыми ссылками: команда `agent-loop.sh` ведёт в клон ссылкой из `~/.local/bin`. Движок читает файл один раз при старте запуска, построчно: строка — «ключ: значение», у пределов и порога — целое число, у модели — строчные латинские буквы; комментарии `#` и пустые строки пропускаются; нет файла или ключа — значение по умолчанию: 10, 10 секунд, 3, 200, 60 минут. Неизвестный ключ, значение не того вида или строка другого вида — отказ запуска с путём конфига и номером строки. Строка старта называет действующие пределы и их источник — путь конфига или значение по умолчанию; правка файла действует со следующего запуска. Режим запуска — контейнер, хост, открытая сеть — живёт только во флагах строки запуска: конфиг правят сессии по задачам самого agent-box, где он в рабочем дереве, и ключ режима в нём вывел бы следующий запуск из песочницы. До решения пользователя 2026-10-15 (`DECISIONS.md`) — один конфиг на все проекты — те же ключи жили файлом образца в корне каждого проекта под git. Проба 2026-10-15 файла в корне проекта на тестовом проекте с заглушкой `claude` вместо сессии: без файла — значения по умолчанию; файл образца и файл с частью ключей — значения файла и источник каждого в строке старта; `max_iterations: 1` — одна итерация, `pause_seconds: 01` — пауза 1 с, `max_turns: 7` — `--max-turns 7` в строке итерации, `alert_minutes: 1` — алерт через минуту; буквы в значении, отрицательное число, неизвестный ключ, строка без двоеточия — отказ с кодом 2 и номером строки. Живая проверка 2026-10-15 на пересобранном образе, файл в корне проекта с `max_iterations: 1` — одна итерация сессии в контейнере и остановка по лимиту. Проба 2026-10-15 конфига клона: копия движка во временной папке на тестовом проекте, запуск путём к скрипту и по имени через ссылку из папки в `PATH` — без `config.yml` рядом строка старта называет значения по умолчанию и путь отсутствующего файла; с `max_iterations: 1` — значение и путь файла; неизвестный ключ и буква в значении — отказ с кодом 2, путём и номером строки.

Строка итерации на хосте:

```bash
CONTEXT_GUARD_MODE=protocol CLAUDE_CODE_PROMPT_CACHE_TTL=5m claude -p "/box-next <задача>" --session-id <uuid> \
  --permission-mode auto --permission-prompts none --append-system-prompt "<строка итерации>" \
  --output-format json --max-turns 200
```

Строка итерации в контейнере — тот же запуск через сервис проекта, через точку входа ограничения сети и в bypass:

```bash
docker compose -f claude-box.yml --progress quiet run --rm -T --entrypoint claude-box-firewall \
  -e CONTEXT_GUARD_MODE=protocol -e CLAUDE_CODE_PROMPT_CACHE_TTL=5m claude -p "/box-next <задача>" --session-id <uuid> \
  --permission-mode bypassPermissions --permission-prompts none --append-system-prompt "<строка итерации>" \
  --output-format json --max-turns 200 </dev/null
```

С `--no-firewall` — без `--entrypoint` и с `--permission-mode auto`; с `--api` — ещё `-e CLAUDE_BOX_API_KEY` перед именем сервиса (абзац о флаге `--api` ниже). Флаги после имени сервиса уходят в Claude Code. Образ, собранный до ограничения сети, точки входа `claude-box-firewall` не несёт: контейнер не стартует, итерация падает, и движок останавливается — bypass без ограничения сети не запускается. Поведение Compose 5.6.0 по пробам 2026-10-03:

- код выхода процесса контейнера `docker compose run` возвращает движку;
- `-T` выключает терминал сервиса (`tty: true`): stdout с JSON итога идёт отдельно от stderr;
- при `-T` ввод контейнера — открытый канал без конца, а `-p` добавляет поданный ввод к промпту: ввод — `/dev/null`;
- `--progress quiet` оставляет в stderr только ошибки и предупреждения — их хвост уходит в уведомление о провале;
- SIGINT Compose отдаёт процессу контейнера и сам сразу выходит с кодом 130, не дожидаясь итога.

Сессии контейнера лежат в его домашней папке: доследование — `docker compose -f claude-box.yml run --rm claude --resume <id>` из папки проекта, с открытой сетью.

Флаг движка `--resume <id>` продолжает сессию без человека: первая итерация запуска идёт строкой итерации той же ступени изоляции, с `--resume <id>` вместо `--session-id` и просьбой продолжить с места обрыва вместо `/box-next`; дальше цикл идёт свежими сессиями. Сессия сохраняет id и дописывает свой файл истории (проба на хосте 2026-11-01, CLI с флагами итерации), ход в журнал идёт с первой новой строки файла. Файла истории нет — отказ запуска, код 2.

Флаг движка `--api` ведёт итерации на API-ключе организации Console — ради ежемесячных API-кредитов плана подписки: их тратит `claude -p` с ключом связанной организации, а интерактивный Claude Code они не покрывают (`researches/2026-11-21-loop-api.md`). Ключ — строка `ANTHROPIC_API_KEY` в `~/.config/agent-loop.env` хоста, рядом с токеном Telegram; строки нет — отказ запуска, код 2: итерация без ключа тратит лимит подписки. Итерация с `--host` получает ключ переменной `ANTHROPIC_API_KEY` в своём окружении — в `-p` ключ из окружения берётся всегда. В контейнер ключ идёт под именем `CLAUDE_BOX_API_KEY`: строка итерации несёт `-e CLAUDE_BOX_API_KEY` без значения, Compose берёт значение из окружения движка, и в тексте команды и списке процессов ключа нет (проба 2026-11-21, Compose 5.8.0); программа чтения `.env` отдаёт его Claude Code как `ANTHROPIC_API_KEY` (`container.md` § Образ и скрипт запуска). Образ, собранный до флага, отдаёт Claude Code ключ под именем движка, и итерации идут по подписке: `--api` в контейнере работает после пересборки образа. Без флага ключа нет ни у итераций, ни у интерактивных сессий — `box-claude`, ручной запуск контейнера, доследование `--resume`: они работают по подписке. Ключ в окружении Claude Code видят и команды агента: `printenv` его покажет, тесты проекта его получат. Кредиты покрывают итерацию по признаку запуска — переменной `CLAUDE_CODE_ENTRYPOINT`: итерация `--host` из сессии в терминале идёт как Agent SDK, из расширения IDE — как IDE, и кредиты её не покрывают, API отвечает ошибкой кончившихся кредитов (ресерч). Флаг ставится с прочими в любом порядке; строка старта называет его и файл ключа, строка повтора в подсказках и журнале несёт флаг. Проба 2026-11-21 на временном проекте с заглушками `claude` и `docker`: без строки ключа и без файла — код 2 со строкой причины; `--host --api` — у `claude` в окружении `ANTHROPIC_API_KEY` из файла; в контейнере — `-e CLAUDE_BOX_API_KEY` в аргументах `docker` и ключ в его окружении; без флага при ключе в файле — ключа нет ни у одного; `--api` с `--sandbox-rule` — код 2.

Флаги и поведение CLI, на которые опирается строка; сверено с докой и пробами на CLI 2.1.287 — `researches/2026-08-31-audit-and-headless.md` § Часть 4:

- `/box-next <задача>` в промпте `-p` раскрывается до запуска и при `disable-model-invocation: true`: тело скилла с подставленным именем задачи приходит первым сообщением сессии.
- `-p` стартует в Manual; сессия без загрузки флагов функций с сервера — сторонний провайдер, выключенная телеметрия — с CLI 2.1.285 стартует в auto. Режим разрешений передаётся явно при каждом запуске (`container.md` § Ступени изоляции).
- `--permission-prompts none` (CLI ≥ 2.1.259): запрос, который ждал бы ответа человека, получает отказ с указанием его не повторять, инструменты вопроса пользователю убраны, прогон продолжается — отказ ведёт сессию к блокеру.
- `--append-system-prompt` — строка итерации в конце системного промпта, правило итерации без человека целиком: сессия — итерация движка, человека рядом нет, последнее сообщение никто не читает, а статус «в работе» движок запускает на тот же шаг новой сессией; вопрос, просьба сделать руками и отклонённая проверкой разрешений команда — блокером (`docs/PROTOCOL.md` § Таск-файлы), отклонённая команда — в секцию просьбой сделать руками, готовой строкой. Дом правила — эта строка: она доходит до сессии каждой итерации, и правило не ждёт загрузки протокола; проба 2026-11-26 с заглушкой `claude`, которая печатает свои аргументы, — строка целиком в журнале цикла. Тело `/box-next` у итерации и у интерактивной сессии одно, и по нему сессия своего места не знает: в пилотном проекте 2026-11-11 пять итераций из шести на шаге с выкладкой на прод писали вопросы и просьбу о пуше последним сообщением со статусом «в работе» — «напиши „дальше“, сессию не закрывай», — и движок дважды встал на трёх итерациях без прогресса.
- `--output-format json` — один JSON-объект на stdout: `session_id`, `is_error`, `subtype`, `terminal_reason`, `num_turns`, `total_cost_usd`, `permission_denials`; итоговый текст `result` — у дошедшей до ответа сессии, текст ошибки — в `result` или массиве `errors`. Исходы по пробам:
  - штатное завершение — код 0, `is_error: false`, `subtype: success`, `terminal_reason: completed`;
  - упор в `--max-turns` — код 1, `is_error: true`, `subtype: error_max_turns`, `terminal_reason: max_turns`, `result` нет;
  - ошибка API (проба — нет логина) — код 1, `is_error: true` при `subtype: success`, `terminal_reason: api_error`, ошибка в `result`;
  - SIGINT — ход обрывается, итог записан: код 0 при `is_error: true`, `subtype: error_during_execution`, `terminal_reason: aborted_streaming`;
  - SIGTERM — ход обрывается без итога: код 143, stdout пуст;
  - неверный флаг — код 1, stdout пуст, ошибка в stderr.
- `--session-id <uuid>` — идентификатор сессии задаёт движок до запуска: алерт таймера называет сессию, пока она идёт, и сообщение о провале без JSON — тоже; в итоге JSON `session_id` тот же (проба 2026-10-01).
- `--max-turns 200` — потолок ходов итерации против зацикливания, только для `-p`; 200 — значение по умолчанию, оставлено пользователем после замера обкатки 2026-10-04 — вчетверо выше самой длинной итерации, 50 ходов (`researches/2026-08-31-audit-and-headless.md` § Часть 5); пересматривается, когда наберутся итерации с кодом. Окно контекста итерацию не ограничивает: у предела автосжатие продолжает сессию, а context-guard останавливает её только через послушание модели.
- `CLAUDE_CODE_PROMPT_CACHE_TTL=5m` в окружении итерации (CLI ≥ 2.1.242) — кэш промпта на пять минут вместо часового, который Claude Code на подписке берёт для `-p` по умолчанию: отсчёт идёт от последнего вызова, вызовы внутри итерации идут чаще, а следующая итерация — новая сессия с другим снимком git, то есть с другим началом кэша; запись в кэш на час стоит 2× входа, на пять минут — 1,25× (https://code.claude.com/docs/en/prompt-caching). Пауза между вызовами дольше пяти минут — одна перезапись кэша. Проверка — `usage.cache_creation` в JSON итога: записи в `ephemeral_5m_input_tokens` (проба 2026-10-06 на CLI 2.1.291).
- Лимит подписки общий для всех поверхностей — пятичасовое окно и недельное; headless-прогон при упоре в лимит падает.
- Живое наблюдение — `--output-format stream-json --verbose --include-partial-messages` с `tee` в лог.

Разбор итога итерации:

- провал итерации — ненулевой код выхода, `is_error: true` или stdout без JSON: падение, `--max-turns`, лимит подписки, SIGINT итерации — стоп с уведомлением: `session_id`, `terminal_reason`, текст ошибки из `result` или `errors`; без JSON — код выхода и хвост stderr. Сессия умерла до шагов завершения, в рабочем дереве могут лежать правки, которых «Контекст» не знает; доследование руками — `claude --resume <id>` из любого каталога, у контейнера — через сервис `claude`; без человека — флаг движка `--resume <id>`, его ставит оркестратор (`orchestrator.md`). SIGINT итерации даёт код 0 при `is_error: true`, и правило по `is_error` останавливает движок вместе с ней: вмешательство пользователя по алерту таймера кончает цикл;
- код 0 и незакоммиченные правки в дереве — та же остановка: сессия не дошла до коммита;
- статус «блокер» без строки «ответ:» в секции «Блокер» — стоп, секция в терминал и уведомлением; пользователь пишет строку «ответ:» и запускает движок снова. Блокер с ответом движок снимает сам: статус «в работе» в рабочем дереве — его забирает коммит итерации — и итерация; регистр слова «ответ» любой — в UTF-8 локали хоста;
- статус «готово» — стоп, уведомление с именем задачи;
- три итерации подряд без прогресса — стоп с уведомлением. Прогресс — закрыт чекбокс очереди либо дифф итерации затронул что-то кроме служебных файлов завершения: таск-файла, `JOURNAL.md`, `DECISIONS.md`. Правило — алерт, не приговор: шаг длиной в несколько сессий чтения или дебага пишет только в «Контекст» и остановит цикл при живой работе, а три сессии с правкой одной записи в `AGENTS.md` пройдут как прогресс; в обоих случаях пользователь смотрит журнал цикла и перезапускает движок. Три — значение по умолчанию, оставлено пользователем после замера 2026-10-04: правило не срабатывало ни разу;
- лимит итераций за запуск, по умолчанию 10; Ctrl+C;
- иначе — пауза, по умолчанию 10 секунд, и следующая итерация. Пауза — окно чистой остановки Ctrl+C: прошлая итерация закоммичена, следующая не начата; Ctrl+C в терминале доходит и до идущей сессии `claude` и обрывает её ход.

Проба Ctrl+C движка из инструмента Bash сессии Claude Code: запуск через `&` внутри команды наследует игнор SIGINT, и `kill -INT` группе процессов движка ничего не делает; фоновая команда инструмента (`run_in_background`) в CLI 2.1.296 игнора не несёт (проба 2026-10-11). Запуск пробы — `env --default-signal=INT setsid -w <команда>`, как у оркестратора (`orchestrator.md`), или через `python3 -I` со сбросом `signal.signal(signal.SIGINT, signal.SIG_DFL)`, `os.setsid()` и `os.execv`. `pgrep -f` по строке запуска находит и оболочку самой команды пробы — сигнал уходит ей; шаблон — с якорем `^bash <путь к скрипту>`. `pkill -f` с шаблоном, который есть в строке той же команды Bash, убивает и её оболочку: команда кончается кодом 144, её дальнейшие части не выполняются (проба 2026-10-13).

Таймер итерации — алерт без остановки: порог превышен → уведомление с `session_id` и длительностью, итерация продолжается; вмешательство — лог, `claude --resume`, SIGINT. Порог по умолчанию — час: оставлен пользователем после замера 2026-10-04 по jsonl-журналам сессий — самая длинная итерация шла 13 минут; пересматривается вместе с потолком ходов.

Журнал цикла — файл `.git/agent-loop.log` проекта рядом с lock-файлом, вне рабочего дерева, у дополнительной рабочей копии git — в её папке `.git/worktrees/<имя>` основного репозитория (`git rev-parse --absolute-git-dir`); путь движок печатает при старте, файл копится от запуска к запуску. Строка — дата, время и событие: запуск — строкой повтора с флагами; начало итерации — номер, шаг очереди (первый незакрытый чекбокс «Постановки», его номер из их числа и начало текста до 80 символов) и сессия; ход итерации — строки с отступом; предупреждения ограничения сети — строки `claude-box-firewall: предупреждение:` из stderr итерации, перед строкой её конца; конец итерации — длительность, код выхода, `terminal_reason` и число ходов из итога или «итога JSON нет», статус задачи, коммиты итерации с сообщениями; алерт таймера; остановка — текст терминала, включая отказ запуска после захвата lock. Ход берётся из истории сессии Claude Code — файла `<session_id>.jsonl` в `~/.claude-box/.claude/projects/<папка проекта>/` у контейнера и в `~/.claude/projects/<папка проекта>/` у `--host`; движок ищет файл по `session_id`, он появляется со стартом сессии. Из ответов агента основной сессии идут текст, чтение и правка файлов с путями от корня проекта, команды, поиск и прочие инструменты именем и вводом; длинное обрезается до 200 символов. Ход пишется вживую: на время итерации движок держит процесс-метку `sleep`, фоновый `tail -f` с `jq` переводит новые строки истории в журнал, а по снятию метки `tail --pid` дочитывает файл и выходит — строка конца итерации ложится после всего хода. Формат истории сверен на образцах CLI 2.1.287 и 2.1.296 (2026-10-10); строка другого формата пропускается, и журнал остаётся без хода — строки событий движок пишет сам.

Уведомления — Telegram Bot API `sendMessage` и `sendDocument` через `curl`. Токен и chat_id — строки `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` в `~/.config/agent-loop.env` хоста, вне репозиториев; движок берёт из файла только их и ключ `--api`, токен и chat_id в окружение сессий не попадают. chat_id, которого в файле нет, движок при старте берёт из последнего сообщения боту (`getUpdates`) и дописывает в файл; Telegram хранит входящие бота 24 часа — годится только свежее сообщение. Уведомление уходит на каждой остановке цикла и на алерте таймера: текст терминала с именем папки проекта впереди — движок один на все проекты машины; отказ запуска (код 2) остаётся в терминале — пользователь в этот момент у терминала. Последняя строка текста — «дальше:» со следующим шагом пользователя: проверка готовой задачи, `claude --resume`, повторный запуск; у блокера это строка «Как ответить:», которой секцию «Блокер» заканчивает сессия (`PROTOCOL.md` § Таск-файлы). Текст до 4000 символов уходит сообщением — предел сообщения Telegram 4096; длиннее — файлом `<проект>-<задача>.md` целиком, в подписи — первые 600 символов и строка «дальше:»: подпись Telegram ограничивает 1024 символами. Токен уходит в `curl` через stdin и в списке процессов не виден. Сбой отправки — строка в терминале с ответом Telegram, код выхода остановки прежний. Токен движок проверяет при старте запросом `getMe` — до поиска chat_id и первой итерации, пока пользователь у терминала. Неверный токен вида `<число>:<ключ>` Telegram отклоняет ответом 401 «Unauthorized», токен другого вида — без двоеточия, с пустой или нецифровой частью до него — ответом 404 «Not Found» (проба 2026-10-04); на оба движок стартует со строкой «уведомления выключены: неверный токен», ответом Telegram и подсказкой, где поправить токен. Проверка, на которую Telegram не ответил, — строка с ошибкой, уведомления остаются включены. Без токена или chat_id движок стартует со строкой «уведомления выключены» и причиной и сообщает только в терминал. Флаг `--quiet` выключает Telegram на запуск целиком, вместе с проверкой токена: строка старта называет флаг, остановки и алерт таймера идут только в терминал, подсказки «дальше:» повторяют запуск с флагом. Режим для сессии, которая ведёт движок и читает его вывод сама.
