# Оркестратор — `/box-orchestrate`

Оркестратор — интерактивная сессия Claude Code на хосте, которая ведёт задачу движком за пользователя: скилл проекта `/box-orchestrate <задача>`, рабочий оригинал — `template/.claude/skills/box-orchestrate/`, шаги — в его `SKILL.md`, скрипт страницы задачи — `page.py` рядом, устройство страницы и метки — в `pages.md`, образцы вопросов пользователю «плохо → понятно» — в `questions.md`, две страницы-примера вымышленной задачи — в `examples/`. Скилл лежит в проекте рядом с `/box-next`: скиллы контейнера сессия хоста не видит. Папку скилла целиком кладут в проект `/box-init` и `/box-update`, как `/box-next` (`template.md` § Скиллы контейнера). Канал к пользователю — Remote Control: сессия на проект в приложении Claude, вопросы и пуши приходят на телефон (`researches/2026-10-10-orchestrator-remote.md`).

Движок — фоновая команда Bash сессии `env --default-signal=INT setsid -w agent-loop.sh --quiet <задача>`: завершение команды будит сессию; своя группа процессов и снятый игнор Ctrl+C дают остановку по просьбе пользователя сигналом `kill -INT -- -<PID>`, PID — из lock-файла движка, — тот же путь, что Ctrl+C в терминале (проба 2026-10-11 заглушкой с обработчиком движка: выход 130). Тихий режим — по умолчанию, Telegram — словом `telegram` в аргументе (`DECISIONS.md` 2026-10-10 — уведомления движка под оркестратором). Начало итерации и алерт таймера ловит сторож — вторая фоновая команда, поставленная раньше движка: опрос журнала цикла раз в 30 секунд, выход на первой строке начала итерации или алерта после его старта. Шаблон сторожа берёт только строки событий движка — время и через один пробел «задача»: в строках хода итерации бывают те же слова — поиск по одним словам «идёт дольше» нашёл в журнале 2026-10-11 две строки хода, команды агента. Сессия просыпается по событиям — остановка движка, начало итерации, алерт, сообщение пользователя; в ожидании ходов модели нет.

Страница задачи — приватная страница claude.ai, которую оркестратор ведёт по событиям цикла (`DECISIONS.md` 2026-10-10 — ход цикла: журнал и страница статуса). Её файл — `my_local/pages/<задача>.html` проекта, вне git: он же копия страницы (`DECISIONS.md` 2026-10-10 — копии страниц задач); адреса страниц — `my_local/pages/links.md`, строка на задачу. Обновление — на выходе сторожа, вопросе пользователю, ответе, остановке движка без перезапуска и «готово». Строка начала итерации ложится в журнал после строки конца прошлой, и одно пробуждение на итерацию даёт странице и исход прошлой итерации, и идущую. Копия, открытая из файла: Chrome 155 показывает кириллицу примера без `<meta charset>` верно — распознаёт UTF-8 (проба 2026-10-11).

Скрипт страницы — `page.py` на Python 3 со стандартной библиотекой (задача page-script): файл страницы он правит по 16 меткам-комментариям в разметке, всё вне меток — каркас примера `examples/running.html`. Шаги и этапы очереди скрипт берёт из таск-файла — этап по строке «Этап <N> — <название>.» (`template/docs/PROTOCOL.md` § Таск-файлы), итерации — из журнала цикла, сквозной нумерацией по всем запускам задачи, раздел «Проверка в браузере» — из файла сценариев QA и снимков экрана шага прогона; от оркестратора — только фразы события со stdin: заголовок, лид, цели и пояснения к этапам при создании, вопрос с вариантами и рекомендацией, ответы, итог итераций, причину остановки. Команды — `new`, `iteration`, `question`, `answer`, `stop`, `done`, `link` для адреса в `links.md` и `sent` — отметка кадров прогона, дошедших до страницы; ответ — одна строка: изменённые метки, все картинки вопроса к публикации при каждом вопросе — их копии скрипт кладёт рядом со страницей, — пути картинок без файла в папке проекта, которых вопрос на странице лишился, кадры прогона, ещё не отмеченные командой `sent` после удачной публикации, — кадр на каждое действие сценария, и JSON всех кадров в каждой публикации занимал бы контекст оркестратора, — и адрес страницы или «первая публикация»; повторная отправка картинки, загруженной прежней беседой, проходит, и картинки сорвавшейся публикации и прежнего адреса страницы доходят со следующей публикацией вопроса (`docs/researches/2026-10-15-page-agent.md` § Картинки вопроса файлами); страницы или меток нет или на странице нет этапа, появившегося в таск-файле после создания, например этапа ревью, — код 3, и оркестратор создаёт страницу командой `new` с пояснением к новому этапу; вопросы и ответы и адрес страницы переходят на новую. Публикует оркестратор инструментом `Artifact`, загрузив его `ToolSearch` один раз за беседу. Повод — беседа оркестратора пилотного проекта 2026-10-19: подагент, который вёл страницу до задачи page-script, запускался 10 раз, 6 на начала итераций и 4 на один вопрос с повторами; каждый стартовал с 56 тыс. токенов контекста и кончал на 90–113 тыс., а сама правка у него — одна команда по файлу и одна публикация (`DECISIONS.md` 2026-10-18 — агент на отметки, 2026-10-19 — задача page-script). До этого подагента оркестратор к первой публикации занимал 105–115 тыс. токенов из предельных 150 тыс.: правила страниц около 8,5 тыс., файл страницы 7–22 тыс., схема `Artifact` 13 тыс., отказ «не видел живую версию» с живой страницей 22 тыс. (задача orchestrator-context). Скрипт убирает из контекста оркестратора правила и файл страницы, схема `Artifact` и отказ остаются; сколько добавляет событие, меряет живой прогон задачи page-script. Вопрос пользователю идёт порядком страница, фоновая команда `sleep 5`, сообщение текстом, которым кончается ход, пуш на уведомление `sleep`, окно: текст ответа с вызовом инструмента сразу после результата другого Claude Code в половине случаев сворачивает, а текст, которым кончается ход, и ответ на уведомление фоновой команды видны всегда (`docs/researches/2026-10-15-page-agent.md` § Второй прогон и где модель кладёт текст).

Агент проверок — подагент общего назначения сессии оркестратора на вопрос блокера, снимаемый проверкой с однозначным итогом или сведениями вне сети контейнера (задача orchestrator-context): оркестратор передаёт ему вопрос и предложение сессии из секции «Блокер», агент читает код, документы, ресерчи и историю git, запускает команды и тесты, ищет в интернете и отвечает одним абзацем — что проверено, итог, источник. Ему же идут пункты просьбы сделать руками, до которых сессии в контейнере не дотянуться: запрос к локальной базе, запись её данных, осмотр контейнеров проекта, публичное значение из сервиса, к которому у Claude на хосте есть инструмент, — в файл вне git, который называет просьба. Сервис агент только читает; секрет — пароль, ключ сервера — кладёт пользователь, значение неясной публичности — итог неоднозначен, вопрос пользователю. Повод — две беседы оркестратора пилотного проекта 2026-10-26: публичный ключ облачных таблиц площадки, который сборка отдаёт каждому игроку, консоль площадки вернула оркестратору при заведении таблиц, а скилл отдал его пользователю руками — у агента проверок запись была только в файл хода. Миграции делает пользователь: схему базы меняет только он (`DECISIONS.md` 2026-10-18 — проверка из просьбы сделать руками); данные базы меняет агент (`DECISIONS.md` 2026-10-21 — запись в локальную базу). Строку «ответ: оркестратор —» оркестратор пишет по этому абзацу, а прочитанное остаётся в контексте агента: до задачи оркестратор читал ресерч задачи ради ответа на блокер, уже занимая 130–137 тыс. токенов из предельных 150 тыс. Задание агента — четыре строки прямо в скилле: поручение с формой ответа и файлом хода, вопрос, предложение сессии и строка файла хода — новый или продолжение. Модель — ключ `check_agent_model` конфига agent-box, по умолчанию `opus`, параметр `model` вызова (`DECISIONS.md` 2026-10-15 — модель помощников оркестратора). Агенты нескольких вопросов идут разом — в проект они пишут только свои файлы хода и публичные значения в файлы вне git; вопрос пользователю ждёт итогов всех: их итоги — ответы оркестратора на странице и в сообщении перед окном. Ход проверки агент ведёт в файле хода `my_local/checks/<задача>-<n>.md` проекта, вне git, — пункты с итогом, запущенное им и пункт продолжения; файл постоянный: проверка вопроса того же номера в следующем блокере его перезаписывает. Обрыв — отчёт без итога по всем пунктам или конец агента без отчёта: следующий агент того же вопроса продолжает по файлу хода, и вопрос пользователю идёт только после двух обрывов подряд без новых закрытых пунктов. Последний агент останавливает запущенное по файлу и отвечает абзацем по всем его пунктам. Повод — беседа оркестратора пилотного проекта 2026-10-26: агент проверок на прогоне тестов, двух сборок и двух сценариев в браузере сделал 92 действия, дошёл до 206 тыс. токенов, по сигналу context-guard вернул половину и оставил запущенными сервер сборки и браузер; правило «агент упал — вопрос пользователю» дало вопрос без решения, а второй агент по пересказу оркестратора начал с 54 тыс., за 28 действий дошёл до 109 тыс. и до непроверенных пунктов не добрался (`DECISIONS.md` 2026-10-26 — обрыв агента проверок). Итог неоднозначен — вопрос уходит пользователю с абзацем агента. Интерактивная сессия запускает подагентов фоном — режим форков в ней включён по умолчанию (code.claude.com/docs/en/sub-agents, 2026-10-15): ответ агента — его отчёт, сообщение, которое будит сессию; уведомление о конце приходит следом и сессию обычно не будит (`docs/researches/2026-10-15-page-agent.md` § Третий прогон и конец подагента), поэтому вопрос пользователю ждёт отчётов. Запуск шагом скилла классификатор режима auto пропускает без согласия в беседе, а разрешение только в «Постановке» таск-файла отклоняет (`docs/researches/2026-10-15-page-agent.md` § Запуск подагента в режиме auto).

Остановку оркестратор разбирает по коду выхода и строке остановки движка (`engine.md`), журналу цикла и таск-файлу:

- блокер: вопрос, снимаемый проверкой с однозначным итогом или сведениями, закрытыми сети контейнера, оркестратор снимает своим ответом по итогу агента проверок — строкой «ответ: оркестратор —» (`docs/PROTOCOL.md` § Таск-файлы, `DECISIONS.md` 2026-10-10 — что оркестратор решает сам); вопрос с решением — выбор с разными последствиями, согласие на очередь, цель и проверка задачи, ручное действие, неясная граница — пользователю. Ответ ложится в таск-файл сразу, как получен, а перезапуск движка ждёт ответа на каждый вопрос блокера: первая строка «ответ:» снимает блокер для движка целиком. Ответ только в беседе стирает `/clear`: в обкатке 2026-10-26 ответы пользователя на два вопроса блокера ждали третьего пункта, беседу очистили, и новая беседа оркестратора задала те же вопросы заново. Перед каждым запуском оркестратор сверяет секцию и вопросы без строки ответа задаёт сам, без запуска движка: движок по первой строке «ответ:» запускает итерацию и с открытым вопросом пользователя. На страницу ответы уходят, когда ответ есть на каждый вопрос: команда `answer` убирает со страницы блок «Ждёт решения». Коммитит ответы следующая итерация — в обкатке на пилотном проекте оркестратор закоммитил ответы до разбора всех вопросов, и пользователь его остановил;
- лимит итераций, сбой сети или API, лимит подписки после сброса, шаг на несколько сессий с живым ходом в журнале — перезапуск без вопроса; итерация, упавшая на сбое сети, API или лимите подписки с правками без коммита, — перезапуск с резюме её сессии, тоже без вопроса: обрыв застаёт сессию посреди работы, и решать пользователю тут нечего (`DECISIONS.md` 2026-11-01); прочие правки без коммита в рабочем дереве — всегда вопрос пользователю, и сверка перед каждым запуском находит их и после разрыва беседы; таск-файл задачи — без счёта: в нём строки «ответ:»;
- «готово» — вопрос о следующей задаче: задачи переключаются только по согласию пользователя, шаги — сами (`DECISIONS.md` 2026-10-10 — переход оркестратора к следующей задаче).

Идущий движок оркестратор останавливает только по прямой просьбе «останови»: в обкатке он остановил идущий цикл на «не запускай», а пользователь имел в виду следующий запуск. Явный пуш — на «готово», вопрос пользователю и остановку, которую оркестратор не снял сам.

Предел контекста: от 150 тыс. токенов занятости контекста сессии оркестратор новых запусков движка не делает — ни перезапуска, ни следующей задачи (`DECISIONS.md` 2026-10-11 — предел контекста оркестратора). Сессия идёт часами, и каждое пробуждение добавляет в контекст вывод движка, журнал и правку страницы; новые запуски уходят в новую сессию со свободным контекстом. Проверка стоит перед каждым запуском, поэтому идущий движок доходит до своей остановки, оркестратор её разбирает, пишет ответы на блокер и заканчивает итогом со строкой продолжения. Занятость — по файлу переписки сессии `~/.claude/projects/*/<id сессии>.jsonl`: сумма токенов последнего ответа модели, как у хука context-guard без снимка (`container.md` § Хук context-guard); id сессии CLI передаёт командам Bash переменной `CLAUDE_CODE_SESSION_ID` (бинарь CLI 2.1.296). Источник работает без хука и строки состояния, на `jq`, который нужен и движку. Снимок строки состояния даёт то же число: на шести сессиях хоста 2026-10-11 совпадение в пяти; в шестой, возобновлённой сессии Remote Control, снимок — 0 до первого запроса к модели, а файл переписки хранит последнее число, 237 тыс. Цифра отстаёт на шаг, как у хука.

Id беседы Claude Code для поиска её истории — имя файла `~/.claude/projects/<папка проекта>/<id>.jsonl`, оно же поле `sessionId` записей. Окно, продолженное `/clear`, пишет каждую беседу в новый файл, а поле `session_id` записей и папка фоновых команд `/tmp/claude-<uid>/<папка проекта>/<id>/tasks/` хранят id запуска окна: оркестратор беседы `2c65a213-…` назвал в тексте шага своей беседой id запуска `299c845e-…`, и файл с этим именем хранит беседу 2026-10-10 о другом (2026-10-16). `$CLAUDE_CODE_SESSION_ID` после `/clear` ведёт на файл новой беседы: замер предела в шаге «Запуск движка» скилла оркестратора в беседе `2c65a213` дал её числа, 62,9 и 70,2 тыс.

Инструменты сессии, на которые опирается скилл, — по схемам инструментов и настроек CLI 2.1.296:

- окно вопроса `AskUserQuestion` — от одного до четырёх вопросов за вызов, у вопроса от двух до четырёх вариантов, свой ответ окно добавляет само; ответа ждёт без срока — настройка `askUserQuestionTimeout` по умолчанию `never`;
- пуш `PushNotification` — строка до 200 символов, с подключённым Remote Control — и на телефон; пропускается, когда пользователь у терминала. Ответ инструмента «Mobile push requested» — запрос пуша ушёл с компьютера, доставку на телефон он не подтверждает (бинарь CLI 2.1.296): в прогоне предела контекста 2026-10-11 пуш с таким ответом до телефона не дошёл, причина не выяснена;
- страница `Artifact` — у интерактивной сессии хоста: ею опубликованы страницы-примеры (2026-10-11); отложенным инструментом — загрузка `ToolSearch` запросом `select:Artifact`: так его получил фоновый подагент (проба 2026-10-15), так его загружает оркестратор, когда инструмент отложен, один раз за беседу; схема `Artifact` бывает в инструментах беседы с первого запроса, тогда оркестратор публикует сразу (`docs/researches/2026-10-15-page-agent.md` § Старт оркестратора и схема `Artifact`); интерактивная сессия `/box-next` хоста 2026-10-13 на CLI 2.1.296 инструмента не получила, причина не выяснена, — тогда страница живёт только файлом (скилл оркестратора, шаг «Страница задачи»); у итерации движка — `claude -p` на хосте — инструмента нет, публикацию страниц проверяет сессия хоста. Публикация берёт путь файла; первая — ещё `icon` и `description` одной фразой. Тот же путь в той же беседе публикуется по прежнему адресу; новая беседа правит прежнюю страницу, только передав её адрес в `url`, без него появляется новая страница по новому адресу. Открытая у зрителя страница получает новую версию сама. Потерянную ссылку на страницу инструмент называет в ответе, и её адрес больше не передаётся. Отказ «не видел живую версию» и проба публикации из другой беседы — `docs/researches/2026-10-15-page-agent.md` § Отказ «не видел живую версию»;
- фоновая команда Bash игнора SIGINT не несёт — проба 2026-10-11; `env --default-signal=INT` держит остановку и при запуске через `&` (`engine.md`, проба Ctrl+C). Описание инструмента с CLI 2.1.288 называет предел времени фоновой команды; в пилотном проекте движок фоном без `timeout` шёл 3 ч 01 мин и закончился своей остановкой (CLI 2.1.292, 2026-10-10).

Предпросмотр HTML-страницы через Playwright MCP: адрес `file://` он блокирует, а скриншоты сохраняет только внутри проекта: без имени файла — в `.playwright-mcp/` (вне `.gitignore`), с параметром `filename` — по пути от корня проекта, например сразу в `my_local/` (проба 2026-10-13); снимок с `filename` приносит в ответ только строку с путём, картинки в контексте нет (проба 2026-10-30, сервер `@playwright/mcp@latest`); в `.playwright-mcp/` же каждая загрузка страницы кладёт снимок разметки `.yml` и журнал консоли `.log`. Страница отдаётся локальным HTTP-сервером из `/tmp` в обёртке публикации — charset, viewport, сброс стилей, — скриншоты и служебные файлы после проверки уносятся из репозитория. Копия опубликованной страницы claude.ai со схемами Mermaid грузит библиотеку с адреса площадки `/_runtime/mermaid-<версия>.min.js`: без файла по этому пути в папке сервера схемы остаются текстом; копия библиотеки есть в официальном плагине Claude Code `code-modernization`, папка `assets/vendor/` (проба 2026-10-12). Страница с `scroll-behavior: smooth` прокручивается к якорю и по `scrollIntoView` плавно: замер и снимок сразу после перехода ловят середину прокрутки; перед ними — `document.documentElement.style.scrollBehavior = 'auto'` (проба 2026-10-12).
