# Контейнер — образ, изоляция, хук context-guard

## Образ и скрипт запуска — `container/`

Образ `maksim44/claude-box` — `node:20` с `jq` (сборка настроек при старте, хук context-guard), `python3-venv` (чтение `.env` проекта при старте; виртуальные окружения и pip для Python-проектов: системные пакеты ставит только root) и `iptables` (ограничение сети). Несёт образец, скиллы, базовые настройки с регистрацией хука context-guard (`/etc/claude-box/settings.json`), скрипт запуска — точку входа `/usr/local/bin/claude-box`, — точку входа ограничения сети `/usr/local/bin/claude-box-firewall` и программу чтения `.env` `/usr/local/bin/claude-box-env`. Собирается из корня репозитория под архитектуру машины сборки, сейчас amd64, — на каждой машине из клона agent-box: на Docker Hub образа пока нет, публикация — задача релиза (`ROADMAP.md` § Вехи). Claude Code ставит скрипт запуска при первом старте, официальным установщиком, в `~/.local` пользователя `node` — в домашнюю папку контейнера, дальше Claude Code обновляется сам в фоне; первый старт на пустой домашней папке шёл 40 с, повторный — 0,3 с (проба 2026-10-19, CLI 2.1.303, 273 МБ в домашней папке); `PATH` образа включает `/home/node/.local/bin`.

Подключения сервиса `claude`:

- папка проекта → `/workspace/<проект>`, явной строкой в рабочем каталоге и подключениях: сессии, автопамять и доверие Claude Code раскладывает по пути рабочего каталога, так у каждого проекта в общей домашней папке они свои. `<проект>` — имя проекта Compose проекта, у проекта без compose-файла — имя папки; подставляет его `box-update` (`template.md` § Обновление проекта). Путь — тот же, что давал `/workspace/${COMPOSE_PROJECT_NAME}` прежней схемы с общим именем проекта Compose, и сессии прежних запусков остаются на месте; у `claude-box.yml` своё имя проекта (`template.md` § Образец проекта). Строка `name:` основного файла в git общая у всех копий репозитория — клонов и рабочих копий git, — и путь в контейнере у них один: общие сессии, автопамять и доверие Claude Code; без строки путь у каждой копии от имени её папки;
- `claude-box.yml`, `.git/config`, `.git/hooks` и `.git/info` → те же пути внутри папки проекта, только на чтение, поверх её подключения: запись, `mv` и `rm` изнутри отклоняются, коммит проходит (пробы 2026-10-03, 2026-10-04, для `.git/info` — 2026-10-11, git 2.43.0); у дополнительной рабочей копии git (worktree) `.git` — файл, строка `gitdir:` в нём ведёт в `.git/worktrees/<имя>` основного репозитория, и с подключениями `./.git/…` контейнер не стартует: вместо них — `.git` основного репозитория по его абсолютному пути на хосте и поверх только на чтение его `config`, `hooks`, `info` по тем же путям — git рабочей копии и коммит проходят, запись, `mv` и `rm` в них отклоняются (проба 2026-10-14, `researches/2026-10-14-compose-local.md` § Проба worktree); строки пишет `box-update`; `git sparse-checkout` в контейнере отказывает — он пишет в `.git/config`. Обе папки git создаёт при `git init` и `git clone`; нет их на хосте — репозиторий создан `git init --template=` — Compose при запуске создаёт их пустыми от root: git хоста работает, а хук или строку списка исключений пользователь ставит только через `sudo` (проба 2026-10-11, Compose 5.6.0);
- `~/.claude-box` → `/home/node`: домашняя папка контейнера, общая для проектов машины — логин, история сессий, сам Claude Code; при первом запуске Compose создаёт её от root, скрипт запуска отдаёт её `node`;
- `~` → `/root/host-home`, только на чтение: `/root` закрыт для `node` — ни напрямую, ни через `/proc/<pid>/root`.

Права сервиса — `cap_add: [NET_ADMIN, NET_RAW]`: ими часть запуска от root ставит ограничение сети.

Модель сессий — `ANTHROPIC_MODEL: opus` в `environment:` сервиса: по приоритету Claude Code переменная окружения выше ключа `model` настроек (https://code.claude.com/docs/en/model-config), а в настройки контейнера этот ключ приезжает с хоста, где его пишет `/model` по Enter в любой сессии (п. 6 ниже). Смена модели проекта — другой псевдоним в строке, варианты — в комментарии над ней; на одну сессию — `/model` в ней.

`node` в образе — uid 1000: файлы, созданные в контейнере, на хосте принадлежат пользователю с тем же uid.

Скрипт запуска стартует от root и при каждом старте:

1. отдаёт домашнюю папку контейнера `node`;
2. ставит Claude Code, если лаунчера `~/.local/bin/claude` ещё нет;
3. переносит с хоста `~/.claude/CLAUDE.md`, `~/.claude/hooks/` и `~/.gitconfig` — автор коммитов протокола: есть на хосте — свежая копия, нет — копия прошлого запуска убирается;
4. кладёт свежую копию скиллов образа в `~/.claude/skills`;
5. берёт команду `statusLine` из хостового `settings.json`, переводит в ней пути внутри хостовой `~/.claude` в контейнерную и копирует файлы по ним;
6. собирает `~/.claude/settings.json` контейнера: регистрация хука из образа — при наличии скрипта хука; `language`, `model`, `effortLevel`, `modelSettings`, `attribution`, `includeCoAuthoredBy` и `statusLine` с переведённой командой — из хостового `settings.json`;
7. кладёт свежую копию конфига agent-box (`engine.md`) в `/etc/claude-box/config.yml` — оттуда порог раздела берут `/box-init` и протокол, `node` файл только читает. Клон — цель ссылки `~/.local/bin/agent-loop.sh` хоста, абсолютный путь хоста; от него отрезаются ведущие части, пока остаток не найдётся в подключённой домашней папке хоста: `/home/<пользователь>/tools/agent-box/agent-loop.sh` → `tools/agent-box/agent-loop.sh`. Клон вне домашней папки хоста или ссылки нет — копии нет, сессии берут порог по умолчанию. Правка конфига доходит до сессий со следующего старта контейнера. Проба 2026-10-15 на временной папке вместо домашней папки хоста, `dash`: ссылка и конфиг — копия; ссылка без конфига, ссылка вне папки, ссылки нет — копии нет, копия прошлого запуска убрана; на настоящей домашней папке — копия `config.yml` клона;
8. запускает `claude` от `node` через `setpriv` и программу чтения `.env`, аргументы запуска уходят в него. Ограничивающий набор прав пуст, повышение прав запрещено: права root, включая `NET_ADMIN`, процессам `node` недоступны и через setuid-программы (проба 2026-10-04: у `node` `CapBnd` 0, `NoNewPrivs` 1, `iptables -F` — отказ).

Из хостового `settings.json` берутся отдельные ключи: хуки и прочие пути в нём — абсолютные пути хоста. Правка хостового действует со следующего старта. Креды и переписка хоста, его скиллы, плагины, MCP из `~/.claude.json`, `keybindings.json` и ключи `~/.ssh` остаются на хосте.

Программа чтения `.env` работает уже от `node`: добавляет к окружению переменные `.env` из папки запуска — их получают Claude Code, MCP-серверы (`${VAR}` в `.mcp.json`) и команды агента — и запускает `claude`. Часть скрипта от root работает без переменных `.env`: строки `PATH` и `LD_PRELOAD` в нём действуют только на процессы `node` (проба 2026-10-04: из окружения контейнера, как при `env_file`, те же строки выполнили программу и библиотеку из папки проекта от root десятки раз, через программу чтения — ни разу). Ключи входа и переключатели провайдера — `ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN`, `CLAUDE_CODE_OAUTH_TOKEN`, `CLAUDE_CODE_USE_BEDROCK`, `CLAUDE_CODE_USE_VERTEX`, `CLAUDE_CODE_USE_FOUNDRY` — программа убирает из окружения: Claude Code в контейнере работает по подписке, программы агента этих ключей тоже не видят. Исключение — ключ итерации `agent-loop.sh --api` (`engine.md`): движок кладёт его в окружение контейнера под именем `CLAUDE_BOX_API_KEY`, программа убирает это имя и отдаёт значение Claude Code как `ANTHROPIC_API_KEY` — его видят и команды агента. Ключ она берёт только из окружения контейнера: строки `ANTHROPIC_API_KEY` и `CLAUDE_BOX_API_KEY` в `.env` проекта ключа не задают, а интерактивный запуск контейнера ключа не получает. Проба 2026-11-21 на хосте, `printenv ANTHROPIC_API_KEY` через программу: с `CLAUDE_BOX_API_KEY` в окружении — его значение, и при обеих строках в `.env`; без него — пусто, и при обеих строках в `.env`, и при `ANTHROPIC_API_KEY` в окружении.

Ограничение сети — точка входа `claude-box-firewall`: её задаёт итерациям в контейнере движок (`--entrypoint`), ручной запуск идёт через обычную. От root, до скрипта запуска, она собирает адреса: домены — `getent ahostsv4` на момент старта, диапазоны GitHub `web`, `api`, `git` — из `api.github.com/meta`, сети контейнера — маршруты без шлюза из `/proc/net/route`. GitHub не ответил — он закрыт до конца сессии, остальной список работает, а в stderr идёт строка `claude-box-firewall: предупреждение:`; её движок переносит в журнал цикла. Правила iptables:

- исходящие — loopback, ответы установленных соединений, DNS на любой адрес; сети контейнера — сервисы проекта и сам компьютер по адресу шлюза — и свои адреса проекта на все порты; Claude Code (`api.anthropic.com`, `claude.ai`, `platform.claude.com`, `downloads.claude.ai`, `code.claude.com`), npm и PyPI (`registry.npmjs.org`, `pypi.org`, `files.pythonhosted.org`) и GitHub — порты 80 и 443; прочее — отказ сразу (REJECT);
- входящие — loopback, ответы и сети контейнера;
- IPv6 — только loopback.

Затем самопроверка — `example.com` закрыт, `api.anthropic.com` открыт — и обычный скрипт запуска с `ENABLE_CLAUDEAI_MCP_SERVERS=false`: подключения аккаунта claude.ai идут через `mcp-proxy.anthropic.com`, а его адрес — адрес модели (2026-10-04 — 160.79.104.10, тот же у `claude.ai`, `platform.claude.com`, `code.claude.com`). Свои адреса проекта — `CLAUDE_BOX_ALLOW` в `environment:` сервиса `claude`: домены, адреса IPv4 и подсети через пробел или запятую, значение вписано в `claude-box.yml` — подстановку `${…}` Compose берёт из `.env`, который агент переписывает скриптом. Строку пишет `/box-init`, сессия, упёршаяся в закрытый адрес, ставит блокер с ней, дополненной адресом (`docs/PROTOCOL.md` § Таск-файлы). Закрытый адрес отвечает ошибкой соединения сразу (проба 2026-10-04: `curl` и `git` — `Couldn't connect to server`, Python — `Network is unreachable`, `fetch` Node — `fetch failed`). Без права `NET_ADMIN`, при домене без адреса или проваленной самопроверке старт останавливается с сообщением; без права — со строкой `cap_add` для compose-файла. Адреса доменов разрешаются один раз при старте: домен, сменивший адрес за время сессии, получает отказ. Пробы 2026-10-04: старт дольше на 1–2 секунды, первая установка Claude Code за ограничением проходит.

Разбор `.env` повторяет `env_file` Compose (compose-go, пакеты `dotenv` и `template`): комментарии, `export`, запись `ключ: значение`, кавычки и экранирование, многострочные значения в кавычках, подстановки `$VAR`, `${VAR}` с `:-`, `-`, `:+`, `+`, `:?`, `?` и `$$`, ссылки на имена ниже по файлу; ошибка разбора останавливает старт сообщением с номером строки, как отказ Compose. Сверено пробой 2026-10-04 с Compose 5.6.0: совпали 41 запись, строка из одного имени и шесть ошибочных записей. Расхождения с Compose:

- подстановки и строки из одного имени берут значения из окружения контейнера, у Compose — из окружения хоста: `${HOME}` в `.env` даёт `/home/node`;
- имена, уже заданные в окружении контейнера — образом (`PATH`), compose-файлом, движком (`CONTEXT_GUARD_MODE`), точкой входа ограничения сети (`ENABLE_CLAUDEAI_MCP_SERVERS`), — `.env` не перекрывает, у Compose `.env` перекрывает переменные образа;
- строка из одного имени последней в файле, без перевода строки, берёт значение из окружения, Compose на ней отказывает в старте.

## Ступени изоляции — режимы разрешений

Назначение ступеней — `DESCRIPTION.md` § Ключевые решения.

**Хост** — `--permission-mode auto --permission-prompts none`: чтение и правки внутри рабочего каталога проходят сами, остальное оценивает классификатор. Отказ классификатора прогон `-p` не останавливает: сессия видит отказ и ставит статус «блокер» — запись в таск-файл тоже правка внутри каталога. Интерактивная сессия с CLI 2.1.283 на любом плане стартует в том же auto, но после повторных отказов классификатора (3 подряд или 20 за сессию) переходит к вопросам пользователю, а модель может спросить его напрямую — поэтому пробный прогон включает строку итерации, запущенную руками. Auto бывает недоступен — выключен на сервере, модель без поддержки: тогда сессия стартует в Manual, в `-p` отказ получает любая правка, итерации идут без прогресса, и цикл останавливается по правилу трёх итераций.

Строгая альтернатива на хосте — `--permission-mode dontAsk` со списком разрешений: проходит только список и встроенный набор чтения. В списке обязательны правка файлов и коммит — `--allowedTools "Edit(./**)" "Bash(git add *)" "Bash(git commit *)"`: без них итерация не запишет ни результат, ни блокер. Команды проекта (тесты) дописываются в `.claude/settings.json` проекта. В правилах разрешений пробел перед `*` обязателен: `git diff*` цепляет и `git diff-index`.

**Контейнер** — итерации движка: ограничение сети и `--permission-mode bypassPermissions`, полная автономия; с `--no-firewall` — сеть открыта, режим auto с `--permission-prompts none`, как на хосте. Ручной `docker compose -f claude-box.yml run --rm claude` — сеть открыта, режим выбирает человек. Контейнер работает под non-root `node`: под root CLI bypass отклоняет. Bypass открывает агенту всё, что доступно в контейнере, — сеть ограничивает список адресов. Папка проекта подключена напрямую — правки ложатся в хостовый репозиторий; домашняя папка хоста агенту закрыта (§ Образ и скрипт запуска), push — с хоста. Контейнер следующего старта агент мог бы менять правкой `claude-box.yml`, файлом `compose.override.yml` или строкой `COMPOSE_FILE` в `.env`, а команды на хосте выполнять через `.git` проекта: настройки и хуки git срабатывают на `git status` хоста, а движок делает его после каждой итерации (`researches/2026-10-03-deny-rules.md`). Защита — четыре слоя:

- Правила запрета `permissions.deny` в `.claude/settings.json` образца — для сессий на хосте и в контейнере, действуют и в bypass. Агент не читает и не меняет `.env` и его рабочие варианты — `.env.local`, `.env.*.local`, `.env.development`, `.env.dev`, `.env.production`, `.env.prod`, `.env.staging`, `.env.test`; примеры вроде `.env.example` ему открыты. Не меняет `claude-box.yml` и настройки Claude Code проекта — их правит человек; не делает принудительный push. Основной compose-файл проекта с дополнениями агент правит, как остальной код: контейнер Claude собирается без него (явный `-f claude-box.yml`, слой ниже), правка видна в коммите. Правила ловят только инструменты Claude Code и распознанные им команды: скрипт агента их обходит, а в bypass агент может и стереть их — запись в защищённые пути `.claude/`, `.git/` bypass пропускает. Значения `.env` агент контейнера видит в окружении (§ Образ и скрипт запуска): правило закрывает сам файл.
- Подключения только на чтение поверх папки проекта — `claude-box.yml`, `.git/config`, `.git/hooks`, `.git/info`, у дополнительной рабочей копии git — те же три папки основного репозитория (§ Образ и скрипт запуска): изнутри контейнера их не меняет ничто. В `.git/info` лежит список исключений `exclude` — скрытая настройка: его строка прячет файл от git без следа в файлах проекта. Правку в нём сессия контейнера после «да» пользователя отдаёт ему командой для терминала хоста (`template/docs/PROTOCOL.md` § Личные данные и скрытые настройки); на хосте список охраняет только это правило. Живая проверка 2026-10-12, один разговор трижды в контейнере тестового проекта: на просьбу спрятать файл от git только на машине пользователя сессия проверяет доступ `test -w` и чтением, называет `.git/info/exclude`, спрашивает разрешения и после «да» даёт команду для терминала хоста; свои прошлые коммиты оставляет в истории ветки, свою строку `.gitignore` отменяет `git revert --no-commit` и `git commit -m`.
- Явный `-f claude-box.yml` у движка и ручного запуска, git хоста у движка — с выключенными fsmonitor и хуками (`engine.md`): основной compose-файл проекта, дополнение `compose.override.yml` и `COMPOSE_FILE` из `.env` контейнер следующего запуска не меняют, подложенные в `.git` fsmonitor и хуки на хосте не выполняются.
- Ограничение сети итераций движка (§ Образ и скрипт запуска): исходящие — только на адреса Claude Code, GitHub, npm, PyPI, сети контейнера и свои адреса проекта; прочие сайты, SSH, телеметрия и домашняя сеть отвечают отказом. Поиск в интернете работает — его ведёт бэкенд Anthropic, — а страницу по ссылке агент из контейнера не откроет: её загружает сам контейнер (`researches/2026-10-04-firewall.md`). Процесс агента правила не снимает: права сети у него отобраны.

Открыто: файл `.git/commondir` переадресует чтение настроек git в папку, которую агент может создать, — ручной `git status` пользователя на хосте выполнит команду из её настроек; у дополнительной рабочей копии то же делают её файл `.git` и файл `commondir` в её папке основного репозитория — оба открыты агенту на запись (проба 2026-10-14); `.claude/settings.local.json` с хуками, записанный скриптом агента, сработает в сессии Claude Code хоста в этом проекте. Ограничение сети работает по адресам, а адреса общие: у `mcp-proxy.anthropic.com` — подключений аккаунта claude.ai — адрес модели, их закрывает настройка Claude Code, и агент, обходящий её намеренно, до них дотянется; npm отвечает с адресов Cloudflare, PyPI — с адресов Fastly, где живут и чужие сайты, — доступны ли они через эти адреса, не проверено. Остаются каналы утечки через аккаунты постороннего на разрешённых сервисах и через DNS (`researches/2026-10-04-firewall.md` § Выводы для шага).

**Сессия хоста над контейнером** — интерактивная сессия Claude Code на хосте в режиме auto, которая запускает итерации в контейнере: оркестратор, просьба пользователя. Строку итерации классификатор читает как Create Unsafe Agents — автономный агент без вопросов о разрешениях, — а что за точкой входа `claude-box-firewall` стоит контейнер с ограниченной сетью, из текста команды не следует; правило разрешений Bash сверяет текст буквально и ломается от имени compose-файла и флагов (`researches/2026-10-10-auto-mode-host.md`). Исключение — правило песочницы, запись с меткой `Claude-box Sandbox:` в `autoMode.allow` личных настроек хоста `~/.claude/settings.json`: блок `autoMode` классификатор читает оттуда, из managed-настроек и флага `--settings`, настройки проекта ему закрыты. Правило пишет `agent-loop.sh --sandbox-rule` — человек в терминале: правку своих разрешений сессия хоста в режиме auto получает с отказом `[Self-Modification]`. Режим кладёт копию настроек `settings.json.bak-<дата>` рядом — первую за день, — заменяет запись с меткой текущей, ставит `"$defaults"` в начало списка, пока своего нет, — список без этой строки заменяет встроенные исключения целиком, — пишет поверх файла, сохраняя ссылку и права, и сверяет запись по `claude auto-mode config`; файла нет — создаёт его. Текст правила — в `agent-loop.sh`: разрешён запуск через `claude-box-firewall` с compose-файлом в корне проекта — с `-p`, `--resume`, `--session-id` и bypass, — не покрыты compose-файл вне корня проекта, запуск без этой точки входа — `--no-firewall`, ручной запуск, команда доследования итерации, которую печатает движок, — флаги подключения папок, пользователя и прав и переменные запуска `-e`/`--env` и `--env-from-file`, кроме двух переменных движка `CONTEXT_GUARD_MODE` и `CLAUDE_CODE_PROMPT_CACHE_TTL`: переменная запуска перекрывает строку `environment:` сервиса, и `-e CLAUDE_BOX_ALLOW=0.0.0.0/0` открывает сеть контейнера за точкой входа ограничения (проба 2026-10-11, Compose 5.6.0). Строку итерации с `--api` — с `-e CLAUDE_BOX_API_KEY` — правило не покрывает: сессия хоста запускает `agent-loop.sh`, строку контейнера собирает движок (`researches/2026-11-21-loop-api.md`). Правило — подсказка модели классификатора: отказы редки, гарантии нет. Проба 2026-10-11 в контейнере на временной домашней папке: создание файла, замена записи, свой список без `"$defaults"`, ссылка и права файла, файл не JSON — отказ без правки. Живая проверка 2026-10-11 на хосте с установленным правилом: сессия Claude Code в режиме auto в тестовом проекте с `docker-compose.yml` запустила строку итерации в контейнере и `agent-loop.sh <задача>` без отказа классификатора.

## Хук context-guard — сигнал на пороге контекста

Хук живёт в `~/.claude` хоста: скрипт `hooks/context-guard.sh` с порогами в `hooks/context-guard.conf`, его регистрация в `settings.json` на событиях `UserPromptSubmit` и `PostToolUse`, снимок занятости в конце скрипта строки состояния и раздел «Контекстное окно» в `CLAUDE.md` — текст сигнала выполнять как инструкцию. Хук сравнивает занятость контекста с порогом и печатает текст сигнала агенту в контекст; повтор — после роста занятости на заданный шаг.

Занятость считается по-разному:

- интерактивная сессия — по снимку строки состояния: размер окна приходит только в её данные, строка состояния сохраняет занятость и размер окна в файл сессии;
- headless — строки состояния нет: занятость по файлу переписки сессии, свой порог, размер окна неизвестен;
- подагент — по своему файлу переписки, свой порог; его сигнал — прекратить сбор данных и вернуть накопленное вызвавшему агенту.

Цифра отстаёт на шаг: токены считаются по факту запроса к модели, крупное чтение попадает в счётчик к следующему вызову инструмента.

Режим сигнала главной сессии — `CONTEXT_GUARD_MODE`; источник по приоритету: окружение процесса `claude` → строка `CONTEXT_GUARD_MODE=…` в `.claude/context-guard.conf` корня проекта → умолчание.

- Без режима — остановиться и предложить варианты: продолжить как есть; конспект в файл и новая сессия; свой вариант.
- `rules` — те же варианты, сохранение — по протоколу проекта, идущее завершение доводится без вопросов. Образец кладёт этот режим в проект файлом `.claude/context-guard.conf`.
- `protocol` — выполнить протокол завершения молча. Его ставит движок переменной окружения при запуске итерации.

Сигнал в сессии проекта — то же завершение, что штатное (`docs/PROTOCOL.md` § Протокол сессии), только раньше; так длинная сессия сохраняется по протоколу до встроенного автосжатия.

В контейнере скрипт хука приезжает копией `~/.claude/hooks/` хоста, регистрация — из образа, включается при наличии скрипта. Строка состояния хоста копируется вместе со своим скриптом ради снимка, когда скрипт лежит внутри `~/.claude` хоста: копируются только файлы оттуда (§ Образ и скрипт запуска, п. 5); хост без строки состояния — интерактивная сессия в контейнере считается по ветке headless. Хук работает на `jq`: без него выходит молча, и длинная сессия доходит до встроенного автосжатия; `jq` стоит в образе.
