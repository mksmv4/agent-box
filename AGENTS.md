# agent-box

Чтение на старте: @docs/RULES.md @docs/README.md @docs/PROTOCOL.md

## Суть проекта

agent-box — обвязка проектов под работу с Claude Code (`docs/DESCRIPTION.md`). Продукт — три папки, скрипт и конфиг: образец проекта `template/`, скиллы контейнера `skills/`, образ `container/`, движок автоцикла `agent-loop.sh` и конфиг agent-box `config.yml`; их файлы правятся как код. Хаб и документы в `template/` — правила проектов, куда ляжет образец; в этом проекте они не действуют: настройка `claudeMdExcludes` в `.claude/settings.json` выключает хаб образца, `template/CLAUDE.md` и `template/AGENTS.md`, а с ним и документы, которые он подгружает. Протокол и скиллы образца действуют и здесь — через ссылки (§ Жёсткие ограничения). Сам репозиторий ведётся по обвязке своим каркасом в корне — `AGENTS.md`, `docs/`, `.claude/`.

## Жёсткие ограничения

- Протокол и скиллы проекта в этом репозитории — ссылки на рабочие оригиналы: `docs/PROTOCOL.md`, `.claude/skills/box-next/`, `.claude/skills/box-orchestrate/`, `.claude/skills/box-task/` и `.claude/skills/box-review/` — на одноимённые пути в `template/`. Правка оригинала сразу действует в сессиях этого репозитория. Запись через ссылку Claude Code отклоняет и называет её цель — правится оригинал.
- `/box-init` на этом репозитории разберёт `template/` и `skills/` как старую документацию и унесёт их в архив; каркас этого репозитория правится руками.
- `/box-update` здесь не запускается: копию образца из образа он кладёт поверх протокола и скиллов проекта, а через ссылки она ляжет на рабочие оригиналы в `template/`. Свежесть протокола и скиллов здесь держат сами ссылки.
- Контейнер, открытый до пересборки образа, работает со старыми скиллами: копию скиллов образа скрипт запуска кладёт в `~/.claude/skills` только при старте. Правка `skills/` проверяется в новом контейнере после пересборки (`docs/architecture/ARCHITECTURE.md` § Правила зависимостей); повторный `/box-init` в старом контейнере сверяет очередь сборки со старым шаблоном и находит «совпадение».
- Беседа оркестратора, которая ведёт задачу правки своего же скилла, до конца работает по тексту `SKILL.md`, загруженному при вызове `/box-orchestrate`: правку, закоммиченную итерацией движка, она не видит, хотя ссылка ведёт на рабочий оригинал. Правка скилла оркестратора действует с новой беседы: `/clear` и снова `/box-orchestrate <задача>`.
- Движок по задачам самого agent-box — с `--host`: правил запрета и подключений только на чтение здесь нет, compose-файл и настройки — код продукта, и итерация в контейнере без вопросов о разрешениях меняет контейнер следующего запуска правкой `compose.yml`.
- Команды пользователю в блокере и итоге идут и в zsh: двоеточие сразу после имени переменной zsh читает модификатором — в `$p:template/compose.yml` модификатор `:t` берёт от `$p` последнюю часть пути, за ней идёт `emplate/compose.yml`. Переменная перед двоеточием — `${p}:…` или значение буквально.
- Команда инструмента Bash с `bash -c '<скрипт>'`, в тексте которого есть `rm` — даже словом шаблона `grep`, — получает отказ встроенной проверки удалений Claude Code: скрипт внутри `-c` она не разбирает и ждёт одобрения человека, а без него отклоняет команду. Скрипт пробы в контейнере — файлом в отдельной папке, подключённой в контейнер, вызов — `bash <файл>`.
- Правка настроек Claude Code в сессии хоста в режиме auto получает отказ классификатора `[Self-Modification]`: проба правила, расширяющего разрешения, даже на копии настроек во временной папке, запись скриптом в образец `template/.claude/settings.json`, убирающая правила запрета, и коммит файла настроек. Такую запись и такой коммит делает пользователь командой из блокера, пробу ведёт контейнер, установку на хосте — пользователь руками; подробности и команда пробы — `docs/researches/2026-10-10-auto-mode-host.md` § Отказы на правку настроек.

## Точки входа

- `README.md` — для человека: быстрый старт, задача скриптом и оркестратором, обновление agent-box и проектов, пересборка образа
- `template/` — образец проекта, который `/box-init` кладёт в проект
- `template/docs/PROTOCOL.md` — рабочий оригинал протокола
- `template/.claude/skills/box-next/SKILL.md` — рабочий оригинал `/box-next`
- `template/.claude/skills/box-orchestrate/SKILL.md` — рабочий оригинал `/box-orchestrate`: сессия хоста ведёт задачу движком
- `template/.claude/skills/box-task/SKILL.md` — рабочий оригинал `/box-task`: заведение задачи
- `template/.claude/skills/box-review/SKILL.md` — рабочий оригинал `/box-review`: шаги ревью готовой задачи
- `template/.claude/skills/box-qa/SKILL.md` — рабочий оригинал `/box-qa`: сценарии QA готовой задачи и этап их прогона на хосте
- `skills/box-init/SKILL.md` — `/box-init`: заведение проекта и шаблон задачи сборки документации
- `skills/box-init/documents.md` — карточки документов проекта
- `skills/box-update/SKILL.md` — `/box-update`: свежие протокол и `/box-next` в проекте
- `agent-loop.sh` — движок автоцикла на хосте: итерации `/box-next` в контейнере проекта или на хосте
- `box-connect` — первый запуск Claude в контейнере в папке проекта до `/box-init`; команду ставит первый `./agent-loop.sh`
- `config.yml` — конфиг agent-box, один на все проекты машины: пределы движка, порог раздела документации и модель агента проверок оркестратора
- `container/Dockerfile` — образ `claude-box`
- `container/entrypoint.sh` — скрипт запуска контейнера
- `container/env-run.py` — чтение `.env` проекта по правилам Compose и запуск Claude Code с его переменными
- `container/firewall.sh` — ограничение сети итераций движка: точка входа контейнера перед скриптом запуска
- `container/settings.json` — базовые настройки образа с регистрацией хука context-guard
- `compose.yml` — сервис `claude` этого репозитория
- `.claude/settings.json` — настройки Claude Code этого репозитория: `claudeMdExcludes` для `template/`
