Образец проекта — `/etc/claude-box/template/`, карточки документов — `~/.claude/skills/box-init/documents.md`. Текущий каталог — корень проекта.

1. **Git.** Коммит в конце забирает всё рабочее дерево, кроме правок пользователя в таск-файлах, поэтому на старте остальное дерево чистое. `.git` в корне — файл со строкой `gitdir:`, а git репозитория не видит, — это дополнительная рабочая копия git (worktree), и контейнер запущен без подключения основного репозитория: назвать это и закончить без правок, в итог — команда первого запуска рабочей копии для терминала хоста из её папки, `n=$(basename "$PWD" | tr A-Z a-z | tr -cd 'a-z0-9_-' | sed 's/^[-_]*//'); g=$(git rev-parse --path-format=absolute --git-common-dir); docker run --rm -it -v "$PWD":/workspace/"$n" -w /workspace/"$n" -v "$g":"$g" -v "$g"/config:"$g"/config:ro -v "$g"/hooks:"$g"/hooks:ro -v "$g"/info:"$g"/info:ro -v "$HOME"/.claude-box:/home/node -v "$HOME":/root/host-home:ro maksim44/claude-box`, и снова `/box-init` в нём. Каталог без git-репозитория: пустой — `git init`; с файлами — назвать это и закончить без правок: первый коммит проекта, что уходит в git, решает пользователь. `git status --porcelain` непуст — перечислить правки и закончить без правок. Исключение — повторный заход (в `docs/tasks/` есть таск-файл `docs-*`, шаг 2): строки таск-файлов `docs/tasks/*.md` — ответ на блокер, правка «Постановки» — в счёт не идут, кроме таск-файла `docs-*` со статусом не «готово»: его дорабатывает шаг 6. Такие таск-файлы остаются в рабочем дереве как есть, их забирает коммит сессии задачи.

Строка `gitdir:` ведёт git рабочей копии в основной репозиторий, а с подключениями `./.git/…` образца контейнер не стартует.

6. **Задача сборки.**
   - Доработка — есть таск-файл `docs-*` со статусом не «готово»: новая задача не заводится, «Постановка» этой задачи сверяется с шаблоном ниже. Шаг очереди узнаётся по началу строки — документу или слову до двоеточия. Незакрытый шаг «архив» сверяется с вариантом хранения, чей текст в нём стоит; ни одного варианта в нём нет — в списке правок вопрос о хранении, как у новой задачи. Шаги шаблона, которых в очереди нет, встают на своё место по шаблону незакрытыми; шаги раздела по областям — шаги своего документа: незакрытый шаг документа одним файлом они заменяют, за закрытым встают незакрытыми; незакрытые шаги и остальной текст «Постановки», расходящиеся с шаблоном, получают текст шаблона; шаги, которых в шаблоне нет, остаются на местах. Все правки — одним списком пользователю до записи, закрытые шаги с изменённым текстом — с вопросом, открыть ли их заново; запись — после ответа: «Постановку» меняет только пользователь. Открыть — чекбокс снят, текст шаблона; оставить — строка как есть. Опись в «Контексте»: у строк источников дописываются адресаты новых шагов, источники, которых там нет, — строками по шагу 5, строки раздела по областям — заново по шагу 5. Предложения в хвостах «Контекста», закрытые доработкой, убираются; «Следующий шаг» — первый незакрытый шаг очереди. Веха в `docs/ROADMAP.md` остаётся прежней.

В `docs/ROADMAP.md` § Вехи (раздела нет — дописать в конец) веха `Сборка документации <ISO-дата>` с чекбоксом, под ней строка задачи с чекбоксом и ссылкой на таск-файл.

Источники описи, разнесённые по документам, переносятся туда без правок, с тем же путём внутри архива, что был в проекте. <хранение архива> Дальше в `README.md` архива — карта: раздел `## <ISO-дата>` на сборку, строка на файл или папку: исходный путь в проекте (для переименованного — имя до `.old`) → путь в архиве, у бывших под gitignore — пометка «под gitignore». Источник, который сам остаётся документом проекта на прежнем месте, — глоссарий, собственный документ проекта в `docs/`, — в архив не переносится. Источники, что остаются на месте, отмечены в «Контексте» с причиной.

Проверка шага: документ соответствует своей карточке — обязательные разделы и границы, прежняя история от шага «история» — в своём формате; факты из кода и источников, относящиеся к документу, лежат в нём или в своём доме по карточкам; личные данные в документе обезличены, их исходные значения — в `my_local/personal.md` (`docs/PROTOCOL.md` § Личные данные и скрытые настройки); источники, взятые в работу, отмечены в «Контексте».

Чего не вывести из кода и файлов проекта — вопрос пользователю; в итерации движка окно вопроса (`AskUserQuestion`) получает отказ, и вопросы шага уходят одним блокером (`docs/PROTOCOL.md` § Таск-файлы); ответ — в `docs/DECISIONS.md` шагом 2 завершения.

Блокер: факт, без которого документ не написать, из кода и файлов не выводится, а ответа пользователя в сессии нет.

Шаги раздела по областям — на место строки своего документа в очереди, дословно; строка области — на каждую область из описи, `<область>` и `<папки>` — из её строки.

Раздел архитектуры:

```text
- [ ] `docs/architecture/ARCHITECTURE.md` — общая часть раздела по областям: сервисы, связи между областями, деплой, правила зависимостей между областями, § Области; прежний `docs/ARCHITECTURE.md`, когда он есть, переезжает сюда `git mv`
- [ ] `docs/architecture/<область>.md` — устройство кода области `<область>` (<папки>), правила зависимостей внутри неё, анти-паттерны
```

Раздел правил:

```text
- [ ] `docs/rules/RULES.md` — конвенции работы и общие конвенции кода; прежний `docs/RULES.md`, когда он есть, переезжает сюда `git mv`, строка хаба `@docs/RULES.md` становится `@docs/rules/RULES.md`
- [ ] `docs/rules/<область>.md` — конвенции кода области `<область>`; указатель — строка `@`-импорта этого файла в `CLAUDE.md` каждой папки области (<папки>), путь от папки указателя; свой `CLAUDE.md` папки остаётся на месте с отметкой в «Контексте», строка дописывается в него
```

Раздел одних правил — строка `docs/ARCHITECTURE.md` в очереди кончается так: `— устройство системы, правила зависимостей, анти-паттерны; § Области`.

Варианты хранения — текст на место `<хранение архива>`, дословно.

В git:

```text
Архив в git: файл в git — `git mv`; файл под gitignore — `mv` и строка на его путь в архиве в корневом `.gitignore` под комментарием `# сборка документации: бывшее под gitignore` (комментария нет — дописывается), прежняя строка сборки на него убирается; так он остаётся вне git и после удаления архива из git. `README.md` архива: первая строка `# Архив сборки документации`, под ней — «Артефакт сборки документации: что где лежало до неё. Папка в git; удаление — `git rm -r` папки: файлы, бывшие под gitignore, остаются в ней вне git — копии в истории у них нет.»
```

На диске:

```text
Архив на диске вне git: строка `/<папка архива>/` в корневом `.gitignore` под комментарием `# архив сборки документации`; файл в git — `git rm --cached` и `mv`, его прежняя версия остаётся в истории git под прежним путём; файл под gitignore — `mv`, его строка под комментарием сборки в корневом `.gitignore` убирается, опустевший комментарий — тоже. `README.md` архива: первая строка `# Архив сборки документации`, под ней — «Артефакт сборки документации: что где лежало до неё. Папка вне git, только на этой машине; удаление — кроме файлов с пометкой «под gitignore» в карте: копии в истории у них нет.»
```
