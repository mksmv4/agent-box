Образец проекта — `/etc/claude-box/template/`, карточки документов — `~/.claude/skills/box-init/documents.md`. Текущий каталог — корень проекта.

1. **Git.** Коммит в конце забирает всё рабочее дерево, поэтому на старте оно чистое. Каталог без git-репозитория: пустой — `git init`; с файлами — назвать это и закончить без правок: первый коммит проекта, что уходит в git, решает пользователь. `git status --porcelain` непуст — перечислить правки и закончить без правок.

2. **Заготовки.**
   - Первый заход — в `docs/tasks/` нет таск-файла `docs-*`. Занятые имена образца освобождаются переименованием: файл → `<имя>.old`, папка `docs/tasks/` или `docs/researches/` → `<имя>.old/`; `.old` тоже занято — `.old2`, `.old3`… Переименованное, что было под `.gitignore` проекта, остаётся вне git: новое имя — строкой в корневом `.gitignore` под комментарием `# сборка документации: бывшее под gitignore`, один комментарий на все такие строки. Папки `docs/`, `.claude/` и `.claude/skills/` остаются на месте, образец ложится в них рядом с содержимым проекта: в `.claude/` живут настройки проекта.
   - Повторный заход — таск-файл `docs-*` есть: `docs/PROTOCOL.md` — свежей копией поверх; остальные документы каркаса — рабочие документы проекта, остаются как есть.
   - `.claude/skills/box-next/` при любом заходе — свежей копией поверх: имя принадлежит обвязке, скиллы проекта под другими именами, включая `next` прежней обвязки, остаются на своих местах.
   - Затем недостающие файлы образца — копией (`cp -rn`).
   - `.gitignore` и compose-файл проекта при любом заходе остаются на своих местах — на них держатся git и Compose проекта. В `.gitignore` без строки `my_local/` она дописывается. При `compose.yaml`, `compose.yml`, `docker-compose.yaml` или `docker-compose.yml` в корне сервис `claude` из образцового `compose.yml` вписывается в `services:` файла проекта, если его там нет, — в подключении только на чтение `compose.yml` заменяется именем файла проекта; образцовый файл в проект не кладётся: Compose взял бы его вместо файла проекта. Сервису `claude` в compose-файле проекта недостающие подключения только на чтение образца дописываются с тем же именем. Строка `env_file` с `.env` у сервиса `claude` убирается: переменные `.env` скрипт запуска контейнера передаёт Claude Code сам, а через `env_file` они доходят и до его части с правами root.
   - В `.claude/settings.json` проекта дописываются через `jq` правила `permissions.deny` образца, которых в нём нет; остальное содержимое файла остаётся как было. Файла нет — он ляжет копией образца.
   - Запись в compose-файл или настройки отклонена — защита образца уже действует в этой сессии: недостающие строки и строку `env_file` на удаление — в итог, правит пользователь.

3. **Опись источников** — документы и заметки проекта вне каркаса, по путям и заголовкам: `*.md`, `*.txt`, содержимое `docs/`, раскладки других агентских инструментов, переименованное шагом 2 — с исходным именем (`README.md.old` ← `README.md`). Файлы под `.gitignore` — тоже, с пометкой «под gitignore»: копии в git у них нет; зависимости и артефакты сборки (`node_modules`, `.venv` и подобное) в опись не входят. Каркас — пути образца, `docs/tasks/`, `docs/researches/` и архив прошлых сборок — в опись не входит. Строка на источник: путь → для каких документов. Код и манифесты сборки шаги сборки читают напрямую. Пустой проект — опись пустая, содержимое документов придёт из вопросов пользователю.

4. **Задача сборки.**
   - Доработка — есть таск-файл `docs-*` со статусом не «готово»: новая задача не заводится, «Постановка» этой задачи сверяется с шаблоном ниже. Шаг очереди узнаётся по началу строки — документу или слову до двоеточия. Незакрытый шаг «архив» сверяется с вариантом хранения, чей текст в нём стоит; ни одного варианта в нём нет — в списке правок вопрос о хранении, как у новой задачи. Шаги шаблона, которых в очереди нет, встают на своё место по шаблону незакрытыми; незакрытые шаги и остальной текст «Постановки», расходящиеся с шаблоном, получают текст шаблона; шаги, которых в шаблоне нет, остаются на местах. Все правки — одним списком пользователю до записи, закрытые шаги с изменённым текстом — с вопросом, открыть ли их заново; запись — после ответа: «Постановку» меняет только пользователь. Открыть — чекбокс снят, текст шаблона; оставить — строка как есть. Опись в «Контексте»: у строк источников дописываются адресаты новых шагов, источники, которых там нет, — строками по шагу 3. Предложения в хвостах «Контекста», закрытые доработкой, убираются; «Следующий шаг» — первый незакрытый шаг очереди. Веха в `docs/ROADMAP.md` остаётся прежней.
   - Новая задача — таск-файла `docs-*` нет или все со статусом «готово»: `docs-<ISO-дата>` (имя занято — `docs-<ISO-дата>-2`), таск-файл `docs/tasks/<задача>.md` по шаблону ниже. До записи таск-файла — вопрос пользователю, где хранить архив разобранных файлов: «в git» — архив в репозитории и в каждом клоне; «на диске» — архив вне git, только на этой машине; в шаг «архив» ложится выбранный вариант хранения. В `docs/ROADMAP.md` § Вехи (раздела нет — дописать в конец) веха `Сборка документации <ISO-дата>` с чекбоксом, под ней строка задачи с чекбоксом и ссылкой на таск-файл.

5. **Завершение** — как у работы вне задачи: `docs/PROTOCOL.md` § Протокол сессии, «Завершение», шаги 1, 2, 4–6.

6. **Итог пользователю:** что легло из образца, что переименовано в `.old`, что дописано в `.gitignore`, compose-файл и `.claude/settings.json`, строки, запись которых отклонена, — с файлом и действием: дописать или убрать, имя задачи, при доработке — что изменилось в её очереди; файлы каркаса, попавшие под `.gitignore` проекта (`git check-ignore`), — назвать: в git они не попадут; дальше — `/box-next <задача>` в интерактивной сессии, сессия за сессией: сборка задаёт вопросы. Запуск был через `docker run` без compose-файла — дальше `docker compose run --rm claude`.

Шаблон таск-файла:

```markdown
статус: в работе

# docs-<ISO-дата>

## Постановка

Цель: документация проекта соответствует карточкам `~/.claude/skills/box-init/documents.md` и текущему коду; каждый факт живёт в одном документе; разобранные старые файлы лежат в архиве с картой исходных путей.

Очередь — шаг на документ:

- [ ] `docs/DESCRIPTION.md` — цели, стек, ключевые решения
- [ ] `docs/ARCHITECTURE.md` — устройство системы, правила зависимостей, анти-паттерны
- [ ] `docs/RULES.md` — конвенции кода и работы
- [ ] `docs/GLOSSARY.md` — канонические термины проекта; шаг закрывается без файла, если у проекта нет своих терминов
- [ ] `AGENTS.md` — суть проекта, жёсткие ограничения, грабли, точки входа; `CLAUDE.md` — одна строка `@AGENTS.md`
- [ ] `README.md` — quick start, запуск, деплой
- [ ] `docs/ROADMAP.md` — вехи и открытые вопросы из прежних планов, TODO и заметок
- [ ] история: прежние журналы и архивы вех из описи — в `docs/JOURNAL.md` и `docs/DONE.md` ниже записей сборки, под разделителем `## <ISO-дата> — записи до сборки документации`, без заголовка файла; прежние логи разведки — файлами в `docs/researches/`, имя `<дата>-<тема>.md`. Записи, карточки и логи копируются без правок, в прежнем формате; сами источники уходят в архив последним шагом
- [ ] `docs/DECISIONS.md` — решения пользователя из прежней истории: журналов, закрытых вопросов, заметок; запись на решение по карточке, дата — день решения, порядок — по дате, новые сверху; ответ — как записан в источнике, строки, которых источник не сохранил, — «не записано»; решения агента внутри работы остаются в журнале
- [ ] `docs/README.md` — строка на каждый документ `docs/`
- [ ] архив: папка `archive/` в корне (имя занято папкой проекта — `archive-2/`, `archive-3/`…; папка прошлой сборки, её `README.md` начинается строкой `# Архив сборки документации`, берётся она же). Источники описи, разнесённые по документам, переносятся туда без правок, с тем же путём внутри архива, что был в проекте. <хранение архива> Дальше в `README.md` архива — карта: раздел `## <ISO-дата>` на сборку, строка на файл или папку: исходный путь в проекте (для переименованного — имя до `.old`) → путь в архиве, у бывших под gitignore — пометка «под gitignore». Источник, который сам остаётся документом проекта на прежнем месте, — глоссарий, собственный документ проекта в `docs/`, — в архив не переносится. Источники, что остаются на месте, отмечены в «Контексте» с причиной.

Проверка шага: документ соответствует своей карточке — обязательные разделы и границы, прежняя история от шага «история» — в своём формате; факты из кода и источников, относящиеся к документу, лежат в нём или в своём доме по карточкам; источники, взятые в работу, отмечены в «Контексте».

Чего не вывести из кода и файлов проекта — вопрос пользователю в сессии; ответ — в `docs/DECISIONS.md` шагом 2 завершения.

Блокер: факт, без которого документ не написать, из кода и файлов не выводится, а ответа пользователя в сессии нет.
```

Варианты хранения — текст на место `<хранение архива>`, дословно.

В git:

```text
Архив в git: файл в git — `git mv`; файл под gitignore — `mv` и строка на его путь в архиве в корневом `.gitignore` под комментарием `# сборка документации: бывшее под gitignore` (комментария нет — дописывается), прежняя строка сборки на него убирается; так он остаётся вне git и после удаления архива из git. `README.md` архива: первая строка `# Архив сборки документации`, под ней — «Артефакт сборки документации: что где лежало до неё. Папка в git; удаление — `git rm -r` папки: файлы, бывшие под gitignore, остаются в ней вне git — копии в истории у них нет.»
```

На диске:

```text
Архив на диске вне git: строка `/<папка архива>/` в корневом `.gitignore` под комментарием `# архив сборки документации`; файл в git — `git rm --cached` и `mv`, его прежняя версия остаётся в истории git под прежним путём; файл под gitignore — `mv`, его строка под комментарием сборки в корневом `.gitignore` убирается, опустевший комментарий — тоже. `README.md` архива: первая строка `# Архив сборки документации`, под ней — «Артефакт сборки документации: что где лежало до неё. Папка вне git, только на этой машине; удаление — кроме файлов с пометкой «под gitignore» в карте: копии в истории у них нет.»
```
