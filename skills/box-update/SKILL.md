Образец проекта — `/etc/claude-box/template/`. Текущий каталог — корень проекта.

1. **Проверки.** Нет `docs/PROTOCOL.md` или `docs/tasks/` — назвать это и закончить без правок: проект заводится в обвязку `/box-init`. Коммит в конце забирает всё рабочее дерево, кроме таск-файлов, поэтому на старте остальное дерево чистое: строки `git status --porcelain` с путями вне `docs/tasks/` — перечислить правки и закончить без правок. Правки пользователя в таск-файлах — ответ на блокер, правка «Постановки» — остаются в рабочем дереве как есть: их забирает коммит сессии задачи.

2. **Сверка.** `diff -r` образца с проектной копией — у `docs/PROTOCOL.md`, `.claude/skills/box-next/` и `.claude/skills/box-orchestrate/`; проектной копии нет — проект заведён до появления скилла — тоже расхождение. Совпали все три — назвать это и закончить без правок: обвязка проекта свежая, либо контейнер открыт до пересборки образа и несёт старый образец.

3. **Копии.** Разошедшееся — свежей копией из образца поверх, папка скилла — целиком.

4. **Завершение** — как у работы вне задачи: `docs/PROTOCOL.md` § Протокол сессии, «Завершение», шаги 1, 2, 4–6. Таск-файлы в коммиты скилла не идут: `git add -A -- . ':!docs/tasks/'`.

5. **Итог пользователю:** что изменилось в работе сессий — словами поведения, по разнице из шага 2; скилл оркестратора лёг впервые — что он делает и запуск: `/box-orchestrate <задача>` в сессии Claude Code на хосте, настройка — раздел «Вести задачу оркестратором» в README agent-box; копии под `.gitignore` проекта (`git check-ignore`) — назвать: в git они не попадут. Дальше — `/box-next <задача>` в новой сессии: протокол приходит автозагрузкой хаба на старте сессии, эта сессия работает по старому.
