Текущий каталог — корень проекта. Задача — `$ARGUMENTS`; пусто — первый вопрос пользователю: какая задача.

1. **Проверки.** Нет `docs/PROTOCOL.md` или `docs/tasks/` — назвать это и закончить без правок: проект заводится в обвязку `/box-init`. Коммит в конце забирает всё рабочее дерево, поэтому на старте оно чистое: `git status --porcelain` непуст — перечислить правки и закончить без правок. Нет таск-файла `docs/tasks/<задача>.md` или статус в его первой строке не «готово» — назвать это и закончить без правок: ревью идёт по сделанной задаче.

2. **Коммиты задачи** — все, от первого: `git log --reverse --format='%h %s' --grep '<задача>'`; коммит, где имя задачи — часть имени другой задачи или слово в другом смысле, — не её.

3. **Деление.** Объём шага ревью — изменения его коммитов, таск-файл и `ARCHITECTURE.md` вместе; таск-файл, журнал и реестр шаг читает в нынешнем виде, поэтому их изменения в счёт не идут: `{ git show --format= <хэши> -- . ':!docs/tasks/<задача>.md' ':!docs/JOURNAL.md' ':!docs/DECISIONS.md'; cat docs/tasks/<задача>.md docs/ARCHITECTURE.md; } | LC_ALL=C.UTF-8 wc -m`; норма — размер шага из `docs/PROTOCOL.md` § Таск-файлы. Все коммиты в норме — один шаг. Больше — коммиты делятся на группы подряд, каждая в норме; коммит больше нормы — шаг сам по себе.

4. **Запись.** Шаги ревью — в конец очереди «Постановки», после её последнего чекбокса, по шаблону ниже. Первая строка таск-файла — `статус: в работе`. «Контекст» перезаписывается: следующий шаг — первый шаг ревью; неразобранные предложения прежнего «Контекста» переносятся.

5. **Завершение** — `docs/PROTOCOL.md` § Протокол сессии, «Завершение», шаги 1, 2, 4, 5; таск-файл — коммитом с именем задачи в сообщении: его хэш войдёт в следующую запись журнала о задаче.

6. **Итог пользователю:** сколько шагов ревью и по скольким коммитам; дальше — запуск в Claude `/box-next <задача>` или в терминале хоста из папки проекта `agent-loop.sh <задача>`. Шаг ревью с находками кончается вопросом: находки и предложенные шаги правок, ответ — «ок» или свой вариант строкой «ответ:»; шаги правок цикл ведёт как обычные. Без находок задача снова получает «готово».

Шаблон шага ревью; частей несколько — после «Ревью задачи» вставка `, часть <N> из <M>`; `<хэши>` — коммиты шага через запятую:

```text
- [ ] Ревью задачи, коммиты <хэши>: изменения — `git show <хэши> -- . ':!docs/tasks/<задача>.md' ':!docs/JOURNAL.md' ':!docs/DECISIONS.md'`, таск-файл, журнал и реестр — в нынешнем виде — сверяются с целью задачи, критериями её шагов, ответами пользователя по задаче (`grep 'задача: <задача>' docs/DECISIONS.md`), `RULES.md` и `ARCHITECTURE.md` и проверяются на ошибки — логика, краевые случаи, безопасность; другие коммиты и файлы проекта читаются по нужде; сомнительная находка перепроверяется чтением кода или запуском до записи; находка, отклонённая пользователем в `docs/DECISIONS.md`, повторно не предлагается. Находки — в секцию «Блокер» со статусом «блокер»: у каждой номер, что сломается, где, как чинить; под ними предложенные шаги правок — номера находок, что делается, чем проверяется, какие файлы читает, размер шага по `docs/PROTOCOL.md` § Таск-файлы, мелкие находки — одним шагом. По согласию пользователя шаги правок слово в слово, личные данные — обезличенным вариантом, вписывает в «Постановку» сразу после этого шага сессия, свой вариант — пользователь; чекбокс этого шага ставит сессия, увидевшая шаги там. Находок нет — чекбокс ставится сразу.
```
